# 首次配置引导

在已确定的目标仓库中初始化或修改配置时读取本文件。问卷由 Agent 发起，脚本负责补齐文件、校验配置和保存引导状态。安装方式和安装器版本不参与判断。

## 进入与准备

- `policy_query` 只解释规则，不建目录、不启动引导。
- 用户明确要求初始化或配置 handler 时进入 `configure`；仅需 Python 3.10+、PyYAML 和可写目标目录，不检查 Token/CANN、不访问 API、不 fetch，也不处理 Issue。若明确只补文件、不做配置引导，调用 `init_config.py --repository-root .` 后结束。
- `single`/`batch` 首次进入目标仓库时先补齐配置；安装器已创建目录或模板也必须检查。已确定缺 Token 的真实处理仍优先遵守原缺 Token 等待点，不插入新的配置问卷；凭据恢复后再继续引导。
- 目标仓库有歧义时先澄清，不能把配置写入 Skill 源码目录或全局安装目录。`repo` 的推导与冲突沿用 [runtime-setup.md](runtime-setup.md)；只配置时可留空，需要读 remote 才检查 Git。

```bash
python3 "$ISSUE_HANDLER_SKILL_ROOT/scripts/setup_config.py" --repository-root .
```

脚本只补齐缺失文件，并返回当前常用设置。配置格式错误、自动开关组合无效或引导状态损坏时，保留原文件并报告问题，不覆盖成默认值。
用户明确要求配置或调整参数时，在该命令后附加 `--reconfigure`，即使已有自定义配置或已完成引导，也按当前请求展示设置；普通首次检查不附加此参数。

| 返回 status | Agent 行为 |
| --- | --- |
| `pending` | 新配置、仅有模板，或用户主动重新配置；按下面的方式引导 |
| `existing` | 已有自定义或旧路径配置，直接沿用；可简要提示用户随时要求修改，不强制重配 |
| `configured` / `kept` | 用户已完成引导或明确保留当前设置；继续原任务，不因升级或再次启动重复询问 |

引导状态保存在目标仓库的 `.cannbot/gitcode-issue-handler/config/setup-state.json`，与是否存在配置文件分开判断。未收到回答时保持 `pending`；同一待回答问题只问一次，恢复会话时复用。用户已在当前会话明确给出相关设置或要求保留默认值时，直接采用该回答，不再询问同一件事。

## 询问与保存

先展示 `settings` 中的当前责任范围和两个自动开关，再询问“是否现在调整常用配置”，提供“配置常用参数”和“保留当前设置，继续”。责任范围必须如实展示：模板默认处理公共组件及 A5/arch35 相关问题，不能描述为默认处理所有 Issue。

用户选择配置时，只询问尚缺的信息，能合并成一轮的合并询问：

| 常用项 | 配置方式 |
| --- | --- |
| 目标仓库 `repo` | 沿用已确认目标；唯一候选可自动填写，有歧义才问；仅配置时可留空 |
| 责任范围 `responsibility` | 用自然语言询问正常处理、仅列举和忽略的范围；用户回答后转成 YAML 列表 |
| 响应方式 | 让用户在下表三种组合中选择，保留当前有效设置；新模板默认均关闭 |

| 选择 | auto-response | auto-assign | 含义 |
| --- | --- | --- | --- |
| 先审稿，确认后发送 | false | false | 先保存分析和草稿 |
| 自动响应和明确负责人转交 | true | false | 包含必要首响、已有修复 PR 作者或明确 owner 的分配 |
| 同时自动临时指派候选人 | true | true | 责任仍不明确时，可从调查候选中临时指派一人，仍需确认真正负责人 |

候选自动分配不能在自动响应关闭时开启。配置引导不改变 [automation.md](automation.md) 中的授权范围；关闭、挂起、代码修改和交付仍遵守原流程。负责人映射、兜底账号和扫描窗口按用户需要再配置，不强制在首次引导中填完；Token 不写入配置或引导记录。

根据用户回答，只编辑选中的 YAML 字段，保留其他字段、注释和已有负责人映射；不以整份模板替换配置。保存后展示结果；明确回答已经覆盖准确字段和值时不再重复确认。随后校验并记录完成：

```bash
python3 "$ISSUE_HANDLER_SKILL_ROOT/scripts/setup_config.py" --repository-root . --complete
```

用户明确选择保留当前设置时，不编辑 YAML，只记录该选择：

```bash
python3 "$ISSUE_HANDLER_SKILL_ROOT/scripts/setup_config.py" --repository-root . --keep
```

`--complete` / `--keep` 只在收到用户相应回答后执行；超时、取消、无问卷能力或仅创建文件都不代表确认。没有问卷工具时用普通文字询问；无人值守且没有明确配置选择时保留 `pending`，不擅自启用开关。未收到回答时，只推进不依赖该配置选择的独立工作；依赖责任范围或自动开关的分类、发布等操作等待回答。记录完成后，仅配置任务到此结束，真实处理任务继续原检查点。

## 再次配置

用户明确要求调整现有配置时，重新打开引导并展示当前设置：

```bash
python3 "$ISSUE_HANDLER_SKILL_ROOT/scripts/setup_config.py" --repository-root . --reconfigure
```

配置文件由用户手工修改后仍按当前值生效，不因与引导时不同而恢复旧值。`init_config.py` 保留为只补文件的手工入口，它不记录“用户已配置”，也不替代上述引导。
