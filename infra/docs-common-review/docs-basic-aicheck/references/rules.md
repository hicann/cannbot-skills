# 通用 Markdown 文档质检规则 - 详细说明

**重要提示：**

- 仅使用本文件中明确定义的规则进行检查
- 规则名称、规则级别必须与本文件完全一致

## 1. 正确性检查

检查文档内容是否存在事实性或书写性错误。此类检查基于文档文本内容，不需要读取代码。

| 规则项名称 | 规则名称 | 规则类型 | 描述 | 级别 |
| ---------- | -------- | -------- | ---- | ---- |
| AICheck | 中文错别字检查 | 正确性 | 检查中文字符是否存在漏写、拼写错误、形近字、音近字等错别字 | 严重 |

### 中文错别字检查

- 位置：Markdown 文档中的所有中文字符（包括标题、正文、列表项、表格内容等，不包括代码块、代码段内的内容）。
- 规则：
   1. 漏写字：中文词语中缺少必要的汉字（如"硬盘固件"写成"硬盘固"）。
   2. 拼写错误：汉字顺序颠倒或位置错误（如"硬盘固件"写成"硬件固盘"）。
   3. 形近字错误：使用字形相近但含义不同的汉字（如"型号"写成"形号"、"既使"写成"即使"）。
   4. 音近字错误：使用读音相近但含义不同的汉字（如"即使"写成"既使"）。
- 排除范围：
   1. 英文字符、英文单词、英文缩写的拼写错误等。正例："inferhape"的拼写错误不需要统计。
   2. 中文标点符号、英文标点符号。
   3. 代码块、代码段、命令行中的代码内容（不含注释）。
   4. URL 链接、文件路径。
   5. 内容完整性、术语缺失、语法结构、文档结构等问题不属于本规则检查范围。
- 判断标准：检查到的中文字符是否在语义上正确，是否存在上述 4 类错误。

## 2. 可读性检查

检查文档的表达质量、结构组织和信息呈现方式，提升文档的可理解性和专业性。

| 规则项名称 | 规则名称 | 规则类型 | 描述 | 级别 |
| ---------- | -------- | -------- | ---- | ---- |
| AICheck | 写作风格一致性检查 | 可读性 | 检查同一文档内写作风格与 Markdown 格式样式是否统一 | 提示 |
| AICheck | 内容一致性检查 | 可读性 | 检查同一文档内术语、概念、参数、单位、名称等表达是否一致 | 一般 |
| AICheck | 内容冗余性检查 | 可读性 | 检查文档内同类或跨类元素是否存在信息冗余 | 一般 |
| AICheck | 内容可读性检查 | 可读性 | 检查文档内容是否易理解、句式清晰、无语义赘述、保持专业性 | 提示 |
| AICheck | 代码段可读性检查 | 可读性 | 检查代码段中的注释是否准确、代码逻辑是否清晰 | 提示 |

### 写作风格一致性检查

- 位置：同一 Markdown 文档内的写作风格与 Markdown 格式样式，包括章节标题、段落内容、列表项、表格内容、代码注释等文本元素。
- 规则：
   1. 语气与语调：检查全文语气是否统一，是否保持专业、严谨的风格，避免口语化表达。
   2. 人称与视角：检查全文人称是否统一，不要相互矛盾。建议使用"开发者"、"您"、"用户"表示阅读者，避免同一文档内对同一对象一会儿用"用户"一会儿用"开发者"。
   3. 中英文标点符号习惯：检查以下场景中，语句末尾标点符号（如句号、分号等）的有无是否遵循同一惯例（即该场景中多数条目句末有标点则应有，无则应无）：
      - 代码注释中的句末标点
      - 表格单元格中的句末标点
      - 无序列表项的句末标点
      - 有序列表项的句末标点
      - 不检查正文段落的标点使用。
   4. Markdown 渲染样式一致性：检查同一个列表（无序列表/有序列表）内各项之间的 Markdown 格式样式是否一致，包括：
      - 加粗的使用是否一致（仅检查 Markdown 语法如 `**text**`，不检查 HTML 语法如 `<b>`、`<strong>`）
      - 斜体的使用是否一致（仅检查 Markdown 语法如 `*text*`，不检查 HTML 语法如 `<i>`、`<em>`）
      - 颜色标注的使用是否一致（检查 HTML 语法实现的颜色标注，如 `<span style="color:red">`）
   5. Markdown 写作元素一致性：AI 需识别文档中是否为同一类型阐述维度（如参数说明、约束说明、公式、配置项等），若是，则检查其 Markdown 样式是否一致。具体包括：
      - 无序列表/有序列表与表格并存时：当同一类型内容既有无序列表/有序列表形式又有表格形式，且列表项数量超过 10 个时，推荐使用表格样式呈现，以提升信息密度和可读性。
      - 无序列表/有序列表与语句并存时：当同一列表上下文中，部分条目使用了无序列表/有序列表标记（如 `-`、`1.`），部分条目缺少标记变成了独立语句段落，推荐将独立语句补充列表标记融入列表样式，保持呈现形式统一。
   6. 同类元素格式一致性：检查文档中列表之外的同类元素的 Markdown 格式样式是否一致，包括但不限于：
      - 同类标题/标签项的格式一致性（如"交付件 1"和"交付件 2"应统一使用加粗或不加粗格式）
      - 同类参数名/变量名的格式一致性（如加粗、斜体、代码格式等）
      - 同类说明文字的格式一致性
- 排除范围：
   1. 代码块、代码段、命令行中的代码内容（不含注释）。
   2. URL 链接、文件路径。
   3. 不同类型阐述维度之间的样式差异（如参数说明用表格、约束说明用列表，属于合理差异，不算不一致）。
- 判断标准：
   1. 同一文档内写作风格是否保持连贯，是否存在明显的风格切换或矛盾。
   2. 同一类型阐述维度内的 Markdown 格式样式是否保持统一。
   3. 标点符号是否遵循"跟随大部分场景"的多数一致原则。
- 补充参考：[写作风格一致性补充说明](./consistency_in_writing_style.md)

### 内容一致性检查

- 位置：Markdown 文档内的术语、概念、参数、单位、名称等表达。
- 规则：
   1. 术语一致性：同一术语在全文中的表达应一致（如"算子库"不能一会儿写成"算子库"，一会儿写成"Operator 库"）。
   2. 概念一致性：同一概念的表述应一致（如"神经网络"不能一会儿用全称，一会儿用"NN"缩写，除非首次出现已定义）。
   3. 参数一致性：同一参数名称、参数格式应一致（如"input_size"不能一会儿用下划线，一会儿用驼峰"inputSize"）。
   4. 单位一致性：同一物理量的单位表达应一致（如长度单位不能一会儿用"mm"，一会儿用"毫米"）。
   5. 名称一致性：人名、机构名、产品名等应保持一致。
   6. 语义一致性：同一文档内对同一对象、功能、约束的描述应保持语义一致，不应出现前后矛盾（如一处说"支持X"，另一处说"不支持X"）。
- 检查位置：包括正文、标题、列表项、表格内容、代码注释、公式等所有文本内容。
- 排除范围：
   1. 代码块、代码段中的变量名、函数名等技术术语（这些有编程规范约束）。
   2. URL 链接、文件路径。
   3. 必要的缩写变化（如首次出现用全称并标注缩写，后续使用缩写）。
- 判断标准：同一术语、概念、参数、单位、语义在同一文档内的多次出现是否表达一致。

### 内容冗余性检查

- 术语约定：本规则中"列表"指 Markdown 无序列表（`-` 或 `*` 标记）和有序列表（数字 `.` 标记）；"NOTE 段"指 Markdown 引用块（`>` 标记）。
- 位置：Markdown 文档内的标题、段落、表格、列表、语句、参数、代码段、NOTE 段等信息单元。
- 规则：同一 Markdown 文档内，同一章节或跨章节均需检查。分为两类：

  **一、同类元素冗余（信息重叠度≥80% 判定为冗余）**
   1. 标题冗余：检查是否存在内容相同或高度相似的重复标题。
   2. 段落冗余：检查是否存在内容相同或高度相似的重复段落。
   3. 表格冗余：检查是否存在内容相同或高度相似的重复表格。
   4. 列表冗余：检查是否存在内容相同或高度相似的重复列表项。
   5. 语句冗余：检查是否存在内容相同或高度相似的重复句子。其中，在表格、列表、代码块、NOTE 段等结构化元素内，若两处连续 80 个字符完全一致，判定为冗余语句。
   6. 参数冗余：检查是否存在重复定义或重复说明的参数。
   7. 代码段冗余：检查是否存在内容相同或高度相似的重复代码段。
   8. NOTE 段冗余：检查是否存在内容相同或高度相似的重复 NOTE 段。

  **二、跨类元素冗余（不同类型元素之间表达同一信息）**
   9. 表格与列表冗余：表格中的信息与无序列表/有序列表项表达的内容重叠度≥70%，即同一信息在表格和列表中重复表达。
   10. 表格与代码段冗余：表格中包含代码示例，而文档其他段落（如正文、列表）中也存在相同或高度相似的代码样例。
   11. 列表与 NOTE 段冗余：无序列表/有序列表项的信息与 NOTE 段中的信息重叠度≥70%。
   12. 列表与代码段注释冗余：无序列表/有序列表项的信息与代码段中的注释内容重叠度≥70%，即列表已在说明的内容在代码注释中又重复描述。
   13. 段落与列表冗余：正文段落的信息与无序列表/有序列表项表达的内容重叠度≥70%，即段落中已说明的内容在列表中又重复描述，或反之。
   14. 段落与代码段注释冗余：正文段落的信息与代码段中的注释内容重叠度≥70%，即段落中已说明的内容在代码注释中又重复描述。
   15. 段落与 NOTE 段冗余：正文段落的信息与 NOTE 段中的信息重叠度≥70%，即段落中已说明的内容在 NOTE 中又重复强调。

- 排除范围：
   1. 不同章节对同一概念从不同角度、不同深度的说明（见判断标准 3）。
   2. 示例代码的合理重复（如多个示例展示同一功能的不同用法、不同参数组合）。
   3. 代码块、代码段内非注释内容的命名差异（如仅变量名、函数名不同但逻辑结构相同的代码段，仍属于第 7 条代码段冗余的检查范围）。
   4. 表格标题、图片标题等必要的说明性文字。
- 判断标准：
   1. 同类元素冗余：信息重叠度≥80% 判定为冗余；语句冗余以连续 80 个字符完全一致为判定阈值。
   2. 跨类元素冗余：信息重叠度≥70% 判定为冗余。
   3. 如果重复有明确的目的（如强调关键风险、对比差异、不同用法示例、从不同角度或不同深度说明同一概念），则不算冗余。
   4. 跨类冗余中，若一方信息是另一方的子集（摘要/概括）或超集（补充/扩展），不算冗余。
   5. 信息重叠度判定方法：对比两个元素的核心语义信息点，重叠信息点数量占较少一方信息点总量的比例。
- 补充参考：[内容冗余性补充说明](./content_redundancy.md)

### 内容可读性检查

- 位置：Markdown 文档的正文内容、标题、列表项、表格内容等文本内容（不包括代码块、代码段内的内容）。
- 规则：
   1. 内容易理解性：检查内容是否易于理解、无歧义、无模糊表达。
      - 歧义表达：语句存在多种理解方式，未明确唯一含义（如"这个参数可以设置"未说明具体设置方式，无法确定是"允许设置"还是"能够设置某值"）。
      - 模糊表达：使用不确定的措辞，使读者无法获得明确的信息（如具体数值、确定条件、明确范围）。常见模糊词语包括但不限于：比较、相对、大概、可能、也许、似乎、差不多等——仅当这些词语使读者无法从该表述中获得明确信息时，判定为模糊表达；若模糊词本身即为所需表达（如"比较两个方案"中的"比较"表示对比动作），则不算违规。
   2. 句式结构清晰性：检查句子结构是否清晰，是否存在语法错误。
      - 病句：如缺少主语、缺少谓语、语序混乱等。中文技术文档中符合语言习惯的省略句不算病句（如"配置完成后，重启服务"省略了"需要"，属于合理省略）。
      - 标点与断句错误：如逗号缺漏导致长句无停顿、句号误用导致语义被错误切分、引号或括号不匹配等。
   3. 语义赘述与篇幅冗长：检查单句或同一段落内是否存在语义层面的冗余表述，导致核心信息不明确。本条检查的是语句级语义赘述，与内容冗余性检查互补——内容冗余性检查关注段落、表格、列表等结构化元素之间的信息重复，本条关注语句内部的语义冗余。具体子类型如下：
      - 近义/包含义词语堆叠：连续使用含义相同或存在语义包含关系的词语（如"道路崎岖不平"——崎岖已包含不平的含义；"完全彻底"——完全已包含彻底的含义）。
      - 修饰词冗余：修饰词的含义已包含在被修饰词中（如"非常巨大"——巨大已包含非常大的含义；"免费赠送"——赠送已包含免费）。
      - 语法冗余主语/宾语：在语法上可省略的代词或名词重复指代（如"FA 算子，它是一种"——"它"在语法上可省略，去掉后句子结构完整）。
      - 副词冗余：使用可省略的强调或程度副词，包括副词堆叠（如"可能也许"——两个情态副词堆叠）和可省略副词（如"基本上算是"——"算是"可省略）。
      - 句内含义重复：同一句话内出现含义重复的表述（如"通过分块计算的方式进行分块计算"——方式与动作完全重复）。
      - 句间语义重复：同一段落内两句（含非相邻句）的核心语义信息点重叠度≥80%，且第二句未提供第一句未涵盖的新信息。
      - 换言重述/正反重述：说完一条信息后，又用不同措辞（包括换用否定方式）重述同一信息，无新信息增量（如"它避免存储完整矩阵，也就是说它不需要把整个矩阵保存下来"——后半句换言重述前半句；如"能减少显存占用，也就是说不会占用太多显存"——后半句用否定方式重述前半句）。
      - 解释过度：对术语或概念的解释部分未提供超出术语名称本身已传达的任何新信息（如"HBM 即高带宽显存，是一种高带宽的显存"——解释重复了缩写已包含的信息，未提供任何新内容）。
   4. 专业性检查：检查是否存在口语化表达（如"咱们"、"咋样"、"搞定"等），应保持技术文档的专业性。
   5. 术语首次出现规范：检查术语首次出现时是否同时提供拼写全称和中文释义（如"CANN（Compute Architecture for Neural Networks，神经网络计算架构）"）。仅首次出现时需要标注，后续使用缩写不算违规。若术语无中文释义，提供拼写全称即可。术语的判断标准：在当前文档领域中，非通用词汇且具有特定技术含义的专有名词、缩写、框架名称、协议名称等（如 CANN、HBM、OPS 算子）；通用词汇（如"参数"、"配置"、"部署"）不算术语。
- 排除范围：
   1. 代码块、代码段、命令行中的内容。
   2. URL 链接、文件路径。
   3. 已定义的缩写后续使用（即术语首次已规范标注，后续仅使用缩写）。
   4. 合理的修辞手法（如排比、反复等有明确修辞目的的表达不算赘述）。
   5. 必要的强调性重复（如风险警告、安全提示等有明确目的的重复表述）。
   6. 中文技术文档中符合语言习惯的省略句（如"配置完成后，重启服务"省略了"需要"，属于合理省略，不算病句）。
- 判断标准：
   1. 歧义/模糊表达：是否存在使读者无法确定唯一含义或无法获得明确信息的表述。
   2. 句式结构：是否存在语法错误或标点断句问题影响语义理解。
   3. 语义赘述：是否存在语句级冗余表述，且该冗余无修辞目的或强调目的。
   4. 专业性：是否存在口语化表达破坏技术文档风格。
   5. 术语规范：术语首次出现时是否提供了完整的全称和释义。
- 补充参考：[内容可读性补充说明](./content_readability.md)

### 代码段可读性检查

- 位置：Markdown 文档中的代码块（用 ` ``` ` 标记的代码段）和命令行示例。
- 前置条件：仅当代码块或命令行示例中包含注释时，才执行本规则的检查。如果代码块或命令行示例中没有注释，则跳过本规则检查。
- 规则：
   1. 注释准确性：检查注释内容是否准确描述代码功能，是否存在误导性注释（如注释说明与实际代码逻辑不符）。
   2. 内容逻辑清晰性：检查代码逻辑是否清晰易懂，变量命名是否合理，代码结构是否清晰（仅检查有注释的代码段）。
- 排除范围：
   1. 没有注释的代码块和命令行示例（不执行任何检查）。
   2. 代码语法错误（这属于代码正确性，不属于可读性）。
   3. 代码性能问题。
   4. 代码风格问题（如缩进、空格等格式问题）。
   5. 注释的完整性（不检查是否缺少注释，仅检查已有注释的准确性）。
- 判断标准：代码段中的注释是否准确描述代码功能，是否存在误导性注释，代码逻辑是否清晰易懂。
