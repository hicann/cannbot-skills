# docs-branch-update（分支固定项修改）

对仓库分支必要的固定修改项进行自动修改。**需在需要修改的版本分支上执行**（脚本按当前
git 分支确定版本映射；在 master/main/HEAD 分支上执行链接更新会被拒绝）。两类修改项由两个
独立脚本分别承载，可按需单独执行，也可依次执行完成全部处理：

| 修改项 | 脚本 |
| --- | --- |
| 文档参考链接的版本号更新 | `scripts/update_links.py` |
| 删除不必要的产品内容（npu 标签） | `scripts/remove_npu_tags.py` |

两个脚本**根据用户意图直接修改文件**，修改完成后输出修改清单（可用 `git diff` 复查、
`git checkout` 回退）。全程字节级处理，保持文件原有编码与行尾（LF/CRLF）不变。

## 使用方法

命令中 `<技能目录>` 指本 skill 所在目录：本仓中为 `infra/docs-branch-update`，安装后为 `.agents/skills/docs-branch-update`。命令在目标仓库根目录执行，`<目录|文件>` 缺省为 `<仓库根>/docs/zh`。

```bash
# 模式一: 只更新链接
python3 <技能目录>/scripts/update_links.py [-d <目录|文件>] [-b <分支>]

# 模式二: 只删除产品内容 (NPU 标签)
python3 <技能目录>/scripts/remove_npu_tags.py [-d <目录|文件>] [--npu 类型...]

# 模式三: 两者都处理 (依次执行两个脚本)
python3 <技能目录>/scripts/update_links.py
python3 <技能目录>/scripts/remove_npu_tags.py
```

| 参数 | 是否可选 | 说明 | 适用脚本 |
| --- | --- | --- | --- |
| `-d, --dir` | 可选 | 目标目录（递归全部 `.md`）或单个 `.md` 文件，默认 `<仓库根>/docs/zh` | 两者 |
| `-b, --branch` | 可选 | 目标版本分支，默认自动获取当前 git 分支 | update_links |
| `--npu` | 可选 | 待删除的 NPU 标签类型，可多个；缺省从文档写作规范"分支文档维护要求-产品标签使用要求"在线获取不允许存在的标签范围（仅在未显式指定时查询一次） | remove_npu_tags |
| `--output` | 可选 | 将修改清单写入指定文件（markdown） | 两者 |

## 工作流

1. **分支前置校验（强制拒绝）**：链接更新前先确认分支——当前 git 分支（`git branch --show-current`）或用户通过 `-b` 指定的分支。若分支为 `master`/`main`/`HEAD`，必须拒绝执行链接更新：不调用脚本、不修改任何文件、不输出修改清单，并明确回复用户："当前分支为 '<分支名>'，链接版本更新无意义。请先切换到版本分支（如 `git checkout 9.3.0-beta.1`），或通过 `-b` 显式指定版本分支。"（仅删除 NPU 标签与分支无关，不受此限制）；
2. 按用户意图选择模式直接执行（只更新链接 / 只删除产品内容 / 两者都处理）；
3. 查看脚本输出的修改清单（分支映射、逐文件命中统计、链接替换前后对照、404 回退统计、NPU 删除/改写统计）；
4. 复查后按需提交，必要时用 `git checkout` 回退。改动文件较多时不逐行人审，按以下方式复查：
   - **范围对账**：`git diff --stat` 的文件清单、增删行数与修改清单的文件列表和统计比对，不一致说明有异常（如并发写入或误伤）；
   - **抽查明细**：选取代表文件 `git diff` 看具体改动内容；
   - **完备性自检**：重新执行一次应零命中（幂等验证，确认无遗漏）；改动集中在少量文件时可逐行复查。

## 处理规则

### 链接版本更新（update_links.py）

以当前分支 `9.3.0-beta.1` 为例（Ascend 分支 `26.2.0`、文档版本号 `930beta1`）：

| 规则 | 匹配 | 替换 | 示例 |
| --- | --- | --- | --- |
| gitcode cann | `gitcode.com/cann` 仓的 `/blob/master/`、`/tree/master/`（`cann-samples`、`pypto-gym` 仓除外） | `master` -> 当前版本分支 | `master` -> `9.3.0-beta.1` |
| gitcode cann/pypto-gym | `cann/pypto-gym` 仓的 master 链接（该仓无 beta 分支） | `master` -> 上一个正式版本（beta 按分组规则映射） | `master` -> `9.2.0` |
| gitcode Ascend | `gitcode.com/Ascend` 仓的 master 链接（`Ascend/docs`、`Ascend/pytorch` 仓除外） | `master` -> 映射的 Ascend 分支 | `master` -> `26.2.0` |
| gitcode Ascend/pytorch | `Ascend/pytorch` 仓的 master 链接 | `master` -> CommonTerms 手册名称汇总表第三列第一个 pytorch 链接的分支号（懒加载在线查询） | `master` -> `v2.14.0-26.2.0` |
| hiascend CANN 社区版 | `CANNCommunityEdition` 的 `/latest/` | `latest` -> 分支名删除 `.` 与 `-` | `latest` -> `930beta1` |
| hiascend Pytorch | `Pytorch` 的 `/latest/` | `latest` -> Ascend 分支删除 `.` | `latest` -> `2620` |
| hiascend TensorFlow | `TensorFlowCommunity` 的 `/latest/` | `latest` -> 分组后的 `9.x.0` 删除 `.` | `latest` -> `920` |

分支映射规则（9.x.0 与 9.(x+1).0-beta.* 同组）：

- CANN 正式版 `9.X.0` -> Ascend `26.X.0`；CANN 测试版 `9.X.0-beta.N` -> Ascend `26.(X-1).0`
  （如 `9.1.0` 与 `9.2.0-beta.*` 均对应 `26.1.0`，`9.2.0` 与 `9.3.0-beta.*` 均对应 `26.2.0`）；
- TensorFlowCommunity 分组规则同上，得 `9.x.0` 后删除 `.`（如 `9.3.0-beta.1` -> `9.2.0` -> `920`）；
- `cann/pypto-gym` 仓无 beta 分支，分组规则同上并保留版本号格式
  （beta `9.X.0-beta.N` -> `9.(X-1).0`，如 `9.3.0-beta.1` -> `9.2.0`；正式版 -> 同名版本）。

当前分支为 `master`/`main`/`HEAD` 时拒绝执行；分支不符合版本号规则时对应链接保持原样并告警；
`Ascend/pytorch` 的分支映射需在线访问 gitcode.com（懒加载，仅当目标中存在该类链接时才查询，
整个运行过程只查询一次），**映射未获取时该类链接不做替换、保持原样**，并在修改清单
“未替换链接”部分逐条列明链接与具体原因（如 Ascend/docs 仓还未创建
`'<Ascend分支> TorchNPU手册名称汇总.md'`、请等待创建；或汇总表第三列未找到
Ascend/pytorch 链接或分支号，请检查该表）。

先按映射直接修改链接，修改完成后对全部替换后链接（去重）在线校验：**校验发现替换目标为 404
的链接逐处回退为原链接**（不保留无效修改），修改清单"404 回退明细"部分逐条列明链接列表与
原因（替换后目标 404：分支或路径不存在）并告警；限流/不可达/跳过（hiascend 为 SPA 站点）
不回退，如实报告并建议复查。

仅替换**完整的 `master` 分支段**：`master` 之后不能是字母、数字、下划线、点或连字符
（`/`、`?`、`#`、`)`、空格等任意非分支字符或链接结尾均可），
`master-backup`、`masterDocs` 等以 master 为前缀的其他分支链接不受影响。

### 产品内容删除（remove_npu_tags.py）

**待删除标签缺省范围**：从 cann/docs 仓文档写作规范 `specification/document_writing_specs.md`
"分支文档维护要求"章节的"产品标签使用要求"列表项在线获取——即"不允许存在`IPV350,5162A,x90,9020,9030,9050,kirin1,kirin2,kirin3` 标签内容"中不允许存在的标签列表；
仅在未显式指定 `--npu` 时查询一次，获取失败时退出并提示显式指定 `--npu`。

标签格式：
```
<!-- npu="950,A3,910b,910" id1 -->...<!-- end id1 -->
```
""中间为类型列表，idX为id+数字格式，start/end 按 id 配对，嵌套可正确匹配。

| 场景 | 处理方式 |
| --- | --- |
| 类型列表仅含目标类型（如 `npu="x90"`） | 整块删除（行首 `>` 引用前缀及缩进随块整行删除，行内标签仅删块本身，兼容 LF/CRLF） |
| 混合类型包含目标类型（如 `npu="950,A3,x90"`） | 从列表移除目标类型，保留块内容 |
| 移除后列表为空（含多类型逐个移除，如 `x90,9030`） | 删除整个标签块及内容 |
| 嵌套目标类型子块 | 删除子块，外层混合块改写后保留 |

删除接缝处同步清理冗余内容（**局部生效**，仅处理与接缝相邻的序列，不处理文件其他位置的
既有 `<br>`/空行，避免误删正常格式）：

- 接缝处 3+ 连续 `<br>`：整体删除；
- 接缝处 2+ 个 `<br>` 紧跟表格单元格分隔符 `|`：收敛为单个空格；
- 接缝处 3+ 连续空行：收敛为 1 个空行（行尾风格保持不变）。

## 修改清单

两个脚本各自输出所属修改项的清单：分支与版本号映射（链接脚本）、逐文件命中统计、
链接替换前后对照明细（去重）、404 回退统计、未替换链接明细（保持原样，含具体原因）、
NPU 标签列表改写明细（按最终数据对账：仅统计最终存活的改写，已整删块不计入；
被改写多次的块沿改写链合并，报告原始列表 -> 最终列表）、汇总与告警，可用 `--output` 落盘留档。

**修改后链接有效性校验**（update_links.py 修改完成后自动执行，结果追加到清单）：

- 对本次修改产生的所有唯一链接（去重后）做在线校验，gitcode.com 链接通过 GitCode API
  校验分支与路径存在性（有路径用 contents API、仓库根链接用 branches API），
  按 OK / 404 / 格式异常 / 限流 / 不可达 / 跳过分级报告；
- **校验 404 的链接逐处回退为原链接**（不保留无效修改），在清单"404 回退明细"部分
  逐条列明（规则、原链接 -> 替换目标、处数）与原因说明（替换后目标 404：分支或路径不存在）
  并告警请人工确认；限流/不可达的链接不回退、修改保留，如实报告并建议重跑复查；
- 并发校验内置 WAF 突发限流防护：API 请求全局限速（相邻请求起始间隔 ≥ 0.1s，约 ≤10 req/s），
  429 优先按 Retry-After 头等待、否则指数退避（1s/2s/4s + 抖动）重试，耗尽报"限流"并告警，
  403（WAF 拦截页常见）延迟重试一次；限流与不可达区分，避免误报；
- www.hiascend.com 为 SPA 站点，HTTP 状态不反映内容存在性，跳过校验、修改保留。
