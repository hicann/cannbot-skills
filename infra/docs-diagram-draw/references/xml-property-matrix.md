# drawio 改图范围矩阵

本矩阵服务于**改图（工作流二）**：可修改键白名单与逐键规则——按 XML 结构元素分表（第 1/2 节）+ 样式键按类别分表（第 3 节）；矩阵外属性一律保留原值。

规范源（仅限这两个源头；源仓 gitcode.com/cann/docs，版本指纹 `sources.manifest`，漂移用 `scripts/check_sources.sh` 校验）：
- 条款：https://gitcode.com/cann/docs/blob/master/specification/drawing_specs.md
- 取值：https://gitcode.com/cann/docs/blob/master/writing_template/drawing_template_drawio.xml（46 条模板条目统计取证）

## 0. 判定总则

改图默认**一切保持原样**。权限列按两个场景分别标注两态：

| 场景 | 驱动 | 可修改的判定 |
| --- | --- | --- |
| **规范化** | 规则批量执行 | 有可推导目标值的具体规则（/，或检视沉淀规则） |
| **自定义** | 用户点名执行 | 该键允许经 edit 指令修改（键集 = edit 白名单 + value/label 文字通道） |

**规则列只写可修改场景的规则，不可修改不列规则**（⛔ 的依据在含义列与第 0.5 节兜底原则中）。

**改动的合法性 = 场景内可修改 + 改后可验证**（未触碰项 diff 为零、渲染产物可正常打开）。
两条铁律不变：不手写 SVG 画面；样式串从 `references/style-library.md` 原样复制。

## 0.5 用户输入 → 矩阵映射与兜底原则

- **规范化调整**：用户三个选择（颜色/字体/容器）映射到键组（颜色→3.1、字体→3.2 仅 fontFamily，规范化暂不支持改字号、容器→2.4 画布行）；未选类别按规则默认执行（描边/白字守卫/线型/箭头类型/圆角）。全图扫描 → 按规则推导目标值 → edit 指令集批量执行。
- **自定义调整**：每个点名 `(元素, 属性, 目标值)` 查该行权限列——两场景均 ⛔ 的键不执行，告知依据与替代建议（用可修改键等效实现，或走工作流一重画）；✅ 则生成元素级决策单（对象×属性×现值→目标值×依据，联动项显式）确认后经 edit 指令执行，回读 diff 验证只动点名对象（所有自定义修改的统一流程：用户点名 → edit 执行 → 回读 diff 验收）。
- **模糊诉求**（"太乱/好看点"）→ 反问澄清分流到两模式，不猜不擅动。
- **矩阵外属性一律保留原值**（兜底）。
- **结构性硬约束**（全场景生效）：不删/不增/不重排 root 子元素、不解包 UserObject、不改任何元素的 id/parent。

## 1. 顶层结构 —— 两场景均不可修改

### 1.1 文件骨架

```xml
<mxfile host modified agent version type pages compressed page>   ← 文件外壳
  <diagram id name>                                                 ← 页（可多页；内容可为压缩文本）
    <mxGraphModel dx dy grid gridSize guides tooltips connect arrows
                  fold page pageScale pageWidth pageHeight math
                  shadow background backgroundImage>               ← 模型（视口+画布属性）
      <root>                                                        ← 元素容器（无属性）
        <mxCell id="0"/>                                            ← 根占位（恒为空）
        <mxCell id="1" parent="0"/>                                 ← 默认图层（parent 恒为 0）
        … UserObject / mxCell …
```

顶层结构属性（`mxfile` 外壳 / `diagram` 页签 / `mxGraphModel` 视口与页面尺寸、背景等）两场景均 ⛔——与渲染输出和图内容无关，由兜底规则（矩阵外属性一律保留原值）覆盖；结构红线见 0.5 节硬约束。

## 3. 样式键（style 串内，按类别）

### 3.1 颜色键（顶点与边通用）

| 属性 | 含义 | 权限 | 规则 |
| --- | --- | --- | --- |
| `fillColor` | 形状填充色（#RRGGBB） | 规范化 ✅ / 自定义 ✅ | 规范化：①微偏色（同族色距 ≤8）先合并 ②板内色→保持自身 ③无彩色（黑/灰）→保持原样 ④有彩色→**优先级取色**（深色块按序取高亮色 #5478FB→#03B5A5→#2AA6F3→#FB8F2B→#CD0000，浅色块按序取默认色 #C2D5FE→#B0F0E2→#B9E9FC→#E0E2E6→#FEE2BA→#FAB9B6；组内按亮度从深到浅依次取位；全部有彩色都是深色时→深对浅全取默认色；**一对一铁律**）。完整规则与示例见附录二；自定义：点名，目标值=用户指定或按附录二建议 |
| `gradientColor` | 渐变第二色（与 fillColor 成渐变） | 规范化 ⛔ / 自定义 ⛔ | - |
| `strokeColor`（顶点） | 顶点描边色 | 规范化 ✅ / 自定义 ✅ | 规范化：二态判定——原来有描边→统一 #686D75（边框色），原来无描边→保持 none（见 3.1.1）；自定义：点名 |
| `strokeColor`（边） | 连线颜色 | 规范化 ✅ / 自定义 ✅ | 规范化：按 3.1.1 边线判定（语义彩色线原样保留，仅中性黑灰归一 #686D75）；自定义：点名（语义线也依用户指定） |
| `fontColor` | 文字颜色 | 规范化 ✅ / 自定义 ✅ | 规范化：→#202329；深底（高亮色系/#686D75）→#FFFFFF；**白字守卫**（深块映射浅色后 value 内白字改 #202329；fill=none 浮动标签按空间包含判定背后块色） +；自定义：点名（白字守卫仍适用） |
| `labelBackgroundColor` | 标签底色（边分支"是/否"标签用） | 规范化 ✅ / 自定义 ✅ | 规范化：→#FFFFFF；自定义：点名 |

### 3.1.1 strokeColor 判定细则

**顶点描边**（二态判定）：

| 判定条件 | 目标值 | 说明 |
| --- | --- | --- |
| 原来有描边（strokeColor 有值，含白色/深色/彩色描边） | **#686D75**（统一边框色） | 描边统一为规范边框色 |
| 原来无描边（strokeColor=none） | **none**（保持无描边） | 不新增描边 |

fill=none 的层级框/线框/异形描边（花括号等）属于"有描边"，同一规则统一为 #686D75。

**边线色**：

| 判定 | 通道极差 = max(R,G,B) − min(R,G,B) | 处理 |
| --- | --- | --- |
| 语义彩色线 | 极差 > 64（如 #26C4B1 青、#FF0000 红） | **原色保留 + 原线宽保留**（线宽不归 0.75） |
| 中性黑灰线 | 极差 ≤ 64（如 #000000、#666666、#A0A0A4、#191919） | 归一 #686D75 + 线宽 0.75 |

彩色线承载原图语义（红=依赖、青=数据流、蓝=指令流），全量归灰曾致"连线语义丢失/视觉淹没"；自定义场景用户点名可覆盖（含语义线）。

## 4. 权限分布总结

- **规范化可改**：fillColor（优先级取色）、strokeColor 顶点（二态归一）与边（语义保留/中性归一）、fontColor（白字守卫）、labelBackgroundColor、fontFamily、圆角三键、strokeWidth、dashed/dashPattern、startArrow/endArrow（类型归一）、画布容器 width/height（用户选归档时）。
- **仅自定义可改**（规范化 ⛔）：fontSize、startSize/endSize、startFill/endFill、value/label 文字、顶点几何 x/y/width/height、连线路由 13 键。
- **两场景均 ⛔**：不在本文档行内的全部属性（兜底规则一律保留原值）——结构（id/parent/增删元素/解包）、形状（shape/stencil）、拓扑（edge/source/target）、文字锚点（align/spacing）、透明度、路由子元素（waypoints/显式端点）等。

## 附录二：颜色一对一入板映射（目标值判定链）

规范化调整批量推导目标值，或自定义调整时给用户建议目标色，均按此判定链（保类型区分、禁多对一）：

```
收集待改色块的原填充色（排除 none/白/无彩色——黑白灰不参与映射）
  → 微偏色合并（同族色距 ≤8 并为代表，块数多者代表）
  → 板内原色（#C2D5FE/#E0E2E6/#B9E9FC/#B0F0E2/#FEE2BA/#5478FB/#03B5A5/#686D75/#EDEFF2/#F4F5F7）→ 映射自身并占位
  → 无彩色（黑/灰，通道极差 ≤16）→ 保持原样不动（黑底白字/灰底深字自洽；
    不计内容色数）
  → 有彩色 → 按下方"有彩色映射三步法"处理
```

### 有彩色映射规则（优先级取色）

**色板（优先级从高到低）**：

| 类别 | 色值（优先级序） |
| --- | --- |
| 高亮色（深位池） | #5478FB > #03B5A5 > #2AA6F3 > #FB8F2B > #CD0000 |
| 默认色（浅位池） | #C2D5FE > #B0F0E2 > #B9E9FC > #E0E2E6 > #FEE2BA（警示） > #FAB9B6（警示） |
| 中性色 | 文字 #202329；边框 #686D75；填充 #E0E2E6 / #EDEFF2 / #F4F5F7 / #FFFFFF |

**流程**：

```
第 0 步 排除：黑白灰（无彩色）不参与映射，保持原样
第 1 步 分深浅：亮度 = (0.299R + 0.587G + 0.114B) / 255；≤0.5 为深色、>0.5 为浅色
第 2 步 场景判定（判断范围 = 图内全部有彩色 fillColor）：
  A. 深浅兼有：
     深色块 → 按亮度从深到浅排序，依次取高亮色优先级位
              （第 1 深取 #5478FB、第 2 深取 #03B5A5、第 3 深取 #2AA6F3、
                第 4 深取 #FB8F2B、第 5 深取 #CD0000；
                超过 5 个深色 → 溢出接默认色优先序）
     浅色块 → 按亮度从深到浅排序，依次取默认色优先级位
              （#C2D5FE → #B0F0E2 → #B9E9FC → #E0E2E6 → #FEE2BA → #FAB9B6）
  B. 全部有彩色都是深色（无浅色）→ 深对浅：全部按默认色优先序取
     （全深图若映射高亮色会形成大面积强调，违反"强调色非必要不用、避免大面积"）
  C. 全部浅色 → 同样按默认色优先序取
第 3 步 一对一铁律：图内不同原色不得映射同一目标色
```

**示例**（深浅兼有图，4 深 + 2 浅）：

| 原色 | 亮度 | 档位 | 组内排位 | 分配结果 |
| --- | --- | --- | --- | --- |
| #FE0203 | 0.30 | 深 | 第 1 | **#5478FB**（高亮优先级 1） |
| #305497 | 0.32 | 深 | 第 2 | **#03B5A5**（高亮优先级 2） |
| #538135 | 0.42 | 深 | 第 3 | **#2AA6F3**（高亮优先级 3） |
| #379E90 | 0.49 | 深 | 第 4 | **#FB8F2B**（高亮优先级 4） |
| #668CBC | 0.53 | 浅 | 第 1 | #C2D5FE（默认优先级 1） |
| #5C9BD5 | 0.57 | 浅 | 第 2 | #B0F0E2（默认优先级 2） |

注意：优先级取色**不做色相匹配**（深红映射高亮蓝是本规则的预期行为）；色板内高亮/默认两组各自池位在图内被"板内原色保持自身"占用时，分配顺延跳过（保一对一）。
