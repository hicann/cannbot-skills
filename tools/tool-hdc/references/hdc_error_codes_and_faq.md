# hdc 错误码与常见问题

> 不同版本返回的错误文本可能变化。脚本判断应优先使用错误码，不要依赖提示文案。

## 错误码分类

| 前缀 | 主要范围 |
| --- | --- |
| `E000xxx` | 通用、授权、连接 |
| `E001xxx` | 连接与命令参数 |
| `E002xxx` | 服务进程 |
| `E003xxx` | shell 命令 |
| `E005xxx` | 文件传输 |
| `E006xxx` | 应用安装 |
| `E007xxx` | 其他 |
| `E00Cxxx` | 调试拦截 |

## 常见错误码

| 错误码 | 典型含义 | 建议动作 |
| --- | --- | --- |
| `E000001` | hdc 版本过低，不支持授权 | 升级 SDK |
| `E000002` | 设备未授权 | 在设备上确认信任弹窗 |
| `E000003` | 设备用户未授权 | 切换或登录正确用户后重试 |
| `E000004` | 通信不稳定 | 等待几秒后重试 |
| `E000006` | 当前电脑被禁止调试 | 在开发者选项中允许当前电脑调试 |
| `E000010` | 设备鉴权失败 | 重新插拔或重新授权 |
| `E001000` | tmode 不支持设置 USB 调试 | 改用设备端开关 |
| `E001001` | 命令未知 | 用 `hdc -h` 核对拼写 |
| `E001003` | USB 连接异常 | 换线/换口，必要时 `hdc reconnect` |
| `E001005` | 设备未知或已断开 | `hdc list targets` 后重新连接 |
| `E001104` | tconn 的 IP 格式非法 | 核对 `IP:port` |
| `E001106` | `-e` 指定的 IP 不正确 | 核对监听地址 |
| `E001300` | 模拟器不支持 tmode | 在真实设备上执行 |
| `E002101` | server 进程无法结束 | 清理 hdc 进程后 `hdc kill -r` |
| `E002105` | 当前版本不支持该命令 | 升级 hdc 或换用其他命令 |
| `E002106` | 设备通信异常 | 执行 `hdc kill -r` 后重试 |
| `E003001` | bundle 名非法 | 用 `bm dump -a` 查询正确包名 |
| `E003002` | 当前参数不支持交互模式 | 去掉交互用法 |
| `E003004` | 设备端不支持该参数 | 升级设备系统或更换参数 |
| `E003005` | 命令参数有误 | 核对参数个数和格式 |
| `E005003` | 文件传输缺少参数 | 补全源路径和目标路径 |
| `E005004` | SDK 或设备不支持 `-b` | 升级到 hdc 3.1.0e / API 15+ |
| `E005005` | 创建目录失败 | 检查目录权限，或先 `hdc shell mkdir -p` |
| `E005008` | 不支持的文件传输操作 | 检查参数组合，避免使用未开放的 `-z` |
| `E005101` | `-b` 的 bundle 名非法 | 核对包名 |
| `E005102` | 远端路径非法 | 确认路径存在且没有越出应用目录 |
| `E006001` | 安装包路径非法 | 核对 HAP 本地路径 |
| `E007100` | 当前版本或平台不支持该命令 | 换命令或升级环境 |
| `E00C001` | client/server 调试被拦截 | 按提示解除拦截 |

## 常见问题

### `hdc list targets` 返回 `[Empty]`

按顺序排查：

1. 设备管理器或 `lsusb` 是否能看到 HDC 设备。
2. 设备上的 USB 调试开关是否打开。
3. 是否出现授权弹窗，需要在设备上确认信任。
4. 更换 USB 线、接口或电脑，排除硬件问题。

### 设备显示 `Unauthorized`

设备尚未授权当前电脑。在设备上点击信任；如果反复失败，可在开发者选项中撤销 USB 调试授权后重新插拔。

### Linux/macOS 普通用户找不到设备

Linux 下通常需要配置 udev 规则，或把当前用户加入 USB 访问组。可以先用管理员权限验证是否为权限问题。

### hdc 无法启动

- 缺少 `libusb_shared`：把依赖文件和 hdc 放在同一目录。
- PATH 未配置：把 toolchains 目录加入 PATH 后重开终端。

### 中文文件名传输异常

较新版本支持中文文件名；旧版本建议统一使用英文文件名，避免编码问题。

### Windows 报 `CryptAcquireContext failed`

系统加密服务异常。重启 Windows Cryptographic Services 后重试。

### 命令卡住或无响应

```bash
hdc kill -r
hdc -l 5 start
```

日志通常位于执行 hdc 的机器的临时目录：Windows `%temp%`、Linux `/tmp`、macOS `$TMPDIR`。

### 通用排查顺序

1. `hdc list targets` 查看设备状态。
2. 检查 USB 设备是否被系统识别。
3. `hdc kill` 后以高日志级别重启 server。
4. 查看 hdc 日志定位失败阶段。
5. 核对 hdc 版本与设备系统版本是否配套。
