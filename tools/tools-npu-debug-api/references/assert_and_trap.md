# assert、ascendc_assert 和 __trap

资料基线及版本适用性见 [平台与编程模式支持矩阵](platform_matrix.md#来源基线)。示例为调用片段，使用前需核对目标版本和编程模式。

## 断言

### 接口功能

- **输入**：条件表达式，以及目标模式支持的可选格式字符串和参数。
- **行为**：启用时检查条件；为真则继续，为假则触发异常并按模式输出断言上下文。
- **输出**：失败时的诊断信息和算子异常，而非一个供业务逻辑使用的布尔返回值。SIMT/SIMT VF 的自定义消息应使用受支持的 `ascendc_assert` 形式。
- **不保证**：关闭断言后不会继续保护访问边界；条件和格式参数中不得放置程序正确性所依赖的副作用。消息也可能受模式和容量限制。
- **最小示例**：以下单参数示例用于检查不变量，多参数形式使用前核对模式。

```cpp
#include "utils/debug/asc_assert.h"

ascendc_assert(baseM % 16 == 0);
ascendc_assert(idx < limit, "idx=%u limit=%u\n", idx, limit);
```

在支持的模式下，单参数 `assert(expr)` 和 `ascendc_assert(expr)` 均用于检查条件：条件为真时继续执行；条件为假时输出断言上下文并触发异常，算子执行失败。

### 重要限制

- Release 工程通常定义 `NDEBUG`，此时断言不生效。
- `ASCENDC_DUMP=0` 也会使该调试接口不生效。
- 自定义格式字符串和参数的能力依赖编程模式；CPU 调试时多参数调用不输出自定义消息；按来源基线，SIMT/SIMT VF 的 `assert` 只支持不带消息的形式，`ascendc_assert` 支持自定义消息。具体模式仍需核对目标版本文档。
- 需要包含 `<cassert>` 时，先包含 `<cassert>`，再包含 `kernel_operator.h` 或 `utils/debug/asc_assert.h`，避免标准库覆盖 AscendC 的宏定义。
- 断言会影响性能，主要用于调试检查；必须始终生效的访问保护应使用独立的条件判断。

## `__trap`

### 接口功能

- **输入**：无参数；触发条件由调用者在外层判断。
- **行为**：执行到调用位置时，在支持的 SIMT/SIMT VF 场景中中断算子运行。
- **输出**：异常中断，无返回值，不自动输出变量值或自定义消息。
- **不保证**：不能理解为仅退出当前线程，也不负责异常恢复或资源清理；需提前记录的上下文应由少量打印或其他观测手段提供。
- **最小示例**：下例假设 `x` 有效且 `idx` 位于实际元素范围内；访问保护必须先于 `isnan(x[idx])`。

```cpp
#include "utils/debug/asc_assert.h"

if (isnan(x[idx])) {
    __trap();
}
```

`__trap` 无参数、无返回值，在 SIMT 代码中用于立即中断 Kernel。它适合与 NaN、非法索引或不可恢复状态的条件判断配合；需要条件表达式、源码位置或自定义消息时使用断言更合适。

当前公开文档将 `__trap` 的支持限定在特定 SIMT/SIMT VF 场景，不能向 A2、A3 或通用 SIMD 无条件承诺可用。目标平台未明确时先查当前 API 文档。

## 判断“没有失败”的方法

断言未触发不一定表示条件正确，至少要区分：

1. 条件确实为真。
2. 当前代码路径没有执行。
3. `NDEBUG` 或 `ASCENDC_DUMP=0` 禁用了断言。
4. 目标编程模式不支持该断言形式。

在独立最小用例中使用确定失败的输入验证断言链路，不修改原始用例的真实检查条件。
