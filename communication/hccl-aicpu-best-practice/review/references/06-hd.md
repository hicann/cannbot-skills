# 06 · HD 族评审（H01–H06）

选路侧也没有登记；这只是历史版本观察。直接核对目标文件、接口与登记，不要求先找到同类蓝本或用 `--all` 扫仓。和 ring 一样，评审新 HD template 的第一条是 **X01（BLOCKER）**，
四个登记点与判据见 `references/05` §1 那张表（枚举 + `ALGO_TYPES` + 两张名字映射表）。

>  **判据性质：通用算法假设，尚未获得 CANN 实现验证。**

## 2. 非 2 的幂 rankSize：H01（MAJOR）/ H05（MAJOR）

**这是 HD 唯一的"必须写、写漏必错"的部分**，也是 HD 比 NHR 难写的原因。

> **H01 报 MAJOR 而不是 BLOCKER。** 判据本身有 MPICH / Rabenseifner 背书（写漏了非 2 幂
> 卡数确实算错），但脚本的检测靠代码里出现 `part1` / `blockSize` / `IsPowerOfTwo` 这类
> **字面命名**——换一套等价命名就会误报（已实测复现）。BLOCKER 要求"证据确凿"，
> 这条够不上，所以降一级；**它仍然必须要作者答复**。

标准做法：

```
blockSize = 不大于 rankSize 的最大 2 的幂
part1Size = 2 * (rankSize - blockSize)        // 参与两两合并的 rank 数

① 前 part1Size 个 rank 里，偶数 rank 把数据发给 rank+1 并退出主循环；
② 主循环只在 blockSize 个 rank 上跑（log2(blockSize) 步）；
③ 末尾，rank+1 把最终结果回传给被淘汰的偶数 rank。
```

- **H01**：看不到 `blockSize` / `part1` / 2 的幂判断（`1 << k`、`x & (x-1)`）→ MAJOR。
  没有这一段，非 2 幂卡数（比如 6 卡、12 卡）**直接算错**，而 2 幂卡数的 ST 全绿。
- **H05**：有 2 的幂判断但看不到淘汰与回传的成对处理 → 被淘汰的 rank 拿不到结果。

Rabenseifner 的 3-2 elimination 是这一段的优化版（把额外开销从 2m 降到 3/2 m），
用它也可以，但**必须能在代码里指出"谁被淘汰、什么时候回传"**。

## 3. 步数、对端、数据量：H02 / H03（MAJOR）、H04（MINOR）

| 阶段 | 步数 | 第 k 步对端 | 每步数据量 |
|---|---|---|---|
| halving（ReduceScatter 语义） | `log2(blockSize)` | `blockIdx ^ (1 << k)` | **减半** |
| doubling（AllGather 语义） | 同上，逆序 | `blockIdx ^ (1 << (round-1-k))` | **翻倍** |

- **H02**：步数不是从 `log2(blockSize)` 推导（写死、或用 `rankSize`）。
- **H03**：看不到 XOR / 距离折半的对端推导。
- **H04**：整段用同一个 size → 说明写成了纯 recursive doubling（每步交换全量），
  通信量比 halving-doubling 多 log N 倍，是**性能 bug 而不是正确性 bug**，故 MINOR。

**注意 blockIdx ≠ 算法内序号 ≠ userRank**：淘汰之后参与主循环的 rank 要重新编号（0..blockSize-1），
取 channel 时还要映射回通信域 userRank。这里是 HD 最容易出错的地方，**人工必须逐行核**（对应 C15）。

## 4. 与 NHR 的关系（评审时最常见的争论）

NHR 本身就是"非 2 幂也能用"的 halving-doubling 变体，仓内已经有成熟实现。
所以评审新 HD template 时，**合理的第一个问题是：为什么不用 NHR？**
让作者把"HD 相对 NHR 的收益、适用卡数区间"写进 spec 第 2 章（适用条件）与第 8 章（cost model），
否则新增一族的维护成本换不回收益。这不是阻塞项，但要问。

## 5. 资源模型：H06（INFO）

> **只报 INFO**，理由同 `references/05` §5：这是把算法性质映射到本仓 API 约定的推论，
> 无文献背书、仓内也无已验证实现可比对。

`CalcScratchMultiple` = **1**（AllReduce 的原地折半累加；不落 scratch 可为 0）。
in/out 不等大的算子上 `templateRankSize_` 也可能是对的。
线程模型同 ring：同一时刻只有一个对端，线程数与 rankSize 无关。
