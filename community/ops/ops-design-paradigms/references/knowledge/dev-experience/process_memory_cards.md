# 上下文恢复与验证要点

## 恢复所需输入

恢复分析前，从调用方提供的资料中确认：

- 目标平台、开发语言及其版本或能力证据。
- 算子规格、当前问题、设计约束和已有决策的依据。
- 当前源码与构建产物，以及已执行的测试、结果和未解决项。

按当前问题读取本 Skill 内相关参考。缺少必要信息时，在输出中列出缺项及其影响，由调用方补充；没有证据的既有结论保留为待确认。

## 区分结构与数学进展

分别记录工程骨架、Host 参数契约、Kernel 编译、计算正确性和验证证据。前一项成功不能证明后一项完成；能编译的骨架不代表数学路径正确。

## 核实构建产物

检查目标算子是否在构建范围内、目标 SoC 是否受支持、对象文件或二进制是否真实生成，以及输出文件是否属于本次构建。以实际产物和验证结果判断完成状态。

## 核实 API 语义

涉及 API、同步或搬运时，读取相关 API 参考并确认其适用平台。相似的 regbase 与 membase 代码可能对应不同的执行模型，不能仅依据记忆迁移结论。

## 定位当前问题

区分输入事实、算法设计、Host 参数、Kernel 计算、精度验证与构建安装问题。根据证据定位首个出错环节，并围绕该环节提出修改与验证方法。
