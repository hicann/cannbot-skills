# Reduction 范式同步模型（RAW/WAR 依赖 → 同步点推导）

> **层级**：通用知识层（generic/），语言中立。
>
> 来源：adapters/ascendc/templates/*/kernel-template.md §7（原 reduction-*-kernel-template.md）、原范式入口 patterns.md 各"流水同步方案"节指引、adapters/ascendc/survival-node.md 持有法则。同步原语实体（AscendC: SetFlag/WaitFlag/HardEvent/eventID）在适配层与范式公共知识。

## 1 同步的本质

同步 = **跨执行单元的数据依赖**。同一个 buffer，执行单元 A 写、执行单元 B 读（RAW），或执行单元 A 读、执行单元 B 写（WAR）——就必须同步。

- 同一执行单元内自动串行，不需同步
- 不同 buffer 互不干扰
- 无跨执行单元数据依赖时，不需要任何显式同步

## 2 执行单元与事件对

执行单元划分由 `EXEC_UNITS` 谓词定义。本范式涉及三个单元：搬入单元（片上←外部存储）、计算单元、搬出单元（片上→外部存储）。

| 依赖类型 | 含义 | 事件对（源→目标） | 方向 |
|---------|------|------|------|
| RAW | 搬入写 buffer → 计算读 | 搬入→计算 | 正向 |
| RAW | 计算写 buffer → 搬出读 | 计算→搬出 | 正向 |
| WAR | 计算读 buffer → 搬入覆写同一 buffer | 计算→搬入 | 反向 |
| WAR | 搬出读 buffer → 计算覆写（跨迭代） | 搬出→计算 | 反向 |
| WAR | 搬出读 buffer → 搬入覆写（跨迭代） | 搬出→搬入 | 反向 |

**融合链内部无同步**：同属计算单元的连续操作由硬件/流水线保证串行。

## 3 同步点推导方法（持有法则驱动）

同步点**必须由持有法则 trace 推导，禁止凭直觉预设**：

1. 取**无同步版** Process 代码，逐行标注三态持有：`// 执行前/中/后: 持有=[...]`
2. 遍历每个 buffer 的生命周期，标记跨执行单元的 RAW（生产者写→消费者读）与 WAR（消费者读→生产者覆写）
3. 每个 crossing 插入对应的正向/反向同步对
4. 产出**同步点推导表**：buffer × crossing 类型(RAW/WAR) × 事件类型 × 事件编号 × 循环内/循环间，**每行标注 buffer 名称**
5. 产出**事件编号分配表**：事件类型 × 编号 × 数量 × 用途；未使用的事件类型标注"不需要"并附理由

### 3.1 三层 WAR 必查

⚠ 跨迭代 WAR 必须**验证 buffer 身份**——上轮消费者读的 buffer 与下轮生产者写的 buffer 是**同一个物理 buffer** 才构成 WAR；不同 buffer 不构成，不得插入同步。三层都必须检查：

1. **同一迭代内**：如 Phase A 主块→尾块对同一片上块的覆写
2. **跨内层迭代**：内层循环下一轮覆写同一 buffer
3. **跨外层迭代**：外层循环下一轮覆写同一 buffer

### 3.2 循环间反向同步（首轮/末轮规则）

跨迭代的反向同步（如 搬出→计算、搬出→搬入）：**首轮跳过等待、末轮跳过置位**——仅第一轮不需要等上一轮（不存在），最后一轮不需要为下一轮置位（不存在）。

⛔ Tuple Reduce 场景："首轮/末轮"按**全局（跨归约过程）**判定——仅第一个过程的首轮跳等待、最后一个过程的末轮跳置位，中间轮次正常置位/等待（见 [tuple-reduce.md](tuple-reduce.md) §3）。

### 3.3 典型 buffer 非复用约束（推导的设计输入）

以 Base 模板为例（具体 buffer 命名随语言适配层）：

- 归约后段输出块与归约前段输入块**独立分配**、跨外层迭代不复用 → 搬出与下轮搬入**不构成 WAR**，不需要 搬出→搬入 反向同步
- 输出块跨外层迭代复用：本轮搬出读 → 下轮归约后段计算写 → 构成 搬出→计算 WAR，需反向同步
- 输入块跨内层迭代复用：本轮计算链末尾读 → 下轮搬入覆写 → 构成 计算→搬入 WAR，需反向同步
- 输入块跨外层迭代复用：本轮最后内层块的计算 → 下轮第一内层块的搬入 → 构成跨外层的 计算→搬入 WAR

> ⚠ 不同算子的 buffer 复用方式不同，同步点可能不同——以上是方法示例，不是可照抄的结论。

### 3.4 循环控制流检查

⚠ 各循环内 `continue`/`break` 可能导致同步对不匹配（置位了没等待、或等待了没置位），必须**逐轮检查配对完整性**。

## 4 核内单流水的同步形态

Base / Empty 模板：核内一条流水（搬入→计算→搬出），无跨核同步。同步全部由 §3 的持有法则推导；Empty 的 EMPTY_A 全核早退、无任何同步。

## 5 跨核栅栏（Group 两阶段）

Group 模板 Phase 1→Phase 2 用**跨核栅栏**（`CROSS_CORE_FENCE` 谓词）：

- Phase 1 各核将 partial 归约结果写中间存储（workspace）→ 栅栏 → Phase 2 各核从 workspace 读入做剩余归约
- 栅栏要求**全部参与核到齐**才放行；host 侧须按语言要求声明调度模式（如 AscendC 需 `SetScheduleMode(1)`，否则栅栏挂死）
- Phase 1 内部/Phase 2 内部的核内流水同步仍按 §3 推导，与栅栏独立
- Phase 1 的核内同步事件在栅栏前全部消费完毕，Phase 2 开始时事件池无残留

## 6 同步产出的验收要点

1. 同步原语必须成对（置位/等待各一次），事件编号经管理接口获取、不可硬编码
2. 同类型事件可共用 1 个编号（前一个等待消费后可复用）
3. 禁止插入任何未由持有法则推导出的同步点
4. 无同步需求的分支（如 EMPTY_A）显式声明"无同步"并说明原因
