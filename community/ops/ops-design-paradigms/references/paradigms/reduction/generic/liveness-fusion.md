# Reduction 范式存活节点分析与融合决策

> **层级**：通用知识层（generic/），语言中立。
>
> 来源：adapters/ascendc/survival-node.md（原 reduction-survival-node.md）全文、adapters/ascendc/vf-fusion-rules.md（原 reduction-vf-fusion-rules.md）全文。RegBase 指令清单、白皮书核对方式在适配层。

## 1 L/P 双层存活节点模型

**逻辑存活节点（L）**：
- 计数域：计算图 tensor（每个独立数据实体计 1）
- 由计算图拓扑 + 最优调度决定，与物理媒介无关，**L 对给定计算图是固定的**，不随硬件/API/实现改变
- 跨阶段驻留的 tensor 归属其分配阶段，不计入其他阶段（如归约结果驻树缓存，计入归约段）

**物理存活节点（P）**：
- 计数域：片上 buffer。寄存器不在计数域——片上→寄存器→片上是过路中转，中间值留在寄存器时不占 P
- **P 不由计算图唯一确定**——同一计算图，不同 API 策略/融合决策 → 不同 P。寻找在给定约束下可达的**最小峰值**
- buffer 计入其分配阶段的 P，跨阶段复用不占复用阶段的 P；独占分配的 buffer（生命周期内不允许复用）视为全程驻留
- L 是 P 的下界和收敛目标——P == L 时已到最优，P > L 时还有优化空间

**公平基线（L 和 P 共用）**：
1. 二元及以上操作，不假设 dst 与 src 复用——每个 op 的 src 和 dst 各占独立节点
2. 单步内不假设 in-place
3. 跨步的"用完释放"允许——一个节点的所有消费者执行完后从存活列表移除

**物理基线 = 逻辑基线 + 以下差异**（只能来自 API/硬件能力）：

| 差异来源 | 公平？ | 说明 |
|---------|--------|------|
| 跨步 buffer 复用 | ✓ | 生命周期不重叠可共用物理 buffer |
| 硬件融合指令（dst 就地覆写） | ✓ | 硬件保证，计为 API 能力（`FUSED_ARITH` 谓词） |
| 软件覆写复用 | ✗ | 逻辑侧/物理基线均不假设 in-place |
| 寄存器链融合 | ✓ | 中间值全程在寄存器（`REG_CHAIN_FUSION` 谓词） |

### P ≥ L 与例外

P ≥ L 一般成立。`REG_CHAIN_FUSION`=true 的语言可打破：中间值全程在寄存器，不落片上。L 仍包含（按 tensor 计数），P 不包含（寄存器不计入 P）。此时 **P < L 合法**。设计产出必须说明哪些中间值被融合消掉。

### 精度转换（Cast）对 P 的影响

- **转换串入融合链**（`CONVERT_IN_CHAIN`=true 的语言）：转换在寄存器内完成，src 和 dst 不同时占两个片上 buffer，不额外增加 P
- **转换不串链**（独立转换操作）：src 和 dst 是两块独立片上 buffer，纳入物理 trace 取峰值

## 2 归约范式的三段式分析结构

计算图按三段式划分（见 [scene.md](scene.md) §4），存活节点分析按段独立进行：

- **归约前段 / 归约后段各自独立分析**：各自追踪存活峰值，两段独立分配 buffer、不复用（前段 buffer 含 R 维，后段不含——归约后 R 维消失，空间大小不同）
- **归约前段结果独占分配**：不与本段内任何节点复用（含写入前）——Phase A 主尾配对时要保持不动等待尾块，提前写入会被覆写
- **其余节点**：生命周期不重叠时可复用同一物理 buffer；所有片上 buffer 统一按本算子参与计算的最大 dtype 宽度分配容量（`COMPUTE_PRECISION` 与输入 dtype 取宽者），跨 dtype 复用不受尺寸约束，buffer 份数统一覆盖全部 dtype 实例
- **归约段固定 3 buffer**：归约 src + 归约指令 scratch（由尾配对块兼作，见下）+ 归约 dst（树缓存兼作，不额外分配）——buffer 份数与 src 复用语义（isReuseSource）无关
- **树缓存的额外影响**（二分缓存树引入，见 [tree-reduction.md](tree-reduction.md)）：主尾配对块是归约前段的额外 +1 份（P_pre_ext，固定 1）；树根（归约结果）驻树缓存最高层，不占归约后段 P

## 3 融合决策方法论

### 3.1 穷举所有相邻操作对

列出计算图中**所有连续 Vector 操作对，逐对判据。禁止只检查"看起来像"的那一对**。方法：从计算图第一条 Vector 操作开始，相邻两两配对，每一对都走三条硬判据，全部检查完才进决策。

**三条硬判据**：
1. **链长 ≤ `FUSION_CHAIN_MAX_LEN`**——超过上限必须拆为多次调用
2. **精度转换可参与**（`CONVERT_IN_CHAIN`）——可串入寄存器链路，不作为断点
3. **指令必须存在**——对应操作在该语言的可用指令集（`FUSED_ARITH` / 指令白名单）中存在

**多消费者不打断链**。即使某个中间结果被链外步骤引用，链仍可继续——链内把该值写回片上即可，寄存器链路不受影响。代价是多写一次片上会多占一个 P 槽，需纳入物理 trace 做峰值验证。

### 3.2 融合改变存活节点大小

融合前每个中间结果各占 1 个片上 buffer；融合后中间结果在寄存器内不进片上——存活节点 = 所有输入操作数 + 最终输出 + 其他还活着的 buffer。

```
A+B+C+D = E
全融 A+B+C+D： 5 个节点（A, B, C, D, E 同时活着）
融 A+B+C：     4 个节点（A, B, C, TMP1 活着）→ 再 TMP1+D = E
只融 A+B：     3 个节点（A, B, TMP1）→ 再 TMP1+C = TMP2 → TMP2+D = E
```

### 3.3 P 压力取舍：融合 vs 主动拆分

多消费者融合虽然合法，但会增加 P 压力：融合链需同时持有所有输入 buffer + 所有输出 buffer（包括为外部消费者多写的）。若合并后峰值超过目标 P，需**主动拆分**链来降压。

**判据流程**：
1. 先推满最长链（≤ `FUSION_CHAIN_MAX_LEN`）
2. 做物理 trace，检查峰值是否 ≤ 目标 P
3. 若超 P → 在分叉输出最多的位置拆分链，释放部分 buffer 后再续链
4. 重复直到峰值 ≤ P

**存活节点扩大限制**：融合使更多输入 buffer 同时活着——融合后的物理存活节点数不得超过融合前的 P + 3。超过 → 只部分融合，或调整调度先释放不再需要的 buffer。**关键不是公式，是结合实际持有 trace 看**——在融合发生的那一步，加上所有输入 operands 之后的持有数是否超 P。

### 3.4 转换在融合链中的位置

- **扩位转换（窄→宽，如 b16→fp32）**：通常在链头部——载入 → 寄存器内扩位 → 后续计算
- **缩位转换（宽→窄，如 fp32→b16）**：通常在链尾部——寄存器内缩位 → 写回片上

## 4 互斥分支流规则（Tuple Reduce 场景）

对 N 次独立归约（Tuple Reduce，见 [tuple-reduce.md](tuple-reduce.md)）的场景，存活节点分析**分阶段**（前/归约/后段，Group 为 Phase 1/Phase 2）各自画**一条流**，禁止按 for 循环展开成多轮：

1. **公共步骤**（所有过程都执行）在流中只出现一次
2. **过程独有步骤**写成 `if (processIdx == …) {…} else if …` 并列分支，分割粒度 = 归约过程（同一过程的多个分叉输出在该分支内合并 trace）
3. **分支峰值取 max**：分支互斥——任一时刻只执行一个分支，各分支的 buffer 不可能同时存活；一处 if/else 的峰值 = 各分支峰值的 max，**禁止相加、不按分支单独记账**
4. **存活期照常判定**：分支的中间 buffer 在分支结束即释放；释放后的普通复用池 buffer 可被后续任意步骤复用，与它来自哪个分支无关
5. 每个阶段一条流走完，阶段峰值 = 该阶段存活节点数；buffer 份数按汇总表分阶段相加

以上规则对 L、P 均适用；"共用物理片上/记账/份数"只作用于 P——L 无物理复用概念，仍按公平基线逐 op 计节点。

## 5 追踪方法（L 与 P 共用）

1. 画出完整计算图（含归约）
2. 识别分叉结构（同一数据被多处引用）
3. 按最优调度逐步追踪每步的**执行中**存活数："执行中"取峰值瞬间 = 输入未释放 + 输出写入；输入仅在"执行后"其**所有消费者完成**时才移除
4. 取全流程最大值 = 存活节点数
