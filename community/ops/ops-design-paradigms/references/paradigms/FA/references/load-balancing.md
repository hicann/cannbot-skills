# 负载均衡策略

> 与 tiling 核心（基本块 / Buffer / 流水）解耦，放在流程末尾单独决策。
>
> 本文给的是**决策框架 + 候选手段 + 权衡**，不是固定套路。具体选型随形态（GQA / MHA / MLA）、trait（稀疏 / 量化）、芯片与 spec 变化，由 agent 结合输入自行判断。
> 参考案例：非量化 GQA 的分核元数据预生成见 [flash_attn-arch35-best-practices.md](../design_sample/flash_attn-arch35-best-practices.md) 的 S6——**仅是其中一种做法，可借鉴而非照搬**。

**回答：任务如何分配到多个计算核，并保证负载均衡？**

产出（每个决策点给出选择 + 理由，不必面面俱到）：

- **任务维度构造**：沿哪些轴切、任务粒度多大。
  - 常见：`(B × 头)` × M 轴块（`Sq × G` 合轴或纯 `Sq`）× KV(S2) 轴块；头轴取 kvHead 还是 qHead 取决于是否合轴。
  - 稀疏 / MLA 等可能改变切分轴（如不切 G、按行任务），以 trait 契约为准。
  - 顺带估个任务数上界量级，用于判断核数是否吃得下。
- **负载怎么估**：估算口径决定分配精度。
  - 从简到繁：块数（最简）→ 加权代价（区分满块 / 尾块 / 行首开销）→ 平台实测 / 拟合代价。
  - 模型越细越准、实现与调参成本越高；按 shape 差异程度和收益取舍，并让**估算口径与分配粒度自洽**。
- **用几个核**：先定并行度，再谈怎么分。
  - 可选：吃满可用核（简单）；或在合法区间（下界 ~ 与任务粒度相关，上限 = `min(设备核数, 任务数)`）内评估取更优（如最慢核耗时最小）。
  - 权衡：核数过多有空核 + 调度/同步开销，过少有慢核拖尾；任务数 < 核数时必然有核空闲，此时考虑下面的 split-KV。
- **怎么摊到核上**：分配启发式。
  - 可选：均匀切片（基准）/ 分级贪心（先粗后细）/ 水位线 + 容差 / 二分搜索阈值 / 其他自创启发式。
  - 共性要点：以「块 / 行」为最小分配单位减少碎片；容差类机制可避免「差一点装不下」浪费核数。
- **稀疏怎么剪**：跳过无效 KV 块（仅命中稀疏 trait / 规则掩码时）。
  - 常见：按 M 行推导有效 S2 块区间（causal → 下三角、band → 对角带），区间外整块跳过；行级 + 块级两级。
  - 注意**双侧跳过**（GEMM 与 softmax 状态更新都跳，否则 NaN）；细则见 [trait-sparse.md](./trait-sparse.md)。
- **要不要 split-KV（FlashDecoding）**：核数富余时的补核 / 均载手段。
  - 适用动机：M 轴小（decode 短行）→ 任务数少、核数富余，且 KV 够长值得切。这是 decode 短行优化的常见承载点。
  - 权衡：能补核数与均载，但引入跨任务 reduce 与 workspace。启用判据可以是简单阈值（核数富余 + KV 足够长），也可以是「切 / 不切」两套方案的收益比较——由 agent 按精度需求选。

可选手段参考（非规范，可选用或另起炉灶）：
- **L2 复用段**：按 L2 预算把相邻 head 归组为段、段内共享 Q/K/V 驻留、段间独立调度；L2 预算未知或数据规模小时不分组。

禁止：
- 核数硬编码；核数应作为运行时输入

检查点：
- [ ] 任务空间完整覆盖、无重复、无遗漏
- [ ] 负载估算口径与分配粒度自洽（用块数估就按块分配；用加权代价则考虑尾块 / 剪枝后的有效块）
- [ ] 核数来源为运行时输入，且给出核数取值的理由
- [ ] 启用 split-KV 时已配跨任务 reduce（I4），并说明启用理由
