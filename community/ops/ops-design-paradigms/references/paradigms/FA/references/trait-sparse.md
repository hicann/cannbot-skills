# 稀疏 trait

> 触发条件：KV 稀疏 pattern 由**外部数据给定**（稀疏索引 / 掩码张量），非块坐标解析可推导。稀疏 trait 不改变核心计算路径，仅影响块跳过。
>
> **边界**：causal / 滑动窗口 / Sink 等 pattern 由 Sq/Sk 坐标关系**解析确定**的规则掩码，属于 Feature，不触发本 trait——它们无需外部索引数据，块跳过仅需坐标比较，buffer 也无不定长问题。

## 核心影响

稀疏关注被 mask 掉的 KV 块，引入块跳过逻辑，buffer 与字段随之改变。

## S3 buffer（不定长块）

- 稀疏块长度不定，buffer 按最坏块长分配
- 块跳过逻辑下的 buffer 生命周期

实测要点（蒸馏自量产稀疏算子）：

- **基本块仍是编译期常量**：不定长只表现为"有效长度 ≤ 常量块"，buffer 按常量 s2BaseSize 分配，稀疏索引的有效数量在运行时只裁剪**循环范围**，不改变块尺寸——稀疏度不进基本块。
- **稀疏 KV 收集数据面（稀疏 trait 引入的前置 stage）**：当稀疏粒度是 token 级 / paged 时，分散的 KV 须先按索引 gather 聚合成连续块再供 Cube 消费。聚合由 Vector 侧完成，聚合结果经片外周转（多份槽池）交回 Cube——这实质是在 C1 之前插入一个 **V0 gather stage**，流水 stage 序列变为 `V0 → C1 → V1 → C2 → V2`，V0 的槽池份数与 K/V 槽池一致（≥ r+1）。
- **地址计算可与数据搬运解相位**：paged 场景下"索引 → 物理块号 → 物理地址"的换算可用向量单元批量预计算（每拍处理一个对齐批的索引），其同步 flag 与 KV 数据搬运各自成对、互不阻塞。

## S6 负载均衡（块跳过）

- 稀疏块长度不定，块跳过逻辑影响任务切分与负载均衡
- 跳过空块的调度方式

实测要点：

- **两级跳过**：行级（M 方向）——按稀疏窗口推导整行不可能有有效 KV 的阈值，跳过 M 轴前部无效块；块级（S2 方向）——按每行有效索引数裁剪 S2 循环上界，无效组合整块 continue。两级都须**双侧跳过**（GEMM 与 softmax 状态更新都跳，否则 NaN）。
- **任务区间预算前置**：稀疏使每核实际工作量与索引分布强相关、kernel 内现场算均衡代价高——把 per-core 任务区间（起止坐标 + split-KV 槽位）在 host / 调度侧**预生成、以定长元数据传入**，kernel 只读表执行。这是稀疏变体在 arch35 类平台上的标配做法。
- **G 维切分与稀疏的耦合**：若稀疏索引是逐 query 行独立的，G 合轴共享 KV 的前提被破坏——此时选"逐行任务（不切 G）"路线（见 trait-mla 的 S6 对照）；若索引按 kvHead 共享，仍可 split-G。

## 常见变体

- **BlockSparse**：块级稀疏，跳过空块的索引预计算
