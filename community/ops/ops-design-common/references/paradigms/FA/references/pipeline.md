# 流水编排

> 流水编排把 S2 定义的 stage 序列（逻辑计算流）映射为物理执行的时间排布：几级流水、不同块的 stage 如何重叠并行、跨 Cube / Vector 核如何同步握手、需要几份 buffer 支撑重叠。S2 回答「做什么、数据怎么流」，本步骤回答「几级、怎么并行、怎么同步」。

**回答：几级流水？stage 顺序？同步语义？slot 与 buffer 策略？**

- 候选流水排布及其阶段延迟，由关键等待、状态依赖与 buffer 余量权衡
- 数据流 stage 顺序（同一块内的严格依赖方向 C1→V1→C2→V2）
- **V2 vs V1 相对顺序**：逐项列 max/sum、逐工作项缩放系数和 O_acc 的读写者及最后读取。V1 先于 V2 时保留 V2 所需的旧版本；V2 先于 V1 时也核对更早工作项仍在使用的版本。执行顺序与版本隔离共同满足依赖。
- **阶段数、阶段延迟与预取深度 r**：分别定义。C1/V1/C2/V2 有四个计算阶段；每级延迟一个推进步的示例，其最大阶段偏移为3。r 由实际预取排布决定，按所选 K/V 槽池协议代入 S3 的份数公式。
- **按各对象生命周期推导容量**：活跃块指已进入流水且阶段尚未全部完成的工作项；每个对象的活跃版本从首次写到最后读完成计数。S、P、O_tile、Q/K/V、max/sum、缩放系数和 O_acc 各自推导份数。
  - **流式中间结果**：按实际生产、消费偏移与先读/先写顺序确定 S、P、O_tile 的最大占用。S3 中共享 K/V 槽池及 `N_P_L1=r+1` 对应相应预取模型；采用独立 K/V 队列或其他交接偏移时，回填实际生命周期推导。
  - **任务状态**：max/sum 从该 task 首次 V1 保留到最终使用完成；O_acc 从首次 V2 保留到末次输出读取完成。两类状态的活跃 task 数分别计算。缩放系数按工作项保留到对应 V2，另列其版本数。
  - **容量约束**：对每个候选排布分别求 UB、L1、L0 的实际分配，包含预取副本、转换两侧、填充和所有版本；各池容量与可复用条件共同限制深度。详见 [完整示例](pipeline-example.md) 与 [阶段成本](stage-cost.md)。
- **块内三通路重叠（L0，与 r 正交）**：L0A / L0B / L0C 恒 pingpong（N=2，结构硬约束，S3 已定死、不经本步骤回填），只受 L0 容量约束。
- **buffer 通信策略**：中间矩阵数据量大 → 双缓冲；数据量小 / buffer 紧张 → 单缓冲（**仅指 UB / L1 上的中间矩阵 buffer，不含 L0——后者恒 pingpong**）
- **slot 语义分离**：不同语义槽用不同计数器 / 常量，禁止共用

## 软件流水的 preload / 稳态 / drain

> 下面只是**非量化 GQA / MHA、3 级流水**的一种典型排布示例，preload 方式并非唯一：流水级数（2 级 / 3 级）、量化 / MLA / 稀疏变体都会改变 stage 填充序列与本表。以下仍以 3 级流水（C1 → V1 → C2 → V2，每级延迟 1 tick）为例展示。**注意：同一栏内的多个 stage（如 `C1(块2) + C2(块0)`）表示同一核在该 tick 内先后串行执行，不是并行**——Cube 核一次只跑一个 GEMM，Vector 核同理一次只跑一个 stage。

| tick | Cube 核（串行）      | Vector 核（串行）    |
| ---- | ----------------- | ------------------- |
| 0    | C1(块0)            | —                   |
| 1    | C1(块1)            | V1(块0)              |
| 2    | C1(块2) + C2(块0)   | V1(块1)              |
| 3    | C1(块3) + C2(块1)   | V2(块0) + V1(块2)     |
| 稳态   | C1(块j) + C2(块j−2) | V2(块j−3) + V1(块j−1) |

> 上表选择 V2 先于 V1，列内顺序即发射顺序；其正确性仍需逐对象证明旧版本保留到最后读取。采用 V1 更新 max/sum、V2 更新 O_acc 且缩放系数独立保留的方案时，也可选择 V1 先于 V2，完整实例见 [时序与状态示例](pipeline-example.md)。

> Cube 侧 C1/C2 的准备、计算与搬出分别核对依赖；L0 pingpong 支持不同块的装载与消费重叠，交接数据和可用槽也须在发射前满足完成条件。

- **preload（填充）**：按表的步0、1、2推进；首个 C2 出现在步2，首个 V2 出现在步3。
- **稳态**：Cube 核 `c1 c2` 交替；本表 Vector 核 `v2 v1` 交替。两类核之间的重叠由实际数据可见性与资源能力支持。
- **drain（排空）**：停止 C1 后继续剩余 V1、C2、V2，直到最后输出及槽释放完成。

按 tick 展开的 stage 序列：

- Cube 核：`c1, c1, c1, c2, c1, c2, c1, c2, …`（preload 后进入 c1 / c2 稳态交替）
- Vector 核：`v1, v1, v2, v1, v2, v1, …`（对应上表；稳态每 tick 内 v2 先于 v1）

产出：

- 流水级数 + stage 执行顺序（含 V2 vs V1）+ 选择理由
- 预取深度 r（代入 S3 的份数下界 `N_KV ≥ r+1`，份数数值以 S3 为准）
- 各跨核传递段的 buffer 策略
- 各 buffer 份数 N（所选预取模型及逐对象生命周期代入 S3 得到）
- L0A / L0B / L0C 份数（恒 2、与 r 正交，本步骤只需声明未被降级为单缓冲）
- 同步语义
- 带 task/KV 工作项索引的 warmup/steady/drain 时序表与一致伪代码
- max/sum、缩放系数、O_acc 的所有权、版本、最后读取及分别计入的物理份数
- 共用 Cube 与 Vector 资源的累计阶段负载、短流收尾开销及选择依据

检查点：

- [ ] 流水 stage 顺序与数据流方向一致（无 stage 重排）

禁止：把同一块内的 stage 依赖方向重排；不同语义的槽 / 状态用同一个量表达；把 L0 降级为单缓冲（换取容量或简化同步均不成立）。
