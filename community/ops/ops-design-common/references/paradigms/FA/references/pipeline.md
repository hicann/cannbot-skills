# 流水编排

> 流水编排把 S2 定义的 stage 序列（逻辑计算流）映射为物理执行的时间排布：几级流水、不同块的 stage 如何重叠并行、跨 Cube / Vector 核如何同步握手、需要几份 buffer 支撑重叠。S2 回答「做什么、数据怎么流」，本步骤回答「几级、怎么并行、怎么同步」。

**回答：几级流水？stage 顺序？同步语义？slot 与 buffer 策略？**

- 流水级数（2 级 / 3 级，由延迟隐藏需求与 buffer 余量权衡）
- 数据流 stage 顺序（同一块内的严格依赖方向 C1→V1→C2→V2）
- **V2 vs V1 相对顺序**：3 级下 V2 须先于 V1（保护 softmax 状态不被覆写）；2 级下靠 slot 隔离可 V1 先于 V2
- **流水级数 → 预取深度 r**：2 级流水 r=1，3 级流水 r=2。预取深度是结构决策，必须定死（禁止退化为逐块串行）；代入 S3 的份数下界 `N_KV ≥ r+1`。
- **预取深度 r 的容量影响 = f(buffer 持久性 × 累积域)，与具体场景无关**：定义"**活跃块**"= 已进入流水、其 stage 序列尚未全部完成的块，任一时刻活跃块数 ≈ `r+2`；定义"**活跃累积域**"= 已开始计算、尚未完成归一化输出的 task（其 max/sum/O_acc 须保留）。一个 buffer 是否被 r 放大，按两条正交属性判定——
  - **流式 buffer（块内一拍生产即消费，块间复用）**：K/V 槽池、S、P、O_tile。份数规则：K/V 槽池 `N_KV ≥ r+1`；S（UB）恒 2（L0C→UB 通路 pingpong）；P（UB vec1res）恒 2（Vector 生产/搬出交替）；**P（L1）`N_P_L1 = r+1`**——preload 阶段 Vector 连续产出多块 P 囤于 L1，与 K/V 槽池同构；O_tile（UB）恒 2。**与 r 的耦合体现在 K/V 槽池与 P 驻留的 L1**（每 +1 级各占 `s2BaseSize×D×d_s` 与 `mBaseSize×s2BaseSize×d_s`），UB 中的 S/P/O_tile 份数不随 r 增长。
  - **常驻状态 buffer（跨块保留，按累积域（task）各持一份）**：max / sum / O_acc。份数 = **同时活跃的累积域数**。task 内块数 ≥ r+2 时，任一时刻活跃块同属 1~2 个相邻 task，份数 = task 内 1 + 跨 task 边界 1 = 2，与 r 无关；task 内块数 < r+2 时，preload 的 r+2 个活跃块分属多个不同 task，活跃域数 = `ceil((r+2)/每task块数) > 2`，**UB 状态占用随 r 增长**。
  - 推论：r 的上界**总是受 L1 约束**（K/V 槽池与 P 的 L1 份数，均 = r+1），**仅当活跃累积域数 > 2 时才额外受 UB 约束**；`r_max = floor((L1_avail − Q_tile − (r+1)×P_L1)/(s2BaseSize×D×d_s)) − 1`（P_L1 为单份 P 的 L1 占用 `mBaseSize×s2BaseSize×d_s`，其份数随 r 增长故需迭代求解或按预选 r 代入校验），并代入 UB 校验状态份数。禁止一律用 UB 余量限制 r，也禁止忽略状态 buffer 的活跃域多份。
- **块内三通路重叠（L0，与 r 正交）**：L0A / L0B / L0C 恒 pingpong（N=2，结构硬约束，S3 已定死、不经本步骤回填），只受 L0 容量约束。
- **buffer 通信策略**：中间矩阵数据量大 → 双缓冲；数据量小 / buffer 紧张 → 单缓冲（**仅指 UB / L1 上的中间矩阵 buffer，不含 L0——后者恒 pingpong**）
- **slot 语义分离**：不同语义槽用不同计数器 / 常量，禁止共用

## 软件流水的 preload / 稳态 / drain

> 下面只是**非量化 GQA / MHA、3 级流水**的一种典型排布示例，preload 方式并非唯一：流水级数（2 级 / 3 级）、量化 / MLA / 稀疏变体都会改变 stage 填充序列与本表。以下仍以 3 级流水（C1 → V1 → C2 → V2，每级延迟 1 tick）为例展示。**注意：同一栏内的多个 stage（如 `C1(块2) + C2(块0)`）表示同一核在该 tick 内先后串行执行，不是并行**——Cube 核一次只跑一个 GEMM，Vector 核同理一次只跑一个 stage。

| tick | Cube 核（串行）      | Vector 核（串行）    |
| ---- | ----------------- | ------------------- |
| 0    | C1(块0)            | —                   |
| 1    | C1(块1)            | V1(块0)              |
| 2    | C1(块2) + C2(块0)   | V1(块1)              |
| 3    | C1(块3) + C2(块1)   | V2(块0) + V1(块2)     |
| 稳态   | C1(块j) + C2(块j−2) | V2(块j−3) + V1(块j−1) |

> **同 tick 内 V2 必须先于 V1**：V2 rescale 并覆写 softmax 状态（max / sum / O_acc），若 V1 先跑会用旧状态算出错误的中间值、再被 V2 覆写，导致状态错乱。上表列内顺序即执行顺序。

> **同 tick 内 Cube 侧 `C1 + C2` 连续执行不互相阻塞，前提是 L0 pingpong**；L0 若单缓冲，表中每格的 `C1 + C2` 会退化为「等装载 → 算 → 等搬出」的纯串行。

- **preload（填充）**：流水未满，Cube 核先连续 `c1 c1 c1`（填 QK 三级），Vector 核同理连续 `v1 v1 v1`（填 softmax）。
- **稳态**：Cube 核 `c1 c2` 交替、Vector 核 `v1 v2` 交替；Cube 与 Vector 两核并行，核内各 stage 串行。
- **drain（排空）**：末尾只跑后段 stage（c2 / v2），直到流水排空。

按 tick 展开的 stage 序列：

- Cube 核：`c1, c1, c1, c2, c1, c2, c1, c2, …`（preload 后进入 c1 / c2 稳态交替）
- Vector 核：`v1, v1, v1, v2, v2, v1, v2, v1, …`（preload 填 v1 三级；稳态每 tick 内 v2 先于 v1）

产出：

- 流水级数 + stage 执行顺序（含 V2 vs V1）+ 选择理由
- 预取深度 r（代入 S3 的份数下界 `N_KV ≥ r+1`，份数数值以 S3 为准）
- 各跨核传递段的 buffer 策略
- 各 buffer 份数 N（预取深度代入 S3 的份数公式得到）
- L0A / L0B / L0C 份数（恒 2、与 r 正交，本步骤只需声明未被降级为单缓冲）
- 同步语义

检查点：

- [ ] 流水 stage 顺序与数据流方向一致（无 stage 重排）

禁止：把同一块内的 stage 依赖方向重排；不同语义的槽 / 状态用同一个量表达；把 L0 降级为单缓冲（换取容量或简化同步均不成立）。
