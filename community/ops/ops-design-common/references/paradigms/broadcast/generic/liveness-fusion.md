# Broadcast 范式存活节点分析与融合决策

> **层级**：通用知识层（generic/），语言中立。
>
> 来源：adapters/ascendc/dag-buffers.md §1/§2（原 broadcast-standard-dag-buffers.md）。RegBase/MemBase 对比、具体融合指令清单、buffer 管理实体在适配层。

## 1 L/P 双层存活节点模型

buffer 划分采用 **L/P 双层分析模型**：

**逻辑存活节点（L）**：
- 计数域：计算图 tensor（每个独立数据实体计 1）
- 由计算图拓扑决定，与物理媒介无关
- **L 对给定计算图是固定的**，不随硬件/API/实现改变

**物理存活节点（P）**：
- 计数域：片上 buffer。寄存器不在计数域——片上→寄存器→片上是过路中转，中间值留在寄存器时不占 P
- **P 不由计算图唯一确定**——同一计算图，不同 API 策略/融合决策 → 不同 P。寻找在给定约束下可达的**最小峰值**

**公平基线（L 和 P 共用）**：
1. 二元及以上操作，不假设 dst 与 src 复用——每个 op 的 src 和 dst 各占独立节点
2. 单步内不假设 in-place
3. 跨步的"用完释放"允许——一个节点的所有消费者执行完后从存活列表移除

**L 与 P 的关系**：P ≥ L 恒成立（每个 op 的 src 和 dst 各占独立片上 buffer）。`CAP_REG_CHAIN_FUSION`=true 的语言可打破此规律：中间值全程在寄存器，不落片上。L 仍包含（按 tensor 计数），P 不包含（寄存器不计入 P）。此时 **P < L 合法**。

**物理基线差异来源表**：

| 差异来源 | 公平？ | 说明 |
|---------|--------|------|
| 跨步 buffer 复用 | ✓ | 生命周期不重叠可共用物理 buffer，物理侧允许 |
| 硬件融合指令（dst 就地覆写） | ✓ | 硬件保证 dst 就地覆写，计为 API 能力（`CAP_FUSED_ARITH`） |
| 搬运随路广播 | ✓ | 搬入阶段完成（`CAP_BROADCAST_IN_TRANSFER`），不另占 buffer |
| 软件原地覆写 | ✗ | 逻辑侧/物理基线均不假设 in-place |
| 寄存器链融合 | ✓ | 中间值全程在寄存器（`CAP_REG_CHAIN_FUSION`） |

## 2 持有法则

持有法则是通用分析工具：每个执行动作标注**执行前/执行中/执行后**三态持有，验证峰值 ≤ P。

| 动作 | 执行单元 | 对片上 buffer 的行为 |
|------|--------|-------------|
| 搬入（CopyIn） | 搬入单元 | **写** buffer — 从 GM 搬入新数据 |
| 计算（Compute） | 计算单元 | **读** src buffer + **写** dst buffer |
| 搬出（CopyOut） | 搬出单元 | **读** buffer — 搬出到 GM |

- **写**：写入后 buffer 是否保留在持有中，取决于新数据有无未来消费者
- **读**：读本身不改变持有，但读完后该 buffer 少了一个未来消费者。如果是最后一个消费者，执行后 buffer 从持有消失
- **原地读写**（如硬件融合指令的目的操作数）：buffer 被读的同时也被写，按写处理

三态定义：

| 态 | 含义 |
|----|------|
| 执行前持有 | 上一动作执行后留下的持有列表 |
| 执行中持有 | 执行前 + 当前动作新占用的 buffer（dst 写入 + src 正在被读尚未释放）。P 压力最大时刻 |
| 执行后持有 | 执行中 − 当前动作后无未来消费者的 buffer |

前一动作的执行后 = 下一动作的执行前。第一步执行前为 `[]`。

示例（三元输入，搬入→乘→乘→搬出；操作动词为 AscendC 示例，其他语言按适配层映射）：

```pseudocode
// S1: in0 → square（第一步，执行前为空）
// 执行前: 持有=[]
// 执行中: 持有=[UB0]                   ← 搬入单元正在写 UB0
// 执行后: 持有=[UB0]                   ← in0 后面 S2 还会读, 有未来消费者, 保留
CopyOneInput(coord, IN0, UB0);
// 执行前: 持有=[UB0]
// 执行中: 持有=[UB0, UB2]              ← 计算单元读 UB0, 写 UB2
// 执行后: 持有=[UB0, UB2]              ← in0 后续 S2 会读, square 后续 S4 会读, 都有未来消费者
Mul(UB2, UB0, UB0, count);

// S2: in0·mul1_x → mul_1
// 执行前: 持有=[UB0, UB2]
// 执行中: 持有=[UB0, UB1, UB2, UB3]    ← 计算单元读 UB0,UB1, 写 UB3
// 执行后: 持有=[UB2, UB3]              ← UB0(in0)和UB1(mul1_x)无未来消费者, 消失; square/mul_1 有, 保留
Mul(UB3, UB0, UB1, count);

// 搬出: 读 UB，对 UB 是最后一次读
// 执行前: 持有=[UB2, UB3, UB4]
// 执行中: 持有=[UB2, UB3, UB4]         ← 搬出单元正在读 UB4
// 执行后: 持有=[UB2, UB3]              ← UB4 被搬出读后无未来消费者, 消失
CopyOutOne(coord, OUT0, UB4);
```

**验证**：任意执行中持有数 ≤ P；执行后持有与释放时机一致。

## 3 精度转换（Cast）对 P 的影响

- `CONVERT_INPLACE`=false 的语言（AscendC 即是）：转换 src 和 dst 是两块独立片上 buffer，不能原地（源/目的字节宽不同，硬件不支持重叠读写）→ 需要额外**转换中转 buffer**
- 并发放宽：若基线 P ≤ 6，可扩大 P（**最多 +2**），为转换分配更多 buffer，减少多输入争抢同一中转；按需取，用不到 2 时不强拉到上限
- 转换前后的计算精度统一为 `COMPUTE_PRECISION`（见 [splitting.md](splitting.md) §2.4）

## 4 寄存器链融合降节点三场景

`CAP_REG_CHAIN_FUSION`=true 时：

1. **常量/标量在寄存器构造**：标量不占片上 buffer
2. **链式中间值留在寄存器**：连续计算，中间结果全程在寄存器链上
3. **寄存器内 broadcast/replicate**：从片上取一个元素到寄存器，寄存器内复制，省掉广播源在片上的独立驻留

不改变的情况：单次二元操作 src 本就在片上，仍需 片上→寄存器→计算→寄存器→片上，片上需求不变。

## 5 融合决策方法论

计算流以 element-wise + broadcast 为核心。以二元算子 `out = f(x, y)` 为例，融合后的 DAG 流图：

```
[段 1: 搬入（随路广播）]
  搬入 x → 片上 B0（B 轴 stride=0）
  搬入 y → 片上 B1（B 轴 stride=0）

[段 2: 计算（寄存器链）]
  取 x: B0 → 寄存器
  取 y: B1 → 寄存器
  融合计算 → B2

[段 3: 搬出]
  搬出 B2 → GM
```

**关键**：随路广播在搬入阶段直接完成，不另占片上 buffer；寄存器链将中间结果留在寄存器传递，不落片上，进一步降低 P。

### 5.1 融合穷举判据

列出计算图中**所有**连续计算操作对，逐对判据。禁止只检查"看起来像"的那一对。方法：从计算图第一条计算操作开始，相邻两两配对，每一对都走三条硬规则判据：

1. **链长 ≤ `FUSION_CHAIN_MAX_LEN`**——超过上限必须拆为多次融合调用
2. **精度转换不参与融合**——`CONVERT_BREAKS_CHAIN`=true 时，转换前后必须断链
3. **对应融合指令必须存在**——操作在该语言的计算指令集合（含 `CAP_FUSED_ARITH` 融合指令）中能找到

**多消费者不打断链**。即使某个中间结果被融合链外的其他步骤引用，链仍可继续——链内部把这个值写回片上即可，寄存器链路不受影响。代价是多写一次片上会多占一个 P slot，需要纳入物理 trace 做峰值验证。

**连续可融对合并为单条融合链**：从第一条计算 op 开始，只要指令存在、非精度转换、累积未超链长上限，链就延续。不因分叉而断链。

### 5.2 融合 vs 拆分取舍

多消费者融合虽然合法，但会增加 P 压力：融合需要同时持有所有输入 buffer + 所有输出 buffer（包括为外部消费者多写的）。如果合并后峰值超过目标 P，则需要**主动拆分**融合来降压。

判据流程：
1. 先推满最长链（≤ `FUSION_CHAIN_MAX_LEN`）
2. 做物理 trace，检查峰值是否 ≤ 目标 P
3. 若超 P → 在分叉输出最多的位置拆分融合，释放部分 buffer 后再续链
4. 重复直到峰值 ≤ P

**融合改变存活节点大小**：融合前每个中间结果各占 1 个片上 buffer。融合后中间结果在寄存器内不进片上——存活节点 = 所有输入操作数 + 最终输出 + 其他还活着的 buffer。

```
A+B+C+D = E

全融 A+B+C+D： 5 个节点（A, B, C, D, E 同时活着）
融 A+B+C：     4 个节点（A, B, C, TMP1 活着）→ 再 TMP1+D = E
只融 A+B：     3 个节点（A, B, TMP1）→ 再 TMP1+C = TMP2 → TMP2+D = E
```

**存活节点扩大限制**：融合后的物理存活节点数不得超过融合前的 P + 3。超过 → 只部分融合，或调整调度先释放不再需要的 buffer。

## 6 额外 buffer 要求

- 精度转换场景：`CONVERT_INPLACE`=false 时须额外分配一个转换中转 buffer（src/dst 不可原地）
- 多输出算子：若 >1 个输出，每个输出需独立搬出调用，输出 buffer 在搬出前不可被覆写
- Buffer 复用：同一物理 buffer 可多次复用，只要持有数 ≤ P 约束。代码中 buffer 角色变更须标注 `// UBx 释放` / `// UBx 重新分配为{新角色}`

## 7 单缓冲策略（范式级决策）

- **本范式 standard 路径固定单缓冲**：搬入与计算串行，由显式同步保序（见 [sync-model.md](sync-model.md)）
- 单缓冲是精控 buffer 复用的核心优势——每个 buffer 就是片上一块固定大小的空间，先做搬入、再做中间结果、最后做搬出，动态复用；buffer 数 = P，每块 perBufBytes 最大化 tile 大小
- 队列式管理（`BUFFER_MODEL`=队列）自带双缓冲，P 个队列会变成 2P 个 buffer，perBufBytes 减半、每轮处理数据量砍半——因此本范式不采用
- 单缓冲无自动同步：所有跨单元同步手动插入（约束落地见各适配层）

## 8 buffer 划分产出

| 类别 | dtype | 双缓冲 | 份数 | 用途 |
|------|-------|----|------|------|
| buf_[0..P-1] | 计算精度 | 关 | P × 1 | P 个 buffer 槽位，按 perBufBytes 均分片上容量 |

**perBufBytes** = `(片上容量 / P)` 按 `ALIGN_GRANULARITY` 向下对齐；**perBufElems** 按统一计算精度字节宽算（见 [splitting.md](splitting.md) §2.4）。
