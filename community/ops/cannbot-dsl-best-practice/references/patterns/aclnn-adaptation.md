# aclnn 适配：先对齐参数语义，再接真实接口

适配层把公开契约映射到目标 SDK 接口。函数、描述对象和资源释放约定必须来自目标版本的头文件或官方资料，不能根据命名习惯假定某个 `aclnn*` 接口已经存在。

## 核心例子：长度与累计偏移不是同一种参数

假设公开契约接收每段长度，目标契约接收带末尾哨兵的累计偏移。二者虽可能都是一维整数张量，含义不同：

```text
公开 lengths:        [2, 0, 3]
目标 offsets:        [0, 2, 2, 5]
关系：offsets[0] = 0
      offsets[i + 1] = offsets[i] + lengths[i]
      offsets 的元素数 = lengths 的元素数 + 1
```

目标接口确实需要这一转换时，显式确定它在哪执行、输出谁持有以及整数范围。设备上的长度不能在适配 helper 中默认搬回 Host；设计要求的设备转换应进入 DSL 计算路径。若两端接受同一种表示，直接映射即可。

**反例：** 将 lengths 指针按参数位置直接转发为 offsets；把缺省 scale 从公开语义的自动推导改成 SDK 的固定值；交换两个 dtype 相同但含义不同的参数。

## 执行结构：按已核实的 SDK 契约展开

```text
公开参数 → 明确的目标参数顺序、类型、布局和默认值
张量描述 → 指向正确的存储、shape、stride，并保留所需所有权
若接口要求 workspace 查询：检查返回状态，再按查询结果准备存储
提交执行 → 传入本次 stream；检查提交状态
按接口约定维护描述对象、执行对象与存储的生命周期
返回公开契约要求的输出顺序与 alias 关系
```

此结构不假定每个接口都有两阶段调用。查询失败不得继续执行；零 workspace 按真实接口约定处理。异步提交成功不代表设备完成，释放与复用依据实际资源约定；不能机械销毁所有对象或永久保留所有对象。

**检查：** 不等长度与零长度段、非默认可选参数、多输出顺序、查询与提交失败、连续异步调用。将适配引入的真实转换成本计入性能评估，零拷贝视图须有 stride 与存储依据。布局细节见 [布局与尾块](layout-tail.md)。
