# 同步：为具体的数据依赖建立顺序

每次同步要回答：哪次写入必须先完成，谁接着读取，哪个资源随后可以复用。事件、屏障、Channel 各自的作用域和内存可见性不能互相猜测替代。

## 使用原则：作用域恰当，数量必要

每个同步点都要对应具体的生产者、消费者或存储复用依赖，并选择能够覆盖该依赖的最小作用域。同步过多会限制计算与搬运重叠；同步不足会产生竞态，不能只按屏障数量判断好坏。

| 实际依赖 | 使用原则 |
|---|---|
| 纯寄存器计算的值依赖 | 通过值传递表达，不额外添加内存或跨核屏障 |
| VF 内重叠存储的读写顺序 | 核实后使用对应模式的 `reg.vmem_bar`，见 [VF](vf.md) |
| MTE 与计算流水线之间的数据就绪 | 按生产与消费流水线配对事件，明确事件 ID 的复用时机 |
| 跨核生产消费或多个消费者完成 | 使用支持该参与范围和内存可见性的跨核协议 |
| 整个 launch 的阶段依赖 | 确实要求全体到达时使用全 launch 屏障，并满足驻留条件 |

- 通知放在所保护的生产操作之后，等待放在首次依赖访问之前；可将不依赖结果的工作安排在等待之前，但不能提前读取数据。
- 不在每次 load/store、每个 helper 首尾或每轮循环机械添加同步；已有同步仅在确实覆盖相同地址、参与者和代次的依赖时才可复用。
- 局部依赖不升级为全局屏障；也不能用局部事件替代必要的跨核或全局同步。不要叠加多种同步“兜底”。
- 合并或删除同步前，核对真实地址重叠、异步完成、事件配对和分支路径。数据就绪与允许覆盖可能是不同依赖，不能因为访问同一 Buffer 就删掉其中一个。

**正例：** 同一流水线的一组生产操作共用一个已确认覆盖整组的完成事件，消费者在首次读取前等待；中间安排无关计算。

**反例：** 每个独立向量运算后都全局同步；等待已经覆盖同一依赖后再加一组等价屏障；将共享槽位的“读完可覆盖”事件当成“新数据已写好”事件。

**轻量检查：** 先逐点标出所保护的访问、作用域与配对关系；不能说明用途的同步先核实依据。改变同步后，只对受影响的复用、空任务或分支路径做必要的正确性验证，并复用 [生产代码](../production-code.md) 的短采样规则检查性能。不以单次运行成功证明不存在竞态。

## 核心结构：区分数据就绪与允许覆盖

下图式伪码适用于两个异步执行角色共享一个槽位；任务代次只是依赖标识，不假定 SDK 提供同名参数。

```text
生产者                                消费者
等待 free(slot, 上一代)
提交写入 data[slot]
等待写入完成
发布 ready(slot, 本代)  ------------>  等待 ready(slot, 本代)
                                      提交读取 data[slot] 和计算
                                      等待最后一次读取完成
等待下一次 free        <------------  发布 free(slot, 本代)
```

将 `slot` 与任务代次绑定，可避免复用事件误匹配旧任务。实际 API 若用固定 flag，需要确认 flag 的初始化、等待/重置语义，以及再次发布前的消费顺序；不能直接把任意任务号映射到有限 flag。

**反例：** 发出 DMA 就发布数据就绪；等待本核事件却假定跨核写入可见；用一次“结果完成”事件代替多个消费者各自的最后读取依赖。

## 跨流水线事件：notify 与 wait 参数同序

```text
from cannbotdsl.ops.sync import PIPE, vec_sync_notify, vec_sync_wait

向量侧提交 MTE2 读取到 UB
vec_sync_notify(PIPE.MTE2, PIPE.V, LOAD_TO_VECTOR_EVENT)
vec_sync_wait(PIPE.MTE2, PIPE.V, LOAD_TO_VECTOR_EVENT)
向量侧读取 UB 并计算
```

两次调用都按“生产流水线、消费流水线、事件 ID”排列，wait 不能交换前两个参数。事件常量来自当前任务的资源规划，同一 ID 的再次使用要与已完成的配对一致。Cube 侧有对应的 `cube_sync_notify/cube_sync_wait`；单核内的流水线事件不能代替跨核同步。

## 集体同步与资源复用

```text
from cannbotdsl import global_sync_all, channel_rewind

if 本核有任务:
    完成本核当前阶段
# 所有参与核均到达，不能放在“有任务”分支内
global_sync_all()
# 只有下一阶段显式复用片上地址时才需要，且旧存储已无后续访问
channel_rewind()
进入下一阶段
```

`global_sync_all()` 用于整个 launch 的屏障。launch 必须满足单驻留波次要求：参与同步的核型有足够有效核数容纳全部 block；否则可能等待尚未被调度的 block。核数查询与选择规则见 [编译与启动](compilation-launch.md)。

默认屏障使用固定的三个 flag ID；有重叠的手工协议时，使用 `flag_ids=(FUNNEL_IN, CROSS_BLOCK, FUNNEL_OUT)` 明确规划三个互不相同、位于 `[0, 15]` 的 ID，避免冲突。手工 block arrive/wait 配对必须保持相同 mode。

`channel_rewind(reset_sync_id=True)` 声明地址、Buffer ID 和计数器分配阶段边界；它不插入硬件屏障、不释放仍被使用的存储。`reset_sync_id=False` 只保留该边界的计数器分配阶段，也不能替代同步。普通阶段衔接仅需建立实际依赖，无需机械调用 rewind。

**检查：** 任务数小于核数、任务数非整除、慢消费者、重复槽位复用、分支事件配对，以及屏障的参与核和驻留条件。诊断记录具体等待的生产者与消费者。
