# CANNBotDSL 实现单元规划

## 输入

- 算子规格文件：数学、接口和边界语义的来源。
- 设计资料：调用方提供的单份文档或分文件目录。阅读其中与当前规划有关的执行路径、Host/Kernel 阶段、资源、同步和验证方案；若有索引，按索引查阅。缺少实现必需的事实时指出具体缺口。
- 可选：已有实现代码、测试和用户指定的实现约束，用于确定改动范围与可复用能力。

## 输出

在调用方指定的 Unit 目录生成 `U01.yaml` 至 `U<n>.yaml`。每个文件只有一个 `unit` 对象，格式见 [Unit YAML 格式](references/unit-format.md)。Unit 数量由真实能力边界决定。每个 Unit 写明目标、实际设计来源、依赖、交付能力、实现面、可区分的检验义务与失败返回点。

## 划分方法

1. 从设计资料中识别真实执行路径、阶段、任务映射、资源、同步、最小合法输入和验证要求。设计引用记录实际文件与章节；单份文档可重复引用同一文件的不同章节。
2. 需要独立流水框架时，首 Unit 建立任务映射、阶段派发、缓冲槽、同步及 warmup/steady/drain，并以可观察的结构行为验收。没有独立流水阶段时，首 Unit 直接建立可承载计算的执行框架。
3. 首个数值 Unit 实现最小合法端到端数学链，输出可与独立 Golden 对比的结果。它沿用前序框架。
4. 后续按独立能力和故障面递增，如特殊值、尾块安全、跨任务并行、布局或可选输入。按纵向能力拆分，不把搬入、Cube、Vector、写回等横向工序分别当成完整 Unit。
5. 每个 Unit 说明前序结果为何可保留、独立验收点是什么；共享源码的 Unit 给出依赖顺序。只做性能采样而不交付实现能力的工作不列为实现 Unit。

已有设计 Case 可作为来源线索。具体测试输入、Case ID、Golden 和命令由测试设计决定。此 Skill 只输出 Unit YAML。

## 逐份产出与检查

先读 spec、Unit 格式和设计索引，确定能力边界与依赖轮廓；随后只展开当前 Unit 所需的设计章节。聚合设计文档与其分文件择一阅读相同内容，不同时全文加载两份；仅在引用缺失或事实冲突时补查。测试 runner、Golden、工作流调度器源码不属于常规规划输入。

按依赖顺序生成 Unit：每份内容足够明确后立即写入正式输出目录的 `U*.yaml`，用 YAML 解析器检查单一 `unit` 对象、ID/文件名一致、必需字段和检验义务；再推进下一份。已完成文件作为后续依赖依据，不等全部细节分析完才集中写入。整体边界变化时同步修订受影响的已写 Unit。

全部写完后，统一检查 ID 与义务 ID 唯一、依赖目标存在且无环、requires 能由依赖提供、设计引用真实以及首个数值 Unit 的端到端检验义务。部分文件落盘不等于完成；中断恢复先检查已有 Unit 与待补能力，不重读全部资料或生成占位 Unit 冒充交付。
