# 检视报告格式

报告写入调用方指定的位置；文件名由调用方安排。

**撰写三原则：清晰、可读、简洁。**
- 结论先行，三句话说清"什么问题最多、最该先改什么"
- 全部问题一张表，一行一条，不展开细节
- 证据链一行压缩：`+40 规范违反@1234 -20 防御@1200 → 85%`
- 代码片段只在"非看不可"时给，且只给最短足以证明的几行

---

# {算子名} CANNbot DSL 可读性检视报告

## 撰写要求

- 问题清单一行一条，问题和修复各一句话；超过一行说明没抓住重点
- 证据链格式：`+分值 类型@行号`，空格分隔，末尾 `→ 置信度%`
- 只有当"一句话说不清、必须看代码才懂"时才在表格下方附最短片段
  （≤6 行），并在表格该行标注 `[见下]`
- 待确认表说明"需要作者确认什么"，不是罗列
- 全零问题也出报告：结论写"未发现可读性问题"+ 豁免说明一句
- 不写"检视过程""规则介绍"等元信息——读者是算子作者，不是技能用户
