# 项目架构设计

> 三层架构（Plugin→Agent→Skill）与各开发路径的逻辑视图。

📖 [功能清单](feature-list.md) · [开发规范](STANDARDS.md) · [贡献指南](CONTRIBUTING.md) · [README](../README.md)

## 整体架构

```
cannbot-skills/
├── ops/                             # 算子 Skills
├── model/                           # 模型推理与训练 Skills
├── graph/                           # 图模式 Skills
├── runtime/                         # Runtime Skills
├── plugins-official/                # 官方应用 Plugins
│   ├── ops-registry-invoke/         # AscendC 算子注册调用开发
│   ├── pypto-op-orchestrator/       # PyPTO 算子开发
│   └── tilelang-op-orchestrator/    # TileLang 算子开发
├── plugins-community/               # 社区 Plugins
│   ├── install-helper/              # CANNBot Install Helper 工具
│   ├── ops-qa-suite/                # 算子测试套件
│   ├── tilelang2ascendc-ops-generator/   # AscendC 算子自动生成 Team（实验性）
│   └── science-model-npu-migration/ # 科学计算模型 NPU 迁移
├── infra/                           # 基础设施维护 Skills
├── docs/                            # 项目文档
└── tests/                           # 自动化测试框架
```

> `ops-direct-invoke`、`ops-direct-invoke-flash` 已迁至 cannbot 应用仓（[直调](https://gitcode.com/cann/cannbot/tree/master/plugins-official/ops-direct-invoke) / [快速版](https://gitcode.com/cann/cannbot/tree/master/plugins-official/ops-direct-invoke-flash)），不再位于本仓目录树中。

### Catlass 算子开发

`catlass-op-generator` 工作流入口位于 [cannbot](https://gitcode.com/cann/cannbot/tree/master/plugins-official/catlass-op-generator)。它通过本仓 `ops/catlass-cpp-*` 的六个 Skills 执行接口、标杆、设计、开发和验证五阶段，并从 cannbot-knowledge 的 `knowledge/ops/catlass/` 读取知识。原有 `catlass-op-design`、`catlass-op-develop`、`catlass-op-perf-tune` 公共 Skills 继续作为独立资源保留。

### Triton 算子开发

`triton-op-generator` 插件（Triton 算子端到端生成与优化）已迁移至 cannbot 仓（`plugins-official/triton-op-generator`），其 Skills 仍由本仓 `ops/` 维护，知识卡片由 cannbot-knowledge 仓供给。

### torch.compile 图模式

`torch-compile` 的编排入口、Agent、Hook、安装脚本与评测由 [cannbot 应用仓](https://gitcode.com/cann/cannbot/tree/master/plugins-official/torch-compile) 维护。本仓 `graph/` 保留全部 7 个基础 Skills（`torch-npugraph-ex-knowledge`、`torch-npugraph-ex-dfx-triage`、`torch-custom-ops-guide` 等），名称和内容保持不变，可独立安装；应用仓通过 `plugin-sources.json` 引用这些 Skills。

### NPU 模型推理优化

`model-infer-optimize` 的基础优化、SOTA 探索工作流及配套 Agent 由 [cannbot 应用仓](https://gitcode.com/cann/cannbot/tree/master/plugins-official/model-infer-optimize) 维护，本仓保留 `model/` 下的原子 Skill。

### NPU 模型训练精度诊断

`model-train-precision-diagnose` 插件编排 NPU 训练精度端到端诊断流程。Primary 负责信息收集、症状路由和环境预检，Scope Reducer
负责缩小复现范围；症状 Agent 分别调用 `model-train-precision-numerical-mismatch`、`model-train-precision-nonfinite`、
`model-train-precision-determinism` 三个独立 Skill，定位精度有限值首差异、首个 NaN/Inf/Overflow 和受控确定性重复运行结构不一致，最后由 Reviewer 复核证据闭环。详见
[`model-train-precision-diagnose`](https://gitcode.com/cann/cannbot/tree/master/plugins-community/model-train-precision-diagnose) 插件目录。

### Runtime

`runtime_migration` 是独立 Skill（无 Plugin/Agent 编排），位于 `runtime/` 目录，提供 Runtime 接口迁移的兼容层实现与迁移参考，覆盖设备管理、内存管理、流、事件、IPC、库管理、VMM 等接口及错误码映射。仅用于用户自身合法拥有或已获授权代码的处理。

### 科学计算模型迁移

`science-model-npu-migration` 是社区 Plugin（位于 `plugins-community/`），提供框架级代码 NPU 迁移全流程：环境门禁、脚本适配、精度/性能对比与 `mig_docs` 交付归档，覆盖 `torch_npu` / MindSpore Ascend。无 Plugin/Agent 编排，以 Skill 形式直接提供服务。
