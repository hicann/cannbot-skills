# 规则名称：小矩阵常驻L1：只分次搬运大矩阵以减少搬运次数

## 1. 需求场景 (Requirement)
- **业务背景**：在进行 Cube 计算时，L1 Cache 无法同时容纳左右两个输入矩阵的完整数据。
- **形状/数据类型上下文**：左右矩阵规模差异显著（如一侧为轻量级权重，另一侧为重型特征图）。

## 2. 模式描述 (Pattern)
- **优化原理**：调整切分逻辑，优先将较小的矩阵加载至 L1 并使其在整个计算循环中常驻，仅针对大矩阵进行外循环分次搬运。
- **目标**：最大限度减少小矩阵的重复搬运次数，缓解总线带宽压力。

## 3. 性能损耗因果链 (Inference / Physics)
- **因果说明**：搬运次数与算子执行时间成正比。若循环切分顺序不当，较小的矩阵会被反复搬入重排，造成严重的带宽资源浪费。
- **事实桥接**：
  - 缓存复用 -> 小矩阵在 L1 层的读取（LoadData）速度远高于主存（DataCopy）。
  - 带宽平衡 -> 将瓶颈引导至核心计算段而非搬运段。

## 4. 触发信号 (Triggers — 与原始 profiling 表头对应)
- **需要查看的字段（以 `op_summary` 原始表头为准）**：
  - `aic_mte1_ratio` / `aic_mte2_ratio`（表征不同层级搬运负载）
  - `Input Shapes`（判定 M、N、K 维度的物理规模）
  - `Task Duration(us)`（耗时走向）
- **如何解读（定性）**：
  - 判定小矩阵部分的单次搬运量是否远小于大矩阵，且搬运频率却更高。
  - `S.TransferDominated` 标签显著，且带宽利用率曲线呈现明显的锯齿状重复模式。

## 5. 动作实现 (Action)
- **参考代码位置**：`assets/rules/special_rules/R_MEM_L1_RESIDENT_SMALL_MATRIX/code_snippets/`
- **实施步骤**：
  - 在外层循环前初始化小矩阵的 `CopyIn` 与 `Split`（L1/L0B 准备）；
  - 将大矩阵的搬运放入内层循环；
  - 重新分配 L1 缓冲区大小以适配常驻需求（需符合 `C.L1.Capacity`）。

## 6. 约束与副作用 (Constraints)
- **内存/UB 使用**：受 `C.L1.Capacity` 约束，小矩阵必须能被 L1 完整吞下，否则此规则退化。
- **适用场景**：`O.MatMul`, `O.Conv` 等涉及双输入大算子。
- **不适用场景**：两个矩阵都很大或都很小的情况；计算本身已受限的情况。

## 7. 验证逻辑 (Verification)
- **验证原则**：搬运总量的物理级下降。
- **推荐验证项**：
  - `aic_mte2_ratio`：期望呈显著下降趋势；
  - `Block Dim`：确保各核工作量均衡。
- **验证方法**：计算 MTE2 对应的数据总量变化，确认是否接近 “矩阵A量 + 矩阵B量” 而不是 “矩阵A量 * N + 矩阵B量”。

## 标签
- Domain: `U.Cube`, `O.MatMul`
- Symptom: `S.MemoryBound`, `S.TransferDominated`
- Context: `C.L1.Capacity`
