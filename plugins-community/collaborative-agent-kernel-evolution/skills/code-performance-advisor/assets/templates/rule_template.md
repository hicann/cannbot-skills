# 规则模板：通用性能优化规则模板

> 说明：本模板用于撰写通用算子/模式的性能优化规则。模板为通用格式，不包含任何特定算子的实现细节或具体数值阈值，仅以趋势/方向和需要查看的 profiling 字段进行描述。

## 标题（Rule Name）
- 填写简短描述，例如："XXX 切分/并行化 优化"。

## 1. 需求场景 (Requirement)
- 业务背景：简要说明该规则关注的性能情形或业务场景（例如搬运主导、计算主导、缓存/对齐敏感等）。
- 形状/数据类型上下文：指出需关注的 shape 特征或数据类型（使用标签体系中的 `C.*` / `T.*` 进行标注）。

## 2. 模式描述 (Pattern)
- 优化思路：概述要采用的优化策略（例如切分某维、融合搬运与计算、增加并行片、改用单核累加等），避免实现细节。 
- 目标：描述优化希望达成的物理/性能方向（并行度上升、搬运占比下降、带宽利用改善等）。

## 3. 性能损耗因果链 (Inference / Physics)
- 因果说明：描述关键的性能因果关系或近似公式，便于专家复核（例如数据拷贝成本、带宽/延迟与并行度之关系）。
- 事实桥接：列举该模式改善/恶化性能的物理机制（例如减少重复搬运、避免原子操作、增加 tile 数等）。

## 4. 触发信号 (Triggers — 与原始 profiling 表头对应)
- 需要查看的字段（以 `op_summary` 原始表头为准）：
  - `Task Duration(us)`（整体耗时趋势）
  - `Input Shapes` / `Output Shapes`（判断维度关系）
  - `Block Dim`（分核/分片粒度）
  - `cube_utilization(%)`（算力/核利用）
  - `aic_mte2_ratio` / `aiv_mte2_ratio`（搬运单元占比）
  - 其他上下文字段（例如 `aic_mac_ratio`、`aiv_vec_ratio` 等）
- 如何解读（定性）：
  - 判断是否为搬运主导或计算主导样例，以决定是否适合采用本模板；
  - 关注带宽与核利用的趋势（偏低/偏高/有增长潜力）；
  - 使用 `C.*` 标签来标注 shape/context（例如 `C.MN.Small` / `C.K.Large`）以便筛选样例。

## 5. 动作实现 (Action)
- 参考代码位置：`code_snippets/case_{x}/base_code` 或 `good_code`（在各 rule 目录下维护示例）。
- 实施步骤（示例性、非强制）：
  - 在模板层面引入切分/并行策略；
  - 分配必要的 workspace/UB 缓冲以支持跨片累加或临时存储；
  - 以单核内累加替代跨核原子操作（如适用）；
  - 记录实现中对内存与同步的额外开销以便验证。

## 6. 约束与副作用 (Constraints)
- 内存/UB 使用：备注额外 workspace 的类型与规模影响（与 `C.UB.Capacity`、对齐等约束相关）。
- 适用场景：用标签描述适用的 Domain / Symptom / Context（例如 `O.*`、`S.*`、`C.*`）。
- 不适用场景：列出会使该优化无效或产生负面影响的情形（例如 compute-bound 场景、内存不足、已充分并行的形状等）。

## 7. 验证逻辑 (Verification)
- 验证原则：聚焦指标的趋势与方向，避免使用固定数值阈值。以“改善/上升/下降/无明显变化/恶化”等定性词描述结果。 
- 推荐验证项（使用原始表头字段）：
  - `Task Duration(us)`：期望呈下降（改善）趋势；
  - `aic_mte2_ratio` / `aiv_mte2_ratio`：期望呈下降（搬运占比减弱）；
  - `Block Dim` / 实际参与核数：期望呈上升（并行度提升）；
  - `cube_utilization(%)` 与带宽相关字段：期望呈上升（利用率改善）；
- 验证方法：对比“优化前 / 优化后”的趋势曲线，覆盖多个 representative shapes 并确认 workspace/内存限制未被突破。

## 标签（建议填写）
- Domain（示例）：`U.Cube` / `U.Vector` / `U.Mix` / `U.DMA` / `O.General`。
- Symptom（示例）：`S.MemoryBound` / `S.TransferDominated` / `S.MteBusy`。
- Context（示例）：`C.MN.Small` / `C.K.Large` / `C.UB.Capacity`。

## 参考与示例
- 将具体实现示例放在对应 rule 的 `code_snippets` 子目录；参考项目内部性能优化文档与样例。
