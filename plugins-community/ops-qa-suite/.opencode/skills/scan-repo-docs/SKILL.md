# 仓库文档质量扫描

## 概述

本技能用于对 Ascend C 算子仓库进行全面的文档质量扫描，帮助判断：
- 资料正确性：文档内容是否正确、命令是否可执行、目录结构是否匹配
- 资料易理解性：文档结构是否清晰、内容是否易于理解
- 资料规范性：链接是否有效、安全声明是否完整、许可证是否正确

---

## 入口参数

| 参数名 | 含义 | 取值约束 | 初值推断 |
|-------|------|---------|---------|
| repo_type | 仓库类型 | 枚举值["ops-math", "ops-nn", "ops-transformer", "ops-cv", "others"] | 根据工作目录推断 |
| repo_root | 仓库根目录 | 绝对路径 | 默认为自动检测（使用 `.opencode/scripts/repo_detector.py`），支持任意嵌套深度 |
| scan_scope | 扫描范围 | 枚举值["full", "correctness", "understandability", "normative"] | 默认 "full" |
| output_path | 报告输出路径 | 绝对路径 | 默认为 **当前工作目录** 下的 `reports/{date}/{repo_type}/repo-docs-scan_report_{time}.md` |

> **路径推断规则**：repo_root 默认为**自动检测**，检测规则如下（优先级从高到低）：
> 1. **用户指定路径** → 使用 `--repo-root` 参数指定的路径
> 2. **当前目录是 ops-* 仓库** → 直接使用当前目录
> 3. **当前目录包含 ops-* 子目录** → 使用子目录作为仓库路径
> 4. **向上遍历父目录** → 查找包含 ops-* 的根目录（支持任意嵌套深度）
> 
> 检测工具：`.opencode/scripts/repo_detector.py`
> 
> 例如：
> - 当前工作目录为 `/path/to/ops-transformer/` → 自动检测 repo_root = `/path/to/ops-transformer/`
> - 当前工作目录为 `/path/to/ops-transformer/docs/` → 自动检测到父目录 repo_root = `/path/to/ops-transformer/`
> - 扫描时间为 `2026-04-28 14:59:58`
> - date_str = `20260428`, time_str = `145958`
> - output_path = `/path/to/project/reports/20260428/ops-transformer/repo-docs-scan_report_145958.md`

## 扫描项分类与执行方式

### 简化分类原则

| 类型 | 执行方式 | 扫描项 | 说明 |
|------|---------|--------|------|
| **批量检查** | 调用脚本 | 断链检查 | 需遍历所有 md 文件，批量检查效率高 |
| **逐项分析** | Skill 直接分析 | 其他所有项 | 找到文档 → 分析检查项 → 检查 → 执行验证（如需要） |

### 扫描项执行方式

| 扫描项 | 执行方式 | 是否需执行验证 | 说明 |
|--------|---------|---------------|------|
| 断链检查 | **脚本批量** | ❌ | 调用 link-checker 脚本 |
| LICENSE/SECURITY存在 | Skill分析 | ❌ | 文件存在检查 |
| 目录结构匹配 | Skill分析 | ❌ | 对比文档描述与实际 |
| examples目录完整性 | Skill分析 | ❌ | 目录和文件检查 |
| 源码下载方法 | Skill分析 | ❌ | 静态分析文档内容 |
| 环境部署 | Skill分析 | ⚠️ | 检查环境就绪后执行 source 命令 |
| genop命令 | Skill分析 | ✅ | 执行 `bash build.sh --genop=...` |
| 编译命令 | Skill分析 | ✅ | 执行 `bash build.sh --pkg ...` |
| 运行命令 | Skill分析 | ✅ | 执行 `bash build.sh --run_example ...` |
| msprof工具检查 | Skill分析 | ⚠️ | 检查工具是否存在并可用 |
| 易理解性全部项 | Skill分析 | ❌ | 文档语义分析 |

**执行验证策略：**
- 默认行为：执行验证（除非用户指定 `--skip-exec`）
- 环境满足：从文档提取命令 → 执行 → 判断结果
- 环境不满足：标记"环境未就绪，跳过执行验证"，继续静态分析

## 扫描流程

### Step 1: 断链批量检查（调用 link-checker 技能）

```bash
python .opencode/skills/link-checker/scan_links.py {repo}
```

输出断链清单，报告保存在 `/tmp/{repo}_broken_links_report.txt`。

**注意：使用现有的 link-checker 技能脚本，无需重复实现。**

### Step 2: Skill 逐项分析其他扫描项

对于每个扫描项，Skill 执行：

```
1. 找到文档
   - 根据检查项确定目标文档（README.md、quick_install.md、develop_guide.md 等）
   - 读取文档内容

2. 分析检查项
   - 理解检查项的检查目标（如"编译命令是否正确"）
   - 从文档提取相关信息（如编译命令、目录结构描述）

3. 进行检查
   - 静态检查：文件是否存在、目录结构是否匹配、内容是否合理
   - 语义分析：文档描述是否清晰、是否提供了有效指导

4. 执行验证（如需要）
   - 检查项需要执行 → 检查环境是否满足
   - 环境满足 → 从文档提取命令 → 执行文档写的命令
   - 环境不满足 → 标记"环境未就绪，跳过执行验证"

5. 输出结果
   - 状态：passed / failed / skipped
   - 问题描述
   - 执行验证结果（如有）
```

### Step 3: 生成报告

合并断链结果 + Skill 分析结果，生成统一报告。

## 扫描脚本

### scripts/link_checker.py

断链检查脚本（唯一需要用脚本批量执行的扫描项）：

```bash
python scripts/link_checker.py --repo ops-transformer

功能：
- 扫描所有 .md 文件
- 提取链接并验证有效性
- 分类断链类型
- 输出断链清单
```

**为什么断链用脚本：**
- 需遍历仓库所有 md 文件（可能上百个）
- 逐个文件检查链接效率低
- 批量脚本执行效率高

**其他扫描项不用脚本：**
- 文件存在检查（LICENSE、SECURITY）→ Skill 直接检查
- 目录结构匹配 → Skill 直接读取对比
- 命令验证 → Skill 从文档提取并执行
- 语义分析 → Skill 直接分析

## Skill 逐项分析示例

### 检查项：编译命令

```
1. 找到文档
   → README.md、docs/QUICKSTART.md

2. 分析检查项
   → 目标：编译命令是否正确、是否能成功执行

3. 从文档提取
   → "bash build.sh --soc=Ascend910B2 --pkg=release"

4. 进行检查（静态）
   → 命令是否存在？参数是否合理？

5. 执行验证（如需要且环境满足）
   → 检查 CANN 环境是否就绪
   → 执行文档写的命令
   → 判断结果

6. 输出
   → passed: 命令正确，执行成功
   → failed: 命令有误，执行失败（附错误信息）
   → skipped: 环境未就绪
```

### 检查项：目录结构匹配

```
1. 找到文档
   → README.md 的"目录结构"章节

2. 分析检查项
   → 目标：README 描述的目录是否与实际一致

3. 从文档提取
   → 提取 README 列出的目录（examples、op_kernel、docs 等）

4. 进行检查
   → 对比实际目录结构
   → README 提到的目录是否存在？
   → 实际目录 README 是否遗漏？

5. 输出
   → passed: 完全匹配
   → failed: 存在不匹配（列出差异）
```

### 检查项：源码下载方法

```
1. 找到文档
   → README.md、docs/zh/install/quick_install.md

2. 分析检查项
   → 目标：是否提供有效的源码下载指导

3. 从文档提取
   → README 是否有 git clone 命令？
   → README 是否指向下载文档链接？

4. 进行检查（语义分析）
   → 直接提供命令 ✓
   → 指向文档链接（文档内有下载方法）✓
   → 都没有 ✗

5. 输出
   → passed: 提供有效指导
   → failed: 缺少源码下载方法
```

## 执行验证原则

**核心原则：从文档提取命令，验证文档正确性**

| 情况 | 处理 |
|------|------|
| 环境满足 | 从文档提取命令 → 执行 → 判断结果 |
| 环境不满足 | 标记"环境未就绪，跳过执行验证"，继续静态分析 |
| `--skip-exec` | 不执行验证，仅静态分析 |

**判断文档正确性：**
- 执行成功 → 文档命令正确
- 执行失败 → 文档命令可能有误，记录错误信息供用户排查

| 断链问题 | `documentation`, `broken-link` |

```markdown
### Issue #1: [Documentation|文档反馈]: [AI 识别] 编译命令参数说明不完整

Thanks for sending an issue! Please fill in the following template to help quickly solve your problem.

### Document Link（文档链接）

https://gitcode.com/cann/ops-transformer/blob/master/docs/zh/invocation/quick_op_invocation.md

### Issues Section（问题文档片段）

当前文档仅提供了基本编译命令，缺少以下关键参数说明：
- `--ops` 参数：指定编译的算子列表
- `--vendor_name` 参数：指定厂商名称

### Existing Issues（存在的问题）

1. 用户无法按需编译特定算子
2. 用户无法自定义厂商名称
3. 用户无法优化编译速度
```

## 断链分类与修复

### 断链类型

| 类型 | 占比 | 修复难度 |
|-----|------|---------|
| 路径错误（context应为install） | 常见 | 低（批量替换） |
| 路径缺少 zh 层级 | 常见 | 低（批量替换） |
| 文件不存在 | 中等 | 中（需创建文件） |
| 目录不存在 | 低 | 高（需确认目录结构） |
| 双斜杠 | 低 | 低（批量替换） |

### 批量修复命令

```bash
# 修复 docs/zh/context 路径错误
find . -name "*.md" -exec sed -i 's|docs/zh/context/quick_install|docs/zh/install/quick_install|g' {} \;

# 修复缺少 zh 层级
find . -name "*.md" -exec sed -i 's|docs/context/|docs/zh/context/|g' {} \;

# 修复双斜杠
find . -name "*.md" -exec sed -i 's|docs//zh|docs/zh|g' {} \;
```

## 指令调用流程

### /repo-scan 指令执行步骤

当用户执行 `/repo-scan <repo>` 指令时：

```
Step 0: 解析参数与环境检查
  → 解析仓库类型和 --skip-exec 参数
  → 检查 CANN 环境（ASCEND_HOME_PATH）
  → 检查 NPU 设备（npu-smi info）
  → 检查编译工具（cmake, gcc, python3）
  → 确定执行策略：执行验证 或 仅静态分析

Step 1: 断链批量检查
  → 调用 link_checker.py 脚本
  → 输出断链清单

Step 2: Skill 逐项分析其他扫描项（共30项）
  → 严格按照扫描项清单逐一检查，不得遗漏
  → 对于每个检查项：
     1. 找到文档（README、quick_install、develop_guide 等）
     2. 分析检查项目标
     3. 从文档提取相关信息
     4. 进行检查（静态 + 语义）
     5. 执行验证（如需要且环境满足且未指定--skip-exec）
     6. 输出结果

Step 3: 生成报告
  → 合并断链结果 + 各项分析结果
  → 输出 Markdown 报告
  → 说明执行验证情况
```

### Skill 执行验证判断

对于需要执行验证的检查项（编译命令、运行命令、genop命令等）：

```markdown
1. 检查是否指定 --skip-exec
   - 指定了 → 标记"用户跳过执行验证"，继续静态分析
   - 未指定 → 继续检查环境
   
2. 检查环境是否满足
   - CANN 环境（ASCEND_HOME_PATH）
   - NPU 设备（可选，仿真不需要）
   - 编译工具（cmake, gcc）
   
3. 判断：
   - 环境满足 → 从文档提取命令 → 执行 → 判断结果
   - 环境不满足 → 标记"环境未就绪，跳过执行验证"，继续静态分析
   
4. 执行的是【文档写的命令】，不是写死的命令
```

## 用户交互规则

### 扫描请求判断

| 用户表述 | 扫描范围 | 是否执行验证 |
|---------|---------|-------------|
| "扫描仓库文档"、"全面扫描" | full | **默认执行验证** |
| `/repo-scan ops-math` | full | **默认执行验证** |
| `--skip-exec` 或 `--no-exec` | full | **不执行验证** |
| "仅静态分析"、"不执行验证" | full | 不执行验证 |
| "检查链接" | normative | 不需要执行验证 |

### Skill 执行策略

**默认行为（用户未指定 --skip-exec）：**
- 检查环境是否就绪（CANN环境、NPU设备、编译工具）
- 环境就绪 → 执行验证（编译、运行、genop等命令）
- 环境不就绪 → 标记"环境未就绪，跳过执行验证"，继续静态分析

**用户指定 --skip-exec 或 --no-exec：**
- 不检查环境
- 仅执行静态分析 + 语义分析
- 所有需执行验证的项标记"用户跳过执行验证"

**注意：无论是否执行验证，都必须完成所有31项扫描项的检查，不得遗漏。**

### 报告生成后

报告生成后应询问用户：
1. 是否需要修复脚本（针对断链等可批量修复问题）
2. 是否需要针对特定问题进行详细分析
3. 是否需要生成 JSON 格式数据（用于后续处理）

## 输出检查项

完成扫描后，确保输出以下内容：

### 终端输出检查

| 检查项 | 内容 |
|-------|------|
| 统计摘要 | 三大类别扫描项数、通过数、问题数 |
| 问题严重程度 | 严重/中等/轻微问题数量及占比 |
| 核心功能验证 | 关键命令执行结果 |
| Issue 创建提示 | 是否生成 Issue 文件（针对断链/文档错误） |

### 报告文件检查

| 文件 | 位置 | 内容 |
|------|------|------|
| Markdown 报告 | `reports/{date}/{repo}/repo-docs-scan_report_{time}.md` | 完整扫描结果（带时间戳） |
| Issue 文件 | `reports/{date}/{repo}/issues/doc_error_issue_{time}.md` | 文档问题 Issue（自动生成） |
| Issue 文件 | `reports/{date}/{repo}/issues/link_error_issue_{time}.md` | 断链问题 Issue（自动生成） |

### Issue 创建流程

**核心原则**：
| 原则 | 说明 |
|------|------|
| **所有问题都创建 Issue** | 不考虑问题级别，所有发现问题都生成 Issue 文件 |
| **报告后询问提交** | 每次生成报告后，询问用户是否提交 Issue 到对应仓库 |
| **同类问题合并选项** | 同类问题涉及多个算子/文件时，询问是否合并（按问题类型+仓库） |

**流程概览**：
```
扫描完成 → 提取问题 → 分类问题 → 询问合并 → 生成 Issue → 询问提交 → 执行提交
```

**Issue 文件命名**：
- **合并模式**：`reports/{date}/{repo}/issues/{issue_type}_merged_issue_{time}.md`
- **单文件模式**：`reports/{date}/{repo}/issues/{issue_type}_issue_{time}.md`

**合并场景示例**：
| 问题类型 | 合并条件 | 合并标题 |
|---------|---------|---------|
| 断链问题 | 同一仓库多个断链 | `[Documentation]: [AI 识别] {repo} 存在{n}个断链` |
| 文档错误 | 同类型错误多处出现 | `[Documentation]: [AI 识别] {repo} 文档描述错误（{n}处）` |

**询问合并流程**：
```
发现以下问题：
- 断链问题：3个链接不存在
- 文档错误：2处描述不准确

合并选项：
1. 合并同类问题（推荐）- 每种问题类型合并成一个 Issue
2. 不合并 - 每个问题单独一个 Issue

请选择处理方式：
```

**询问提交流程**：
```
已生成 Issue 文件：
| 序号 | Issue 文件 | Issue 标题 | 目标仓库 |
|:---:|-----------|-----------|---------|
| 1 | reports/{date}/{repo}/issues/link_error_issue_{time}.md | [Documentation]: [AI 识别] {repo} 存在3个断链 | cann/{repo} |

是否提交 Issue 到对应仓库？
1. 是，全部提交
2. 是，选择提交
3. 否，暂不提交
4. 否，手动提交
```
