# ops-nn arch35 Artifact Layout

> **W8** (2026-05-12, ROADMAP §1.5) — extracted from gitcode `cann/ops-nn` PR #4778 covering 7 ops with full A5 artifact sets (gather_elements_v2, group_norm_silu_quant, index_put_with_sort, rms_norm_quant, apply_adam_w_quant, ctc_loss_v3, top_k_top_p_sample_v2).
>
> **When to load**: any arch22→arch35 port op (internal op-class tag `a3_to_a5_port`). Authoritative for what files must be produced + their schemas.

## Per-op directory shape

For an op at `cann/ops-nn/<category>/<op>/` (e.g. `loss/ctc_loss_v3/`):

```
<op>/
├── op_host/
│   ├── config/
│   │   ├── ascend910b/                    # existing A2 — leave unchanged
│   │   ├── ascend910_93/                  # existing A3 — leave unchanged
│   │   └── ascend950/                     # NEW (A5)
│   │       ├── <op>_binary.json
│   │       └── <op>_simplified_key.ini
│   ├── <op>_def.cpp                       # MODIFIED — add ASCEND950 entry
│   ├── <op>_tiling.cpp                    # usually unchanged (target-agnostic)
│   └── <op>_tiling.h
├── op_kernel/
│   ├── arch35/                            # NEW — A5 SIMD/SIMT impl
│   │   ├── <op>.h
│   │   ├── <op>_base.h                    # if op has sub-variants
│   │   └── <op>_<variant>.h ...
│   └── <op>_apt.cpp                       # NEW — A5 entry-point .cpp
├── pytorch/                               # OPTIONAL (for ops needing torch binding)
│   ├── CMakeLists.txt
│   ├── build_and_test.sh
│   ├── <op>.asc
│   └── test_<op>.py
├── tests/ut/
│   ├── op_host/{arch35/test_<op>_tiling.cpp, test_<op>_infershape.cpp}
│   └── op_kernel/{test_<op>.cpp, <op>_tiling_def.h, <op>_data/gen_data.py}
├── docs/
│   └── <op>_a5_migration_plan.md          # OPTIONAL — design doc (ctc_loss_v3 has it)
├── <op>_precision_report.json             # OPTIONAL — generated by run_*.py
├── <op>_precision_report.md
├── run_<op>_precision_report.py
└── test_<op>_precision.py
```

## File-by-file schemas

### 1. `op_host/<op>_def.cpp` — Add ASCEND950 OpAICoreConfig

Existing structure (pre-port, A2 + A3 only):
```cpp
this->AICore()
    .DynamicCompileStaticFlag(true)
    .DynamicRankSupportFlag(true)
    .DynamicShapeSupportFlag(true);
this->AICore().AddConfig("ascend910b");
this->AICore().AddConfig("ascend910_93");
```

Add for A5:
```cpp
OpAICoreConfig regbaseCfg;
regbaseCfg.DynamicCompileStaticFlag(true)
    .DynamicRankSupportFlag(true)
    .DynamicShapeSupportFlag(true)
    .ExtendCfgInfo("opFile.value", "<op>_apt");
this->AICore().AddConfig("ascend950", regbaseCfg);
```

**Required**: the `ExtendCfgInfo("opFile.value", "<op>_apt")` line wires the registration to `op_kernel/<op>_apt.cpp` as the A5 entry-point. Without it, A5 routing fails.

### 2. `op_kernel/<op>_apt.cpp` — Canonical A5 entry-point body

```cpp
#include "kernel_operator.h"
#include "kernel_tiling/kernel_tiling.h"
#include "arch35/<op>.h"
using namespace <OpNS>;

extern "C" __global__ __aicore__ void <op>(
    GM_ADDR <input_1>, GM_ADDR <input_2>, ..., GM_ADDR <output_1>, ...,
    GM_ADDR workspace, GM_ADDR tiling)
{
    GM_ADDR usrWorkspace = AscendC::GetUserWorkspace(workspace);
    GET_TILING_DATA(tilingData, tiling);
    <OpClass><DTYPE_TEMPLATE_ARGS> op;
    TPipe pipe;
    op.Init(&tilingData, <input_1>, <input_2>, ..., <output_1>, ...,
            usrWorkspace, &pipe);
    op.Process();
}
```

Notes:
- Function signature MUST match the kernel-launcher signature emitted by op_def codegen.
- `usrWorkspace` is the user-callable workspace slice (kernel may also allocate).
- `<OpClass><DTYPE_TEMPLATE_ARGS>` instantiates the op class from `arch35/<op>.h` with `DTYPE_<INPUT_NAME>` template params (compiler generates these macros from the binary.json input dtypes).

### 3. `op_host/config/ascend950/<op>_binary.json` — Compile config

Schema (extracted from PR4778 examples, 7 ops):
```json
{
  "op_type": "<OpType>",
  "op_list": [
    {
      "bin_filename": "<OpType>_<32-hex-hash>",
      "inputs": [
        {
          "name": "<input_name>",
          "index": 0,
          "dtype": "bfloat16",
          "format": "ND",
          "paramType": "required",
          "shape": [-2]
        },
        ...
      ],
      "outputs": [...],
      "attrs": [...],
      "pattern_info": {...}
    }
  ]
}
```

Tips:
- Start from `op_host/config/ascend910b/<op>_binary.json` as a baseline; preserve `op_type`, `inputs[]`, `outputs[]`, `attrs[]` structure.
- `bin_filename` is a per-target 32-hex hash; let the build system generate it or use the existing one if unchanged from A3.
- `shape: [-2]` is the canonical dynamic-shape marker. Don't hardcode shapes.
- One entry per dtype combination supported (e.g. fp16 + fp32 + bf16 = 3 entries in `op_list`).

### 4. `op_host/config/ascend950/<op>_simplified_key.ini` — Minimal

```ini
[<OpType>]
default=0
```

That's it. Mirror the ascend910b version unless the op needs platform-specific keying.

### 5. `op_kernel/arch35/<op>.h` — A5 kernel impl

Usually a near-clone of `op_kernel/<op>.h` (the A3 impl) with these surgical changes (per **W10 arch35 platform-compat patterns**):
- Strip `#include "impl/dav_c220/*"` lines (V220-only reg primitives)
- Strip `#ifdef __CCE_AICORE__ == 220 ... #endif` conditional blocks
- Audit `ToFloat<>` calls — A5 restricts to `bfloat16_t`/`fp8_*`; for FP16, insert `.template ReinterpretCast<bfloat16_t>()` before `.GetValue(...)` (see **W11 A5 ToFloat<> restriction**)

Wrap implementation in a unique namespace matching the op (e.g. `namespace CTCLossV3NS { ... }`) and `using namespace AscendC;`. Class template parameters typically `<TProb, TIndices>` or similar dtype slots.

## Build command (CANN)

From the op's directory:
```bash
source <cann_path>/set_env.sh   # e.g. /usr/local/Ascend/cann/set_env.sh
bash build.sh --pkg --ops=<op> --soc=ascend950 2>&1 | tee build.log
```

**Conventions**:
- `--soc=ascend950` requires **DOUBLE dash**. `-soc=ascend950` errors with usage message.
- Check `build/gen_bisheng_dir/bisheng` first line — if missing `#!/bin/bash`, the build wrapper fails; manually add the shebang.
- OOM during compile: reduce parallel with `-j4`.
- Confirm: `grep -E "[Ee]rror" build.log` should be empty; run package produced.
