**Owner directive 2026-05-25T02:16Z** (verbatim, codified here): "如果 cann 的参考代码是 vec/cube 复合的融合代码，那么如果生成纯使用 vec 的代码要看做一种 hack（与使用 cpu 一样）。安全网很难拦截，因为正常的 op gen 不可能给参考代码。因此需要您们发挥白盒优势，从 cann 代码批量学习什么样的算子需要 vec/cube 融合。"

**Principle**: The harness MUST classify every op being generated by its **architecture requirement** (vec-only / cube-required / boundary) BEFORE worker authors kernel. Worker producing pure-VEC for a cube-required op is reward-hacking — algorithmically same class as CPU-fallback (escapes "kernel produces output" verification but produces architecturally-unfit code that fails on real customer workloads).

**Architecture requirement classification rule** (from `cann_classification/README.md`):

| Class | Detection markers in CANN ref | Op-family examples (from 2026-05-25 grep) | Architecturally-correct kernel |
|---|---|---|---|
| **cube-required** | `matmul::Matmul<` / `MatmulImpl<` / `REGIST_MATMUL_OBJ` / `KERNEL_TASK_TYPE_DEFAULT(KERNEL_TYPE_MIX_AIC_*)` / `cube_block` | ops-transformer/attention (30), ops-nn/matmul (14), ops-transformer/experimental (12), ops-nn/conv (8), ops-transformer/mhc (5), ops-transformer/gmm (5), ops-transformer/ffn (4), ops-nn/rnn (3), ops-nn/experimental matmul (2), ops-transformer/posembedding rotary (1), ops-nn/quant flat_quant (1) — full list in `kb/okf/runbooks/operator-optimization/cube_required_ops.txt` | MUST instantiate `matmul::Matmul<>` library OR equivalent V351 RegBase cube primitives; pure-VEC implementation = HACK |
| **vec-only** | None of the cube markers AND no GEMM/conv/attention-scoring in algorithm | ops-nn/activation, ops-nn/foreach, ops-nn/index, ops-nn/loss, ops-nn/norm, ops-nn/optim, ops-nn/pooling, ops-nn/hash, ops-transformer/common, ops-transformer/moe (routing/expand, NOT gmm) | Pure-VEC AscendC primitives are correct |
| **boundary** | Has both vec-only AND cube-variant paths in upstream (multi-variant dispatch) | `flat_quant` (cube + vec branches dispatched by tiling key — see OL-185), `rotary_position_embedding` (one variant uses cube) | MUST replicate upstream's dispatch logic — per-variant emission per OL-187 |

**Pre-spawn classification workflow** (kw_brief Phase A.1):
```bash
# Detect cube-required class
op_kernel_dir="<backward>/op_kernel"
if grep -rqE 'matmul::Matmul<|MatmulImpl<|REGIST_MATMUL_OBJ|KERNEL_TYPE_MIX_AIC_[12]_[12]' "$op_kernel_dir"; then
    echo "ARCH=cube-required (worker MUST use matmul library or RegBase cube)"
else
    echo "ARCH=vec-only (pure-VEC AscendC is correct)"
fi
```

**Safety-net rejection rule** (finalize gate):
