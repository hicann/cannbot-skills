`applies_to: soc=all; cann=all; bisheng=n/a; op_class=all_modes; phase=cold_start_recovery`
`verified_on: a5_ops:3_FusionAttention restore-spawn 2026-05-21T05:30Z (baseline preserved at /home/npu_user/.opgen_backups/3_FusionAttention/pre-cold-start-1779339343/, restored cleanly, Pass B 9/9 bit-identical + Pass A 1/61 PASS_T1 bit-identical across 3 consecutive determinism runs)`

**Trigger** (decision rule — applies to ANY op-gen mode):
1. Prior cycle reached `PARTIAL_PERSIST` (or `PASS`) verdict with full runners + `verification.json` artifacts, AND
2. A subsequent workspace wipe (orchestrator-side, cold-start scaffold, etc.) removed runtime/runner artifacts (e.g. `run_pass_b.py`, `pass_a_runner.py`, `model_new_ascendc.py`, `kernel/*.{h,cpp}`), AND
3. `.opgen_backups/<op>/<run_id>/` directory is intact, AND
4. The finalize gate's complaint is a SPECIFIC artifact gap (e.g. `phase_o5_runner_failed::await_worker — no Pass B verifier found`), NOT a precision / architecture / verdict-shape issue.

When all four hold, RESTORE is the structurally-correct response — distinct from "retry-from-scratch via fresh kw spawn".

**Principle — why restore beats retry**:
- Retry-from-scratch consumes a full multi-iter kw budget (typically 5-15 iters) when the prior cycle's validated baseline IS the right answer — only the wrapper artifacts were lost.
- Restoration closes the specific finalize-gate signature in 1 iter.
- Restored kernel re-verifies bit-for-bit against the prior baseline (zero regression risk when the build environment is idempotent).
- Frees the iter budget for the proper next stage (`aog-fused-optimizer` per C27 anticipatory WARN, or FA template assembly per OL-159) if architectural improvement is desired beyond the prior baseline.

**Concrete anchor** (restoration path):
```bash
SRC=/home/npu_user/.opgen_backups/<op>/<run_id>
DST=workspace/<op>
cp $SRC/kernel/*.{h,cpp}            $DST/kernel/
cp $SRC/model_new_ascendc.py        $DST/
cp $SRC/run_pass_b.py               $DST/
cp $SRC/pass_a_runner.py            $DST/
bash src/scripts/deploy_to_npu_lane.sh --lane 0 --build
# Then re-run the canonical Pass A + Pass B + determinism to confirm bit-identical reproduction.
```

**Anti-pattern this avoids — re-attempting a failed exploratory path within kw budget**:
- 3_FusionAttention 2026-05-21: kw-1 cold-start respawn returned without producing runner artifacts (root cause never diagnosed — possibly hit iter budget without writing them). The "design hint" pointed kw at a 30-50 iter cube-Pattern-A rewrite that is properly `aog-fused-optimizer` scope (per C27 / DEBT-077 P0g). Restoring from `.opgen_backups` closed the specific gate in 1 iter and preserved the validated 1/61 + 60-skipped baseline; kw was NOT the right entity to attempt the architectural rewrite.

**Anti-pattern this is NOT — restoration is not delegation fraud**:
- Per CLAUDE.md "No CANN/PyTorch delegation": delegation is "call vendor API instead of running our kernel". Restoration copies OUR PRIOR-CYCLE KERNEL SOURCE — auto-generated by a kw spawn in the same project, sealed and preserved by the orchestrator. The kernel under `.opgen_backups/<op>/<run_id>/kernel/` is the operator implementation we built; restoring it is the equivalent of `git checkout <validated-commit>`.

**Detection** (orchestrator pre-flight):
```bash
# When finalize gate rejects with "no Pass B verifier found" or similar artifact-gap signature:
if [ -d "/home/npu_user/.opgen_backups/<op>" ]; then
    last_validated_run=$(ls -t /home/npu_user/.opgen_backups/<op>/ | head -1)
    if [ -f "/home/npu_user/.opgen_backups/<op>/$last_validated_run/verification.json" ]; then
        # check that prior verdict was PARTIAL_PERSIST or PASS
        prior_verdict=$(jq -r '.precision.status' "/home/npu_user/.opgen_backups/<op>/$last_validated_run/verification.json")
        if [[ "$prior_verdict" == "PARTIAL_PERSIST" || "$prior_verdict" == "PASS" ]]; then
            echo "RESTORE-CANDIDATE: $last_validated_run was validated; restore before retry-from-scratch"
        fi
    fi
fi
```

**Scope conditions** (do NOT restore when):
- Prior baseline's verdict was FAIL (no validated baseline to restore).
- The wipe came WITH a kernel-source change request (e.g. user-override `optimization_directive.md` instructed Pattern A rewrite). Restoring would undo the directive's intent.
- The validated baseline is older than the most recent reference-spec mtime (per OL-168) — restoration risks shipping a kernel that no longer matches the current reference.
- `.opgen_backups/<op>/` directory is gone (wipe was full).

**Cross-ref**: OL-168 (reference-spec mtime pre-flight); C27 anticipatory WARN (fused-class fo invocation count); DEBT-077 P0g (kw is not the right entity for unconstrained multi-iter architectural rewrites); OL-159 (FA-class template assembly); CLAUDE.md "No PyTorch/CANN Delegation" (restoration is not delegation).

**Other instances (predicted)**: any cold-start recovery where the orchestrator wipes workspace but `.opgen_backups/` mirror is intact — kernels stuck at PARTIAL with verified baselines, kernels intermittently failing finalize-gate artifact checks after orchestrator restarts, any op whose prior validated state is preserved but transient state was lost. Predicts the orchestrator should add a pre-flight check that flags restore-candidates before scheduling a fresh kw spawn.
