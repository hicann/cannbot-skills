## 优化点 / 选型

arch35 introduces `ASCENDC_TPL_ARGS_DECL` / `ASCENDC_TPL_SEL` macros that let the kernel
author declare which combinations of template axes (e.g. `ATRANS, BTRANS, BIASMODE,
KERNELTYPE, OPTYPE`) get instantiated at compile time, with the dispatcher auto-generated by
the compile pipeline. V220 has no equivalent — V220 kernels either branch at runtime or
hand-roll a switch over template-key bits.

**Applies to** `soc=Ascend950PR; cann=9.0.0; bisheng=15.0.5; op_class=cube-vec-fused`.
Verified on Ascend950PR (fused_quant_mat_mul partial port). Unverified on Ascend910_V220 —
V220 has no equivalent API; pattern is V351-only.

### When to switch to it

When porting an op whose V220 kernel does dispatch by hand AND the op has multiple orthogonal
template axes (transpose, bias mode, dtype-promotion mode, kerneltype, etc.), the arch35 port
should switch to `ASCENDC_TPL_ARGS_DECL` to:
1. Cut hand-written dispatcher code size.
2. Let the compiler skip instantiations not in the `ASCENDC_TPL_SEL` lists (binary-size win).
3. Surface the legal-instantiation matrix explicitly (host can validate before launching).

### Concrete anchor

```cpp
// arch35 kernel header — declare which (axis1, ..., axisN) tuples to instantiate:
ASCENDC_TPL_ARGS_DECL(
    OpName,
    ASCENDC_TPL_BOOL_DECL(ATRANS, true, false),
    ASCENDC_TPL_BOOL_DECL(BTRANS, true, false),
    ASCENDC_TPL_UINT_DECL(BIASMODE, 0, 1, 2),
    ASCENDC_TPL_UINT_DECL(KERNELTYPE, 0, 1)
);

ASCENDC_TPL_SEL(
    ASCENDC_TPL_CASE(/*ATRANS*/ true,  /*BTRANS*/ false, /*BIASMODE*/ 0, /*KERNELTYPE*/ 0),
    ASCENDC_TPL_CASE(/*ATRANS*/ false, /*BTRANS*/ true,  /*BIASMODE*/ 1, /*KERNELTYPE*/ 1)
    // ... only the legal combos; others won't be instantiated
);
```

### Evidence

`fused_quant_mat_mul/op_kernel/arch35/fused_quant_mat_mul_tilingkey.h` (5 axes:
ATRANS × BTRANS × BIASMODE × KERNELTYPE × OPTYPE) plus the master
`fused_quant_mat_mul_kernel_tilingkey.h` 6-axis variant.

**Predicted other instances**: cube-vec-fused ops in general (quant_batch_matmul_v3/v4,
batch_mat_mul_v3 peer family); any op with ≥3 orthogonal template axes where V220 used a
hand-rolled switch.
