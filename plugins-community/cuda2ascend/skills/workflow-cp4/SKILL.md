# CP4 性能验收验收标准

本验收点判定**算子性能是否达标**，即基于算子代码与性能数据，性能是否满足需求文档声明的预期。

## 验收对象

算子代码 + 性能数据（基于功能验收通过后的最终代码采集）。

## 通过指标

以**性能实测数据对照目标**判定，不凭主观印象：

- **指标达标**：实测耗时 / 带宽 / AI Core 利用率等关键指标，达到需求文档声明的性能预期（各指标目标值由绑定实现给定）。
- **覆盖关键 shape**：性能数据覆盖需求关注的典型 / 竞品 shape，非单点数据。
- **数据可信**：采集环境（芯片架构、CANN 版本、采集工具如 msprof op）明确记录，数据可复现。
- **通过条件**：指定 shape 集上的关键指标全部达标。目标值与容许偏差由绑定实现给定，判定形式为"实测值对照目标值，客观数据裁定"。

## 验收步骤

加载本 skill 时执行：

1. 核对性能数据的采集环境记录是否完整、可复现。
2. 核对性能数据是否覆盖指定的关键 shape 集。
3. 将各关键指标实测值对照目标值逐项裁定。
4. 对未达标项做瓶颈分析（计算 / 搬入 / 搬出的利用率与理论值对比），产出性能验收报告。

## 输出

本验收点产出**性能验收报告**，引用 `workflow-doc-templates` 的 `CP4-性能验收报告` 模板组织（勿内联模板）：

- **通过**：报告结论明确为"通过"，附测试环境、性能数据、瓶颈分析、指标对比。
- **不通过**：报告结论为"不通过"，并给出**结构化修改意见**——
  - 问题定位：给出瓶颈分析，定位到未达标的具体指标与 shape。
  - 问题语义归属：算子实现（性能未达标）；若瓶颈根因在上游设计，标注归属于开发方案设计，仅给定位结论、不自行改动切分策略。

报告作为中间交付件随验收结果一并返回。只验收不执行开发动作；允许做瓶颈定位，不自行优化代码、不变更上游 Tiling / 切分设计决策。
