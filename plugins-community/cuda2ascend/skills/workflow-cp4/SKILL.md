# CP4 性能验收验收标准

本验收点判定**算子性能是否达标**，即基于算子代码与性能数据，性能是否满足需求文档声明的预期。按需求文档的**评测来源模式**选择验收口径：模式 A 以评测集 HAP 评分为最终裁定，模式 B 以自建性能采集（msprof op）数据对照需求文档的可量化指标判定。

## 验收对象

算子代码 + 性能数据（基于功能验收通过后的最终代码采集；模式 A 为评测集评测报告的 HAP 得分，模式 B 为自建性能采集框架的耗时/带宽/利用率数据）。

## 通过指标

以**性能实测数据对照目标**判定，不凭主观印象：

- **指标达标**：实测关键指标达到需求文档声明的性能预期。模式 A 以 HAP 阈值表述（默认 ≥ 0.5 即性能不低于 baseline；HAP 是饱和型指标，详见 `repo-knowledge` 的 evaluation-contract.md）；模式 B 以耗时/带宽/AI Core 利用率等可量化指标表述。
- **覆盖关键 shape**：性能数据覆盖需求关注的典型 / 竞品 shape（模式 A 评测器自动对通过精度的用例采集性能，模式 B 由自建框架覆盖需求关注的 shape/dtype），非单点数据。
- **数据可信**：采集环境（芯片架构、CANN 版本、采集工具）明确记录，**取值以 `.cannbot/环境信息.md` 为准**，数据可复现（模式 A 评测集 `--eval-seed` 确定性 / 模式 B 固定输入与 warmup）。
- **模式 A 附加**：无因锚点非法（$T_{cand} \le 0$ 或 $T_{HW} \le 0$）导致的 HAP=None 异常（异常时该用例不计入性能项，但须核查根因）。
- **通过条件**：指定 shape 集上的关键指标全部达标。判定形式为"实测值对照目标值，客观数据裁定"。

## 验收步骤

加载本 skill 时执行：

1. **按评测来源模式采集性能**：
   - 模式 A：执行评测集评测（含性能）：`run_evaluation.sh --source-dir <提交目录> --operator <Op>`（或 docker 等价命令）。
   - 模式 B：用 3.2 搭建的自建性能采集框架（`ops-profiling` msprof op）跑出性能数据，覆盖需求关注的 shape/dtype。
2. 核对性能数据的采集环境记录是否完整、可复现。
3. 核对性能数据是否覆盖指定的关键 shape 集。
4. 将各关键指标实测值对照需求文档目标值逐项裁定（模式 A 对照 HAP 阈值，模式 B 对照耗时/带宽/利用率指标）。
5. 对未达标项做瓶颈分析（计算 / 搬入 / 搬出的利用率与理论值对比），产出性能验收报告。

## 输出

本验收点产出**性能验收报告**，引用 `workflow-doc-templates` 的 `CP4-性能验收报告` 模板组织：

- **通过**：报告结论明确为"通过"，附测试环境、性能数据、瓶颈分析、指标对比（模式 A 含各用例 HAP 得分）。
- **不通过**：报告结论为"不通过"，并给出**结构化修改意见**——
  - 问题定位：给出瓶颈分析，定位到未达标的具体指标与 shape（模式 A 标注 HAP < 阈值的用例）。
  - 问题语义归属：算子实现（性能未达标）；若瓶颈根因在上游设计，标注归属于开发方案设计，仅给定位结论、不自行改动切分策略。

报告作为中间交付件随验收结果一并返回。只验收不执行开发动作；允许做瓶颈定位，不自行优化代码、不变更上游 Tiling / 切分设计决策。
