# CP6 CI 通过确认验收标准

本验收点判定**上库前的交付闭环**，即验证流水线是否最终通过、检视意见是否已闭环，作为算子交付的收口确认。本仓采用 direct launch 工程架构，按需求文档的**评测来源模式**确定 CI 口径：模式 A "CI" 即评测集的三阶段评测（编译 / 精度 / 性能，如 cann-bench）；模式 B "CI" 即自建测试全量通过（`run.sh` 编译 + 精度全过）——CI 全绿 + 检视意见闭环即交付闭环。

## 验收对象

验证报告（模式 A：评测集三阶段评测结果，如 `cann_final_eval_*`；模式 B：自建测试 `run.sh` 全量结果）+ 提交工程状态（CP5 检视意见及其处理情况）。

## 通过指标

以**验证流水线结果状态 + 检视意见闭环状态**判定，不凭主观印象：

- **CI 全绿**：模式 A——评测集三阶段评测（编译 / 精度 / 性能）均为通过状态（编译通过、精度用例全过、HAP 达标）；模式 B——自建测试全量通过（`run.sh` 编译 + 精度全过）；无失败、无阻塞项。
- **检视意见闭环**：CP5 代码检视的意见全部处于已解决 / 已修复状态，无未回应或未修复的遗留意见（A 类反作弊红线为零容忍——模式 A 评测集提交时违反 = 整算子 0 分，须全部通过）。
- **状态一致**：验证报告对应的是提交工程当前最新代码，非过期结果（模式 A `--eval-seed` 确定性复验 / 模式 B 固定输入复验）。
- **通过条件**：CI 全绿 + 检视意见零遗留同时满足。判定形式为"对照验证状态与意见闭环清单，客观状态裁定"。

## 验收步骤

加载本 skill 时执行：

1. 读取验证报告（模式 A：评测集报告如 `cann_final_eval_*`，核对编译 / 精度 / 性能三段状态位；模式 B：自建测试 `run.sh` 结果，核对编译 / 精度全过），核对是否全绿。
2. 核对验证报告是否对应提交工程最新代码（模式 A `--eval-seed` 确定性复验 / 模式 B 固定输入复验）。
3. 遍历 CP5 检视意见，核对是否全部闭环、无遗留（A 类反作弊红线须全部通过）。
4. 汇总裁定，给出上库确认结论。

## 输出

本验收点产出**上库确认**结论：

- **通过**：明确结论"CI 通过确认"，附验证各段状态（模式 A：编译/精度/HAP；模式 B：编译/精度）与意见闭环记录，标记交付闭环。
- **不通过**：返回**结构化修改意见**——
  - 问题定位：逐条列出未通过的验证段（模式 A：编译 / 精度 / 性能具体失败项与 HAP 未达标用例；模式 B：编译 / 精度失败项）或未闭环的检视意见。
  - 问题语义归属：算子实现（编译/精度/性能缺陷）或 PR 检视意见（指明是哪类）。该回退循环受「过程有界」约束，超过最大轮次暂停并向用户报告当前问题清单。

只验收不执行；不修改代码、不代替修复、不重新触发评测（触发由对应流程执行）。
