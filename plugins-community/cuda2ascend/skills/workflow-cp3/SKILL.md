# CP3 功能验收验收标准

本验收点判定**算子功能是否正确**，即执行功能测试（含精度比对）后，功能实现是否符合预期。按需求文档的**评测来源模式**选择验收口径：模式 A 以评测集评测器为最终裁定，模式 B 以自建测试（run.sh + golden + 用例）为裁定。

## 验收对象

算子代码 + 测试代码（模式 A：评测集 golden 引用、补充用例表、白盒补充用例、分支覆盖说明；模式 B：自建 golden、用例表、gen_data、run.sh、白盒补充用例、分支覆盖说明）。

## 通过指标

以**测试执行结果**判定，不凭主观印象：

- **编译通过**：算子代码按 `repo-build-guide` 完成编译验证（`bash build.sh`），无编译错误。
  > 模式 A 下评测集整批编译失败时相关算子全部计 0；提交前须本地 `bash build.sh` 验证编译通过。
- **schema 注册**：`torch.ops.<pkg>.<op>` 可调用；模式 A 下 schema 须与评测集算子原型定义的 schema 字段一致。
- **全量执行、计数一致**：L0/L1/L2 全量功能用例全部执行，禁止子集自测；生成用例数 == 用例表/cases 条目数 == 实际执行数（计数一致，防静默丢用例）。
- **用例全通过**：指定必过用例集全部通过（通过率达验收阈值，默认要求核心用例 100% 通过）；预期报错的 expect_error 用例以「发生错误即通过」判定，不计入数值失败。
- **精度达标**：与 golden 的比对结果，最大相对 / 绝对误差落在容差内（模式 A 容差由评测集框架内置，模式 B 容差引用 `ops-precision-standard` 或需求文档字段）。
- **白盒覆盖达标**：白盒补充用例的分支覆盖说明中，声明的执行分支 / tilingkey 达覆盖阈值（默认全覆盖）。
- **通过条件**：编译通过 + schema 注册 + 全量执行且计数一致 + 必过用例集全过 + 精度误差在容差内 + 白盒覆盖达标，六者同时满足。判定形式为"执行结果对照阈值，客观数据裁定"。

## 验收步骤

加载本 skill 时执行：

1. 按 `repo-build-guide` 完成编译验证（`bash build.sh`）。
2. **按评测来源模式执行功能测试**：
   - 模式 A：执行评测集评测（`run_evaluation.sh --source-dir <dir> --operator <Op> --no-perf` 或 docker 等价命令）；核对 schema 注册与评测集算子原型定义一致。
   - 模式 B：执行自建测试（`run.sh`：编译 + 执行 + 结果比对）；schema 注册自检（`torch.ops.<pkg>.<op>` 可调用）。
3. 全量执行 L0/L1/L2 功能用例（禁子集自测），核对生成/用例表/执行三处计数一致，采集通过率与失败用例清单（expect_error 用例以报错即过判定）。
4. 与 golden 比对，采集最大相对 / 绝对误差，对照容差（模式 A 评测集内置 / 模式 B `ops-precision-standard` 或需求文档字段）。
5. 核对白盒分支覆盖说明中声明分支 / tilingkey 是否达覆盖阈值。
6. 汇总各项结果对照阈值，产出功能验收报告。

## 输出

本验收点产出**功能验收报告**，引用 `workflow-doc-templates` 的 `CP3-功能验收报告` 模板组织：

- **通过**：报告结论明确为"通过"，附验证摘要、关键指标（用例总数 / 通过率 / 测试报告路径）、精度说明。
- **不通过**：报告结论为"不通过"，并给出**结构化修改意见**——
  - 问题定位：逐条列出编译错误 / schema 不对齐 / 失败用例、现象、精度超差点及初步定位。
  - 问题语义归属：算子实现（功能 / 精度缺陷）。

报告作为中间交付件随验收结果一并返回。只验收不执行开发动作；允许做问题定位（复现、缩小范围、给根因证据），不自行改代码、不变更上游设计决策。
