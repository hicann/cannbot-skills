# CP2' 方案确认验收标准

本验收点判定**开发方案与测试方案是否相互吻合**，即两者作为一套整体是否一致、无冲突，可共同进入开发阶段。

## 验收对象

开发方案文档 + 测试方案文档（两份合并确认）。前置约定：两份方案各自的单项检查均已通过，本验收点只做**跨方案一致性**核对，不重复单项评审。

## 通过指标

以**跨方案一致性对照**判定，不凭主观印象：

- **同源一致**：两份方案均承接同一份 Spec，其引用的 dtype、shape 范围、精度容差等真值完全一致，无相互矛盾。
- **验证闭合**：测试方案的分级用例能覆盖开发方案关注的关键路径与边界（如 Tiling/切分策略涉及的 shape 边界在测试用例中有对应验证）。
- **无缝隙**：开发方案声明会实现的功能点，在测试方案中均有对应验证手段；测试方案假设的行为，开发方案均会提供。
- **通过条件**：一致性对照项全命中。对照矩阵由绑定实现给定，判定形式为"跨方案对照表逐项匹配，全命中即通过"。

## 验收步骤

加载本 skill 时执行：

1. 抽取两份方案对同一 Spec 真值（dtype/shape/容差）的引用，核对完全一致。
2. 构建"开发方案关键路径与边界 ↔ 测试用例"的对照矩阵，核对验证闭合、无缝隙。
3. 汇总对照结果，给出通过 / 不通过结论。

## 输出

- **通过**：明确结论"方案确认通过"。
- **不通过**：返回**结构化修改意见**——
  - 问题定位：逐条列出两份方案冲突 / 缺口的具体位置与表现（指明哪一方需调整或双方需对齐）。
  - 问题语义归属：开发方案设计 或 测试方案设计（指明是哪一方需调整或双方需对齐）。

只判定与给意见，不自行修改任一方案，不替上游对齐设计。
