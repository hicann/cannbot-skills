# CP5 代码检视验收标准

本验收点判定**代码变更的质量**，即全部变更文件是否达到可上库的质量水平。

## 验收对象

全部变更文件（算子代码、测试代码、相关文档等本次改动涉及的文件）。

## 通过指标

以**多维度检视项 + 评分**判定，不凭主观印象：

- **代码规范**：对照 `repo-coding-rules` 条款，无违规项。
- **设计一致性**：实现与开发方案 / Spec 一致，无偏离既定设计的私自改动。
- **潜在风险**：无越界、精度、并发、资源泄漏等风险项。
- **冗余清理**：无死代码、无调试残留、无无关改动。
- **通过条件**：各维度检视项无阻塞级问题，且综合检视评分达到绑定实现设定的阈值（默认要求：无"阻塞 / 高"级问题遗留）。检视条款集与评分阈值由绑定实现给定，判定形式为"逐条款检视 + 评分达阈值"，不以整体观感裁定。

## 验收步骤

加载本 skill 时执行：

1. 遍历全部变更文件，按代码规范、设计一致性、潜在风险、冗余清理四个维度逐条款检视。
2. 对照 `repo-coding-rules` 条款与开发方案 / Spec 核实规范与一致性。
3. 按绑定实现的评分机制打分，核对是否达阈值、有无阻塞级遗留。
4. 汇总检视结果，产出代码检视报告。

## 输出

本验收点产出**代码检视报告 / 检视结论**，引用 `workflow-doc-templates` 的 `CP5-代码检视报告` 模板组织（勿内联模板）：

- **通过**：报告结论明确为"通过"，附检视摘要与整体质量评价。
- **不通过**：报告结论为"不通过"，并给出**结构化修改意见**——
  - 问题定位：按问题清单逐条列出维度、严重程度、位置（文件:行）、描述与修改建议。
  - 问题语义归属：算子实现（规范 / 一致性 / 风险问题）。

报告作为中间交付件随验收结果一并返回。只验收不执行；允许指出问题并给建议，不自行改代码、不变更上游设计决策。
