# 黑盒用例设计方法

> 黑盒(需求/接口驱动)分级功能用例的**设计方法**，按评测来源模式分两条路径：
> - **模式 B（无评测集，默认）**：从需求文档出发系统化推导用例，产物为**用例表 + gen_data 用例 + golden 计算路径**。
> - **模式 A（有评测集）**：评测集在算子目录（如 cann-bench `tasks/levelN/<op>/cases.yaml`）已自带用例集；本方法职责为**核对评测集 cases 对算子原型声明维度的覆盖完整性**并**补充未覆盖场景**，产物为**覆盖矩阵 + 补充用例表**。
>
> 下方一～五为两模式通用的设计方法；模式 A 在「落盘与下游」按对齐口径调整。测试工程组成与执行见 [test-framework.md](test-framework.md)；精度与同源纪律见 [precision-and-perf.md](precision-and-perf.md)；白盒补全见 [whitebox-design.md](whitebox-design.md)。
>
> 本文件是基类默认方法（属 virtual），各算子仓可 override；override 时保持逻辑名 `repo-test-develop` 不变。

## 定位

- **输入**：需求文档（数学定义、算子原型、支持 dtype、shape 范围、精度要求）——唯一真值源，冲突时停止上报。模式 A 附加：评测集 cases（待核对的用例集）。
- **产物**：模式 B——按 L0/L1/L2 分级的**用例表**（编号/描述/参数/预期结果）+ `gen_data.py` 输入生成 + golden 计算路径。模式 A——**覆盖矩阵**（算子原型声明维度 × 评测集 cases 逐维对照表）+ **补充用例表**（评测集 cases 未覆盖的场景）；golden 由评测集自带，不产 golden。
- **一句话**：黑盒据"需求 + 对外原型"设计用例（模式 B）或核对评测集覆盖、补缺口（模式 A），刻意不依赖内部实现（内部分支覆盖交给 [whitebox-design.md](whitebox-design.md)）。

## 一、覆盖维度分解

把每个输入/属性拆成**正交因子**，逐因子独立覆盖，再对关键因子做组合：

| 因子 | 含义 | 取值来源 |
|------|------|----------|
| 存在性 | 可选参数存在/缺省 | 需求声明的可选性 |
| format/layout | 数据排布 | 需求声明的 format |
| 维数 rank | 张量维度数 | 需求声明的维度约束（如"≤8 维"） |
| dtype | 数据类型 | 需求声明的 dtype 列表（逐个不遗漏） |
| 取值域 value_range | 数值分布 | 见"二、数值域三段划分" |
| 长度 | list/array 元素个数 | 需求声明的长度约束（可含 0=空） |
| 标量值 | 标量/枚举取值 | 需求声明的取值集/范围 |

## 二、数值域三段划分（等价类 + 边界 + 特殊值）

每个 dtype 的取值域按三段设计，缺一不可：

1. **量级分段等价类**：把数值域切成量级带（次正规 → 小 → 中 → 大），对称覆盖正负（如 `[0,1e-3]`/`[1e-3,1e-2]`/`[1e-2,1]`/`[1,10]`/`[10,1e3]` 及其负镜像）。
2. **边界**：dtype min/max、最小正规数、次正规步长；shape 边界——最小 shape `[1]`、单元素、末维非对齐（非 32B / 非 dtype 对齐倍数）。
3. **特殊值**：`±0`、`±inf`、`nan`（以退化区间/标记编码，符号零区分 `+0`/`-0`）。

**裁剪原则**：按算子语义删不适用带（如归一化删负值带、非负输入删负段），再补算子特有值。**权威容差**引用 `ops-precision-standard`；各 dtype 的默认取值域细表可复用 `ascendc-st-design` 的参数定义默认表（引用其原文，勿照抄）。

> 示例（fp16，需按算子裁剪）：量级带 `[0,1e-3]…[10,1e3]` + 负镜像；边界 `±65504`、最小正规 `±6.1e-5`；特殊值 `±0/±inf/nan`。

## 三、参数间依赖与广播

- **只对跨参数依赖建约束**：类型等值/推导、形状广播、输出形状派生、条件/存在性联动；**固定取值域直接列入因子表，不建约束**。依赖分析优先级：dtype → shape → 数值 → 存在性。
- **广播**：枚举场景（等长 / 少维 / 多维 / 含 1 维 / 扩 1 轴），按右对齐规则校验兼容（逐维相等或一方为 1），输出形状按逐维取 max 派生。

## 四、分级派生策略

沿用本仓 L0/L1/L2 意图（见 [test-framework.md](test-framework.md) 分级表），这里规定**每级用什么覆盖策略选值**：

| 级别 | 覆盖策略 | 选值方法 |
|------|----------|----------|
| L0 门槛 | **单因子覆盖** | 每个因子的每个离散取值至少被一条用例命中（最小集）；常规 shape/dtype、小而快 |
| L1 功能 | **两两组合（pairwise）** | 离散因子（dtype/rank/存在性/format/枚举）做 pairwise 覆盖 + 典型/竞品 shape |
| L2 异常 | **每异常场景一条** | 见下方异常清单 |

**L2 异常场景清单**（每条一个用例）：不支持 dtype、非法 dtype 组合、维数溢出、format 非法、shape 不匹配、空 tensor、属性特殊值（inf/nan）、标量越界。

## 五、空 tensor 与 0 维

- **派生法**：从一条已满足约束的**正常用例**派生——将选定轴置 0、重算输出形状，保证约束自然满足；**每场景一条**，不与 dtype/属性再做组合。
- **区分**：空 tensor（shape 含 0、rank≥1）≠ 0 维标量张量（rank=0、shape=`[]`）。
- **按算子族枚举置零轴**：elementwise（单轴置零）；reduce（归约轴 / 非归约轴 / 全归约）；matmul/bmm（各维 b/m/k/n 及全零）。区分空进空出 vs 空进非空出。

## 六、复用引擎：`ascendc-st-design`（可选，推荐用于复杂算子）

因子 → 约束 → 拓扑求解 → 分级 + 覆盖报告 的机械部分可复用共享引擎，避免手工组合出非法用例：

- **何时用**：参数多、依赖/广播复杂、需要可核对的覆盖报告时。**简单 elementwise 算子**按上面一–五手工设计更轻，可不用。
- **怎么用（直调适配）**：
  1. **驱动**：从需求文档写其参数定义——把 kernel 参数按 `name/type/dtype/dimensions/value_range` 填入；直调无 aclnn 语义时，类型标签取最接近者、名称字段以算子名占位。
  2. **求解**：跑其 因子提取 → 隐式约束 → 求解配置 → 因子值 → 分级 脚本，得到 **harness-neutral 的因子值表**（`07_因子值.csv`）与 L0/L1/L2 **覆盖报告**（`*_coverage_report.yaml`）。
  3. **物化到直调**：把因子值表逐行转成**用例表**（编号/描述/参数/预期结果）与 `gen_data.py` 的 shape/dtype/取值域输入；**丢弃其 ttk 转换尾段**，不产任何 CSV/aclnn。
  4. **留证**：覆盖报告可作为覆盖矩阵核对的**交叉核对物**。

## 落盘与下游

- **模式 B**：用例表 + gen_data 用例 + golden 计算路径 → **test 目录**（随算子工程）。
- **模式 A**：覆盖矩阵 + 补充用例 → **test 目录**（随算子工程的 `tests/whitebox_cases/`）；评测集 cases 为评测权威用例集，补充用例仅供开发期自测，不替换评测集 cases。
- 若用引擎：参数定义/因子值/覆盖报告等设计中间物 → `.cannbot/<算子名>/` 设计目录或 `test/st/design/`，供覆盖矩阵核对。
- 精度容差、同源纪律见 [precision-and-perf.md](precision-and-perf.md)。
