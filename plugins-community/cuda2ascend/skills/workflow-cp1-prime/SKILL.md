# CP1' Spec 确认验收标准

本验收点判定**Spec 是否准确、完整地形式化了需求**，即是否可作为后续开发方案与测试方案的统一真值源。

## 验收对象

Spec 文档（机器可校验的 `spec.yaml`），是需求的形式化表达。

## 通过指标

Spec 是**机器可校验**的结构化契约，判定优先依赖机器校验，辅以对照核对，不凭主观印象：

- **schema 校验通过**：Spec 符合 `ops-spec-gen` 定义的 schema，跑通该 skill 的多阶段校验流程，无校验错误。
- **需求全覆盖**：需求文档中的每一条（数学定义、原型、dtype/shape、精度容差、性能预期等）在 Spec 中均有对应形式化字段，无遗漏、无越界新增。
- **可追溯**：Spec 字段与需求项可双向对应，无凭空引入的约束。
- **通过条件**：机器校验全过 + 需求项逐条对照全覆盖。校验流程与 registries 以 `ops-spec-gen` 为权威，判定形式为"校验器全绿 + 覆盖对照表全命中"。

## 验收步骤

加载本 skill 时执行：

1. 以 `ops-spec-gen` 的校验流程对 `spec.yaml` 跑机器校验，收集报错字段 / 阶段。
2. 构建 Spec 字段与需求项的覆盖对照表，逐条核对全覆盖、无越界。
3. 需用户拍板的形式化取舍，生成结构化问卷 json 作为验收产物返回，交由上游发送用户确认。
4. 汇总校验与对照结果，给出通过 / 不通过结论。

## 输出

- **通过**：明确结论"Spec 确认通过"。
- **不通过**：返回**结构化修改意见**——
  - 问题定位：列出未通过的校验项（报错字段 / 阶段）或未覆盖 / 越界的需求项。
  - 问题语义归属：Spec 形式化（Spec 与需求不一致或缺陷）；若根因在需求本身，标注归属于需求。

只判定与给意见，不自行编辑 `spec.yaml`，不替上游决定形式化取舍。
