# CP1 需求确认验收标准

本验收点判定**需求文档是否完整、明确、可执行**，即是否足以作为后续 Spec 形式化与方案设计的可靠依据。

## 验收对象

需求文档，应覆盖：数学定义、算子原型、目标芯片架构、精度要求、性能预期，以及其他特殊要求（如指定的实现方案）。

## 通过指标

以**检查项清单逐项判定**，不凭主观印象。每个必填项按"存在 / 明确 / 无歧义"三态核对：

- **完整性**：数学定义、算子原型、目标芯片架构、精度要求、性能预期等必填项无缺失。
- **明确性**：每项均为可执行描述——精度有明确容差或标准、性能有可量化预期、shape/dtype 范围明确，无"待定""视情况"等悬空表述。
- **一致性**：各项之间无相互矛盾（如原型与数学定义不冲突）。
- **通过条件**：全部检查项通过。必填项集合与量化基线由绑定实现给定，判定形式为"逐项对照检查项清单，全过即通过"。

## 验收步骤

加载本 skill 时执行：

1. 读取需求文档，按上述检查项清单逐项核对存在 / 明确 / 无歧义三态。
2. 需用户拍板的开放项（如需求边界、性能预期取值），生成结构化问卷 json 作为验收产物返回，交由上游发送用户补齐后再判定。
3. 汇总各项判定，给出通过 / 不通过结论。

## 输出

- **通过**：明确结论"需求确认通过"。
- **不通过**：返回**结构化修改意见**——
  - 问题定位：逐条列出缺失 / 含糊 / 矛盾的具体项及其表现。
  - 问题语义归属：需求（需补充或澄清）。

只判定与给意见，不自行补写或改写需求文档，不臆断补全缺项。
