# 错误处理与回退

> 各 CP 不通过时的回退策略、循环最大轮次、恢复规则。对应设计约束「过程有界」「可恢复性」。
>
> **骨架状态**：结构就位，具体阈值待填充。

## 回退关系（来自流程表）

| 不通过的 CP | 回退目标 | 重走路径 |
|-------------|---------|---------|
| CP1 | 1.1 需求分析 | — |
| CP2.1 | 2.1 黑盒测试设计 | — |
| CP2.2 | 2.2 开发方案设计 | — |
| CP3 | 3.1 算子开发 | 3.3 → CP3 |
| CP4 | 3.1 算子开发 | 3.3 → CP3 → 4.1 → CP4 |
| CP5 | 3.1 算子开发 | 3.3 → CP3 → 4.1 → CP4 → CP5 |
| CP6 | 6.4 / 6.5 修复 | 重触发 CI → CP6 |

## 过程有界（最大轮次，默认值）

所有可循环环节声明最大轮次；达上限即暂停，禁止无限自动重试。默认值如下，子仓可配置覆盖：

| 循环 | 涉及 CP | 默认最大轮次 | 计数对象 |
|------|---------|--------------|----------|
| 设计评审循环 | CP1 / CP2.1 / CP2.2 | 3 | 单个 CP 的打回-重做 |
| 验收状态机 | CP3 / CP4 / CP5 → 3.1 | 3 | 回退到 3.1 的整轮重走 |
| 上库 CI 循环 | CP6 | 3 | CI 触发-修复的往返 |

- 轮次计数写入 `state.json` 的 `blocked.round`（见 [state-schema.md](state-schema.md)）。
- **超上限处理**：暂停 → 落盘可恢复状态点 → 输出结构化问题清单 → 请求用户决策（继续放宽轮次 / 调整设计 / 停止）。

## 错误类型与判定

| 类型 | 典型场景 | 处理 |
|------|----------|------|
| 交付件不合规 | 文档缺项 | 返回对应生成步骤修复，计入设计评审循环 |
| 功能不达标 | CP3 精度/用例不过 | 回退 3.1，计入验收状态机 |
| 性能不达标 | CP4 未达目标 | 定位瓶颈；若涉及设计（Tiling/切分）回退设计角色，否则回退 3.1 |
| 检视不通过 | CP5 规范/一致性/风险问题 | 回退 3.1 按检视意见修复 |
| CI 失败 | 编译/UT/ST/codecheck 失败 | 回退 6.4/6.5，计入 CI 循环 |
| 环境阻塞 | CP0 环境不满足 | 交用户决定修复或停止 |

## 修改不越权

执行角色发现问题时：允许定位（复现、缩小范围、给根因证据），但**不得自行变更上游设计决策**（架构/Tiling/切分/接口）。定位结论回退给对应上游角色（architect），由其决定是否调整设计。

## 恢复规则

- 暂停/失败落盘到 `.cannbot/state.json`（见 [state-schema.md](state-schema.md)）的可恢复状态点：已完成阶段、当前阻塞点、已产出交付件、当前轮次。
- 恢复时从状态点续跑，不重跑已通过阶段。
