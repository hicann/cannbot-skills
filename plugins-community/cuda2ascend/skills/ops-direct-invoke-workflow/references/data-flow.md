# 数据流

> 各阶段的文件输入/输出与 `.cannbot` 产物清单。编号与 [SKILL.md 统一流程表](../SKILL.md#统一流程表) 及 [task-prompts.md](task-prompts.md) 对齐。

## `.cannbot` 目录布局

所有流程中间产物落 `.cannbot`；最终交付物（算子代码 / test / doc）落各自专业目录，不进 `.cannbot`。`.cannbot` 所有角色均可写，任意文件类型；文件命名遵循 `workflow-doc-templates` 模板名（编号 + 中文标题）。

**按算子分目录**：每个算子的流程产物独立放在 `.cannbot/<算子名>/` 下，互不覆盖，支持同一工作区并行推进多个算子。`<算子名>` 取该算子 `state.json` 的 `operator` 字段值，PM 在开启该算子流程时创建子目录。仅 `0-环境信息.md`（与算子无关、可复用）和 init 生成的共享件留在根目录。

```
.cannbot/
├── 0-环境信息.md                # 环境信息文档（0，共享可复用，留根）
├── permissions/                 # 角色权限配置（init Step 4.5 生成，共享）
├── <算子名>/                    # 每个算子一个子目录，流程产物互不干扰
│   ├── state.json               # 该算子工作流状态（见 state-schema.md）
│   ├── LOG.md                   # 开发日志（模板 LOG-开发日志）
│   ├── Issue-问题记录.md        # 问题记录（模板 Issue-问题记录）
│   ├── 1.1-需求分析.md          # 需求文档（1.1）
│   ├── 2.1-测试方案设计.md      # 测试方案（2.1）
│   ├── 2.2-开发方案设计.md      # 开发方案（2.2）
│   ├── CP3-功能验收报告.md      # 功能验收报告（CP3）
│   ├── CP4-性能验收报告.md      # 性能验收报告（CP4）
│   ├── CP5-代码检视报告.md      # 代码检视报告（CP5）
│   ├── questionnaires/          # 该算子的用户确认问卷 json（QA 生成，PM 发送）
│   ├── 7.1-开发报告.md          # 开发报告（7.1）
│   └── 7.2-经验总结.md          # 经验总结（7.2）
├── asc-devkit/                  # 共享依赖仓（init 克隆）
├── cann-samples/                # 共享依赖仓
└── cannbot-skills/              # 共享依赖仓
```

> 文件命名遵循 `workflow-doc-templates` 模板名（编号 + 中文标题），子仓 override 模板时保持交付件语义不变。
>
> 路径约定：环境信息文档固定为 `.cannbot/0-环境信息.md`（共享）；其余阶段产物路径前缀统一为 `.cannbot/<算子名>/`。PM 派发任务时按此约定下发写入路径，子 Agent 回传的交付件路径亦以此为准。

## 阶段数据流

| 编号 | 输入 | 产出 | 落盘位置 | 下游消费方 |
|------|------|------|----------|------------|
| 0 | — | 环境信息文档 | `.cannbot/0-环境信息.md`（共享，developer 写入；已存在且环境未变则跳过 0 与 CP0，新算子直入 1.1） | CP0 |
| CP0 | 环境信息文档 | 问卷 json + 确认结论 | `.cannbot/<算子名>/questionnaires/` + `.cannbot/<算子名>/state.json` | 1.1 |
| 1.1 | 对话上下文、设计约束 | `1.1-需求分析.md` | `.cannbot/<算子名>/1.1-需求分析.md` | CP1 → 2.1/2.2 |
| CP1 | `1.1-需求分析.md` | 确认/修改意见（需用户确认时附问卷 json） | `.cannbot/<算子名>/state.json`（问卷 json 落 `<算子名>/questionnaires/`） | 2.1/2.2 或回退 1.1 |
| 2.1 | `1.1-需求分析.md` | `2.1-测试方案设计.md` | `.cannbot/<算子名>/2.1-测试方案设计.md` | CP2.1 → 3.2 |
| 2.2 | `1.1-需求分析.md` | `2.2-开发方案设计.md` | `.cannbot/<算子名>/2.2-开发方案设计.md` | CP2.2 → 3.1 |
| CP2.1 / CP2.2 | 对应单份方案 | 确认/修改意见 | `.cannbot/<算子名>/state.json` | 阶段 3 或回退 2.1 / 2.2 |
| 3.1 | `2.2-开发方案设计.md`、修改要求 | 算子代码 | 代码目录 | CP3 |
| 3.2 | `2.1-测试方案设计.md` | golden + 用例表 + 性能框架 | test 目录 | CP3 |
| 3.3 | 算子代码、测试代码 | 白盒用例 + 分支覆盖说明 | test 目录 | CP3 |
| CP3 | 算子代码 + 测试代码 | `CP3-功能验收报告.md` | `.cannbot/<算子名>/CP3-功能验收报告.md` | 4.1 或回退 3.1 |
| 4.1 | 算子代码（CP3 通过后） | 性能数据 | test 目录 / 采集输出 | CP4 |
| CP4 | 算子代码 + 性能数据 | `CP4-性能验收报告.md` | `.cannbot/<算子名>/CP4-性能验收报告.md` | CP5 或回退 3.1 |
| CP5 | 全部变更文件 | `CP5-代码检视报告.md` | `.cannbot/<算子名>/CP5-代码检视报告.md` | 阶段 6 或回退 3.1 |
| 6.1 | 算子代码 + 设计文档 | 算子文档 | doc 目录 | 6.2 |
| 6.2 | 全部代码 + 文档 | PR | 远端 | 6.3 |
| 6.3 | PR | CI 报告 | CI 系统 | 6.4/6.5/CP6 |
| 6.4 / 6.5 | CI 报告 / 检视意见 | 修复后代码 | 代码目录 | CP6 |
| CP6 | CI 报告 + PR 状态 | 上库确认 | `.cannbot/<算子名>/state.json` | 阶段 7 |
| 7.1 / 7.2 | 全部交付物 | `7.1-开发报告.md` / `7.2-经验总结.md` | `.cannbot/<算子名>/`（developer-doc 起草→PM 落盘） | — |

## 真值源与字段所有权

- **需求文档** 是算子规格与数学定义的唯一真值源：2.1/2.2 的 dtype/shape/容差以需求文档为准，冲突时停止并报告。
- **测试配置**（test_matrix）由黑盒设计引擎 `ascendc-st-design` 产出（因子值表 + 覆盖报告），物化为本仓用例表；设计中间物落 `.cannbot/<算子名>/` 设计目录或 `test/st/design/`，供 CP2.1 覆盖矩阵交叉核对。
