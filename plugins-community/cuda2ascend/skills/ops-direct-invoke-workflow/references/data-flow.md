# 数据流

> 各阶段的文件输入/输出与 `.cannbot` 产物清单。编号与 [SKILL.md 统一流程表](../SKILL.md#统一流程表) 对齐。

## `.cannbot` 目录布局

所有流程中间产物落 `.cannbot`，最终交付物（算子代码 / test / doc）落各自专业目录，不进 `.cannbot`。`.cannbot` 所有角色均可写，允许任意文件类型；文件命名遵循 `workflow-doc-templates` 模板名。

**按算子分目录**：除共享文件外，每个算子的流程产物独立放在 `.cannbot/<算子名>/` 下，互不覆盖，支持同一工作区并行推进多个算子。`<算子名>` 取该算子 `state.json` 的 `operator` 字段值。

```
.cannbot/
├── 环境信息.md                  # 环境信息文档
├── permissions/                 # 角色权限配置
├── plugin-registry.json         # 可插拔流程插件注册表（init 生成；挂载点、步骤编号、启用状态）
├── <算子名>/                    # 每个算子一个子目录，流程产物互不干扰
│   ├── state.json               # 该算子工作流状态（见 state-schema.md）
│   ├── LOG.md                   # 开发日志（模板 LOG-开发日志）
│   ├── Issue-问题记录.md        # 问题记录（模板 Issue-问题记录）
│   ├── 1.1-需求分析.md          # 需求文档（1.1）
│   ├── 2.1-测试方案设计.md      # 测试方案（2.1）
│   ├── 2.2-开发方案设计.md      # 开发方案（2.2）
│   ├── CP3-功能验收报告.md      # 功能验收报告（CP3）
│   ├── CP4-性能验收报告.md      # 性能验收报告（CP4）
│   ├── CP5-代码检视报告.md      # 代码检视报告（CP5）
│   ├── questionnaires/          # 该算子的用户确认问卷 json（QA 生成并直接发送用户）与用户回复（问卷同名 .reply.json）
│   ├── tmp/                     # 该算子的全部临时产物（脚本、中间分析、日志、调试输出等）
│   ├── 7.1-开发报告.md          # 开发报告（7.1）
│   └── 7.2-经验总结.md          # 经验总结（7.2）
├── asc-devkit/                  # 共享依赖仓（init 克隆）
├── cann-samples/                # 共享依赖仓
└── cannbot-skills/              # 共享依赖仓
```

## 阶段数据流

| 编号 | 输入 | 产出 | 落盘位置 | 下游消费方 |
|------|------|------|----------|------------|
| 0 | — | 环境信息文档（含 Git 凭据位置候选；CP0 问卷不同意记录时由 QA 删除已记录位置） | `.cannbot/环境信息.md`（共享，developer 写入；已存在且环境未变则跳过 0 与 CP0，新算子直入 1.1） | CP0 |
| CP0 | 环境信息文档 | 问卷 json + 确认结论 | `.cannbot/<算子名>/questionnaires/` + `.cannbot/<算子名>/state.json` | 1.1 |
| 1.1 | 对话上下文、设计约束 | `1.1-需求分析.md` | `.cannbot/<算子名>/1.1-需求分析.md` | CP1 → 2.1/2.2 |
| CP1 | `1.1-需求分析.md` | 确认/修改意见 + 用户确认问卷 json | `.cannbot/<算子名>/state.json`（问卷 json 落 `<算子名>/questionnaires/`） | 2.1/2.2 或回退 1.1 |
| 2.1 | `1.1-需求分析.md` | `2.1-测试方案设计.md` | `.cannbot/<算子名>/2.1-测试方案设计.md` | CP2.1 → 3.2 |
| 2.2 | `1.1-需求分析.md` | `2.2-开发方案设计.md` | `.cannbot/<算子名>/2.2-开发方案设计.md` | CP2.2 → 3.1 |
| CP2.1 | `2.1-测试方案设计.md` | 确认/修改意见 | `.cannbot/<算子名>/state.json` | 3.2 或回退 2.1 |
| CP2.2 | `2.2-开发方案设计.md` | 确认/修改意见 + 用户确认问卷 json | `.cannbot/<算子名>/state.json`（问卷 json 落 `<算子名>/questionnaires/`） | 3.1 或按语义归属回退 2.2 / 1.1 |
| 3.1 | `2.2-开发方案设计.md`、修改要求 | 算子代码 | 代码目录 | CP3 |
| 3.2 | `2.1-测试方案设计.md` | golden + 用例表 + 性能框架 | test 目录 | CP3 |
| 3.3 | 算子代码、测试代码 | 白盒用例 + 分支覆盖说明 | test 目录 | CP3 |
| CP3 | 算子代码 + 测试代码 | `CP3-功能验收报告.md` | `.cannbot/<算子名>/CP3-功能验收报告.md` | 4.1 或回退 3.1 |
| 4.1 | 算子代码（CP3 通过后） | 性能数据 | test 目录 / 采集输出 | CP4 |
| CP4 | 算子代码 + 性能数据 | `CP4-性能验收报告.md` | `.cannbot/<算子名>/CP4-性能验收报告.md` | CP5 或回退 3.1 |
| CP5 | 全部变更文件 | `CP5-代码检视报告.md` | `.cannbot/<算子名>/CP5-代码检视报告.md` | 阶段 6 或回退 3.1 |
| 6.1 | 算子代码 + 设计文档 | 算子文档 | doc 目录 | 阶段 7（或按 registry 触发插件） |
| 7.1 / 7.2 | 全部交付物 | `7.1-开发报告.md` / `7.2-经验总结.md` | `.cannbot/<算子名>/`（developer-doc 起草→PM 落盘） | — |

## 真值源与字段所有权

- **需求文档** 是算子规格、数学定义与**代码架构选型**的唯一真值源：2.1/2.2 的 dtype/shape/容差、2.2 的代码架构均以需求文档为准，冲突时停止并报告。代码架构由用户在 CP1 拍板，下游只承接不改选；改选须回到 1.1 由用户重新拍板。
- **测试配置**（test_matrix）由黑盒设计引擎 `ascendc-st-design` 产出（因子值表 + 覆盖报告），物化为本仓用例表；设计中间物落 `.cannbot/<算子名>/` 设计目录或 `test/st/design/`，供 CP2.1 覆盖矩阵交叉核对。
