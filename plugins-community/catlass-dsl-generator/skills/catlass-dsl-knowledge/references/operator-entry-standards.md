# Operator 入库标准

适用于 `knowledge/operator/`；先执行[公共入库标准](common-entry-standards.md)。目标只有一个：给定
workload，能够判断实际实现路径、主要成本和首个可验证的优化候选。

## 取证范围

只审计固定提交中与优化决策直接相关的 host tiling/路径选择、kernel 入口、目标架构实现及
reference/测试。README/API 仅提取会改变路径、成本或正确性边界的条件，不复述完整接口。

## 核心内容

四个固定主题只服务于以下决策链：

1. **路径**（`## 算子算法`）：保留不可改变的关键语义，并列出 workload 条件到
   tiling key、fast/fallback、AIC/AIV 实现的映射。
2. **任务**（`## 分核策略与基本块切分`）：给出任务数、block 数、tile/tail、不可拆依赖轴、
   核间分工和输出所有权。
3. **数据与同步**（`## 数据路径与存储层级`、`## 流水排布、同步关系与数值精度`）：说明
   GM/UB/L1/L0/workspace 的字节与 live range，以及 stage/slot/flag/event/barrier、累加和转换边界。
4. **成本与观测**：按 workload 写计算、搬运、同步、串行依赖和并行度成本，并把 profiler
   症状映射到具体阶段、数据路径或等待关系。
5. **候选与验证**：先确认实际路径，再按单一优化轴排序。每项写清适用条件、修改对象、
   预期 profiler 变化、资源代价、必须保持的语义/所有权/同步/精度、回退信号和正确性矩阵。

## 删除规则

删除完整签名、参数顺序、默认值、导出路径、背景介绍、源码逐文件复述、通用硬件知识，以及
不能帮助定位瓶颈或选择候选的约束。拒绝“提高并行度”“减少访存”等没有对象、条件、代价、
观测和回退的建议，也不得把源码机制写成已证实收益。

## 验收

- [ ] 给定 workload，能确定路径、任务粒度、数据流和最可能的成本项。
- [ ] 给定 profiler 症状，能选择一个保持语义且可证伪、可回退的单轴候选。
