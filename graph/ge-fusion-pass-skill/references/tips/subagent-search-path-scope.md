# tip: 委托子 agent 检索时必须重复路径约束（避免外部目录挂起/误探）

> 📎 导航落点：`references/knowledge-base.md` §四（文档检索规则）。本文件仍是该检索纪律的**唯一权威定义源**，正文未改动。迁移映射见 `tips/MIGRATION.md`。

**读者**：② 开发 / ③ 分析。来源：真实批跑事故——C++ 用例反复硬超时，根因不是"文档探索慢"，而是 task/explore 子 agent 读 CANN 安装目录时触发外部目录权限询问，无人应答永久阻塞；证据是超时用例"权限询问>0"必现、正常用例"询问=0"，相关性 100%。父会话的跳过权限设置**不下传子 agent**。

## 症状

- 把 CANN/GE 文档检索交给子 agent（explore/task/general-purpose）后，任务停滞、长时间无进展、乃至硬超时。
- 或子 agent 跑去探未由环境变量声明的默认安装目录，读到错误环境的文件。

## 根因

- 子 agent 是**冷启动**的，不继承父会话在正文里立的路径约束与权限范围。它会用自己的默认策略去探目录，可能触发宿主的外部目录权限交互（无人值守时挂死），或误探默认安装路径。

## 硬性做法

- **在子任务 prompt 里原样重复路径约束**：CANN 路径一律从 `$ASCEND_OPP_PATH`（op_proto 优先）/`$ASCEND_HOME_PATH`（CANN 根优先）/`$ASCEND_TOOLKIT_HOME` 展开；GE 文档只从 `$GE_REPO_PATH/docs`（仓根由 `"$SKILL_ROOT/scripts/sync_ge_repo.sh"` 解析）；**禁探默认安装路径**（详见 `knowledge-base.md` 检索规则）。
- 明确告诉子 agent**只在这些根下检索**，变量缺失就如实报"环境缺失"并返回，不要自行扩大搜索范围。
- 检索任务尽量收窄（给具体文件名 glob / API 名），别让子 agent 漫游整个安装目录。
- 优先自己用 `rg --files`/`find` 在已知根下定位，能不派子 agent 就不派；确需并行再委托，但约束必须随任务下传。

## 自查

- 交给子 agent 的检索任务里，有没有把"从 env 展开、禁默认路径、缺失即返回"写进子任务 prompt？
- 子 agent 有没有读到默认安装目录里的文件？（应只在 env 指向的根下）
- 长时间无进展时，先怀疑是不是子 agent 卡在目录/权限交互，而非"文档太多"。
