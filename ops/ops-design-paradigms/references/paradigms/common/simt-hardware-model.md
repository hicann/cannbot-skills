# SIMT 硬件模型与芯片约束

> **层级**：公共知识层（common/），语言中立。芯片级行为事实——无论用 AscendC 还是 CANNBotDSL 编写，都在支持 SIMT 的 Ascend 芯片上运行，这些事实不变。语言适配层仅做 API 映射，不重复承载。

---

## 1 存储层级与各域通路

```
GM（全局，跨核共享可见）
 └─ L2（片上共享缓存）
     ├─ SIMT 域：普通 GM 读写（ldg/stg）经 DCache（32KB，SIMT 侧）
     │            ldcg/stcg 绕过 DCache 直达 L2；dcci 失效 DCache 行
     ├─ 向量域：MTE 引擎 GM↔UB 批量搬运（独立引擎，不过 DCache）
     │            SIMD vf 只访 UB/寄存器；向量寄存器 256B 定宽
     ├─ Cube 域：L1 → L0A/L0B/L0C、BIAS
     └─ 标量域：SSBUF（标量共享）
```

## 2 VF / 调度单元执行模型

- 每个 SIMD/SIMT **调度单元（VF 区域）= 一次 vec 计算调度；多区域串行执行**。
- **推论一（跨域有序）**：前一区域全部访存完成后才进入下一区域。跨区域的 WAR/WAW 无需显式屏障。
- **推论二（启动成本）**：调度单元启动有固定成本（数百 cycle 量级）。含搬运的循环留在区域外；纯寄存器/SIMT 计算循环应合入单个区域，消除逐轮启动开销。

## 3 DCache 一致性模型与 volatile 三分法

**硬件事实**：DCache 是 **write-back**（lazy 逐出）+ **读命中 eager**（有则不查 L2）+ **无跨核失效协议**。他核写入对本核不可见，直到本核 DCache 中该行被逐出或显式失效。

由此推导的访问三分法：

| 访问需求 | 正确形态 | 性能代价 |
|---|---|---|
| 跨核新鲜度（他核在写、需最新值） | volatile 读 / L2 直读（绕 DCache） | ~150 cycle/次 |
| barrier 后稳定数据 / 同核热数据 | 普通读（经 DCache） | 命中 ~20 cycle |
| 跨核可见直写 | volatile 写 / L2 直写 | — |

**判定法**：逐处核对参照实现的 volatile 修饰清单。volatile 完整清单通常极短（绝大多数 GM 访问无 volatile，屏障已保证稳定）。勿把 volatile 语义泛化到全部跨核访问。

**复合单 kernel 判定**：参照实现以多 kernel 边界保证可见性的数据，在复合单 kernel 内——写侧经他核回读（线程跨步写 × tile 对齐读跨界）时**写侧必须 volatile 写**。分离 kernel 的参照实现用普通写即可，形态差异源自架构而非误用。

## 4 DCache 预留规则

SIMT 开启后 DCache 从 UB 划走一块（最小 32KB）。预留规则：

- **范围 [32KB, 128KB]**：越大命中率越高、性能可能越好。
- **按剩余 UB 决定**：剩余 UB 越多、预留越大，上限 128KB；剩余不足 32KB 时报错兜底。
- 各语言的 UB 容量查询接口返回值**不含**此扣除——须设计侧自行扣减。
- 含全核同步的嵌入库（如排序库）需要 DCache 预留，tiling 侧必须扣除。

## 5 SIMT 线程模型代价

1. **UB 让出**：SIMT 开启后，UB 预算额外减少 DCache 大小（最小 32KB）——可用 UB 从 248KB 降至 ~216KB（按 32KB 最小预留计）。
2. **线程数→寄存器分档**：寄存器文件总容量固定，线程数翻倍 → 每线程寄存器减半。计算密集算子在大线程数下易**寄存器溢出到栈**（栈在 GM 上），性能反降。调优旋钮 = 线程数。

## 6 超发核屏障参与

- 多核编排中，嵌入库（如排序）内含全核同步；宿主启动核数 > 库所需时，库阶段**凑不齐屏障而死锁**。
- **解法**：库的计算分块域 = active_cores（运行期参数）而非实际启动数——`block >= active_cores` 的超发核计算量为 0，**屏障无条件全核到达**。
- 单核路径：全核冗余执行（幂等共写）或守卫跳过。

## 7 Bank 冲突模型

- 读读冲突：两次读落同一 bank，或同 bank group 超过两次读 → 串行化、矢量流水空档。
- 写写冲突：同一 bank group 同周期两次写必然串行。

## 8 数据通路哲学

**数据停片上（UB/L1）复用 vs 每次 GM 重读，性能可差一个数量级**。纯读收集或分阶段中间数据均须按此模型评估切块与复用，workspace 仅承载跨核共享数据。
