# dW：父段复用、同步与输出初始化

沿用 [通用数据流](../../../generic/filter/compute-flow.md) 的所有权：一个输出任务完整归约自己的 dW 区域，L0C 保存一个归约段，段间合并到 FP32 GM。DSL 的资源对象表达这些依赖，不能靠增加全核屏障代替正确的槽和地址。

## 1 RingBuffer 不是手写队列事件

`next_write()` 选择写游标当前槽并推进游标，`next_read()` 对读游标做同样操作。**选槽本身不搬运、不初始化，也不等待**；后续 tensor 的读写让编译器生成同步。选出的 tensor 保存该槽的地址，不是数据快照。

父段包含多个 K 子块时，只选一次读槽，并把它保存到局部变量：

```python
# 在设备代码中，a1 是按最终计划创建的 RingBuffer。
write_slot = a1.next_write()
cbd.mem_copy(write_slot, parent_source)
read_slot = a1.next_read()
# 后续多个子块都从 read_slot 派生视图；不要每个子块再 next_read()。
```

该片段只说明游标配对，没有展示预取。双缓冲的稳态应是“下一父段开始搬入 → 当前父段装载/计算 → 切换到下一父段”，同时保留第一次装载和最后一次消费的边界。A/B 的 `stepKa` 与 `stepKb` 可以不同，不能让两路游标无条件一起推进。

| 依赖 | 数据访问 | 槽可重用的条件 |
|---|---|---|
| MTE2→MTE1 | 写 L1，Load2D/3D 读该槽 | 当前父段最后一个 L0 子块已读完 |
| MTE1→M | 写 L0A/B，MMAD 读该槽 | MMAD 已完成对该槽的读取 |
| M→FIX | 写 L0C，Fixpipe 读该槽 | 当前归约段计算已完成 |
| FIX→M | Fixpipe 读 L0C，下段覆盖同一槽 | 最后一个输出片段已消费 |

用 `from_tensor` 派生子视图时保留原 storage 身份及准确物理布局。若通过原始指针/外部代码绕过 tensor 依赖，不能再假定自动同步能识别。`Buffer` 适合单份存储，不具有 RingBuffer 的轮转游标。

## 2 父段的元数据也要跟槽走

每次装载 L1B 的有效 H/W、顶部裁剪、左右 pad、源通道起点，与装载的那一份数据一起保存。预取下一槽时不能提前覆盖当前 Load3D 还在使用的元数据。L1A 的父 K stride 同理。

首次任务的 M/N 看起来相同，也必须装载。后续只在操作数对应的坐标、批深度、父 K 范围和宽片都不变时复用。对应 generic 的 `UpdateMNIdx`：仅 M 变化时可以保留匹配的 x 父段；仅 N 变化时可以保留匹配的 dedy 父段。任务切换后的复用条件必须包含实际输入地址，不只比较一个循环下标。

950 的手工 bank 分配从共享 buffer 文档承接。把两槽放在不同 L1 半区有助于并行，但只有提前发射下次搬运、且依赖图允许重叠，才构成有效预取。

## 3 清零先于所有原子写回

既有模板每次调用先清零 dedw，再逐段原子累加。使用 [融合清零实现](../initialization.md)：AIV 分片清零 GM，经 MTE3 mode 0 汇合后，以 MTE3 mode 2 通知 AIC；AIC 在首次 Fixpipe 原子写回前执行 FIXPIPE mode 2 等待。初始化与主计算处于同一个 MIX kernel，完整耗时包含清零。

清零分片不一定与计算任务对应，因此不能省略全部 AIV 的汇合。GM 依赖不由普通片上 Buffer 自动保证；空任务核也要完成该协议。等待在每次调用的公共路径执行一次，不能放进输出块循环。启动配额和事件预留见共享的融合清零说明。

零 L0C 是另一件事：`init=True` 只在有效 MMAD 时建立新部分和。已进入计算但没有贡献时，沿用 generic 的零操作数 MMAD 协议；L1 零值可由 `cube_fill_l1_zero` 建立，经实际 load 和 MMAD 后再写出。该低层 fill 的同步需检查生成代码，不能从函数名推定它和普通 `mem_copy` 具有相同自动依赖。

## 4 段间累加与确定性

`copy_options(atomic="add")` 把当前 FP32 部分和加到 GM；它不定义多个生产者相遇时的浮点加法顺序。当前 `streamkType=0` 保持输出任务互不重叠，一个核按固定段序处理自身区域；还须核对生成的 FIX 写回顺序及重复运行结果，不能仅凭 atomic 接口宣称逐位确定性。

本适配不把跨核 K 拆分加入现有模板。以后若引入多个核写同一输出，必须单独说明归约顺序、工作区与确定性；不能沿用当前所有权证明。输出初始化、有效地址范围与同一段只写一次，也必须保留。
