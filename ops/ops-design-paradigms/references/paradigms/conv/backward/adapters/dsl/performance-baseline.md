# 卷积反向 DSL 性能基线

设备执行与 Host 开销分开统计。

评估卷积反向 dX、dW 及复用 dX 的 Transpose DSL kernel 实现时，默认以 **完整设备计算路径的耗时** 对比原生 ASC，不包含 Host 开销。若用户明确要求公开入口或端到端性能，另列该指标，不与 kernel 性能混用。

在 `cannbot-dsl 0.8.2` 的测试中，已编译程序的重复调用仍有明显的参数解析、校验、Tensor/stream 处理和绑定开销，涉及 Python 与原生运行时；参数多时可能远大于设备计算时间。这是当前框架调用路径的性能问题，不能据此判定 kernel 未达标，也不能把它视为底层启动的固定下限。版本升级后应重新确认，不能泛化为所有 Python 调用或所有 DSL 版本的固有限制。

设置基线和出具报告时遵循以下口径：

- **排除 Host 时间**：DSL 转 ASC、编译、加载、首次初始化、Python 入口、Host tiling、参数绑定、内存分配和 Host 启动提交不进入 kernel 指标。双方先完成预热，再采集稳态设备数据。
- **用设备证据计时**：优先读取 profiler 的设备任务起止时间。`perf_counter` 包围 Python 调用，即使名称写成 `direct`、`program` 或 `kernel`，仍不是纯设备耗时；在 Python 调用两侧放设备 Event 也可能包含 Host 发射不及时造成的设备空等，应核对时间线。不能用墙钟时间减去估算的 Host 常数来代替设备计时。
- **保留完整设备工作**：清零、转置、预处理、归约、cast、必要设备搬运和同步都不能漏计；融合 kernel 内的这些成本也不扣除。单 kernel 统计完整执行时间；串行多 kernel 汇总该次调用的全部设备任务时长。存在并行或跨流依赖时，另按设备时间线说明关键路径与空隙来源，不把重叠任务时长直接相加当作延迟，也不把 Host 提交造成的空隙混入 kernel 指标。
- **对齐比较条件**：相同 shape、dtype、format、数学模式、实际核配额和输入输出语义；声明动态 shape 时，两边按运行时几何比较。需要输出转换的一方计入转换设备成本，基线只执行目标算子所需的工作。
- **分开报告**：列出设备耗时、比值方向、预热与重复次数、统计方式、实际 kernel 列表及 profiler 证据。Host 和端到端耗时按需单列；若尚无设备数据，标记“kernel 性能待测”，不以 Host 计时下达标结论。相对性能写为 `T_ASC_device / T_DSL_device`，大于1表示 DSL 更快；验收阈值由算子规格定义。

优化 kernel 时先根据设备侧证据定位瓶颈。框架绑定、Python 包装及 Host 缓存问题单独归因；不要为降低 Host 计时而偏离设备端 tiling、搬运或计算优化目标。
