# Convolution 范式：卷积正向 tiling 切分算法

> **层级**：通用知识层（generic/）。切分规则与开发语言无关：同一规格不管用 AscendC 还是 DSL，都用同一套切分算法；适配层只负责把结果落地为数据结构与指令参数。
>
> 记号见 [language.md](language.md)；循环结构见 [compute-flow.md](compute-flow.md) §6。

## 0 总览：tiling 切什么、为什么切

tiling 切分 = **核间切分（绑核）+ 核内切分（分块）**。

以 Ascend 950 为例：32 个 cube 核 + 64 个 vector 核。**分核一般指分 cube 核**；vector 核固定按 1:2 跟随 cube 核（卷积主通路在 cube 上，vector 侧只做辅助搬运/后处理）。

所有 tiling 切分算法，最终一定为四件事服务：

| 目标 | 含义 |
|------|------|
| 多核间并行 | 核数绑满、各核负载均衡 |
| 单核内并行 | 搬运与计算重叠（乒乓流水，见 §3.1） |
| 连续地址搬运 | 块越大越连续，burst 越长，带宽越高 |
| 芯片带宽利用率 | 减少重复搬运（尤其 weight 与 fmap 的 L1 重装次数） |

**产出三件东西**：TilingData（块大小/迭代次数/尾块/开关）、blockDim（核数）、TilingKey（模板实例选择，§4）。

**推导顺序（固定，前步约束后步）**：

```
① 模式决策（M/HW/basic block）→ ② 多核切分 → ③ L0 切分 → ④ L1 切分
→ ⑤ 乒乓决策 → ⑥ 尾块/辅助量 → ⑦ TilingKey + 校验
```

> 为什么 L0 先于 L1：L1 的**最小占用**由 L0 块决定（A 侧行推理以 mL0 为下界、B 侧以 nL0 为下界）。先切 L1 会切出装不下最小工作集的块。
>
> 基本块模式的 ③④ 方向相反：块型先固定（取自初值表），L1 只做"夹紧收缩"验证（自底向上，见 §3.4）。

## 1 切分模式：名词解释与选型

### 1.1 M 切分模式（M Mode）

把 output 的 H、W **合轴成一根 M 轴**（`M = Ho×Wo`），然后对整根 M 轴切分。

- 用了**合轴**思路：切分对象从两根轴变一根，切分与负载均衡都更简单；
- M 是"展平坐标"，核内反解时再拆回 (行, 列) 交给 LOAD3D（`mStartPt = m mod Wo`）；
- **默认优先选择**（1D 卷积 Ho≡1，天然是 M 模式）。

### 1.2 HW 切分模式（HW Mode）

H、W 保持两根独立轴，分别切分（实际只切 H，见 §2.2）。

- 价值：W 方向整行保留时，每核 L1 只装"更窄的 H 行带"，适合**图很宽（Wi 大）、M 模式下 A 侧行块装不下 L1** 的场景；
- M 模式准入失败（L1 装不下 / 指令限制超限 / 行带积超 15bit）时落 HW 模式。

### 1.3 基本块切分模式（basic block）

从 **roofline 模型**出发的切分：cube 利用率对 (mL0, nL0, kL0) 的尺寸敏感，存在几组"性能较优"的固定块型；先固定这些高性能 L0 块型，再**向上**推导 L1 切分与绑核策略。

该模式的特点：

| 特点 | 说明 |
|------|------|
| 触发条件 | M 模式下 `mCut×nCut×batch×group > 核数`（多核切分较碎）且 L1 可用空间足够 |
| 块型初值（mTile, nTile） | `Co≤64 → (512,64)`；`Co≤128 → (512,128)`；`HoWo≤64 → (64,1024)`；`HoWo≤128 → (128,512)`；否则 `(256,256)`——**M、N 方向一大一小**，兼顾 fmap 行带与 weight 块的 L1 需求 |
| 调整过程 | 先按 L1 容量夹紧 mTile/nTile，再枚举 (fDim, nDim, groupDim) 绑核组合，取**核利用率**最优 |
| 与普通 M 模式的差别 | 普通 M 模式从"因子候选+代价模型"全局搜索；basic block 从"少数高性能块型"出发局部调整——搜索空间小、决策快，适合绑核已经很碎的场景 |

> 本节只给定义与触发条件；该模式的**绑核决策**见 §2.4（核间），**核内自底向上推导**见 §3.4（核内）。

### 1.4 三种模式怎么选（切分方案决策）

模式决策是 tiling 推导的第一步（§0 顺序①），后续所有切分都在选定模式内进行。决策按**准入检查 + 触发条件**的顺序进行：

```
                    ┌─ 行带积 Hi_L1×Wi > 32767 或 LOAD3D 指令限制超限？──是──► HW 模式（或软件搬运退化）
                    │
输入规格 ──► M 模式准入检查 ─┤
                    │        否
                    └─ M 模式下 L1 可容纳（A 侧行推理下界 + B 侧下界 ≤ L1）？──否──► HW 模式
                     |
                      是（M 模式可行）
                     ┌─ mCut×nCut×batch×group > 核数（因子切分太碎）且 L1 空间足够？
                     │        是
                     └────────────────► 基本块模式
                      否
                     ▼
                   M 模式（默认）
```

| 判定项 | 含义 | 落到哪个模式 |
|--------|------|-------------|
| Hi_L1×Wi 相关积 > 32767 | LOAD3D 的 L1 图积 15bit 限制（Hi_L1≥1 时蕴含 Wi ≤ 32767，并覆盖 DN2NZ nValue 的 16bit 上限；口径与 compute-flow §4.3 限制表一致），M 模式整行带装不下 | HW（H 方向切，行带变窄） |
| stride/dil/pad/膨胀核超限 | LOAD3D 指令参数超限（compute-flow §4.3 限制表） | HW 或软件搬运（GM→UB→L1，软件滑窗） |
| M 模式 A 侧 L1 不可容纳 | 行推理下界 × 全宽超 L1 | HW（更窄行带） |
| 1D（Ho≡1） | 只有 W 方向有空间并行度 | M 模式（天然）或 HW 的 woDim 切分 |
| 因子切分太碎（触发条件见 §1.3） | 绑核维度组合把输出切得碎、核利用率低 | 基本块模式 |
| 以上都不命中 | 常规 2D/3D | **M 模式（默认优先）** |

选择依据的本质：

| 模式 | 优化的东西 | 付出的代价 | 适用前提 |
|------|-----------|-----------|---------|
| M 模式 | 全局最优（块型 + 绑核联合搜索） | 搜索空间大、决策逻辑复杂 | 输出规模与核数匹配，L1 装得下 |
| HW 模式 | A 侧行带窄（省 L1）、W 整行搬运（带宽最优） | H 方向切分后相邻核重复搬行；W 不切导致空间并行度受限 | 图很宽 / M 模式 L1 不可行 / 指令超限 |
| 基本块模式 | 决策快（块型固定）、绑核均衡 | 放弃块型全局寻优 | 绑核已经很碎、L1 有余量 |

## 2 核间 tiling 切分（卷积各个轴绑核）

绑核永远**面向 output**（输出块之间无依赖，天然并行；输入只读共享）。

### 2.1 M 模式绑核

对 output NCHW/NCDHW 绑核：**N（batch 轴）、C（cout 轴）、D（dout 轴）、HW（合轴为 M 轴）**。

```
blockDim = batchDim × nDim × mDim × doDim(3D) × groupDim ≤ 核数
```

groups>1 时的 groupDim：分配到不同核上处理的 groups 数量。例：groups=8、4 个核 → groupDim=4，每核处理 2 个 groups，单核内再按 groups=2 去分配 cout 轴和 cin 轴（当前范围 groups=1，不展开，详见 scene 扩展）。

### 2.2 HW 模式绑核

绑 **N（batch）、C（cout）、D（dout）、H（hout）**，W 不绑核。

**为什么 W 方向不绑核、不切分？** 从 kernel 搬运数据出发：fmap GM→L1 用 DN2NZ 指令搬运时，**最优方案是 W 方向整行搬运**；若 W 也切分，每个核只搬行的一段，相邻核之间相同行会被重复搬运（h 方向数据重复搬运），带宽浪费。因此 W 向切分只在 H 维无法提供空间并行度时启用（典型为 1D：Ho≡1，仅剩 W 维可切）。

### 2.3 HW/M模式绑核策略优劣的判断依据

以 32 核、output (batch=8, cout=512) 为例：`(batch绑4核, cout绑8核)` vs `(batch绑1核, cout绑32核)` 哪个好？分三步判断：

**第一步：核数应尽量绑满。** 按核数和轴大小做**因子切分**——每维绑核数必须是"该维规模（按分形粒度折算）"与"核数"的公因子：

```
cout 轴规模 = CeilDiv(Co, N0)（按 N0 折算）
cout=512 → 32 分形块、核数 32 → cout 可绑 1、2、4、8、16、32 核（6 种候选）
```

因子切分的优化空间：候选值只取公因子集合（保证整除、无碎片），再叠加"核数因子"补齐（如 batch=3、核数=32 时 batch 只能绑 1 或 3，剩余核数交给别的轴）。

**第二步：各轴绑核数之积不许超过总核数。**

```
batchDim × nDim × mDim × doDim × groupDim ≤ 32
cout绑8 × batch绑4 = 32 ✓ 恰好绑满；cout绑32 × batch绑4 = 128 > 32 ✗ 剪枝
```

**第三步：合法组合之间比"搬运开销 + cube 计算开销"。** 对每个合法组合算四笔账（代价模型，均为**每核量**）：

| 代价项 | 公式 | 随绑核数变化 | 说明 |
|--------|------|-------------|------|
| fmapCost | `(N/batchDim) × Kd × Ci^align × Hi·Wi × sizeof(x) / mDim` | 随 mDim/batchDim **减小** | 每核输入行带字节；batch 切分整图复制，M 切分行带变窄 |
| weightCost | `(N/batchDim) × K × Co^align × sizeof(w) / nDim` | 随 nDim **减小** | 每核权重段字节；**乘带宽系数 BwCoef**（weight 流量对性能更敏感） |
| outputCost | `(N/batchDim) × Co^align × Do·Ho·Wo × sizeof(y) / mDim / nDim` | 总量不变仅按核分布 | 每核输出字节 |
| cubeCost | `(N/batchDim) × M × Co^align × K / mDim / nDim` | 总量不变仅按核分布 | 每核乘加次数 |
| **total** | `(fmap + BwCoef×weight + output)/归一化 + cube` | — | 归一化因子把"字节"与"乘加"折到可比量级（常数，不影响排序结论） |

BwCoef 取值：整行 DN2NZ ≈ 4、ND2NZ ≈ 1（见 §3.7）。同 total 时取**核利用率高**者（占满核、各核均衡）。

**三步判断汇总**：

| 步骤 | 判断什么 | 规则 |
|------|---------|------|
| ① 绑满 | 核数是否用完 | 各轴绑核数之积 ≤ 总核数，尽量等于总核数 |
| ② 整除 | 各维是否整除 | 因子切分——每维绑核数取公因子，保证无碎片 |
| ③ 比代价 | 哪个组合总流量最小 | 四笔账加权求 total，取最小者；同 total 取核利用率高者 |

### 2.4 基本块模式如何决策绑核

前置：模式判定已落基本块模式（§1.4 选型；§1.3 触发条件：M 模式下 `mCut×nCut×batch×group > 核数`——普通因子切分把输出切得太碎，且 L1 可用空间足够）。此时绑核对象从"输出轴"换成"**块网格**"：块型固定后，输出被划成若干个 (mTile × nTile) 基本块，绑核要回答的是"块网格怎么分给核"。

**块网格与绑核候选**：

```
输出（M × Co^align）按 (mTile, nTile) 划块：
  mBlkNum = CeilDiv(M, mTile)         nBlkNum = CeilDiv(Co^align, nTile)
  总块数（单 batch）= mBlkNum × nBlkNum ×（组方向规模，groups=1 时 =1）

绑核候选 (fDim, nDim, groupDim)：积 ≤ 核数，每维 ≤ 该维块数
  fDim     沿 batch / M 块方向绑核数
  nDim     沿 Co 块方向绑核数
  groupDim 沿组方向（groups=1 恒 1）
裁决目标：核利用率最高（每核块数均衡、核绑满），
  利用率 = 最小每核块数 / CeilDiv(总块数, 核数)；同利用率再按 §2.3 代价模型比总流量。
```

与 §2.3 的关系：§2.3 的"因子 + 代价模型"是对绑核维度的全局搜索；基本块模式因块型已被固定为少数高性能组合，搜索空间大幅缩小——绑核退化为固定块网格上的分配问题，决策更快。代价是块型本身不再参与全局寻优（接受 §1.3 初值表的次优性换取决策速度）。

四步流程：

1. **定块型**：按 §1.3 初值表取 (mTile, nTile)（按 Co / HoWo 分档，M、N 一大一小，兼顾 fmap 行带与 weight 块的 L1 需求）；
2. **L1 夹紧**：按容量公式校验（A 侧最坏情形行推理 × 全宽 + B 侧展开口径 + bias ≤ L1，见 §3.3），超限则 mTile/nTile 向下收缩至可容纳（核内方向的完整推导见 §3.4）；
3. **算块网格**：按上方公式计算 mBlkNum / nBlkNum / 总块数（分组卷积再乘组方向规模，见 [scene.md](scene.md) §4）；
4. **枚举绑核并裁决**：候选组合 (fDim, nDim, groupDim)，约束为积 ≤ 核数且每维不超该维块数。**裁决目标从"代价最小"换成"核利用率最高"**：每核块数均衡、核绑满——按上方利用率公式量化；同利用率再按 §2.3 代价模型比总流量。

尾块与退化：

- 总块数不整除核数 → 尾核少一块，直接计入利用率（这正是目标函数取最小值的原因）；
- 总块数 < 核数 → 绑不满，说明块型对该规格偏大，应回退 §2.3 的 M 模式全局搜索；
- 块网格某维只有 1 块 → 该维不绑核（如 nBlkNum=1 时 nDim=1）。

## 3 核内 tiling 切分（单核内各个轴切分）

### 3.1 什么是 pingpong？为什么要尽量开启？什么时候开/关？

**什么是 pingpong**：给同一块 buffer 配 2 份（double buffer，db），生产者写第 1 份时消费者读第 2 份，交替使用：

```
单缓冲：  装载 ── 计算等待 ── 计算 ── 装载等待 ── 装载 ...   （串行，搬运时间全浪费）
双缓冲：  装载0 │ 装载1 │ 装载2 │ ...                        （装载与计算重叠）
          等待  │ 计算0 │ 计算1 │ ...                        （只浪费起步一格）
```

**为什么尽量开启**：搬运（MTE2/MTE1）与计算（MAD/FIX）是异步硬件队列，双缓冲是它们重叠的前提——不开就退化为串行，性能可能差数倍。

**什么时候关闭**（关掉省出的空间换更大的块，反而更快）：

| 情形 | 关闭项 | 原因 |
|------|--------|------|
| K 全载且 M/N 同时全载 | AL0/BL0 双缓冲 | 不会再发生 L1→L0 重装，第二份永远闲置 |
| ALL 全载（fmap+weight 都驻留 L1） | AL1 双缓冲 | A 侧不再重装 L1 |
| L1/L0 空间紧张 | 优先保块大小 | 块变小损失的 cube 利用率 > 流水收益 |

乒乓开关打包成 pBufferFlag 位域：`bit0=BL1, bit1=AL1, bit2=CL0, bit3=BL0, bit4=AL0`。**迭代序联动**：AL0 双缓冲 + BL0 单 → M-first；反之 N-first（与 §3.3 全载判定结论冲突时以全载判定为准）。

### 3.2 决策顺序：L0 层级先决策，确保 cube 利用率

L0 切分（mL0/nL0/kL0）决定 MMAD 的块型——**块越大，MMAD 次数越少，cube 利用率越高**。在三条容量不等式约束下取尽量大：

```
L0A:  AlignB(mL0,M0) × AlignB(kL0,K0) × sizeof(x) × pbAL0 ≤ 64KB
L0B:  AlignB(kL0,K0) × AlignB(nL0,N0) × sizeof(w) × pbBL0 ≤ 64KB
L0C:  AlignB(mL0,M0) × AlignB(nL0,N0) × sizeof(acc=fp32) × pbCL0 ≤ 256KB
```

候选与搜索：

```
nL0 候选 = {N1 与容量上限内 2 的幂公因子} × N0     （N0 整数倍）
mL0 候选 = {M1 与容量上限内 2 的幂公因子} × M0     （M0 整数倍，且不超 LOAD3D 16bit 起点）
kL0     = K0 的倍数（默认 K0；取大意味着一次装多个 K 分形）
```

从最小候选开始**交替增大**（`mL0≤nL0 时先增 M，否则先增 N`），每步校验三条 L0 不等式 + **L1 最小占用可容纳**（A 侧行推理下界 + B 侧 `K0×Kh·Kw×nL0` 下界 + bias ≤ L1）。候选取 2 的幂公因子是为了整除关系尽量成立、减少尾块。

**两种合法搜索策略的关系**（生成代码任选其一，前提是容量不等式全查）：

| 策略 | 做法 | 特点 |
|------|------|------|
| 交替增大（完备搜索） | 在候选集内逐步搜最大可行 (mL0, nL0) 组合 | 块型更优（减少 MMAD 次数）；搜索代码多 |
| 容量上限直取（简化） | 各维独立取容量不等式允许的上限，再互相校验 | 代码简单；可能取到次优组合（某维到上限挤压另一维） |

交替增大是通用策略，容量上限直取可视为"候选有序且互不挤压"时的特例；两者结论冲突时以完备搜索为准。

### 3.3 L1 层级后决策，减少重复搬运

L1 切分（mAL1/nBL1/kAL1/kBL1）在 L0 块之上进行，核心是 **fullLoad（全载）判定**——哪侧能整体驻留 L1，哪侧就全载（省掉重装）。

A/B 侧 L1 占用公式（**口径务必区分，严禁混用**）：

```
A 侧（fmap，未展开口径）:  aL1 = cinA × hiLoadL1 × Wi × sizeof(x) × pbAL1
                            cinA = kAL1/(Kh·Kw)，hiLoadL1 用【最坏情形行推理】（见下）
B 侧（weight，展开口径）:  bL1 = kBL1 × nBL1 × sizeof(w) × pbBL1
```

**⚠️ 行推理的"两条公式、两种用途"（两公式混用会导致 AL1 越界写穿 BL1）**：

| 公式 | 用途 | 形式 |
|------|------|------|
| **最坏情形**（tiling 侧，算 AL1 **buffer 尺寸与预算**） | L1 预算、AL1 分配 | `hoSpanMax = CeilDiv(mAL1 + Wo − 1, Wo)`；`hiLoadMax = min((hoSpanMax−1)·sH + dkH, Hi)`。等价的保守写法：`hoL1 = mAL1/Wo + 2`（整除 + 2 行边界冗余，至多比精确最坏情形宽裕一行） |
| **精确值**（kernel 侧，逐块计算） | 每块的实际装载行数、pad 折算 | 对块起点 `mStart`：`hoStart=mStart/Wo`、`hoEnd=CeilDiv(mStart+curM, Wo)`、`hiLoad=(hoEnd−hoStart−1)·sH+dkH`，再按 `hiLoad = min(hiLoad−padTopL1, Hi−hiIdx)` 做**上 pad 折算与 GM 下边界钳制**（见 compute-flow §6.3） |

为什么 tiling 必须用最坏情形：M 块的起点 `mStart % Wo` **不保证为 0**（多核 M 切分或 M 不被 Wo 整除时，块从行中任意列起）。中间列起块的块跨行数是 `CeilDiv(mAL1 + col0, Wo)`，比行对齐假设的 `CeilDiv(mAL1, Wo)` **多出最多 1 行**；stride 越大、Wi 越宽，这 1 行的代价（`sH + dkH` 个输入行 × Wi × 通道数）越大。若 AL1 按行对齐口径分配：

- kernel 侧按精确值装载 → **Dn2Nz 越界写穿 AL1 buffer**；
- L1 中 AL1 与 BL1 相邻 → 溢出数据砸进 BL1，随后 B 侧装载又覆盖回去；
- **故障特征**：仅各 M 块的**尾行**输出错（块尾行窗口恰好读越界区），错值量级正常（读到的是 B 侧数据的"有效值混合"而非垃圾）；行对齐起块的块全对。极易误判为滑窗参数错误，实际是 tiling 预算口径错误。

**配套约束**：`hiLoadMax × Wi ≤ 65535`（Dn2Nz 的 nValue/dstNzC0Stride 为 16bit），超限时在 mAL1 增长环节就要截断 mAL1。

fullLoad 四态判定：

| 优先级 | 状态 | 判定 | 伴随决策 |
|-------|------|------|---------|
| 1 | **ALL 全载** | fmap 全量 + weight 全量 + bias ≤ L1 | 单块；AL1 单缓冲 |
| 2 | **BL1 全载**（weight 主导） | weight 全量可容纳，且 fmap 流量 ≤ weight 流量×系数 | kBL1=全K；**M-first** |
| 3 | **AL1 全载**（fmap 主导） | fmap 全量可容纳 | kAL1=全K；**N-first**。仅 2D（3D 需 dk 打包装载形态，暂缓） |
| 4 | **NONE** | 均不满足 | 先尝试 **K 向单侧全载**（A 或 B 侧 K 全载，比较 MTE2 流量择优）；仍不满足则 M/N/K 三向都切 |

> **参考实现裁剪说明**：配套 example/conv2d 按 **BL1 驻留（含 ALL 退化态）/ NONE 两态**实现（A 侧驻留未做；其 BL1 判定含"A 侧最坏行带同时容纳"约束，且 nBlk 受 BT 段容量封顶）——生成算子按本表完整四态实现时以本表为准，参考实现差异见其 README。

非全载时候选范围（从全载向下回退，贪心取第一个满足 L1 的组合）：

```
kAL1/kBL1 候选 = {Ci1 的因子（3D 并入 dk·Ci1）} × Kh·Kw·K0    ← kAL1 受 LOAD3D posK 16bit 上限截断
nBL1 候选      = {CeilDiv(AlignB(Co,N0), nL0) 的因子} × nL0
mAL1 候选      = {CeilDiv(AlignB(M,M0), mL0) 的因子} × mL0     ← 受 M 起点 16bit 上限截断
```

> **kAL1 记号陷阱**：kAL1/kBL1 是**乘过 Kh·Kw 的展开 K 口径**（= 通道块数×Kh·Kw×K0），便于与 kBL1/kL0 对齐比较；但 A 侧 L1 实际驻留是**未展开 2D 图**，算字节数要除回 Kh·Kw。

### 3.4 基本块模式的核内切分（自底向上）

§3.2/§3.3 描述的是 M/HW 模式的**自顶向下**决策方向（从容量不等式搜索最优块型）；基本块模式方向相反——**自底向上**：L0 块型是**输入**而非输出，先接受固定块型，再向上验证与调整 L1：

```
① L0 定型：mL0/nL0/kL0 沿用 §3.2 的容量不等式在块型内取值（块型给了 m/n 上界）
② L1 夹紧（自底向上校验）：
     A 侧：cinA × hiLoadMax(最坏情形行推理，§3.3) × Wi × 2B ≤ 给 A 侧留的 L1
     B 侧：kBL1 × nTile × 2B ≤ 给 B 侧留的 L1
     超限 → mTile/nTile 向下收缩（按 M0/N0 步进）至可容纳，块网格重算（§2.4）
③ K 轴在块内决策：K 全载优先（§3.6），K 超预算时按 (kd, ci) 组合切 kAL1
④ 迭代结构：每核的每个基本块独立走"块内 K 归约 + MMAD + FIXPIPE"，
   块间无数据依赖（这正是核间能按块网格绑核的原因，§2.4）
```

与自顶向下的差别一句话：M 模式**搜索**最优块型（L0 先、L1 后），基本块**验证**固定块型的可行性（只收缩、不搜索）。

### 3.5 A 侧预算超限时的分级退化（M 块形态决策）

> **实现状态**：级 0（缩 N/K 块）、级 1（行窗口）、级 2（HW 模式）三级退化中前两级已实现并验证；级 2 为原理推演。**块形态搜索**：从 L0C 容量上限向下按 M0 步进搜最大跨行 mBlk（块大小不需 16 对齐——MMAD 的 m=AlignUp(curM,M0) 自动满足），末步允许 < M0。

A 侧行块占用 = `cinA × hiLoad × Wi × sizeof(x)`。当它超出 L1 预算时，按**代价从小到大**分级退化，每级都保持"全宽行装载"不变（避免部分宽搬运的布局复杂度）：

| 级 | 退化动作 | A 侧行块变化 | 代价 |
|---|---------|-------------|------|
| 0 | 缩 nBlk → 缩 kChunk（通道分形块） | cinA 变小 | B 侧重装次数增加（标准动作，§3.3 回退） |
| 1 | **M 块限制在单输出行的 W 窗口内**（M 块不再跨行） | hiLoad 从 `(跨行数−1)·sH + dkH` **退化为恒等于 dkH** | M 块数增加（每行每窗口一块）；Load3D 的 M 起点恒为窗口首列，行推理不再有最坏情形跨行问题 |
| 2 | 完整 HW 模式（切装载宽度 wiLoad < Wi） | wiLoad 变小 | 需部分宽 DN2NZ 布局，实现复杂度最高 |

> 级 1 的适用判据：级 0 缩到最小通道分形块后，`cinA_min × dkH × Wi × sizeof(x) + B 侧最小块 ≤ L1` 仍不满足、但把 hiLoad 压到 dkH 后满足——典型触发场景是大 stride（行跨代价 `sH` 大）或宽输入（Wi 大）。级 1 同时简化了两件事：A 侧预算不再依赖最坏情形跨行数（§3.3 双公式表退化为单公式），M 块起点恒为行首对齐。

**B 侧最小分形块的 L1 下限与不可行判定**：

```
B 侧下限 = K0 × Kh·Kw × N0 × sizeof(w)     （一个通道分形 × 最小 N 块）
A 侧下限 = K0 × dkH × Wi × sizeof(x)        （最小通道分形 × 最小行块 × 全宽）
```

两者之和仍超 L1 时，**单次 L1 驻留的 Load3D 方案不可行**（大核场景：Kh·Kw 乘积大导致 B 侧一个通道分形就占满 L1）。此时不属于 tiling 参数选择问题，必须走**核切分路径**或**软件搬运路径**。生成代码遇此情形应显式报告"超能力"并给出下限数值，而不是给出错误的 tiling。

**级 2（HW 模式，部分宽装载）的数据流组织**：

- A 侧只装载列窗口 `[wiIdx, wiIdx+wiLoad)`（wiLoad < Wi）：输出 W 窗口与装载窗口一一对应（本窗口全部输出的感受野落在装载窗口内），装载窗口数 = CeilDiv(Wo, woBlk)；
- DN2NZ 改逐行形态（dnNum=行数、nValue=wiLoad、源行步进=Wi），FMatrix 的 l1W=wiLoad、padLeft/Right 折算为窗口内坐标（窗口越界部分折进 pad）；
- FIXPIPE 的 GM 偏移仍按全局坐标计算（装载窗口不影响输出寻址）；
- 收益：A 侧预算从 `cinA × dkH × Wi` 降为 `cinA × dkH × wiLoad`，代价是每行装载次数 ×(Wi/wiLoad)。

**软件搬运路径（滑窗指令超限或 L1 下限不可行时的功能保底）**：

- A 侧改普通搬运 GM→UB→L1（无随路布局转换），滑窗索引由软件计算：逐输出窗口在 Vector 侧按 (ci, kh, kw) 展平构造 A 矩阵行（或直接在 UB 拼出 [M, K] 分形）；
- B 侧布局不变（weight 分形与滑窗无关）；
- 判定时机在 tiling 入口（指令限制表 + L1 下限检查），判定命中即整体切换，不做混合；
- 代价：Vector 侧展开开销 + GM→UB→L1 两跳带宽，性能显著低于滑窗指令路径，仅作功能正确性保底。

### 3.6 K 轴（Cin 轴）是 reduce 轴，优先考虑全载

K 是唯一在 MMAD 里做累加（reduce）的轴。**切 K 的代价最高**：每切一刀，A、B 两侧数据都要重新装载一遍参与不同 k 段，且 K 切得越碎，MMAD 次数越多、L0C 累加链越长。因此决策时：

1. K 方向**最先尝试全载**（§3.3 四态里 1/2/3 态的本质都是"K 某侧或双侧全载"）；
2. K 实在装不下才切，且 A/B 两侧 K 块可以不等长（`kAL1 ≠ kBL1`），kernel 按 `kAL1/kL0`、`kBL1/kL0` 两个周期分别重装；
3. kL0 保持 = K0（一个分形深度）是最常见取值，kL0>K0 的收益有限。

### 3.7 不同搬运指令的 L1 带宽利用率不同

代价模型算搬运量时，**必须按指令打带宽折扣**：

| 数据 | format | 指令 | 峰值带宽 |
|------|--------|------|---------|
| weight | NCHW | DN2NZ | **32 B/cycle** |
| weight | DHWCN | ND2NZ | **128 B/cycle** |

同样字节数，带宽可相差 **4 倍**。含义：

- 代价模型里 weight 搬运量乘**带宽系数**（这就是 §2.3 代价公式里的那个系数）；
- format 选择本身影响最优绑核方案（当前验证范围固定 NCHW/NCDHW，走 DN2NZ，按 32B/cycle 计）。

### 3.8 尾块体系

每个切分维度整除不尽时产生尾块，约定 `Tail = 总量 % 块大小`（余 0 取块大小）：

| 尾块 | 影响 |
|------|------|
| mAL1Tail / mAL0Tail | A 侧行推理、LOAD3D 块参数、FIXPIPE srcStride |
| nBL1Tail / nL0Tail | LOAD2D 长度、BT 装载长度、输出通道数 |
| kL0Tail | MMAD 的 k 参数；A 侧通道对齐补零段在此生效 |
| dOut 尾片（3D） | D 向 pad 尾部填零 |

尾块全部写入 TilingData，kernel 最后一步按尾块修正指令参数（compute-flow §6.6）。**容量预算按正常块算，指令参数按尾块修**。

## 4 TilingKey 如何计算

### 4.1 为什么要有 TilingKey

卷积的特性组合太多（分组形态、乒乓开关、搬运通路、迭代序……），其中**改变代码路径**的特性无法靠 kernel 内的运行时分支零开销地处理——热点循环里的分支会拖慢所有规格，且循环结构、模板参数这类差异只能在编译期确定。因此把代码组织成"**公共主干 + 特化路径**"，按特性各自编译一份实例：

- 规格 1 → 通用卷积主干 + 特性 A 代码（实例 1）
- 规格 2 → 通用卷积主干 + 特性 B 代码（实例 2）

TilingKey 是 host 侧按当前规格算出的一个**整数**，launch 时以它选择实例——即区分本次执行走特性 A 还是特性 B。

这个数字的含义由**位段分配约定**给出：每个特性占一段位宽，段内枚举值对应该特性的取值。示例（仅示意，实际维度集与位分配见 §4.2 与适配层 [tilingkey-templates.md](../adapters/ascendc/tilingkey-templates.md)）：

```
第 0 段（占 bit[1:0]，权重 1）：乒乓   0=不开；1=开 AL1 乒乓；2=开 BL1 乒乓
第 1 段（占 bit[3:2]，权重 4）：形态   0=普通卷积；1=ORI_GROUP（原始分组）；2=OPT_GROUP

key = 第0段 + 第1段×4
key=4 → 第0段=0（不开乒乓）+ 第1段=1（原始分组卷积）
key=8 → 第0段=0（不开乒乓）+ 第1段=2（OPT_GROUP）
key=6 → 第0段=2（开 BL1 乒乓）+ 第1段=1（原始分组卷积）
```

⚠️ **位段必须独占位宽**：每段分配 `CeilLog2(取值数)` 位、段间按段权重的幂进位（上例每段 2bit、段间 ×4）

### 4.2 常见的 TilingKey 生成方案

**动机**：块大小是连续值，kernel 模板不可能为每个值实例化一份代码；把影响代码路径的决策**离散化成模板参数元组**，相同元组共享一个编译实例。

**计算方法：拆解 uint64 的 64 位，按每个模板参数的取值范围分配位宽，bit 拼接打包。**

参考维度集（完整集约 16 维，3D 场景可精简到 8 维左右；生成代码应按当前能力范围裁剪）：

| 维度 | 位宽 | 取值 | 驱动的代码差异 |
|------|------|------|---------------|
| FmapTiling | 2 | 全载/仅M全载/其他 | A 侧重装分支 |
| WeightTiling | 2 | 全载/仅N全载/其他 | B 侧重装分支 |
| L1PingPong | 2 | AL1/BL1/全开/全关 | L1 份数与同步 |
| L0PingPong | 2 | AL0/BL0/全开/全关 | L0 份数与同步 |
| OutputOrder | 1 | M 模式/HW 模式 | 循环结构 |
| IterOrder | 1 | M-first/N-first | 循环嵌套顺序 |
| GroupType | 2 | 普通/分组/优化/depthwise | 分组路径 |
| FmapCopyMode | 2 | LOAD3D/软件搬运 | A 侧通路 |
| 其余（InnerBatch/NoPad/SmallKernel/BigKernel…） | — | — | 各优化特化路径 |

可以创建任意模版参数来支持一个独立的新特性。


生成规则：

1. 逐维按 §1-§3 决策结果取值，按位宽拼进 uint64；
2. **互斥修正**：不合法组合归一（如 WeightTiling=仅N全载 仅在 M 模式成立）；
3. kernel 侧用同一 key 枚举合法模板实例（机制见适配层 tilingkey-templates）。

## 5 1D / 2D / 3D 的 tiling 差异

| 差异点 | 1D | 2D | 3D |
|--------|----|----|----|
| K 组成 | Ci^align×Kw | Ci^align×Kh×Kw | Ci^align×Kd×Kh×Kw |
| kAL1/kBL1 候选 | — | —（Kd=1） | 并入 `dk×Ci1` 组合 |
| 多核维 | batch/m/(wo) | batch/m/n | batch/m/n/**do** |
| D 向 pad | — | — | **软件填充，L1 预算计入** |
| 备注 | 视作 H=1 的 2D；HW 模式下 woDim 只在 1D 用 | 基准形态 | 在 2D 算法上扩 D 维 |

## 6 产出校验

tiling 输出前逐项复核：

1. **穷尽性**：每维 `块大小 × 循环次数 ≥ 总量`；
2. **容量**：L0A/L0B/L0C/L1 按最终乒乓份数重算不等式；**A 侧 L1 预算必须用最坏情形行推理**（§3.3：`hoSpanMax = CeilDiv(mAL1+Wo−1, Wo)`，不许按行对齐假设算）；
3. **指令限制**：stride≤63、dilation≤255、pad≤255、膨胀核≤511、16bit 累计量（kAL1 的 posK、mAL1 起点）逐项对照；**LOAD3D 的 L1 图积 15bit**（`Hi_L1 × Wi ≤ 32767`，满足即同时覆盖 Dn2Nz 的 nValue/dstNzC0Stride 16bit 上限 `hiLoadMax × Wi ≤ 65535`）；
4. **对齐**：块大小是分形粒度整数倍；GM 地址 32B 对齐；
5. **确定性**：同输入重复调用输出一致（tiling 缓存/知识库的前提）；
6. **多路径约束一致性**：同一参数（如 M 块大小）在多条决策路径（如跨行模式与行窗口模式）中计算时，**每条路径必须独立校验全部容量约束**（L0A/L0B/L0C/指令限制），不能假设"另一条路径已查过"——同一条约束只在一条路径中检查，是宽图场景设备 fault 的典型根因（某路径漏查 L0A 上限 → 块过大 → L0A 溢出）。

## 7 检查点

- [ ] 模式决策（M/HW/basic block）有准入检查记录
- [ ] 绑核三步（绑满→不超核数→代价模型）完整执行
- [ ] A 侧占用"未展开×行推理"、B 侧"展开"口径无混用
- [ ] A 侧行推理：tiling 预算用**最坏情形**（中间列起块），kernel 装载用逐块精确值，两公式未混用
- [ ] fullLoad 四态优先级与伴随决策（迭代序、乒乓）一致
- [ ] K 轴优先全载的决策路径明确
- [ ] weight 搬运量已按指令打带宽折扣（DN2NZ 32B vs ND2NZ 128B）
- [ ] 尾块全部进 TilingData；TilingKey 维度集与模板实例一一对应
