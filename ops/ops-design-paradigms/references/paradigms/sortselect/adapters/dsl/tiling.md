# SortSelect DSL 选路与容量

本页记录 DSL Sort 参考模板的选路策略，依据 [entry.py](example/sort/entry.py) 的 `INSERTION_TIERS`、`TWO_STAGE_TIERS`、`two_stage_batch` 与 `PreparedSort`。表中路由阈值是本例策略；位宽和容量约束取决于当前数据表示，均不是语言中立定律。

## 全局规划与模板入口

```text
校验 dtype / axis / 连续输入，推导 M、N、I 及输出 shape
空输出直接返回；非空时查询 C 与 UB，扣除 SIMT 保留
先按两阶段档位求候选 B，核对局部容量和行号范围
未选中时尝试插入，按 Ncap 计算行宽和 UB 批次
再检查完整单行的 W=align256(N)、uint16 计数域和局部 Radix 容量
仍不可行则按多核块长候选规划 T、K、blocks 和活跃行 workspace
仅对需要改变排列的布局分配转置区，选择编译配置并启动
```

| 路线 | 独立 Tiling 文档 | 关键区别 |
|---|---|---|
| 插入 | [Tiling](templates/insertion/tiling.md) | 行宽为 dtype 插入上限 Ncap；每批最多 1024 行 |
| 两阶段 | [Tiling](templates/two-stage/tiling.md) | 物理宽度 align256(BN)，仅枚举 B≥2 |
| 单核 Radix | [Tiling](templates/radix-one-core/tiling.md) | groups=1；完整一行与 W≤65280 的计数域 |
| 多核 Radix | [Tiling](templates/radix-more-core/tiling.md) | 两轮任务偏好、块长选择、活跃行 workspace 与单次 launch |

各模板配套的 Kernel 与 Buffer 见[模板导航](index.md#按模板读取)。这些文档展开下列汇总规则的公式、阶段、地址和算例，example 是实现核对来源。

记 N 为轴长、M=O×I 为独立序列数、C 为设备向量核数、B 为每批行数、U 为扣除 SIMT 保留区后的可用 UB。多核全局计数/前缀和中间原轴索引按轴长选编译变体：N<2^30 用 int32，否则 int64；地址和最终输出索引始终 int64；局部 uint16 桶计数、uint32 排列编码仍由 tile 容量约束。先处理空输出；非空输入按以下优先级选路：满足条件的 two-stage → 小轴插入 → UB 可容纳的单核 Radix → 多核 Radix。输入在 N>1 且 I>1 时通过共用 DSL 转置将排序轴变为连续末轴，否则直接使用或 reshape。排序后，各输出字段独立按 L>1 且 I>1 判断是否需要物理逆转置，否则直接 reshape；Sort 示例的 L=N，派生接口须按各自输出长度判断。该布局包装不改变本页算法路由条件。

## 路线覆盖与验收

Sort、Argsort、TopK、KthValue 使用同一选路基线：insertion、two-stage、单核 Radix、多核 Radix。按规格合法域纳入可达路线，two-stage 包括逆映射与稳定行号分组；每条可达路线记录进入条件、资源依据、实现与至少一个真实命中的边界用例。输出区间不构成删除排序路线的依据。

阈值可依据资源或性能证据调整，保留变更依据和替代路径；仅在用户限定范围、合法域无交集或有实际能力/资源证据时排除路线。能力未验证保留缺口，不以任意调阈值使路线不可达。设计与验收共同核对实际原语、完整排序/恢复、统一布局及批次复用，不以读取资料或数值输出正确代替路线命中证据。

## dtype 路由表

| dtype | 插入档位 `(轴长上限, 每核行数门槛)` | two-stage 档位 `(轴长上限, 每核行数门槛)` |
|---|---|---|
| int64 / uint64 | (8, 1)、(16, 4) | (15, 8)、(128, 4)、(512, 8) |
| int32 / uint32 | (8, 2)、(11, 4) | (11, 8)、(64, 4)、(384, 8) |
| int16 / uint16 | (4, 2)、(8, 4) | (7, 8)、(64, 4)、(192, 12) |
| int8 / uint8 | (4, 2)、(8, 7) | (3, 8)、(64, 7)、(128, 16) |
| float32 | (4, 1)、(8, 1) | (24, 64)、(64, 64)、(256, 64) |
| float16 / bfloat16 | (4, 1)、(8, 1) | (54, 64)、(64, 64)、(256, 64) |

两条路线均取第一个覆盖 N 的档位，再检查 `P=ceil(M/C)` 是否达到该档门槛；不能跳过首个命中的档位，借后续较低门槛放行。无匹配档位或容量不足则回退。P 不是最终 B，也不表示尾轮每核都能分到这么多行。优先尝试 two-stage，再尝试插入。

浮点插入的门槛 1 沿用参考基线，**尚未确定性能拐点，属于待调优策略**。生成算子时应按目标 dtype、N、P 比较插入与 Radix，确定适用门槛；当前门槛不作为插入更快的性能保证。具体测量与个案结果保留在库外。

浮点 two-stage 候选扩展至 N≤256，整数和浮点统一按下节阈值选择恢复分支。归并路线尚未适配，小轴路线未选中后依次尝试单核和多核 Radix。

## 两阶段恢复：硬约束与实现策略

| 决策 | 当前表示下的算法硬约束 | 本例实现策略 |
|---|---|---|
| 批次第一阶段 | 全部有效元素稳定排序；保留原行归属和原位置；满足 UB 与计数范围 | 使用上表筛选候选域，再选择 B |
| 逆映射恢复 | 每行按批次秩恢复顺序，无 uint16 紧凑键限制；每行比较量 O(N²) | N≤32 时选择 |
| 稳定行号分组 | Stage1 稳定排序后，仅按行号稳定升序即可保留行内次序 | N>32 时使用，Host 限制 B≤256，第二阶段只需一个字节 |

24/54/256 是候选路线的轴长门槛，32 是进入 two-stage 后的恢复策略门槛，256 是公开入口使用一字节行号的批次限制。

## 容量预算

统一使用输出轴长 L，输出索引为 int64。仅实际需要物理布局转换时分配对应缓冲：输入转置为 `M×N×D`，各输出字段的尾轴布局区在两字段时为 `M×L×(D+8)`；分别按 N、L 和 I 判断，见 [布局判定](../../generic/shape-preprocessing.md#物理转置的判定与验收)。连续尾轴和等价 reshape 不额外分配转置区。最终输出另计。转置优先采用 NDDMA 输入和 DMA 输出，分为普通二维 tile 与完整短行的紧凑写回；小容量 64 位短行保留 SIMT。方块基准 T_tr 在短边≥128 时取 64，否则 32；矩形块、方向差异和回退门槛见 [转置映射](toolkit-transpose-port.md)。静态 UB 为 `max(T_tr×(T_tr+1),128×65)×D`，64 位配置使用 uint32 根参数与两个字组成的末维，物理字节数不变。Host 按最大 D=8 核对容量；独立转置 kernel 的 UB 不与排序模板相加。实际存活与复用按 [统一内存要求](../../generic/liveness-fusion.md#统一批次内存) 核算。

令 S 为键存储字节数：int64/uint64 取 8，其余支持类型取 4；D 为输入元素字节数，H 为多核计数/中间索引字节数（N<2^30 取 4，否则取 8）。W 是按 256 元素向上对齐的处理宽度，T 是多核 Radix 的块长。以下预算包含本例的缓冲组织，修改布局后应重新核算对齐与同时存活区间。

| 路线或资源 | 预算 / 上限 | 含义 |
|---|---|---|
| SIMT 保留区 | 32768 字节；`U=cb.get_mem_size("ub")−32768` | 先扣除，不能重复用于模板缓冲 |
| 插入 | `B×Ncap×(D+S+4)≤U`，Ncap 为 dtype 插入上限 | value、key、uint32 index；B≤1024 |
| 单核 Radix | `W×b+1024≤U`，W=align256(N)；输入 1/2 字节时 b=6/12，其余 b=2S+14 | 窄类型局部排列，或键/索引双缓冲 |
| two-stage | `W×(2S+14)+1024≤U`，W=align256(B×N) | 键/索引双缓冲、排列、digit、byte_order 和桶起点 |
| 局部计数域 | W≤65280 | uint16 计数上限 65535 内最大的 256 整数倍 |
| 多核 Radix | `FT+4096≤U`，F=6+D+H | 局部排列、桶起点、scatter bases；全部 dtype 声明原值/索引 DMA tile |
| 多核局部排列 | uint32、只存活于当前 tile 的 UB | uint16 桶计数限制 T |

局部宽度 W 必须是 256 的倍数，且 uint16 桶计数最多表示 65535；因此 W 的最大合法值为 `floor(65535/256)×256=65280`，不是 65535。多核局部排列索引使用 uint32，频数与局部桶起点仍使用 uint16。

键的存储宽度 S 不等于 LSD 轮数；逐字节排序仅处理输入 dtype 的有效字节。example 的公开 Sort 按活跃行容量分配 GM workspace，在单次 launch 内完成批次复用；输出字段与长度不改变中间排序容量。

## 批次与块长选择

two-stage 通过档位筛选后，按当前实现计算批次：

1. `Emax=min(65280, floor((U−1024)/(2S+14)/256)×256)`；`Bmax=min(P, floor(Emax/N))`。行号分组分支再限制 Bmax≤256。
2. 从 Bmax 降序枚举 B≥2。令任务数 Q=ceil(M/B)、活跃核 A=min(C,Q)、轮次 R=ceil(Q/A)、空闲槽 H=R×A−Q。
3. 记录首个候选的轮次，仅在相同轮次内寻找更小 H；轮次改变即停止。H 相同保留先枚举的较大 B。无可行候选则返回其他路线。

这是一种优先保持轮次、再减少尾轮空闲的启发式，不是全局最优保证。

多核 Radix 按升序尝试 T∈{1024,2048,4096,8192}，保留满足 UB 预算且 `M×ceil(N/T)≥2C` 的最大候选，以尽量保留两轮任务；否则取默认 1024；所选块仍须满足 `FT+4096≤U`（F 见上表），不足时在分配多核工作区和编译前明确报错。最终 blocks=min(C,任务数)。核数、UB 大小从设备查询，不固定为某次测试配置。

## 统一批次工作区

M 是总行数，B 是 UB 批次行数，P_act 是有界复用设计中的活跃行数，不能与选路的 `P=ceil(M/C)` 混用。当前公开 example 按 Host 选择的 P_act 预算，在单次 launch 内以批间屏障保护复用；groups=0 的直接调用仍按 M 行预算。

| 空间 | 分配与生命周期 |
|---|---|
| 最终输出 | 各所需字段 M×L；两字段为 `M×L×(D+8)` |
| 插入、two-stage、单核 Radix | 当前 B 行 UB；排序/恢复按 N，最后写 L 项后复用 |
| 多核原值/原轴索引 ping/pong | 所需每侧 P_act×N；原值宽 D，原轴索引宽 H（N<2^30 时 H=4，否则 H=8） |
| 多核 hist/states | hist 为 `PK×256H`；states 为 `PD(K+1)×256H`，包含各 digit 的前缀状态和全局桶起点；K=ceil(N/T) |
| 保留与布局区 | 转置输入/输出、系统保留和对齐分别列出 |

两侧按 P=P_act 完整分配时，算法 GM 临时字节数为 `PN(2D+2H)+P×256H×[K+D(K+1)]`，另计对齐与运行时要求。六个工作区为两侧原值/id、hist 和 states；原值使用输入 dtype，其余使用 H 字节计数类型。末轮直接写最终输出，输入保持只读。

Host 分配、编译签名、阶段实参和局部/全局寻址一并修改，见 [实现指导](implementation-guide.md#当前活跃批次的工作区复用)。验证覆盖可达路线、输出区间端点、尾轴/非尾轴、多批次/尾批和更新输入后重跑；检查原值位模式、原轴索引及输入未修改。固定 N/核数后，超过驻留目标的 scratch 按有界 P_act 复用；最终输出和布局区仍随 M 增长。

### 多核活跃行容量

令每行工作区字节数 `R=N(2D+2H)+256H×[K+D(K+1)]`，核数为 C_act，`q=C_act/gcd(C_act,K)`。q 行产生的 tile 数是核数的整数倍。以 64 MiB 为软件驻留目标，取 `P=max(q,floor((target/R)/q)×q)`；仅 M≥2P 时启用容量 P，否则使用 M 行。最小均衡批次 q 可能使工作集超过该目标。

route 3 的正 groups 表示 P_act 容量；groups=0 表示全部 M 行。一次 launch 中逐批排序，最后一批仅访问有效行；批间全核屏障后复用状态。详见多核模板的 Tiling/Buffer/Kernel。
