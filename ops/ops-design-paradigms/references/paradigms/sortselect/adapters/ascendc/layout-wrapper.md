# SortSelect AscendC 公共布局包装模板

本模板是所有排序路线的公共前后处理。设计、实现和用例推导先实例化本模板，再选择排序主体；完整实现由调用层布局包装与已选排序模板共同组成。Sort、Argsort、TopK、KthValue 共用这一交接，输出字段与长度 L 按目标接口配置。

## 调用链与交接

以下采用三维折叠，O、N、I 分别为原选择轴前维度乘积、轴长、轴后维度乘积，M=O*I。校验与空输入处理后执行：

```text
调用层：连续化原输入，折叠为 [O,N,I]
  若 N>1 且 I>1：物理转置得到连续 [O,I,N]
  否则：直接使用或 reshape 为 [O,I,N]
  以连续 [M,N]、dim=-1 调用已选排序主体
排序主体：完整处理 N，按输出区间写连续 [M,L]
调用层：对每个输出字段，先视为 [O,I,L]
  若 L>1 且 I>1：物理转置得到 [O,L,I]
  否则：直接使用或 reshape 为 [O,L,I]
  恢复接口 shape，按接口处理 keepdim 和输出 view copy
```

排序主体的输入 GM 元素偏移为 `row*N+j`，输出为 `row*L+t`；UB 对齐 pitch 由各算法模板决定。原始 axis、I、输入/输出转置区由调用层持有，主体只接收规范化后的行布局。索引数值仍为原选择轴坐标，无需重新编号。

输入与各输出分别按 N、L 判定，不能共用一个转置标志；尾轴及等价布局跳过物理转置。仅修改 shape 或生成非连续 view 不等于完成物理转置。条件及缓冲预算按 [布局判定](../../generic/shape-preprocessing.md#物理转置的判定与验收)；布局区与排序 scratch 分开预算。

## 实例化与验证

设计与实现中明确调用链对应的函数及交接 shape/axis；原始非尾轴只进入调用层，排序主体始终接收连续尾轴输入。若尚未实现包装，完整非尾轴路径仍有缺口，Kernel 分支不能通过接收原始 stride 来补齐这一交接。

- 接口用例从原始 shape/axis 进入，覆盖转入、排序与各字段还原，核对实际布局操作符合条件。
- TTK kernel 等绕过调用层的白盒入口，先提供相同规范化后的连续输入及 `dim=-1`。例如 `[4,8,4], dim=1` 先物化为连续 `[4,4,8]`，再折叠为 `[16,8]`；主体输出 `[16,L]`，接口输出为 `[4,L,4]`。保留原始用例与规范化用例的映射。
- 原始非尾轴用例被主体的末轴校验拒绝时，核对包装和测试投影。当前任务的可写范围未覆盖缺失层时，回报跨层缺口及失败证据，由覆盖该层的任务修复；主体继续使用本模板的输入契约。

性能累计实际启动的全部 kernel，包括转入、排序、各输出还原及必要的输出拷贝，排除 Host 建图、编译与日志耗时。完整测试约定见 [分层测试契约](../../generic/shape-preprocessing.md#分层测试契约)。
