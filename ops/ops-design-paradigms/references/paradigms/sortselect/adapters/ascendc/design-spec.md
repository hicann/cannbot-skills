# SortSelect AscendC 设计约束

## 输入与输出

输入包括数学语义、shape/dtype/axis、排序方向与稳定性、NaN/零符号、K/keepdim、目标平台。输出为适用算法及选型依据、模板/TilingData、buffer 生命周期、同步约束；文档格式与保存位置由调用方指定。

## 实现复用与替换约束

### 逐路线确定复用基线

设计须在现有 Kernel/API 设计文档中列出实际采用的机制与目标适配，不要求另建报告文件。基线由命中模板的完整算法描述和 [能力映射](capability-mapping.md) 给出；按 [实现导航](../../source-map.md#ascendc) 找到对应 example 计算体及依赖，核对这些节点的具体实现。算法描述决定执行方案，example 使方案落实到代码，二者按节点对应。

生成代码的类、函数、字段和文件组织可以独立设计；机制等价性按工作域、并行分工、数据通道、资源和生产消费关系判断。算法结果等价与执行机制等价分别核对：计秩的独立累加链、桶状态的 Vector 检查/累计等均属于计算节点的实现内容。

| 路线 | 模板已经选定的执行机制 |
|---|---|
| 小轴插入 | 核间分批、SIMT 按行分工；行内顺序插入，值与原轴索引同步移动；类型转换及写回按批处理 |
| 两阶段 | 全批 Stage1 Radix；逆映射按元素分工和独立累加器计秩，或 uint16 Stage2 升序分组并 Vector Gather；恢复和写回保留批次粒度 |
| MergeSort | 批量 Vector 构键/Cast/索引准备，Sort32 初始 run、四路 MrgSort、proposal ping/pong、Extract；有序索引按目标名次直接定位，必要的完整轴分类按轴内并行；合批与普通模式按模板条件区分；区间输出仍经 Vector 选择/压紧、Queue 与 MTE3 |
| 单核 Radix | 完整 N 项原生 RADIX_SORT 和隐式源索引；Vector 前后处理及区间选择/压紧，输出 Queue 由 MTE3 消费；Queue 槽与共享 scratch/恢复区分别管理 |
| 多核 Radix | 按 N 选择 uint32/int64 计数；桶偏移求和为32位 DMA 原子加/64位 SIMT 原子加；状态发布和前驱快照为256桶批量 DMA，Vector 检查/累计，SIMT 散射并按 digit 全核交接 |

每条采用路线在现有分支设计中对应“模板节点及执行方式 → example 文件/函数 → 目标实现与必要适配”，同时保留适用域、实际排序原语、同步协议及证据位置。设计到编码沿用这组对应关系：已有计算体承担未变化的节点，目标规格造成的差异在相应节点展开。将 Sort32、MrgSort、Sort 或 lookback 改为自写循环/全局阶段扫描，均须显式列为实现替换。

先由模板确定执行机制，再填目标 N/M、输出区间/字段、索引类型、实际资源和 SDK API。名称替换、类拆分和等价字段表示属于代码组织；批量改逐项、DMA 改逐桶原子通信、Vector 改单线程处理属于机制变化。写“Sort/同步协议保持”时，应与实际数据通道和调用粒度相符。

复用范围覆盖构键、类型转换、索引初始化、排序、原值/索引恢复和搬出。前后处理保留批量 Vector/Reg 或多线程分工，不能仅因排序原语未变就将逐行单线程改写视为完整复用。具体函数与恢复方案见 [辅助处理并行度](kernel-helpers.md#辅助处理并行度)。

### 区分未验证与已确认不适用

能力结论分为“已确认适用”“已确认不适用”“未验证”。SDK 路径未找到、scratch 查询未完成、签名未核对、缓冲预算有未定项或特殊值缺少证据，均属于未验证，不能据此断言原语不可用并批量重写。先补查接口/源码、临时空间查询、包装恢复与布局约束；无法完成时保留具体缺口和后续验证义务，受影响项不得判为闭环通过。

核对新增或变化的适用条件时，区分三类事实：原机制在目标条件下是否适用、为什么必须替换、替代机制是否有效。新 VF/API 编译通过只支持第三类中的编译结论，不能证明原机制失效。文档未说明某项保证时，先沿既有生产/消费路径查找并界定缺口；继承适用范围内仍有效的实现和验证结论，不以自创保护协议代替对缺口的核实。

隐式索引原语与接口输出索引宽度不一致时，先核对中间索引和最终宽化；特殊值或布局不满足时，先核对 wrapper；非末轴通过条件转置或等价 reshape 规范化为连续尾轴并按需还原长度 L 的输出。适配仍须有证据，不能把这些候选方案直接标为已支持。

### 按证据限定替换范围

替换需提供以下依据之一：目标 SDK/参考源码的明确限制及调用条件；最小编译或运行失败复现；同口径测量证明的优化收益。记录实际平台/SDK 标识、命令或可定位的源码约束、观察结果，以及受影响的 dtype、shape、方向和路线。单个 overload 或特定值域的问题不能扩张为全部分支不适用。

优先修订受影响步骤并保留可复用的排序主体。原值恢复、算法内部 scatter、索引宽化及参考已有的小轴 SIMT 可按其合同使用；非末轴布局由统一的条件布局包装承担，这些适配不能作为全面自写排序的依据。独立 SIMT 归并的数组布局规则只在该替换已满足本节条件后适用。

特殊值适配先核对 example 已有转换、padding 和恢复路径，仅补目标合同确实缺失的部分；不得默认将整行构键和恢复都改为单线程 SIMT。原语输出已满足目标顺序与值/索引合同后，直接应用输出区间和必要的类型转换；参考算子的内部策略不自动成为目标接口要求，输出截取和索引宽化不要求新增收尾排序。

替换排序主体、比较键或跨核协议时，重新推导受影响路线的 scratch、UB/GM 峰值、索引宽度、缓冲存活与同步参与者；不得继承旧实现的容量或验证结论。代码任务发现此类缺口时回报设计修订，不能在实现中静默扩大替换范围。

### 独立核对偏离与验证状态

验收者逐路线对照基线表、实际 API/VF 算法体和同步协议，检查替换理由、证据及适用域。仅有函数同名、键集合一致、显式数组预算或 CPU 算法模型通过，不能证明遵从基线或设备能力已验证。缺少基线、将未验证写成不可用、无证据整体替换，或未重算受影响约束，均使对应验收项不通过。

先核对“采用的模板机制 → 目标需求造成的差异 → 实际修改及依据”，再核对 API 是否实现了该方案。用模板中的处理域、通信操作和批次交接作比较，不要求代码文本或函数划分一致；已有有效结论直接引用。API 可编译、UB 可容纳和功能精度通过分别保留各自含义，不能替代机制偏离的必要性与代价判断。

设计阶段可核对静态约束；编译、设备精度、多批次内存复用和性能仍须分别保留实际验证状态。任务禁止构建或上板时，只引用已有证据或登记缺口，不能为通过静态验收编造实测结论。修改后须复核所有受影响的分支设计，不能只更新公共 API 文档。

### 比较替换后的代价

自写排序或更换跨核协议须给出验证计划：独立正确性对照、特殊值与边界、内存峰值、多批次复用，以及与可运行基线同口径的设备性能比较。基线确实不能运行时保留最小失败证据，并验证替代路线的设备正确性与目标性能，不虚构基线测量。为优化而替换的方案在比较完成前不得宣称收益或升级为默认优化实现；静态设计通过不替代最终实现验收。个案测量数据留在算子产物中，不写入本范式。

该代价检查同样覆盖构键、恢复、输出截取、索引宽化和搬出粒度的改变，不能因排序原语或 TilingKey 未变而豁免。设计及检视列出受影响路径每批处理的行数/输出项数、VF 调用、DMA 提交和同步次数，明确是否从按批退化为按行。只补测受影响场景，复用仍适用的基线；短轴且行数多、L=1、L=N、尾批及实际输出类型是按批写回适配应核对的代表性条件。确认目标变更的收益和适用范围，不把单个用例的收益扩展为全域保证。

## 一致性检查

TilingKey 与模板实例一致；每个参数有 Host 来源和 Kernel 消费说明；输入/输出 pitch 独立；临时 key、计数、状态与输出索引的宽度分别验证；budget 覆盖并发节点、scratch 与尾块；同步参与者不会因局部无工作而早退。

按 [通用批处理约束](../../generic/output-mapping.md#保持批处理粒度) 检查原本 B>1 合批的路径：若输出适配变成逐行 VF、小块 DMA 和逐行等待，却没有具体接口/容量限制或同口径设备测量依据，判为未保留批处理粒度，应恢复批量实现后再验收。精度通过、VF 内有线程分工、排序原语或 TilingKey 未变，均不能豁免此项。核对直接记录在既有设计/代码检视中，不另建证明材料或重复审计流程。

算法与 API 依据应能追溯到参考资料及其适用范围；编译期特化依据公开元数据。比较关系、原轴索引与原值恢复遵循 [排序不变量](../../generic/compute-flow.md#排序不变量)。

所有输出配置均遵守 [统一输出映射](../../generic/output-mapping.md) 与 [统一批次内存](../../generic/liveness-fusion.md#统一批次内存)：分别列出最终输出、实际需要的 transpose 布局区及当前批次 scratch，核对分配、寻址、释放与批次复用。按 [布局判定与验收](../../generic/shape-preprocessing.md#物理转置的判定与验收) 核对输入/输出各自的条件与实际布局转置次数；连续尾轴及等价布局出现冗余物理转置，属于实现偏离，不能以精度通过代替此项检查。代码表达见 [输出适配](output-mapping.md)。
