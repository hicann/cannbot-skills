# SortSelect 切分与资源

所有接口先规范化为 M=O×I 行、每行 N 项的连续尾轴，布局见 [shape-preprocessing](shape-preprocessing.md)。选路不依赖 Sort、TopK 或 KthValue 名称，也不因输出长度 L 较小而缩小中间排序域。

| 路线 | 工作分配 | 主要容量约束 |
|---|---|---|
| 插入 / 两阶段 | 每核处理若干批短序列 | B 行的值、索引、逆映射或紧凑键及排序临时区 |
| 单核排序 | 每核处理完整序列或一批序列 | value/key/index、排序临时区、对齐 |
| 多核 Radix | 每序列分连续块，按活跃行批次推进 | P_act 行的键/索引 ping/pong、桶计数与前缀状态、局部排序区 |

先扣除框架、SIMT 和 API 保留区，再确定批次或 run 长度；计入对齐、尾块和同时存活 buffer。核数受工作量与设备实际可用核数共同限制。短轴的批处理收益受行数影响，多核成本包含跨块前缀、全局读写与同步。

## 行批次、单行与核组的映射

设可用核数为 C。不同实现组织分别采用以下工作域，不混用批次数和行数：

| 组织 | 总任务与启动量 | 核 c 的数据坐标 |
|---|---|---|
| 轮转行批次 | `Q=ceil(M/B)`、`C_act=min(C,Q)` | `batchId=c+kC_act`，`rowStart=batchId×B` |
| 连续行批次 | 同上，`w=ceil(Q/C_act)` | `batchId∈[cw,min(Q,(c+1)w))`，`rowStart=batchId×B` |
| 每核完整单行 | `C_act=min(C,M)` | `row=c+kC_act` |
| 每行 G 核、活跃 P_act 行 | `C_act=G×P_act≤C` | `slot=c//G`、`lane=c%G`；`row=batch×P_act+slot` |

多核行内块长为 T，`K=ceil(N/T)`。同一行核组内 lane 遍历 `tileId=lane+kG`，每块起点 tileId×T、有效长度 min(T,N−tileId×T)。G 可以小于 K，每核顺序处理多块；不能把“一个 tile 一核”当作唯一组织。

行批次尾部 `v=min(B,M−rowStart)`，以 v 而非 B 决定有效排序/写回范围。活跃核组尾部的无效行槽位可跳过搬运，但核组之外仍可能有其他行执行跨核屏障，所有已启动核须满足相同参与次数。

## 容量与调参的分层

1. 按 dtype、值/索引/计数宽度列出物理缓冲和对齐；扣除实际路线所需保留。
2. 据此求 B 或 T 的候选上界，精确核对排序 scratch、表示范围及搬运限制。
3. 在可行候选内比较执行轮数、尾轮空闲或每核串行块数；经验阈值只参与本层选路。
4. 按选中方案重新计算使用核数、批次数、尾块、清零分工及 workspace，最后提交完整参数。

例如“首个可行批次的轮数内最小化空闲槽”与“联合最小化行批次×行内 tile 轮数”是两种不同启发式，不能互相替代。具体候选与搜索策略由命中模板确定。

## 两阶段紧凑键的范围

设当前批次有 B 行、每行 N 项，E=B×N。紧凑键为 `行号×E+批次排序秩`：行号范围是 0..B−1，批次排序秩范围是 0..E−1，因此最大键为 `(B−1)×E+(E−1)=B²N−1`。使用 uint16 键时最大值为 65535，故须满足 `B²N≤65536`；这里 65536 是可表示值的数量，不是最大键值。尾批按实际有效行数计算。逆映射无需该打包约束，但仍受 UB、计数域与 O(N²) 行内恢复成本约束。

## 批次与尾块

当前批次完成输出后复用临时区。总行数 M、UB 批次 B、长轴活跃行数 P_act 分别建模，不能把 M 当作必须并发保留的行数。transpose 布局区、最终 M×L 输出与排序 scratch 分开预算，见 [统一批次内存](liveness-fusion.md#统一批次内存)。

尾块仅对真实元素计数。填充进入原生排序时须携带原语规定的无效标识或有效长度，不能仅靠数值哨兵区分合法无穷、NaN 或整数极值。
