# SortSelect 能力与资源契约

> **层级**：通用知识层（generic/），语言中立。

## 使用规则

按所选排序路线核对下列能力与资源约束；标识仅用于文档对应，不是 API 或代码开关。每个 adapter 的 capability-mapping 给出实际实现、适用域及限制，未知项标为“待验证”。

排序主体接收规范化后的连续尾轴。输入连续化、条件转置与输出还原由调用层按 [布局规则](shape-preprocessing.md#物理转置的判定与验收) 完成，不参与排序模板的能力选型。

本次生成目标、排序原语的可用域和既有公共接口的支持范围分别确认。目标未要求的 dtype/控制输入类型，不自动变成必须新增的兼容能力，也不自动变成公共接口必须拒绝的输入；是否保留旧路径由实际需求和接口契约决定。标量、空输出等边界先校验原始参数再做内部表示归一化，输出 shape、值及索引仍按原语义恢复；不能用物理长度一的中间表示放宽非法请求。

## 核对项目

| 标识 | 核对内容 | 影响 |
|---|---|---|
| `CAP_STABLE_COMPARE` | 比较关系、相等键顺序及特殊值规则是否满足接口契约 | 稳定性、索引选择、padding |
| `CAP_LOCAL_SORT` | 局部排序实现的 dtype、长度及索引模式 | 初始 run、批次排序 |
| `CAP_MERGE` | 有序 run 归并的实现及适用域 | 归并路线 |
| `CAP_RADIX_SORT` | 稳定 Radix 排列与排序的实现及适用域 | Radix 路线 |
| `CAP_BLOCK_SYNC` | 工作组共享存储的同步与可见性 | 批次搬入、inverse 建表 |
| `CAP_GLOBAL_SYNC` | 跨核阶段完成与全局数据发布协议 | lookback、Radix |
| `ALIGN_GRANULARITY` | 片上物理 buffer 的字节对齐要求 | 分配与预算 |
| `LOCAL_MEMORY_BUDGET` | 扣除当前路线所需保留区后的可用片上字节数 | B、run、tile 的上限 |
| `INDEX_COUNT_DOMAIN` | 原索引、输出索引、计数与状态的合法域 | 窄化、打包、溢出 |

能力依赖不满足时保留数学算法，输出具体缺口。不能自动加载其他语言 adapter 的模板补位。
