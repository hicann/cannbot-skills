# SortSelect 计算流

本页说明排序算法与不变量；平台阈值及 schedule 编号由适配层给出。

## 坐标与中间索引

输入规范化为 M 行、每行 N 项；B 是批次容量，v 是当前批次有效行数，e=vN。下面区分四种索引，避免把临时排列直接写成接口 indices：

| 记号 | 含义 |
|---|---|
| j | 原排序轴坐标，范围 `[0,N)`；接口 indices 的内容 |
| f=bN+j | 批次展平原位置，两阶段的 Stage1 索引 |
| r | 当前完整行或批次的排序名次，含义随阶段说明 |
| perm[p] | 排序位置 p 对应的原位置；inverse 是其逆映射 |

各算法先完成完整 N 域内的排序，只有最终恢复/写回才按 `first_rank` 和 L 选择名次。以下伪码描述算法，语言 API 和物理布局由适配层实现。

## 算法选择

调用层完成布局规范化后，短轴可采用插入或两阶段批处理；较长序列可采用核内归并或 Radix。算法选择取决于 dtype、轴长 N、序列数 M 和片上容量，具体路由顺序与阈值由语言适配层给出。

## 插入排序

插入路线将一批短序列合作搬入片上存储，每个执行线程负责一个序列；依次插入元素，只移动严格大于当前键的前项，保留相等值的原始次序。轴长一执行同样的搬入与写回，索引为零，无需执行比较循环。合作写回前需等待所有序列完成。非末轴由调用层按 [布局判定](shape-preprocessing.md#物理转置的判定与验收) 规范化为连续尾轴后复用该主体，顺序等价时只需 reshape，逻辑序列仍独立。

```text
每行初始化 ids[j]=j
for j in 1..N−1:
  保存 value[j]、比较键和 ids[j]
  依次右移按目标方向严格排在该键之后的前项
  在空位写回保存的 value / key / id
```

每行最坏 O(N²)，行间可并行。只移动严格不等项是稳定性的来源；比较键可归一化正负零/NaN，但原始 value 与原轴 id 的关联保持不变。

## 小轴两阶段

把多个短序列组成批次，第一阶段调用稳定排序得到批次内值的顺序和原位置。第二阶段有两种恢复方式：

- 逆映射：建立原位置到批次排序秩的映射；对每个元素，统计同一原序列中秩更小的元素数，得到序列内输出位置。这条分支不再排序。
- 紧凑键：令批次有效元素数为 E，构造 `原序列编号 × E + 批次排序秩`，按键升序排序即可按序列重新分组，同时保留第一阶段的升序或降序结果。第二次排序的方向不随 value 方向改变。

逆映射恢复每个元素都扫描所在序列，每行比较次数为 O(N²)，只适合足够短的轴。打包位宽、批次容量及两种恢复方式按适配层的资源条件和计算复杂度选择。局部排序的稳定性和原位置映射必须贯穿两个阶段，不能丢掉段归属。

具体恢复伪码：

```text
Stage1 稳定排序展平输入，得到 order[r]=f 和对应的有序值
inverse 分支：
  inverse[order[r]]=r
  对每个 f=bN+j，pos=count(inverse[bN+k]<inverse[f]，k∈[0,N))
  将该原元素写到本行 pos，接口索引写 j
packed 分支：
  key2[r]=(order[r]//N)×e+r
  对 key2 升序排序，得到 perm2[t]=r
  最终原位置 f=order[perm2[t]]，接口索引为 f%N
```

例：`[3,1,5]`、`[4,2,6]` 的 Stage1 order 为 `[1,4,0,3,2,5]`，inverse=`[2,0,4,3,1,5]`，key2=`[0,7,2,9,4,11]`。两分支均恢复两行 `[1,3,5]`、`[2,4,6]`，各行索引 `[1,0,2]`。第一阶段降序时仍按 key2 升序重新分行。

## 归并

先调用局部排序能力产生有序 run，再以多路归并能力合并，轮换输入输出 buffer，尾 run 保留真实有效长度。核内完成全部 run 的排序与归并；具体原生 API 和 run 粒度见语言适配层。

```text
将每行拆成局部 run，各 run 内排序并携带原轴索引
while runCount>1:
  按选定路数分组，计算每个真实 run 的长度
  从各 run 头部选择下一个元素，写入另一缓冲
  按目标等值规则决定相同键的来源次序
  更新 runLength/runCount，交换输入输出侧
提取最终一条 run 的有效 N 项
```

原生 proposal 原语的排列格式和偏移不能从普通 value/index 数组布局推断。小于初始 run 长度、最后不足一个 run、最后不足一组归并输入，分别维护有效长度；语义 padding 和原语记录布局由适配层说明。

## Radix

把原 dtype 的值转换为单调排序键；有符号整数处理符号位，浮点处理符号与负数反向次序。零符号和 NaN 的规则按调用契约单独核对，原始 value 可通过原索引恢复，避免变换丢失 payload。

单核路线在片上调用稳定 Radix 排序并恢复 value/index。多核路线对键从低位到高位逐轮处理：

1. 统计当前 digit 的桶频次，计算桶起点。
2. 稳定排列每个块内的同桶元素，保留它们的输入次序。
3. 取得该桶在更早块中的前缀数量，计算全局目标位置。
4. 将键和值/原索引散射到另一 buffer，所有写入完成后进入下一轮。

目标位置 = 较小桶的总数 + 同桶更早块的数量 + 当前块内同桶秩。该分解保证不重叠、无遗漏及稳定性；每一轮结束后，序列按已处理低位稳定有序。多核 Radix 的直方图、局部排序与前缀发布协议由语言适配层确定，具体同步见 [sync-model](sync-model.md)。局部排序输出的排列还决定后续散射的访问次序；适配时须保留这条数据依赖，不能把与之数学等价的逐元素计数自动视为成本等价。

### 单字节前缀的可复算例子

一行的两个块 digit 分别为 `[1,0,1,2]`、`[0,1,1,0]`。各桶 0/1/2 的总频数为 3/4/1，全行桶起点为 0/3/7。

第二块中 digit=1 的两项，其更早块同桶计数为 2，块内同桶秩分别为 0、1，因此目标位置是 `3+2+0=5`、`3+2+1=6`。全行稳定排列为原位置 `[1,4,7,0,2,5,6,3]`，两个块的相等 digit 按输入先后保留。

多字节键从低字节到高字节重复这一过程，每轮同时搬运键与原轴索引。不能先截取 TopK 再继续剩余 digit，否则后续高位尚未确定时会丢失应入选元素。

## 统一输出映射

全部接口使用同一 [名次区间模型](output-mapping.md)。排序与行归属恢复完整处理 N 项，只在最后恢复/写回输出 `first_rank` 起的 L 项，并保留原轴索引；输出配置不改变中间排序与同步。

## 排序不变量

- 完整排序结果按约定关系有序、索引构成原轴的置换；最终区间输出是该结果的连续子序列，索引在原轴范围内且不重复。
- 按输出索引回读原输入，应得到对应的输出值；键转换不改变原值与原索引的关联。
- 稳定排序中，相等键保持输入次序；稳定降序使用反向比较关系，不能反转稳定升序结果。
- 浮点 NaN、正负零与无穷的顺序由接口契约定义。键编码与原值恢复分别处理比较顺序和 payload。
- 输出字段和区间只控制最终写回，不改变排序中间数据的容量与依赖。
