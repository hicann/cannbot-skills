# SortSelect 统一输出映射

排序主体只处理连续尾轴的完整 N 项，并产生排序名次到原轴索引的对应关系。调用层把目标算子转换为排序方向、输出名次区间、输出字段和最终 shape；主体不按算子名称分支。

## 统一参数

以下名称是生成实现时的逻辑参数，不是 SDK 已有 API 或 example 已有字段。区间使用零基名次，右端不包含。

| 参数 | 含义 |
|---|---|
| `first_rank` | 首个输出名次 |
| `output_length`（L） | 每行输出项数；须满足 0≤first_rank≤N、0≤L≤N−first_rank |
| `descending` | 比较方向，按目标接口转换 |
| 输出字段 | values、indices 或两者；indices 始终为原轴坐标 |
| 输出 shape | 先恢复长度为 L 的原轴布局，再按接口处理 keepdim |

| 接口配置示例 | first_rank | L | 方向与 shape |
|---|---:|---:|---|
| Sort | 0 | N | 指定方向，保留轴 |
| Argsort | 0 | N | 指定方向，仅输出 indices |
| TopK | 0 | K | largest 决定方向，保留长度 K 的轴 |
| KthValue | k−1 | 1 | 此处假定 k 从 1 开始且取第 k 小；按接口处理 keepdim |

公共接口的 k 编号、合法域、稳定性、相等键、NaN、零符号和 `sorted` 行为仍须先按目标规格校验，见 [场景契约](scene.md)。表中配置不能覆盖实际接口约定。L=0 或总行数为 0 时返回空输出，不启动排序。

## 一条计算流程

设原输入有 R 个维度，shape 为 `[d0, d1, …, d(R−1)]`，归一化后的排序轴为 `a`（0≤a<R）。将排序轴之前和之后的维度分别合并，得到逻辑布局 `[O,N,I]`：

| 符号 | 含义 |
|---|---|
| `O`（outer） | 排序轴之前各维度的乘积，即 `d0×…×d(a−1)`；轴为首轴时取 1 |
| `N` | 排序轴的输入长度，即 `da` |
| `I`（inner） | 排序轴之后各维度的乘积，即 `d(a+1)×…×d(R−1)`；轴为末轴时取 1 |
| `M` | 独立排序序列的数量，`M=O×I`；每个固定的 `(o,i)` 对应一条长度为 N 的序列 |

例如输入 `[2,3,5,7]` 沿 `axis=2` 排序时，`O=2×3=6`、`N=5`、`I=7`，折叠布局为 `[6,5,7]`，共有 `M=42` 条排序序列。下面的 L 是上文定义的每行输出项数；恢复接口 shape 时再展开合并的轴前、轴后维度。

```text
输入 [O,N,I]
  → 规范化为连续 [O,I,N]，M=O*I；仅 N>1 且 I>1 时物理 transpose
  → 按 dtype、N、M、容量选择排序模板
  → 每行完整排序 N 项，在最终恢复/写回时输出名次 [first_rank, first_rank+L)
  → 输出恢复为 [O,L,I]；仅 L>1 且 I>1 时物理逆 transpose
  → 恢复接口 shape 和输出字段
```

连续尾轴及内存顺序等价的布局必须直接使用或 reshape，不启动布局转置 kernel，也不分配对应转置缓冲。输入与输出分别按 N、L 判断，完整条件与验收见 [物理转置的判定与验收](shape-preprocessing.md#物理转置的判定与验收)。KthValue 的 L=1 仍使用同一布局模型，输出还原只需 reshape，keepdim=False 再移除该单维。

设 `final_ids[r, rank]` 为完整排序恢复出的原轴索引。最终写回统一为：

```text
rank = first_rank + t                  # 0 <= t < L
axis = final_ids[r, rank]              # 0 <= axis < N
values_tail[r*L+t]  = x_tail[r*N+axis]  # 或直接携带对应原值
indices_tail[r*L+t] = axis
```

插入、两阶段和核内 Radix 在当前行/UB 批次最后写回时应用区间；两阶段先恢复行归属。归并在提取最终有序结果时应用区间。多核 Radix 先完成桶计数、前缀和最终全局名次计算，再于末轮恢复时应用区间。中间轮、有效元素数和同步参与者始终按 N 保留；无需输出的线程仍须完成阶段依赖。

### 保持批处理粒度

对原本 B>1 合批的路径，最终写回按本批有效行数展开 B×L 工作域，L=1 时也在行间并行。不得为复用单行写回函数而在外层逐行提交独立任务并逐行搬运、等待，或把原本合法的合批改为 B=1。B=1、尾批和真实容量限制下的分块按实际有效范围处理；改变原有粒度须有具体接口/容量限制或同口径设备测量依据，并记录在既有设计/检视中。

L=N 时保留已有连续批量写回；L<N 时按批次并行选择所需名次并写入紧凑输出，或先批量压紧再连续搬出。B×L 仅指最终输出域，不能据此把排序、逆映射建表或必要的行内比较缩为 L 项。尚未恢复行内 rank 的模板按自身算法在完整排序域内确定 rank，再判断是否写出；已经得到 `rank→原轴索引` 的模板直接读取目标区间，不为截取重新扫描整行、计秩或排序。语言适配层同时说明输出地址、并行域、外层调用次数和复用依赖；精度通过或声明多线程不能证明保留了批处理粒度。

最终输出按 M×L 分配。排序临时区的目标是按当前 B 行或 P_act 活跃行分配并跨批次复用，见 [统一内存要求](liveness-fusion.md#统一批次内存)。实际分配规模、复用状态及适配缺口在命中适配层核对。不先输出完整 GM Sort 结果再增加 slice/select。Sort 本身的 M×N 是最终输出，仍须与排序 scratch 分开预算。
