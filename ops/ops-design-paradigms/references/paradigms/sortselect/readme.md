# SortSelect 范式算子档案

SortSelect（排序与选择）范式覆盖沿指定轴排序、返回排序索引、选取前 K 项及第 K 个顺序统计量的算子。通过完整排序与统一名次区间输出，共用小轴插入、两阶段排序、归并、单核 Radix 和多核 Radix 等算法模板，按数据类型、轴长、行数与片上资源选择实现路线。

设计入口见 [SortSelect 范式](patterns.md)，具体语言的模板与实现约束由对应适配层提供。

## 典型算子

- Sort：沿指定轴升序或降序排列，返回排序值及原轴索引，提供范式参考实现。
- Argsort：返回排序后的原轴索引。
- TopK：选取最大的或最小的 K 项，返回值及原轴索引。
- KthValue：选取第 K 个顺序统计量，按目标接口约定返回值、索引及输出形状。

## 典型生成耗时与性能

| 算子名称 | 模型类型 | 平均性能（几何平均） | 最差性能 | 算子生成时长 |
|---------|---------|---------|---------|-------------|
| TopK | DeepSeek-V4.1-Flash | 0.88 倍库上已有算子 | 0.11 倍库上已有算子 | 约 30 小时（不含性能优化阶段） |

性能取本轮最终实现，在 Ascend 950PR、CANN 9.3.0 环境下对比 CANN 内置 ACLNN TopkV2。测试共 484 个用例，覆盖 44 组形状与参数配置、11 种数据类型，其中尾轴 165 个、非尾轴 319 个；采用 `sorted=true`、`sort_policy=0`，覆盖取大、取小及不同 K 值。生成算子的数值、稳定索引与原值位模式检查全部通过。

性能比值为 **builtin 耗时 / 生成算子耗时**，大于 1 表示生成算子更快。两条路径独立采集，预热 5 次后测量 5 次，累计一次 API 调用实际执行的全部设备 kernel 耗时，不计编译、内存分配与 Host 提交时间。

总体情况：性能比值统一采用几何平均，全部用例为 **0.88**，尾轴为 **1.03**，非尾轴为 **0.81**，199 个用例快于 builtin。最优用例为 **3.85** 倍，全部用例均高于 **0.1** 倍。最差场景为长轴 `K=1`，当前完整排序基线尚未针对极值选择单独特化。上述结果来自本轮 TopK 用例集，其他算子的性能需分别实测。

## 支持范围

- **开发语言**：AscendC、CANNBotDSL，分别提供语言适配层与 Sort 参考实现。
- **芯片与版本**：本轮 AscendC TopK 实测环境为 Ascend 950PR（arch35）、CANN 9.3.0；其他环境需核对排序原语、SIMT 与跨核同步能力。
- **算法路线**：AscendC 提供插入、两阶段、归并、单核 Radix、多核 Radix 五类模板；多核 Radix 区分 32/64 位计数，结合升降序形成 12 条实现分支。DSL 提供插入、两阶段、单核及多核 Radix，尚未适配 MergeSort 路线。
- **数据类型**：本轮 AscendC TopK 覆盖 float16、bfloat16、float32，以及有符号和无符号的 8/16/32/64 位整数；各语言、算法原语的适用域按对应能力映射核对。
- **接口语义**：覆盖尾轴与非尾轴、升降序、不同输出区间与字段；稳定性、相等值索引、NaN、正负零及索引类型按目标接口约定落实。
- **能力边界**：当前选择操作复用完整排序主体，不包含独立的小 K 选择或 `K=1` 极值算法。64 位输出索引与多核 64 位计数是两个独立维度；超长轴的 64 位计数路线已有模板及小规模强制选路验证，本轮性能集未覆盖其自然触发的大规模输入。

## 未来支持计划

新增 Select 模板，针对 K/N 较小的选择场景，减少完整排序开销，提升性能。
