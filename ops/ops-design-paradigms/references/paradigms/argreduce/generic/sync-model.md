# ArgReduce 同步模型（语言中立）

> **层级**：通用知识层（generic/），语言中立。
>
> **本文回答两个问题**：① 什么时候必须同步（推导规则，与语言无关）；② AscendC 和 DSL 要不要各写一份同步实现（要——但只写"原语怎么用"，不重复推导规则）。
>
> 为什么同步单独成文而不放在 splitting.md：**切分回答"活怎么分"，同步回答"分完怎么等"**。两者是不同的问题，放在一起会让读者误以为同步是切分的附属；而且同步规则同时被 Kernel 计算、Double Buffer、GroupReduce 三处消费，不属于任何单一主题。

## 1 为什么需要同步（白话）

芯片里搬数据和算数据是**两个独立干活的单元**：搬运（DMA）把数据从外部内存搬进片上缓存，计算单元再读缓存做运算。两者各干各的、异步推进——所以会出现两类问题：

| 问题 | 白话 | 例子 |
|------|------|------|
| **RAW（先写后读）** | 算的时候数据还没搬完 | 计算开始读 tile，但搬运只写了一半 |
| **WAR（先读后写）** | 搬运要覆盖缓存时，上一轮计算还没读完 | 第二轮拷贝写进了第一轮还在读的 buffer |

**同步就是在这两类依赖上插入"等待"**：等搬运完成再计算（RAW），等计算完成再覆盖（WAR）。判断哪里有依赖的方法叫**持有法则**：谁持有这块 buffer、什么时候释放、释放前谁还在用——从数据的生命周期推导，不靠"感觉这里该等等"。

## 2 核内同步（单核内部，所有场景都有）

| 依赖点 | 何时出现 | 必须等什么 |
|--------|---------|-----------|
| 载入 → 计算 | 每次 CopyIn 之后 | 搬运完成（RAW） |
| 计算 → 搬出 | 每次 CopyOut 之前 | 计算完成（RAW） |
| 下一轮载入 → 上一轮计算 | 开 Double Buffer 时 | 上一轮计算读完旧 buffer（WAR） |
| 位置流 | 位置在片上生成、不依赖载入 | **不需要**为位置流加载入等待；位置流随块再生（不缓冲）时也无需跨轮同步 |

**双缓冲结论**：值流 tile 可以开双缓冲（搬运与计算重叠）；位置流不缓冲（每块重新生成），因此不产生额外的 WAR。

## 3 跨核同步（仅 GroupReduce）

| 场景 | 需要同步吗 | 原因 |
|------|-----------|------|
| A1 切核（每个核分到不同的输出行） | **不需要** | 核间处理的输出互不相交，没有共享写 |
| A0 切核（每个核分到不同的输出列） | **不需要** | 同上 |
| **GroupReduce（R 切到多个核）** | **需要** | Phase 1 每核写局部冠军到公共内存，Phase 2 要读**所有核**的结果——必须保证全部核写完 |

GroupReduce 的同步语义（语言中立）：

```
Phase 1：每核算局部 (值, 位置) → 写公共内存（workspace）
   ↓
全核栅栏：所有核都到达此点才放行（缺一即挂死或读脏数据）
   ↓
Phase 2：聚合（读全部核的局部结果，逐对 select）
```

**配套约束**：栅栏要求"发起几个核就等几个核"——所以 GroupReduce 的核数必须按**物理核数**（全部核），不能用动态核数（只开一部分核）；混合使用会导致等待数不匹配而挂死。

## 4 AscendC 与 DSL 要不要各写一份？（专家问题的回答）

**要，但分工明确**：

| 层 | 写什么 | 不写什么 |
|---|--------|---------|
| **本文档（generic）** | 依赖怎么推导、哪里必须等、GroupReduce 的三段结构 | 具体 API 名、事件编号、Channel 语义 |
| **adapters/ascendc** | 原语怎么用：核内用事件对（MTE2→V / V→MTE3 的等待与释放）、跨核用 `SyncAll()` + `SetScheduleMode(1)`；双缓冲用队列 `EnQue/DeQue` 的隐式同步 | 不重复推导规则 |
| **adapters/dsl** | 原语怎么用：阶段内 Buffer 无需显式同步（编译框架管理）；跨阶段/跨角色用 Channel 的 `acquire/commit/wait/release` 交接；跨核用 `ops.sync` 类目（如 `global_sync_all`） | 同上 |

**为什么不能只写一份**：AscendC 的事件编号、队列语义与 DSL 的 Channel 交接是两套完全不同的机制（前者手动管理事件，后者用生产/消费契约）；写在通用层会污染语言中立性。但**推导规则只有一份**（本文档）——两套适配层都从同一套"哪里需要等"的结论出发，只是落地原语不同。
