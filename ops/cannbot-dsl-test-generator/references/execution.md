# 脚本生成与执行验收

固定 runner 全量正确性执行使用 `--all --device <设备>`，在同一进程顺序运行 CSV 中全部分组的 active 行，共用 Golden 和目标模块加载，结果仍写入各分组的原生 CSV。单例失败不跳过后续用例，任一失败则整体返回非零；没有 active 行时返回错误。空分组跳过且不生成通过结果，不要求每个分组非空，必测分组由调用方的放行契约约束。

单组执行保留 `--sheet <分组>`；`--all` 与 `--sheet`、`--case-id`、`--grep` 互斥。仅定位失败时使用 case-id，不默认在全量结束后逐例重跑全部用例。数值、行为和重复调用契约不因批量执行改变。

sheet 内的部分用例使用 `--grep` 按 case_id 正则筛选 active 行，与 `--case-id` 互斥。例如 `--sheet tdd --grep '^TD-u01-' --device npu --require-accelerator` 一次运行 U01 的绑定用例；多个 Unit 回归可用 `'^TD-(?:u01|u02)-'`。非法正则或无匹配用例返回非零。选中用例在同一进程内顺序执行，共用 Golden 和目标模块加载；任一用例失败则整批返回非零。

筛选结果写入 `testcase_output/<sheet>/verify_result_<sheet>_grep_<正则SHA256前16位>.csv`，与全量及单例结果分开。Red、Green 和回归阶段分别归档本次结果及日志，记录对应实现版本，避免后续调用覆盖前次证据；没有筛选时原有全量结果路径不变。

`prepare_golden.py` 随 runner 安装 `cannbotdsl_case_cache.py`。`build_tdd_cases.py` 完成校验后，在 `TEST_DIR/.case_cache/` 为blackbox、whitebox、tdd 及非空 performance 分组全部 active 用例按调用保存 CPU 输入、数值 Golden 输出和初始输出缓冲区模板；行为断言与预期异常不计算 Golden，不导入目标实现。后续测试按需加载，缺失、过期或读取失败的条目自动重建；重建或保存失败返回非零。生成阶段必须为当前全部 active 调用准备成功，不以部分缓存完成宣布测试生成通过。

缓存键包含格式版本、Golden 源码哈希、绑定的既有输出契约、PyTorch 版本、分组、case_id、调用序号、输入与输出配方、seed、预期类型和断言。修改目标实现可复用缓存；修改用例、Golden 或绑定契约后自动使用新条目。数值缓存准备和命中均核对实际主参考输出符合已有输出契约；不合法时不能放行，重建后仍不合法则失败。每次目标调用使用独立输入与输出模板副本，序列、repeat、bitwise、AICPU 前处理、实际算子调用及结果检查保持执行。数值比较前同样核对目标输出；合法空张量保留检查记录，未声明的空容器不能以零条比较记录通过。沿用现有 detail 记录结构，不新增外部字段。缓存固定在 CPU 加载并限制反序列化内容，使用临时文件和原子替换写入。

缓存可删除，不作为源码交付的必需文件；独立副本首次执行可自动重建。测试数据按调用加载，避免全部驻留内存。比较优化耗时时分别记录准备成本、首次加载与命中耗时，并计入“准备一次加多次运行”的总成本及缓存占用。

可选输出在准备、目标缓冲区调用、数值比较及 bitwise 重复验证中遵守同一存在性契约；合法 `None` 保留位置，不能作为漏返回必需输出的替代。缺省输出不分配或传递缓冲区，本例实际存在的输出不能遗漏，目标缓冲区的存在性须与主参考及已生效条件一致。TensorList 缓冲区在构建、旧缓存命中及每次目标调用前递归清零，不重算有效主参考。异常输入用例沿原有目标错误判据执行，不增加依赖合法输入的输出 dtype/存在性前置门槛。调用方式和配方沿用 [用例契约](cases.md)，不新增字段或缓存格式版本。

所有成功返回的调用先核对已有输出契约，再执行本例的数值或行为断言；`expected=assertions` 也不能漏返回必需输出、违反存在性条件或改变明确声明的缓冲区 shape/dtype，但仍不计算 Golden、不附加数值门槛。预期异常用例保持原目标错误验证路径。缓存中的主参考输出和重复验证快照使用普通容器表示，保留 Tensor 的值、dtype、shape 与合法 `None`；重复快照按已声明输出名及 TensorList 成员归一化，省略可选键与显式 `None` 不制造差异，真实存在性变化或存储位变化仍失败。`torch.return_types` 等合法元组返回值在保存前去除自定义容器类型，继续使用 `weights_only=True`，不扩大反序列化信任范围。

调用脚本必须保存测试、导出和 Native 子进程的退出码。函数内后续 echo、日志命令不能覆盖失败；含 tee 的管道必须检查被测命令状态，任一必需步骤失败则顶层返回非零。需要继续收集多个分组结果时累计失败，不能用最后一步状态代表全部步骤。

结果只对应本次运行：启动前使旧结果失效，或使用唯一运行目录；退出码为零、预期用例齐全且结果属于当前源码及输入版本三者同时成立才能成功。runner 在加载用例和 Golden 前删除本次目标 CSV，`--all` 清除所有分组的旧全量结果（包括当前空组），完成写入后原子替换；导入依赖失败、进程中断或未产生新文件均不得回退读取旧 CSV。不同运行不能并发写同一结果路径。

从脚本自身位置或显式参数定位文件，路径正确引用以支持空格；使用调用方已激活环境的解释器或显式传入解释器，不固化开发者 home、Python 或 CANN 路径。错误匹配器、固定契约模块和其他辅助依赖随测试交付，运行说明包含模块加载方式。测量区间不包含数据构造、输入快照或断言。

执行 Agent 对本次新建或修改的顶层脚本运行以下验证，并保存命令、退出码和输出；未修改脚本复用对应版本的有效证据：

- 分别让测试、导出、Native 子进程失败，包含经过 tee 的路径，顶层均须非零；同时预置旧成功文件，确认不会判成功。
- 从其他工作目录及含空格的交付路径执行，确认加载的是交付副本；移走必需辅助模块时明确失败。
- 正常批量执行的结果覆盖所有 active 行，失败诊断的单例结果与全量报告区分。

这些要求用于检查本轮脚本，不另生成通用 shell 模板；不能用检查提示词是否存在代替执行验证。

验收 Agent 独立审查脚本、原始结果及版本对应关系，不重复执行已有完整证据的同一批测试。证据缺失、过期或失败时不予通过，由执行 Agent 补齐或修复。

## 交付副本复跑

交付保留包的相对布局、必需辅助模块和运行说明，索引使用相对交付根的路径；中间缓存、框架状态和临时文件不作为源码交付。不覆盖目标目录的无关文件，路径冲突时报告具体文件并停止，相同源和目标不重复复制。

仅用交付清单中的文件构造独立副本，在原工作目录以外复跑测试、导出和 Native 验证。清除旧 PYTHONPATH 绑定，记录实际加载模块路径、源码哈希、命令、退出码和本次结果来源；不能依赖原工作目录的模块、缓存或旧结果。必需辅助模块缺失或仍加载原工作目录时失败。验收 Agent 核对独立副本与交付版本及运行证据一致；设备不可用时如实记录未验证。

performance 正确性检查使用同一 runner 与 Golden，全量执行时由 `--all` 自动纳入，无需额外调用；单独检查该组可用 `--sheet performance`，结果位于 `testcase_output/performance/`。仅当 CSV 中存在该分组 active 行时执行；无用例不制造通过结果。此路径不实现性能计时、采样或 Profiling。

数值用例的期望值由固定缓存直接调用 `GOLDEN_FUNCTION` 计算，主参考与目标执行使用同一次物化输入的隔离副本，不再次调用 `make_inputs()` 或通过 `simulate()` 另取期望值。使用内置比较器，不依赖外部评测库。未指定时使用 staged_relative 完整两阶段（整数/布尔走精确策略），显式 mean_relative 仍为单阶段；按契约可选或必须绑定 NATIVE_REFERENCE_FUNCTION，默认必须存在独立同精度参考，准备与缓存加载时检查绑定，缺失或异常不自动降级；同精度参考在阶段二使用本次同一物化输入的隔离副本，不再次 make_inputs。正式 CSV status 与退出码必须反映完整策略结果，独立比较文件/旁路结果不能代替；未支持的完整标准在准备阶段阻塞，不能延期给实现自行叠加。参考精度与舍入路径见 [Golden 契约](golden.md#独立主参考与计算精度)。runner 与两个辅助模块须版本一致，缓存 v4 按当前有效身份派生；恢复已有运行时使用冻结资产，不将不同比较口径的执行结果补签为通过。
