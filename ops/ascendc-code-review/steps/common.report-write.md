# 撰写报告（文件检视 + PR 检视）

## 执行步骤

1. 按置信度分级汇总：HIGH→「发现问题」、MED→「需关注」、LOW→「疑似」
2. 生成报告文件
3. **设计一致性章节（条件）**：若本次检视含 S1-S7 结果（docs_input 非空、design-check 已派发），在 `## 检视统计` 之后、`## 发现问题（HIGH 置信度）` 之前插入「设计一致性检查」章节（见下方报告格式）。无 S1-S7 结果则跳过。
   - 总体评级：全部 ✅/N/A→一致；有 ❌→不一致；有 ⚠️ 无 ❌→部分一致
   - ❌ 项附代码位置（校对后行号）+ 设计依据（来源文档原文引用，标注文件名+章节）

## 报告格式

### 文件检视报告
路径：`./operators/{operator_name}/{source_file}_review_summary.md`

```

### PR 检视报告

路径：`./operators/pr-{pr_number}/{pr_number}_review_summary.md`
格式同文件检视报告。

## 约束

- 每个 FAIL/SUSPICIOUS 发现必须附 10 行以上代码片段，行号使用校对后结果
- PR 检视报告的代码片段必须标注完整文件路径（相对于 repo_path），禁止只写短文件名
- 设计映射表留作 design-check 子 Agent 内部产物，报告只放 S1-S7 判定表 + ❌ 项定位；无 S1-S7 结果时不生成设计一致性章节，报告退化为纯条例检视报告
