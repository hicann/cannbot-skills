# 开发与精度定位

在实现首个 Stage、排查同步问题或定位定向精度失败时读取本文件。

## 开发前核验

- 使用目标环境实际安装的 CANN、编译器和 CATLASS，确认构建架构与实际 SoC 一致；芯片能力由 `npu-arch` 获取。
- 构建和运行命令以当前算子工程为准。每轮确认测试进程加载的是本轮构建产物，避免旧进程或旧二进制污染结果。

## 逐 Stage 开发

每个 Stage 依次完成实现、构建、设计一致性检查、运行和快速精度比较，再接入后续 Stage。

- 存在跨任务状态依赖时验证初始状态、连续任务和尾任务；独立任务验证地址及状态隔离。
- 跨核 ready/free 与本地 pipe 完成事件分别对应实际生产、消费和地址释放，覆盖首次使用、切换、回绕、空任务和退出排空。
- 固定按单 work、连续 work、slot 切换、slot 回绕、尾块、空任务、多 batch/head 和主模型 case 逐级扩大验证范围。
- 需要观察执行顺序时，只在测试版本使用按核隔离的记录区；定位完成后删除记录并重新构建。
- 连续 Vector 操作使用相同 mask 时，预先设置一次，并在 API 支持时关闭自动设置；mask 模式或有效 lane 改变后重新设置。

## 首个差异定位

精度定位必须保留正式的跨 work 并行和 Stage 流水；串行实现只能作为独立诊断，不得替代正式生产消费关系或写入实现准出证据。

固定失败用例、输入、随机种子、代码版本和有效区域，沿 `docs/design.md` 的数据依赖比较 Stage 中间结果，定位第一个产生差异的 Stage。

在该 Stage 内依次核对公式与累加顺序、dtype/cast、地址与 layout、有效区搬运、同步通知、空间复用和输出写回。临时检查点不得改变原生产消费关系，完成定位和修复后必须删除，并用正式构建重跑受影响用例和必要边界。

在 `docs/validation.md` 记录复现用例、首个差异位置、根因、修改和复验结果。若根因属于 Stage、地址、同步、tiling 或 workspace 设计，执行 `design_problem` 返回 `design / null`，在 03 重新设计并通过校验和评审；经 `design_accepted` 进入 04，按新设计完成实现、构建和快速精度验证；通过后经 `implementation_accepted` 进入 `validation / null`，在 05 重新执行全量验收。
