# 输入契约

> 阶段 0 用它做"能不能开工"的判定。**输入不足时停止询问，不脑补**——编造 shape/dtype/语义是迁移任务最常见的返工原因。

## 1. 三种输入形态

### 形态 A：A5 工程源码（推荐）

判定信号（满足任意两条即可）：

- 存在 `op_kernel/`（含 `arch35/` 或 `__NPU_ARCH__ == 3510` 分支）与 `op_host/`
- 存在 `build.sh` 且支持 `--pkg --soc=`
- 存在 `op_host/config/ascend950/` 或 `_def.cpp` 中的 `AddConfig("ascend950")`
- 存在 `Makefile`/`CMakeLists.txt` 中的 `SUPPORT_COMPUTE_UNIT "ascend950"`

处理：直接进入阶段 1，用 `scripts/scan_a5_only.py` 对 `--root` 扫描。

### 形态 B：A5 设计文档 + 参考实现（无 A5 源码）

处理顺序（缺一不可）：

1. 从文档提取**语义基线**：数学公式、输入输出、dtype 与精度要求、layout、边界与特殊值行为（NaN/Inf/空张量/极值）。
2. 标注文档中依赖 A5 硬件能力的设计点（如"用 SIMT 做 index 计算"、"用 L0C→UB 直通省搬运"）。
3. 向用户确认基线（尤其边界行为），确认后才进入阶段 2 的 A2 实现。
4. 精度标杆仍按 `ops-precision-standard` 用更高精度 CPU 实现构造，不能拿"文档描述"当数值标杆。

### 形态 C：信息不足

下列任一情况直接停止，按 §4 模板提问：

- 只有算子名或一句自然语言需求
- 没有 dtype 清单 / shape 范围 / layout
- 没有参考语义（公式、参考实现或 A5 源码三者皆无）
- 目标芯片不明确（只说"迁移到 A2"，但工程同时有 310P 分支）
- 验收口径缺失且用户拒绝给（见 §3）

## 2. 必需事实清单

阶段 0 结束时，下列各项必须已填实并落盘（缺项只能在报告中标 `UNKNOWN` 并说明影响，不能默认）：

| 类别 | 必须确认 | 为什么 |
|---|---|---|
| 目标平台 | `910B` 或 `910_93`；实测 `NpuArch` 是否为 2201 | 决定 `--soc`、`AddConfig`、config 目录拼写 |
| 工具链 | CANN 版本、`ASCEND_HOME_PATH`、Python、编译器可用性 | 决定 API 是否存在、构建命令形态 |
| 工程入口 | `build.sh` 相对路径、算子名、安装方式 | 阶段 3 可复现 |
| 语义 | 支持的 dtype 清单、layout、shape 范围、特殊值行为 | 阶段 3/4 用例设计 |
| 验收 | 精度标准（默认 `ops-precision-standard`）、性能目标口径 | 阶段 4/5 Gate 判据 |
| 设备 | A2 真机可用性（是/否），无设备时的替代方案 | 无设备则 GATE-3/4/5 不能 PASS |

## 3. 性能目标口径（必须与用户对齐）

"高性能"不是形容词，必须落到可判定口径，任选其一并记录：

| 口径 | 判据示例 | 说明 |
|---|---|---|
| 相对基线 | 对比 A2 上同语义既有实现（仓内参考/社区实现），中位耗时加速比 ≥ 目标值 | 最常用；基线必须同 dtype、同 shape、同计时协议 |
| 硬件利用率 | VEC/MTE 主 Bound 占比 ≥ 目标值，或 MFU/MBU 达理论上限的 X% | 需 `ops-profiling` 的成本模型 |
| 绝对时延 | 指定 shape 下 ≤ X us | 需固定计时协议（warmup 次数、中位数） |
| 用户未给 | 按"识别主瓶颈 + 收敛规则"（见 `references/performance-tuning-a2.md` §6）判定 | 报告中标注 `TARGET=user-unspecified` |

**禁止**：把 A5 实测耗时直接当 A2 基线；跨架构加速比只能作参考信息，不能作为 A2 验收判据。

## 4. 提问模板（一次问清，不反复打断）

```
开始 A5→A2 迁移前需要确认 5 项（缺项会阻塞阶段 0）：
1) 目标芯片：910B 还是 910_93？（两者同 DAV_2201，但 --soc 与部分配置不同）
2) CANN 版本与 ASCEND_HOME_PATH：
3) 工程构建入口（build.sh 路径）与算子名：
4) 支持的 dtype / layout / 重点 shape：
5) 性能验收口径：相对哪个基线、目标加速比或时延；若无目标，是否接受"瓶颈证据 + 收敛规则"作为验收？
```

## 5. 开工前的红线

- 目标不是 `DAV_2201`（例如 310P、Kirin、A5 本身）→ 说明不在本技能范围并停止。
- 用户要求"保证与 A5 数值完全一致"→ 说明 FTZ 不可逆，最多保证在 `ops-precision-standard` 容差内一致，请用户确认。
- 用户要求"跳过精度验证先上性能"→ 拒绝：精度未过的性能数据无意义，先 GATE-4。
- 用户要求"用 A5 机器跑 A2 编译产物选优"→ 拒绝：架构不同，结果不可迁移。
