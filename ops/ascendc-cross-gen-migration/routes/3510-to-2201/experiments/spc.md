# 案例：简单搬运类算子下沉 A2 的实现路径对比

> 实验记录，非通用规范。环境 910B3 + CANN 9.2.0。

## 环境与对象

| 项 | 值 |
|---|---|
| 仓库 | `ops-transformer@ba5162411c919e15fbabb28298e8b420c11ad905` |
| 算子 | 单输入单输出的 scatter/cache 更新类算子（`--ops=scatter_pa_cache`） |
| 目标 | `--soc=ascend910b`（DAV_2201 / arch22） |
| 测量 | msprof `op_summary` 的 `Task Duration`，50 次取中位数 |

## 实现路径对比

| 路径 | 说明 |
|---|---|
| 路径 1 | 复用 A5 通用类（`ScatterPaKvCacheNormalSiso`），仅改 tiling/入口 |
| 路径 2 | 新建 arch22 文件但仍 include 通用类 |
| 路径 3 | arch22 内自实现，但用 TQue 双缓冲 + 每 token 队列操作 + 批量 slot 预取 |
| 路径 4 | arch22 内自实现，单 `TBuf` + 两次 `DataCopyPad` + `PipeBarrier` |

## 收益数据（kernel 中位数）

| 路径 | 中位数 |
|---|---|
| 路径 1 | 13.21 / 14.53 µs |
| 路径 2 | 13.54 µs |
| 路径 3 | 12.16 / 13.94 µs |
| 路径 4 | **9.85 µs** |

补充（同机 pipe 指标对比，msprof `op_summary`）：

| 指标 | 路径 3/4（A） | 参考实现（B） |
|---|---|---|
| Task Duration | 12.5–15.0 µs | 10.5–11.0 µs |
| `aiv_time` | ~10.2–10.6 µs | ~3.9 µs |
| `aiv_mte2_time` | ~5.2–5.4 µs | ~1.5 µs |
| `aiv_scalar_time` | ~2.7–2.8 µs | ~1.5 µs |
| `aiv_mte3_time` | ~2.3 µs | ~1.0 µs |

注意：把拷贝改成按字节后，A 的 `aiv_mte2` 仍约 5.4 µs，说明**拷贝 dtype/同步方式不是主因**；A 的 kernel 单位时间内的搬运/标量工作量显著高于参考实现，根因尚未定位（待查：tiling/block 分发、kernel 入口编译产物）。

## 根因定位（受控变体，msprof 同机）

| 变体 | Task Duration | aiv_time | aiv_mte2 | 说明 |
|---|---|---|---|---|
| A7 | 12.48 µs | 10.22 µs | 5.20 µs | 整体 `GET_TILING_DATA`（大结构） |
| A7D | 11.19 µs | 6.00 µs | 1.34 µs | 直接从 GM 读字段，不整体拷贝 |
| A7E | 11.44 µs | 4.61 µs | 1.08 µs | 只在 Init 读 4 个字段到本地 |
| B | 11.00 µs | 3.91 µs | 1.51 µs | 参考实现（小 tiling 结构） |

结论：主要差距来自 **kernel 内对大的 tiling 结构整体拷贝**（scalar/MTE 固定开销），不是拷贝 dtype、同步方式或 buffer 数量；去掉整体拷贝后 AIV 时间从 ~10.2 µs 降到 ~4.6–6.0 µs，Task Duration 接近参考实现（交替复测参考实现 9.94–10.91 µs，A 10.95–11.21 µs，仍余约 5%–15%）——残余差距与 host tiling 结构/入口编译单元有关，尚未完全消除。

## 复现：按 Skill 重新生成 A（A8）

- 正确性通过；但检查源码仍是**复用大 tiling 结构**（新增的是 tiling 注册文件，不是小结构）；
- 交替复测：A 11.06–11.14 µs，参考实现 8.96–9.01 µs，仍慢约 23%；
- 说明只写“建议用小结构”不足以让 agent 落地，后续在 SKILL 中改为四步清单 + 性能硬验收。

## 按 Skill 四步小结构重新生成（A9）

- 实现：`a2_tiling_data.h`（4 字段 POD）+ `tiling_arch22.cpp/h`（A2 host tiling）+ `scatter_pa_cache_arch22.cpp`（独立入口）+ 注册；
- 正确性：`run=0`，`max_abs=0.0`；
- 交替复测（同机 50 次中位数）：A **10.01 µs**，参考实现 **10.38 µs**，A 快约 **3.6%**（aiv_time 5.3–5.7 vs 5.7）；
- 结论：四步小 tiling + 独立入口落地后达到持平/略优，验证该优化点有效。

## 会话成本对比（同任务）

| 组 | 墙钟 | tokens | 说明 |
|---|---|---|---|
| A（按 skill 从零实现） | 41.8 min | ~49.5M | 中间经历大结构返工 |
| 参考实现 | 19.0 min | ~16.8M | 直接按小结构写 |

结论：先写四件套、一次构建/直调/profile，是压缩耗时与 tokens 的关键；返工是主要成本来源。

## 阶段耗时分析（SPC8/9/10 会话，按工具调用实际耗时）

| 会次 | 墙钟 | 主要耗时项 | 占比 |
|---|---|---|---|
| SPC8 | 44.9 min | 构建 + sleep 轮询 | ~84% |
| SPC9 | 41.8 min | sleep 轮询构建 | ~81% |
| SPC10 | 29.9 min | 检索 41% + 其他 shell 28% + 构建 25% | — |

单条 `sleep 90–180` 的轮询命令累计消耗 10 min 以上；`find /` 类全盘检索单条耗时可达 2 min。
对策：前台构建 + timeout、后台构建期间做别的编辑、检索限定目录。
