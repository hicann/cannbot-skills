# 阶段 6：交付

**目标**：产出可复核、可复现、可维护的交付物；把"没做到的"说清楚。

## Step 6.1 交付报告

用 `assets/migration-report.md.template`，必含：

1. **结论**：可运行（是/否）、精度（N/N）、性能（口径 + 结果 + 达标判定）。
2. **范围与平台**：源 A5 形态、目标 `SOC_BUILD`、CANN 版本、`NpuArch`。
3. **A5 依赖清单**：全部 `blocking`/`decision` 项的处置与依据。
4. **变更账本**：文件 → 改了什么 → 依据 → 验证。
5. **gate 证据**：GATE-0…6 的实际输出与证据路径。
6. **残留风险与限制**：不支持的 dtype/特性、条件接受项、未达标项、待验证项。
7. **复现命令**：构建/安装/精度/性能四条命令，路径用变量。
8. **维护提示**：后续接手人最可能踩的坑、为什么保持某个"看起来奇怪"的写法。

## Step 6.2 残留项归档

| 类 | 处理 |
|---|---|
| 功能裁剪（dtype/特性不支持） | 写入报告 + `_def.cpp` 列表一致 + 用户已知 |
| 条件接受 | `CONDITIONAL` + `USER_ACCEPTED` + 豁免明细 |
| 性能未达标 | 瓶颈证据 + 上限估算 + 整改建议 |
| `verify` 未查证项 | 标 `UNVERIFIED`，给出查证方法 |
| `advisory` 未复核项 | 列成 TODO，注明影响 |

## Step 6.3 复现包

- 改动后的工程（分支 + commit）。
- 扫描报告（前后各一份）、分析报告、精度报告、性能报告。
- 关键命令与预期输出片段。

## Step 6.4 自检

- [ ] 报告中的每个数字都有出处（日志/CSV/报告文件路径）。
- [ ] 没有任何"应该是/预计"式结论。
- [ ] gate token 与实际证据一致，没有把 BLOCKED 写成 PASS。
- [ ] 不支持项与用户决策可追溯到记录。
- [ ] 复现命令在干净环境里能跑（至少构建命令验证过）。

## 完成判据

报告完整、证据可查、残留项明确、复现命令可用。

## Gate

```
[GATE-6] DELIVERY=READY REPORT=<路径> RESIDUAL_RISKS=<n>
```

缺报告或缺证据：`DELIVERY=INCOMPLETE`，不得宣称交付。
