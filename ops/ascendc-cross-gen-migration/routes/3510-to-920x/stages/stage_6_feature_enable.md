# 阶段 6：根据目标新特性改造或新增实现

前置：`[GATE-5] PERF=COLLECTED`。产物为 `${EVIDENCE_DIR}/feature_trials.md`、各试验的构建/精度/性能证据和最终交付清单。

**本阶段为必做。** 必须完成逐算子适用性判断，并对任务范围内尚未覆盖的适用能力实际改造或新增实现；不能在原实现兼容运行后直接结束，也不能只列候选而省略实施。已有有效实现走复用验证，不为清单重复新增代码；无索引或无量化接口等明确不适用情形仍按契约排除。

## LOADED 检查点

读取 [feature-catalog.md](../references/feature-catalog.md) 与 [feature-implementation-guide.md](../references/feature-implementation-guide.md)，分别输出 `[LOADED] 3510-to-920x/feature-catalog`、`[LOADED] 3510-to-920x/feature-implementation-guide`；每个候选开始前加载该项声明的专题和实际目标 API 原文，并将文件、版本及小节写入试验记录。

## Step 6.1：逐项判定并确定实现方式

用 Stage 1 能力矩阵与 Stage 5 瓶颈复核每个候选；适用性和实施状态分开：

- `APPLICABLE`：代码模式、dtype/shape、版本与接口条件有依据。
- `NOT_APPLICABLE`：存在明确不匹配条件，写出代码/契约依据。
- `NEEDS_EVIDENCE`：缺知识或环境，不能伪称不适用或直接使能。

每个适用项必须选择“复用已有 / 改造原路径 / 新增专用模板”，列出本次 9201/9202 目标、覆盖范围、真实代码位置、回退和验证计划。已有实现完成可达性及命中验证后记 `REUSED`；其余任务范围内适用项均进入 `PLANNED`，按 Stage 5 瓶颈排序实施。需要新增模板、重构数据通路或前置 tiling 改动本身不构成跳过理由。

任务已明确限定范围、已有预算耗尽或缺少必要环境/证据时可以记录 `DEFERRED`，但它表示未完成。任务范围内的必做项暂缓时不得输出 Stage 6 完成；范围外项单列剩余工作。不得自行以“原实现能跑”或“新增实现复杂”缩小任务范围，也不向非量化接口添加 HiF4 输入输出。

## Step 6.2：实施目标专用路径

按 [feature-implementation-guide.md](../references/feature-implementation-guide.md) 的步骤完成每个 `PLANNED` 项：

1. **定义准入和回退**：目标架构、dtype/shape、对齐、API 参数与资源条件，以及不满足条件时实际可用的兼容实现。
2. **改造或新增 kernel**：复用公共计算部分，实现目标 API、搬运/计算路径和同步；需要专用模板时新增对应实现文件或类。
3. **配套 host tiling**：新增或复用合法的 tiling 数据结构，更新资源划分、offset/mask/scale、字段范围、workspace 和尾块处理。
4. **接入注册与分发**：按工程实际注册模板、设置准入/选择顺序、匹配 host 与 kernel 的 tiling key，接入入口及架构守卫。
5. **接入构建与加载**：检查源列表、compute unit、binary 配置和 tiling 链接，确保新增模板进入实际安装包。

DMA 专用模板必须覆盖以上环节；仅在原代码中替换 API、建立文件或添加平台注册不能代替完整模板接入。每项列出实际改动文件和无需改动环节的既有覆盖证据。

## Step 6.3：逐项构建、验证和保留

每项在改代码前写明：候选 ID、触发分支、预期收益依据、同目标基线、改动范围、完整回退清单、精度电池、A/B 配置与停止条件。任务已有预算与性能目标时直接沿用；没有固定数值时，依据本轮预算与测量波动说明收益判据，并记录实际收益。

1. 为本任务差异创建可恢复快照或 patch，标明已有用户改动；不使用破坏工作树的全局重置。
2. 按 Step 6.2 实施并重跑 Stage 3 构建安装与 Stage 4 **全量计划**精度验证；新增模板必须补充新分支、回退分支及准入边界用例，证明实际命中。
3. 以 Stage 5 的同设备、同输入、同负载与同口径条件重采性能，输出到独立 `perf/trials/<candidate-id>/`。
4. 实际收益满足已记录目标、且能从噪声中区分时可 `KEPT`；无稳定收益、编译/精度失败或预算/停止条件触发时，回退本次代码、宏、CMake、tiling 和安装产物，复验恢复后的基线。
5. 反复出现同一失败且无新依据时停止试探；未开始的项记 `DEFERRED`，已尝试并恢复的项记 `ROLLED_BACK`，恢复失败记 `FAILED` 并阻塞交付。

连续保留多个能力时，每项除对固定 Stage 5 基线报告外，还与上一已保留版本比较，区分单项增量和累计收益；不覆盖任何基线原始数据。

## Step 6.4：最终状态与交付

`feature_trials.md` 至少含：全部候选的适用性、实现方式、实施状态、理由/知识依据；每个应实施项的 kernel/tiling/注册/分发/构建改动、准入与回退覆盖、构建/全量精度结果、A/B 数据与最终回退状态；最终代码/库 hash 与未完成事项。最终保留组合必须完成 Stage 3/4/5 的对应复验，不能只凭各个孤立试验通过认定组合正确。

## Gate

- 全部候选完成有依据的适用性判断；任务范围内适用项均已验证复用或实际尝试，所有 `PLANNED` 项已闭环为 `KEPT / ROLLED_BACK`；无失败残留，最终交付版本已验证：`[GATE-6] FEATURES=EVALUATED RETAINED=k/n DEFERRED=d`。
- `n` 为任务范围内应完成的试验项数，包含未完成必做项，不含已验证复用和已明确排除的范围外项；`k` 为保留数。复用项单列，推迟项 `d` 连同理由及是否属于任务范围单列。仅任务范围内全部不适用或已验证复用时允许 `0/0`，不得将其宣称为新增特性已使能或性能提升。
- `NEEDS_EVIDENCE` 在矩阵中保留未知并显式列为 `DEFERRED`；不得隐藏依赖缺口。任务范围内的未知/暂缓项、只评估未实施的适用项、未闭环试验或恢复失败：`[GATE-6] FEATURES=NOT_VERIFIED BLOCKED`。仅范围外有剩余项时可按本次范围验收，但必须说明剩余新特性适配未完成。
