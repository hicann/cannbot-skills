# DAV_3510 → DAV_9201 / DAV_9202：目标新特性的实现步骤

**使用时机**：Stage 1 为适用能力制定实现方案；Stage 2 实施正确性必需的替代路径；Stage 6 利用目标新特性改造或新增实现。

本流程面向已有算子，保持接口、数学、索引和确定性契约。适用性由 [feature-catalog.md](feature-catalog.md) 和实际目标 SDK 决定；每个适用项必须明确以下一种实现方式。

实现与验收绑定 Stage 0 选定的 `SOC / TARGET_ARCH`。用户要求 9201/9202 双目标时，共用代码的覆盖范围、目标准入及验证证据分别列出，不把 9201 专用模板自动登记为 9202 已支持。

| 实现方式 | 选择条件 | 必须完成的工作 |
|---|---|---|
| 复用已有 | 原代码或实际 SDK 已覆盖目标能力 | 核对分发可达、实际运行命中和相应精度；记录 `REUSED`，不重复新增实现或声称新增收益 |
| 改造原路径 | 现有 kernel 结构可承载目标 API 或数据通路 | 修改命中分支，配套更新 tiling、资源与同步，保留其他适用路径 |
| 新增专用模板 | 需要独立搬运、流水、资源布局或准入条件 | 新增 kernel 和必要的 host tiling/分发实现，接入构建与回退，完成新旧路径验证 |

## 1. 定义覆盖范围和准入

在 `migration_plan.md` 的对应候选下记录目标架构、dtype/layout、shape、属性、对齐、参数范围、资源需求和排除条件。Stage 1 记录预期收益来源，Stage 6 再用 Stage 5 的实测数据复核。列出新增/修改的 kernel、host tiling、注册、入口和构建文件；实际工程无需改动的环节给出现有覆盖依据。

准入条件取实际 SDK 与算子约束的交集。不能把某个参考模板的参数上限、优先级或 tiling key 复制成全部算子的统一规则。

## 2. 实施 kernel 与 host tiling

1. 以现有 kernel 和同类真实实现为依据，按工程习惯新增头文件、实现类或函数；可复用部分通过现有组合/继承机制复用，避免复制整套算法。`arch92/` 可承载专用实现，共用 `arch35/` 是否保留由工程分发机制决定。
2. 对命中项实现目标 API、搬运或计算路径；按实际声明核对输入输出、掩码、舍入及同步，不编造新架构参数类型。
3. 配套新增或扩展 host tiling：计算块划分、资源/临时 buffer、索引与偏移、workspace 和尾块，验证字段位宽及单位。能合法复用原 tiling 数据结构时不强制新增结构。
4. 以原实现作为不满足准入条件时的回退；原路径在目标上不可用时，先提供已验证的兼容路径，不能把回退指向无法运行的源实现。

## 3. 接入注册、分发与构建

| 环节 | 核查内容 |
|---|---|
| 模板注册 | 使用该工程实际的注册机制；核对选择顺序、优先级及失败后是否继续尝试合法模板 |
| 准入 | host 侧 `IsCapable()` 或等效机制限制架构和输入条件，不满足时进入回退 |
| tiling key | host 编码、kernel 解码/模板实例化保持一致，避免覆盖已有 key 或传错数据布局 |
| kernel 入口 | include、架构守卫及运行分支能到达新实现；共享入口仍能选择原有实现 |
| 构建打包 | 源列表、compute unit、binary 配置和 tiling 链接包含新增文件与实例化 |
| 加载 | 按 Stage 3/4 证明实际包与自定义实现命中；仅源码存在或注册成功不算完成 |

平台注册与算子内部模板接入分别验证。注册宏、类名和 key 值从实际工程读取。

## 4. DMA 模板的具体检查

Gather/Scatter DMA 的 API 与同步细则见 [vector-and-dma-guide.md](vector-and-dma-guide.md)。新增 DMA 模板必须同时完成：

- **搬运语义**：元素索引到字节偏移的转换、负索引/非法索引处理、padding、覆盖/累加和重复索引语义。
- **资源与同步**：offset/mask 等新增 buffer、双缓冲与尾块全部计入预算；证明生产和消费的可见性，不能只替换 CopyIn/CopyOut 调用。
- **准入与回退**：分别验证能进入 DMA 的 dtype/shape，以及对齐、参数或资源条件不满足时的合法回退。非法输入仍按原契约处理。
- **运行证据**：验证 DMA 分支和回退分支实际命中；共享文件涉及 3510 时同时检查源路径，缺少源设备则如实记录未执行范围。

可按符号检索 `IndexPutV2` 的配套接入方式：host 的 `IndexPutV2SimdDmaTiling`、`IsCapable()`、`DoUBTiling()`、`GetTilingKey()` 与模板注册，kernel 的 `IndexPutV2SimdDma` 与 `ScatterDataCopy` 调用。以实际工程为准核对这些环节；案例不构成通用 DMA 脚手架，也不能替代目标 SDK 的支持与约束核验。

## 5. 验收与交付

1. Stage 3 编译并安装包含新模板的实际包。
2. Stage 4 全量精度回归，补充新分支/回退分支、准入边界、尾块、索引冲突及资源/位宽用例。
3. Stage 5 所选目标（DAV_9201 或 DAV_9202）的同一设备、同输入和同采集口径下，对兼容基线与新实现做 A/B；验证对应分支命中，保留原始数据和测量波动。
4. 按 Stage 6 判据保留或完整回退。回退覆盖新增文件、模板注册、优先级、key、宏、构建、tiling 和安装产物，并复验恢复后的基线。

`feature_trials.md` 保留候选、实现方式、真实改动文件、准入/分发关系、资源计算、验证结果和最终状态。只完成 API 调研、创建空文件或输出模板代码不能记作实现完成。

## 核查入口

先按 [证据来源规则](platform-and-api-diff.md#6-核查入口与证据记录) 核对目标 SDK 的 Gather/Scatter DMA、资源查询和同步接口，再按需检索实际工程或兼容案例：

- IndexPutV2 host：`index_put_v2_simd_dma_tiling.cpp` 中的准入、UB 划分、key 与模板注册。
- IndexPutV2 kernel：`index_put_v2_simd_dma.h` 中的复用关系与 ScatterDataCopy 实现。
- EmbeddingBag：`embedding_bag_gather_dma.h` 中的偏移生成、同步及 GatherDataCopy。
