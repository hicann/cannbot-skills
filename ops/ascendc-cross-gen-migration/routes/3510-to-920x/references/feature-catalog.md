# DAV_3510 → DAV_9201 / DAV_9202：按算子选择能力

**使用时机**：Stage 1 生成能力适用矩阵与实现方案；Stage 2 实施必需兼容；Stage 6 实施适用的新特性并做 A/B。

本清单提供待核验的能力候选，是否适用以目标 CANN SDK、配套官方文档、平台接口及实际工程为依据，不要求每个迁移算子启用全部能力。保留原算子的接口、数值、索引和确定性契约；扩展 dtype/接口必须有用户需求。

证据目录 `${EVIDENCE_DIR}` 由 Stage 0 为本次迁移单独建立，所有本页产物均写入该目录。

## 1. 适用性与实施结果分开记录

| 适用状态 | 判据 |
|---|---|
| `APPLICABLE` | 算子代码模式、dtype、shape、实际 API 支持和所需前置条件均有依据 |
| `NOT_APPLICABLE` | 缺少对应计算/访存模式，或与明确契约不兼容；给出具体代码/条件 |
| `NEEDS_EVIDENCE` | 工具链支持、参数语义、资源或适用条件尚未查清；记录待查项 |

适用状态不能由算子名称单独决定。一个算子不同 dtype/shape 可以有不同状态。

同时交付 9201/9202 时，每个候选按 `SOC / TARGET_ARCH` 分别记录适用性和实现状态；已验证的 9201 模板不能直接标作 9202 已复用。目标差异速查见 [platform-and-api-diff.md](platform-and-api-diff.md#92019202-按能力核对)。

实施结果使用以下状态：

| 实施状态 | 含义 |
|---|---|
| `REUSED` | 原代码或目标 SDK 已有该实现，无新增改动；核对可达性与实际命中 |
| `PLANNED` | 已选择，尚未开始尝试 |
| `DEFERRED` | 因既定任务范围、已有预算或必要依赖未满足而暂缓，写明依据与后续条件；任务范围内暂缓表示阶段未完成 |
| `KEPT` | 编译、全量精度及性能目标验收通过，保留改动 |
| `ROLLED_BACK` | 实际改动后完整撤回，留失败/收益不足证据和回退验证 |
| `FAILED` | 尝试未通过或回退验证未完成，流程保持未完成状态 |

未尝试不能写 `ROLLED_BACK`；勾选、源码存在或自我声明不能写 `KEPT`。所有 `APPLICABLE` 项均须按 [feature-implementation-guide.md](feature-implementation-guide.md) 明确复用、改造或新增实现；任务范围内未被已有实现覆盖的项必须实际尝试，不能仅完成评估就结束。

## 2. 候选索引

| ID | 能力 | 触发信号与必要条件 | 主要验证/回退 |
|---|---|---|---|
| V1 | MERGING API 实现优化 | 有保留原目标 lane 的掩码计算；核实 SDK 已有实现及 dtype | 掩码/别名/尾部；回到原组合，已由 SDK 实现则记 REUSED |
| V2 | FusedMulSubDst 等目标 API | 存在等价计算模式；当前 API 限定 dtype/掩码满足 | 舍入、抵消、特殊值；回到原计算链 |
| D1 | Gather DMA | 间接 GM 读取且 shape/偏移/stride 合法 | 索引、padding、同步、额外 UB；保留旧搬入路径 |
| D2 | Scatter DMA | 间接写回且覆盖/累加/冲突语义可保持 | 重复索引、确定性、参数边界；保留旧输出路径 |
| D3 | 128 位搬运载体 | 连续块可整除合并，地址和尾部满足对齐 | 原始 dtype、字节偏移、tiling key；回到原搬运粒度 |
| Q1 | HiF4/混合低精度组合 | 原契约或用户需求确实涉及对应模式，完整 API 链支持 | packing、scale、累加、格式；回到原量化/计算实现 |
| Q2 | MX scale 转换 | 命中目标 dtype 与量化算法，原生 Cast 路径可用 | OCP 舍入、zero/NaN/Inf；回到位操作路径 |
| C1 | Cube/MIX 数据路径调整 | 原实现依赖子块路由、Fixpipe 或 epilogue 布局 | 协作、同步、输出布局；正确性适配不可作为可选项跳过 |
| T1 | StreamK/Blaze/负载均衡 | 矩阵计算、模式准入、运行时依赖与资源均满足 | 各 shape 的收益、UB/workspace；回到基线模板 |
| S1 | SIMT 映射调优 | 原线程/合并因子/访存已形成可测瓶颈 | 边界、资源、device 时间；回到原映射 |

API 核查方法与案例检索入口在各专题页维护，使用前读取对应叶子文件：

- V1/V2/D1/D2/D3/S1 → [vector-and-dma-guide.md](vector-and-dma-guide.md)。
- Q1/Q2 → [quantization-guide.md](quantization-guide.md)。
- C1/T1 → [cube-migration-guide.md](cube-migration-guide.md)。
- 所有改变 tile、索引或 buffer 的项 → [tiling-and-memory-guide.md](tiling-and-memory-guide.md)。
- 注册与 API 支持核查 → [platform-and-api-diff.md](platform-and-api-diff.md)。

## 3. Stage 1 的能力矩阵

在 `${EVIDENCE_DIR}/migration_plan.md` 每项记录以下字段；未命中的能力可合并给出代码依据：

| 字段 | 内容 |
|---|---|
| ID 与代码位置 | 对应候选、函数、kernel/host 分支 |
| 适用范围 | dtype、layout、shape、属性与排除条件 |
| 差异类型 | 可复用 / 必须兼容 / 目标新特性 / 待查证 |
| 实现方式 | 复用已有 / 改造原路径 / 新增专用模板；列出 kernel、host tiling、注册分发和构建改动 |
| 证据 | 目标 SDK/官方文档版本与小节、实际声明和分发、平台查询结果；案例另记实际来源与适用范围 |
| 状态与原因 | 适用状态、实施状态、实施顺序；暂缓时列明依据及是否仍属未完成必做项 |
| 验证 | 精度与路径覆盖用例、性能 case、基线与回退方式 |

例如普通 FP16 elementwise 没有间接访存和量化接口时，D1/D2/Q1 可按代码证据记不适用；不要求为了完成清单给算子增加新接口。

## 4. Stage 6 的尝试与交付

在 `${EVIDENCE_DIR}/feature_trials.md` 为适用项记录：实际 SDK/设备、实现方式、基线版本、改动版本、读取的真源、开始/结束、变体、完整验证结果和最终状态。复用已有时完成可达性及实际命中验证；新增实现按实现指南完成 kernel/tiling/注册/分发/构建全链。

1. 从 Stage 5 的已测瓶颈出发确定目标，设定与本轮任务相称的时间/构建预算，记录收益判据。
2. 一次改变一个可归因项；配套 tiling、buffer、宏和分发更改一并计入净收益。
3. 精度使用全量既定电池，并补新分支用例；不得删失败用例或放宽门限以保留能力。
4. 在所选目标（DAV_9201 或 DAV_9202）的同一设备、相同 case 和采集口径下做 profiler A/B，保留原始数据及噪声情况。
5. 达到约定目标才记 `KEPT`；失败或收益不足时完整回退代码、宏、构建选项、tiling 字段，并复验基线。
6. 收尾列出所有候选的状态。`NEEDS_EVIDENCE`、`DEFERRED` 要如实交代，不能改成“不适用”消除未完成项；任务范围内适用项尚未尝试或必要证据缺失时，Stage 6 保持 `NOT_VERIFIED BLOCKED`。

没有设定收益目标或性能数据不可信时，不声称优化成功；先保留基线并说明证据缺口。

## 5. 验收边界

- 注册、ABI/API 合法性、数值/索引正确性、资源和位宽安全是必须满足的迁移条件。
- 新 API、DMA、量化与调度候选按上述矩阵逐算子判定；“目标支持”不等于“本算子适用”。任务范围内适用的新特性实施是必做步骤，包括需要新增目标专用模板的情形；保留结果由真实验收决定。
- 源码依据与真机结果分别记录；本清单的存在不代表候选已经真机验证。
- 9201/9202 均在本路线范围；共同门控的案例逐目标验证，仅 9201 准入的案例不能直接扩大到 9202。未查明的 9202 API 支持继续取证；通过合法兼容路径完成迁移与某个新特性是否适用分别判断。
