# 少走弯路的实验决策

用于新算子接入、批量候选实施前，以及优化方向反复失败或收益趋小时。按当前症状选一项能改变下一步决策的小实验；已有有效证据直接复用，不把本页当作每轮必须全部执行的清单。完整身份、正确性和计时规则沿用[联合流程](workflow.md)。

候选的搜索资格、测前预测与 VF 成本资格统一见
[候选与测前预测](workflow.md#候选与测前预测)。下述实验只解决接入、实现或成本疑点，
不能被记为实际方案搜索；是否需要搜索由 agent 按问题选择。

## 实现前选择最小判别实验

先写清三个问题：预期缩短哪段完整关键路径，新增哪些不可省的工作，什么观测会否定该收益机制。优先处理“即使性能预测成立也无法采用”的假设，如编译资源、实际布局、交接协议和数值范围。

| 当前未知项 | 较便宜的判别方式 | 据此决定 |
|---|---|---|
| 算法变化能否满足原数值标准 | 独立算术参考或小规模实现，覆盖受改动影响的幅值、累加深度、抵消或递推长度 | 不成立则先改数值方案，不批量实现性能变体；小算术试验通过仍不替代最终设备精度 |
| 新布局／复用／流水能否实现 | 保留目标资源占用、布局和生产消费协议的最小可编译骨架，再验证完成性 | 编译及同步机制成立后再补全复杂计算；不能用简化掉争用的小例子证明原方案可行 |
| 收益是否依赖多个执行单元重叠 | 先验证保留真实资源占用、生产消费、槽位释放、前导与排空的最小执行链；需要验证版本次序时，各 tile 使用不同数据 | 孤立服务较快不证明组合吞吐；链路没有收益空间时先解释依赖或争用，不批量扩展完整实现 |
| 稀疏／条件执行比例能否转化为设备收益 | 先按实际调度展开候选、分片、共享计算并集、对齐及回退，核算指令和搬运量，记录要求见[联合流程](workflow.md#模型数量结构与能力) | 理想比例与实际工作量差异足以改变选择时，先修预算再决定是否实现 |
| 理论排名被一个未知成本左右 | 只测该形状／路由／VF 块，或做保持其他条件的完整 kernel 消融 | 结果足以改变选择才校准该项，不先建完整硬件成本库 |
| 局部节省是否值得投入 | 计算乐观关键路径上界，列出新增转换、打包、初始化、存储和同步成本 | 上界已不足以达到本轮有意义的增益时暂缓该具体实现；上界很宽则继续小规模验证 |

固定其余工作和依赖，将可删服务理想化为零，可以估算该固定结构的最大潜在节省；这仅是反事实上界，不是合法候选，也不能推广到会改变依赖或分核的新算法。管线 busy 彼此重叠，不能直接把被删指令的累计服务量当成端到端收益。

涉及未知 VF 时先选择适用成本来源；缺实测可按[VF 成本约定](../framework/vf-costs.md)
估算并继续初步搜索，保留假设与未校准状态。不确定性影响关键选择时再优先做最小
判别测量，无设备时保留候选和排序限制。预测结果保留其条件与缺口。其他遗漏成本写成有依据的范围。如果乐观收益已被必须新增的工作抵消，停止为这个具体结构展开相邻参数；如果未知范围足以反转选择，先做区分该未知项的实验。采用阈值由项目目标、成本和测量波动确定，不沿用其他算子的固定百分比。

最小执行链用于检验未知的重叠收益，不要求简单局部改动重建微核。已有同几何、同资源与交接条件的有效证据可直接复用；链路测量仍须列出未覆盖的供数、选择或精算，不能直接当作完整算子预测。

## 按症状减少重复试错

| 多走的弯路／触发信号 | 更快的下一步 | 停止或恢复条件 |
|---|---|---|
| 配置报错后直接认定框架缺功能，硬编码维度或换入口 | 查当前发行说明、模型 schema、加载错误与支持示例，用最小输入区分表达式写法、变量域、算子映射、搜索资格和执行后端 | 最小加载确认写法即可继续；确有能力缺口时明确近似范围，不反复改名或删校验 |
| 用粗算法图排名大量生产实现，随后靠成本系数弥补差异 | 先核对真实指令、搬运、驻留和依赖；特别检查不存在的中间落盘、重复加载和已删除但仍约束顺序的零成本节点 | 修正实际工作量后再比较旧排名；粗代理可用于探索，但不与生产指令周期混排 |
| 字节容量满足后才发现编译资源不足或物理切片不合法 | 提前编译包含关键 buffer 身份、对齐、切片、布局和交接的骨架；确认逻辑轴对应实际物理轴 | 失败仅约束该编译版本和具体映射；不据此否定整个算法族，也不继续堆叠依赖同一失败机制的变体 |
| 同步等待时反复拆缓冲、加屏障或换完整 shape | 定位首次未完成的生产消费关系，检查生成代码的等待、发布、最后读取和凭证归还，见下节 | 下一次运行必须能检验新的根因假设；未改变假设的原样重试没有新信息 |
| 降精度或重排累加后，做完大量计时才发现范围失败 | 将由改动引入的溢出、下溢、抵消或长依赖链检查前移；有状态时同时查状态及跨调用行为 | 失败版本只做标注清楚的诊断，不进入有效性能排名；补偿或分发形成新的完整入口契约 |
| 少了高成本运算或服务时间下降，就连续扩展同类优化 | 检查新增指令、转换、打包、寄存器存活和结果到达顺序；先做一个可区分服务与重叠影响的对照 | 完整耗时没有收益时，先解释反例；不能仅因运算条数减少继续批量生成同机制变体 |
| 源码顺序或参数不同，就把每个变体都重新完整计时 | 比较实际指令、编译产物和调用条件；无关元数据可使二进制哈希不同，需核对有效差异 | 核心指令及运行条件等价时合并性能候选，保留源码映射；不同地址、启动或缓存条件仍可能需要独立验证 |
| 用完整 kernel 的计数器差额统一降低某个执行单元吞吐 | 数量一致后，分离驻留纯计算、单缓冲供数和重叠供数，或使用适合目标后端的同类对照 | 只有可辨识的服务项进入成本库；不能把数据等待、控制及纯服务重复计费 |
| 边界补偿／预处理正确后只报告快路径性能 | 先确定真实调用入口；正常输入也测检测、同步、分配和调度成本，补偿路径单列 | 完整入口不支持原计时方式时另立口径，不把主机墙钟与设备图时间相加或混算利用率 |

## 等待问题的定位顺序

模型执行完成、函数异步返回和设备同步完成是不同证据。出现等待时，按下面的定位顺序缩小问题，不要求所有后端使用同一种事件机制：

1. **先区分环境失败与算子失败。** 检查错误发生于设备初始化、编译、首次调用还是同步；必要时复用已知可运行控制。初始化失败不能归为候选死锁，也不值得通过改算法重试。
2. **保留失败条件做有界复现。** 选择能保留相关资源占用及跨迭代交接的最小 case，设定适合该环境的超时。单任务通过但流水失败时保留相邻任务及收尾排空；不要因缩小输入消除了协议而宣称修好。
3. **定位首个无法推进的交接。** 按生成代码或事件 trace 记录生产者、槽位／版本、发布、各次读取、最后读取和释放；检查软件游标与实际物理复用是否一致。一次值被多次读取时，特别检查中间发布是否让编译器提前结束当前消费生命周期。
4. **用诊断手段区分假设。** 阶段标记或屏障可以缩小范围，但会改变调度。加入屏障后能完成，仅说明问题受时序影响；不能直接认定缓冲别名是根因，或把有屏障的耗时当最终结果。
5. **修复后恢复真实路径验收。** 去掉仅用于诊断的干预，再验证完成性、输出、状态／副作用及重复调用。保留失败与修复后的生成代码差异；无新定位证据时不扩大长序列或批量变体。

## 让校准和测量更快提供有效信息

- **优先解释差分。** 对同轮、其他条件相近的父子候选，先比较工作量、服务与完整耗时变化，再决定缺哪个成本项。差分也可能包含调度或编译影响，不能自动当作纯指令成本。
- **按竞争解释选择微核。** 大形状驻留接近理论值、小形状或重搬运不同，应检验指令粒度、供数和重叠；不统一套吞吐系数。缺少独立流量或时钟证据时保持该校准未定，不把名义周期写成实际周期。
- **减少无区分力的采样。** 测量时避免同时运行本任务的其他 profiling；出现竞争或噪声时保留原样本及资格说明，不只挑最快样本。采用交错配对时使用逐轮比较，两个中位数之比不能替代配对统计。
- **尽早检查完整收益。** 本轮必要正确性通过后，先用小规模同口径完整对照判断局部收益是否兑现，再决定是否扩展相邻变体、增加采样和补全面回归。采用前仍须完成原契约及仓库要求的检查；收益不稳定时先区分噪声、输入相关回退与流水影响，同机制反例未解释前不继续批量扩参数。
- **核对能力与模型配置。** 先确认当前版本支持的事件／数值机制，再检查模型是否完成绑定、输入是否处于适用域。缺少配置时补充模型声明；超出支持范围时记录最小复现和可行替代方案。

以上步骤只解决影响当前决策的疑点，不要求先达到全算子、全硬件的模型准确性；证据类型按[记录与交付](workflow.md#记录与交付)区分。

## 停止一个分支并保留可复用结论

每个高成本实验在运行前写下会如何影响下一步；若无论得到什么结果都仍要执行同一批候选，应重新选择更有判别力的实验。

满足以下情况时，优先结束该分支：乐观收益不足；同一失败没有新的解释；不同源码已生成等价实现；同机制反例没有被解决；收益低于当前可分辨范围且缺乏新证据。停止的是具体方案／适用域，不是断言整个算法族无解。

沿用现有候选记录保存：失败层次、适用条件、最小反例、未解释项，以及重新打开需要的新证据。示例条件可以是“新布局消除已确认的搬运”“独立微核证明缺失成本更低”或“修复最后消费者协议”；单纯换候选名不是新证据。

用户仍授权继续优化时，从语义、当前最佳与已验证瓶颈提出机制有区别的方案，按需要选择模型搜索、
直接实现或降低不确定性的实验。用户已停止优化或仅要求复盘时，保存这些建议即可；
不因未解释误差而重新开启实验。

## 复用边界

复用部署经验时，保留最小成功／失败示例、后端版本、具体几何和交接协议；检查当前
安装版本的支持情况，不维护脱离适用条件的“不支持清单”，也不新增重复台账。
其他算子复用的是“触发信号 → 最小判别 → 下一步／停止条件”，不继承案例的 shape、
dtype、容差、核数、MFU 目标、实验轮数或误差阈值。这些检查按症状触发，不增加用户审批步骤。
