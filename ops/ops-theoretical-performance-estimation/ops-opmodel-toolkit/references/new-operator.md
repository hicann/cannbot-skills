# 新算子建模

编写时按需读[拓扑与固定定义](new-operator/authoring.md)、[并发与生命周期](new-operator/concurrency.md)、
[非均匀工作量](new-operator/advanced.md)及[Python Stage](new-operator/python-stages.md)。
完整字段、调用与使用限制见[框架参考](framework/index.md)。

用于从公式、实现或已有模型建立用户算子，或添加 stage/模板变体。产物为用户项目中的
可编辑模型、完整 case、规格与验证记录。先读[建模指南](modeling.md)和[字段参考](model-reference.md)。

## 规划与交付要点

用户只问需要哪些定义、如何验证时，说明同一个模型的六份固定定义与完整 case 的
职责、实际任务投影和适用边界检查，不把六份定义误作六个候选，也不重复索取用户已提供的规格。
三份文档需说明内容：`SEMANTICS.md` 覆盖完整输出、可变状态、适用模式和用户 VF
计算步骤；`SPEC.md` 固定任务、资源、硬件和成本；运行 `README.md` 给出命令、产物与验证状态。
仅规划时给出填写及核对方法，不虚构尚未提供的公式或声称文档已经生成。

验证计划分别列数学独立参考、实现精度参考、执行数值回放和设备验收；本轮仅建模时
设备验收标为未执行。新模型默认普通带宽；缺 VF 实测时先按步骤、每次调用工作量、
dtype 和分块形成有依据的估算，注明来源、适用域、不确定性与未校准状态。
确实无法形成可执行成本时保留缺口，不把未知项填零或以补测作为继续建模的前置条件。

## 从语义形成模型

从用户资料填写[语义契约](../assets/templates/semantics.md)与[规格模板](../assets/templates/model-spec.md)，确认完整输入、输出、
dtype/layout、尾块、状态、副作用与原数值标准。有实现时区分数学约束与当前实现选择；
无实现时以公式和独立参考作为语义依据，首个可运行模型只作为模型基线。

按以下关系推导拓扑，保留每项的来源：

| 问题 | 模型中要明确的内容 |
| --- | --- |
| 什么工作可以独立分配 | 任务域、原子与顺序约束、可拆维度、输出归属 |
| 什么工作依赖上一块/组 | 状态版本、跨 task 依赖、初始化与最终写回 |
| 数据在哪里驻留 | GM/L1/L0/UB 路径、读写区域、实际加载次数 |
| 哪些计算能重叠 | 阶段划分、发射关系、数据依赖与共享资源 |
| buffer 何时可复用 | pool、slots、全部消费者、最后读取与释放边界 |
| 每条操作如何计费 | 元素数量、dtype、单位、成本来源与适用域 |

不把已有实现的 tile/phase 当作数学约束。模型无法表达某种布局、同步或控制流时，
记录缺口与可表达的范围；不要借零成本或缺失依赖让模型接受方案。

优化目标由用户定义，记录公式、约束、排序及使用的 provider／配置／依赖与修订；
按[搜索接入](agent-dag-opt/search-integration.md)交接有效评价，不默认目标总是耗时最小。
数据相关控制按[场景与有界控制](framework/runtime-control.md)区分参数分派、冻结输入
和中间值控制；动态方案核对分支、循环、输出／状态、路径和资源归还，未覆盖项写入
规格。静态模型不增加无关动态验收。

## 在用户目录建立固定定义

复制最接近的可运行模型：简单入门使用[矩阵乘示例](../assets/examples/matmul/README.md)，
其他模型可用 `opmodel-assets export` 导出后检查，并按目标算子调整语义、任务和执行定义。

```text
my_operator/
  __init__.py
  case.yaml
  definition/
    semantic.yaml
    workload.yaml
    split.yaml
    operator.yaml
    dag.yaml
    costs.yaml
  optimize/
    search.yaml
    split.yaml
    dag.yaml
  SEMANTICS.md
  SPEC.md
  README.md
```

六份定义的职责与字段见[建模指南](modeling.md)。优先使用声明式 workload/split；
必要时才写 `workload.py`、`split_hooks.py`、`ms_hooks.py`，接口见该指南。
普通模型通过随附 `scripts/run_case.py` 调用 `run_native_case`，输入完整 case 并指定
独立输出目录，保存有效参数和执行结果。

`SEMANTICS.md` 写完整函数、所有输出/状态、适用模式、数值边界和用户 VF 计算步骤；
`SPEC.md` 写当前实现、任务分配、硬件与成本；`README.md` 保存可复现命令。
它们是交付约定，不是模型加载器的新字段。共享语义可链接复用，但须注明本候选覆盖与差异。
硬件与逐路由支持按[硬件选择](hardware.md#选择评估配置)记录，配置存在不等于全部行为已校准。

表达式使用当前 schema 的 `expr` 等声明，不能直接放任意 Python 字符串。
任务分配与逐核投影使用实际分配子集，不能对每个核重复生成完整工作量。

## 验证固定 case

按[快速入门](quickstart.md)的完整 case 入口运行新模型，按[仿真说明](simulation.md)
选择普通/物理路径。先保留有效参数、任务分配、结果与 trace，再核对：

- 独立推导的任务数、输出覆盖、计算量和搬运量，与实际模型产物一致。
- 适用的默认点、尾块、相邻 task、多组与核未铺满场景；改变输入后重新派生，
  不强改 `num_groups/num_tasks` 等派生值来制造测试场景。
- 所有真实消费者读取完成后才复用 buffer；逻辑 pool 名不能增加物理容量。
  不能把减少 `use_pools` 当作消除等待的优化。
- 低精度、转换、padding、归约及最终输出次数符合原语义；多 AIV 分摊不重复缩放。
- 动态数值检查采用模型支持的接口和独立输入；没有执行的项目明确为未验证。

可按[数据流图](dag-dataflow-graph.md)核对声明连接，这不代替容量、生命周期、
数值和完整执行验证。模型完成执行或两个后端周期一致也不能证明原数学语义正确。

验收请求、派生任务计划与实际逐组执行覆盖分别核对，不以配置中的 group 数
代替活动 group 数。合法变长计划保留每组任务数，空组不计为已覆盖的活动组；
控制事件不补足执行任务，合法跳过也不称为普通执行。组间指令数差异可作诊断，
不能单凭不均衡判失败；合法分支、初始化与变长任务允许不同计数。

trace 核对真实指令及已声明依赖的就绪边界，保留同一最早时间戳的全部执行事件；
不按 stage 名、load 关键词或导出排列顺序判合法性。独立输入和允许重叠的事件可以
先发生，不为通过检查添加无来源的串行依赖。空 trace、缺失归因或无法解释的区间
保留失败与证据；轨迹一致不证明全部算法依赖已声明，也不替代数值和完整物理验收。

## 接入搜索与交付

请求包含寻优或完整搜索接入时，按[统一搜索接入](agent-dag-opt/search-integration.md)补充合法参数域和
实验配置，实际运行内置搜索。固定定义先独立可运行，固定 case 不依赖搜索输出。

检查候选参数确实改变工作量、几何、阶段或资源；固定值与不可搜索维度分别说明。
对基线、候选和有辨别力的边界点复核数量、容量和完整 case。搜索同分可能是瓶颈
未改变，也可能是参数未生效，应结合有效参数与 trace 区分。

用户只要求建模时交付模型和适用检查，不强制启动设备实验或所有优化流程。
保存 `SEMANTICS.md`、`SPEC.md`、运行 `README.md`、有效 case、结果位置及支持范围。
数学独立参考、用户实现的精度参考、执行数值回放和设备验收分别报告；图签名或
已声明操作的覆盖不证明完整接口均已建模。候选导出后核对三份文档和共享链接仍齐全。
若还需真实实现，
转到[联合寻优](joint-optimization/guide.md)。

成本与硬件按[VF 成本约定](framework/vf-costs.md)和[硬件选择](hardware.md)准备：
新模型默认普通带宽；无 VF 实测时可先估算并继续已请求的搜索。记录依据、单位、
调用工作量、假设与未校准状态，获得匹配实测后更新对应实现成本并重评。
