# 设计文档生成

解释模型输入、调用和结果时按需查[框架参考](framework/index.md)；性能表的范围与资格见
[评估报告格式](perf-eval/output-format.md)。

用于将实际候选、仿真或搜索结果整理为面向开发交接的 `DESIGN.md`，不限定实现语言。
先识别入口、选定候选和 case，再按[设计模板](../assets/templates/design.md)组织内容。
伪代码描述用户算子的计算、切分、存储和同步要求；已有目标实现时才按依据映射具体 API。
只请求文档时使用已有资料，缺失证据保留为缺口，不自动启动搜索、校准或设备实验。

## 说明如何生成文档

用户只请求生成方法时，按下表给出填写和核对方法，无需实际生成文件或追加实验。
“六份定义”是同一模型的 `semantic/workload/split/operator/dag/costs.yaml`，
不表示六个候选；只有实际提供多个候选快照时才逐候选核对。

| 内容 | 说明中应覆盖的交接要求 |
| --- | --- |
| 语义与执行算法 | 用语言无关模板引用完整输出、状态、模式和用户 VF 步骤；Cube 说明 A/B 切片、dtype/layout、L0C 初始化、K 累加及 FIX 搬出范围和条件，无 Cube 则注明不适用。算法贯通输入到写回，边界展开实际工作项、全部消费者和释放条件。 |
| 承诺与自由度 | 区分固定承诺、有能力依据的受约束选择、真正设计／能力缺口，给出可实现范围；具体地址或事件编号尚未选定不自动阻断交接。 |
| Buffer 与复用 | 区分逻辑 pool 与物理区域、空间复用与数据复用、固定预留与运行峰值；按 owner 核对容量、全部消费者完成及安全覆盖条件，不能用低峰值证明固定预留可行。 |
| 平台与布局 | 记录目标平台／SDK 版本、资料修订，联合核对生产和全部消费端的地址、格式、对齐及生命周期；未知组合另列最小补证计划，不能把计划写成已验证。 |
| 搜索与性能 | 核对候选快照、有效参数和结果身份；列目标修订、原评价／复用依据及完整并列组。周期和统计注明 owner、scope、单位及比值分母，局部评分、完整 case 和设备收益分别报告。 |
| 成本与验证 | 有依据的未实测估算可以支持探索和交接，保留实际采用的成本版本、实现／适用域绑定和不确定性；文档新增估算不回填成过去搜索已采用的成本。数值、结构、性能分别验收，不互相替代；设备未测标为未执行，不自动否定设计完整性。 |
| 动态范围与复现 | 涉及动态控制时限定真实场景、实际路径和覆盖，记录输出／状态及资源归还；列实际复现命令、产物和执行状态，提供命令不等于执行成功。 |

下文给出这些要求的详细证据和填写规则；说明中的关键条件应直接写出，不能仅用章节标题代替。

## 交接目标与决策边界

面向未参与会话的开发者，交付目录及可访问依赖应能说明计算内容、任务归属、
数据位置、读写条件与验收方法。以选定候选为依据，不能为补齐文档暗中换用另一套方案。

| 决策类别 | 文档应给出的内容 | 实现阶段的责任 |
| --- | --- | --- |
| 固定承诺 | 语义、算法、精度、任务映射、通路、复用与同步的适用域、来源和验收引用 | 保留承诺并提供验收证据 |
| 受约束选择 | 允许范围、不变量、能力依据、落实时点、核对方法及失败返回点 | 在范围内自主选择并记录具体映射 |
| 真正待补项 | 缺少的决策或能力依据、受影响步骤及可独立推进范围 | 先补决策或证据，再依赖其结论 |

关系公式与单 case 取值分开。函数／类拆分、代码组织、满足契约的 API 和事件编号
由实现者选择；未选具体地址或原语不自动构成阻断，关键能力无依据仍是缺口。
数值通过不能将已承诺的数据通路、驻留或流水重叠降为可选优化。

先查需求、调用方／评测入口、用户语义与参考实现，再判断信息是否缺失：

- 接口区分数学定义域、模型支持域与目标实现的输入输出、stride、别名、所有权和
  完成语义；已有契约必须继承。无集成约束时可在授权范围内提出最小调用约定，
  标明新增设计与适用域；没有框架 ABI 不自动阻止独立 Kernel 开发。
- 布局固定逻辑切片、owner、槽与生命周期、预算和尾部有效域；格式、对齐和偏移
  可以约束后授权选择，须有可行能力依据及实施时的地址证明要求。
- 跨核协议明确写域或允许的分区、发布／消费／回收、参与集合及空参与者行为。
  每个允许选项都应闭合通知与完成条件；逻辑自洽不证明设备支持该组合。
- 数值规则来自实际参考和需求，分别记录模型参考、设备要求与验证范围。容差验收
  不自动要求相同归约树；特殊值或溢出策略未定时保留缺口，不由比较器推断合法输入。

按模板给出可开始实现、部分可实现或待补充设计及具体范围，分别报告验证状态。
待补设计、首次依赖前的可行性补证、实现后验收分开；尚无设备实测不自动阻止交接。
新的接口约定或物理映射不自动继承原候选的评分和设备资格。

## 平台约束与补证

仅核对当前用户方案实际依赖的机制；通用 API 资料引用对应平台的公开文档，
不在此维护芯片规则副本。记录目标芯片／架构、后端／SDK、资料修订与证据范围；
未选后端时限定条件，不默认套用最新资料。资料支持、组合未验证、不支持和资料
冲突分别记录；冲突保留双方依据，签名、示例、编译与设备结果不相互替代。

1. 分开逻辑尺寸、分配尺寸和指令访问范围，推导 pitch、padding、对齐与容量，
   明确填充责任、仅接收区域和有效输出。沿真实通路核对 dtype、格式、存储、转换、
   拆分、核配比和完成语义，单项可用不证明组合可用。
2. 联合核对同一值的生产、更新及全部消费端，覆盖各槽与子视图的实际地址。
   同址满足所有适用约束，异址分别检查；槽间距对齐不证明基址合法，消费子视图
   不自动继承它未作为生产起点时的要求。访问范围、容量与生命周期须同时成立。
3. 展开边界值触发的默认模式、实际指令参数及布局变化，列每个允许分支的输入准备、
   计算和后续消费条件。分配补齐不证明指令模式改变；新增计算或搬运另核成本。
4. 分别列有效输出者、物理接收者和同步参与者；空输出不自动取消接收空间或通知。
   选项应符合目标机制的参与集合、计数／代次和等待范围，不固定事件编号或额外加屏障。
5. 按已有数值契约展开相关的 NaN/Inf、溢出、subnormal、正负零与舍入边界，
   记录精度／饱和状态和生效范围。语义未定与设备待验分开，不能根据设备结果
   反向选择验收标准或用通用指南替换已有要求。

已知限制在生成时落实；未知组合在模板中给出最小输入、预期、通过条件、依赖、
首次使用位置及失败返回点。同版本且能力条件匹配的证据可复用，条件变化仅补受影响
部分。补证计划不表示已执行，也不扩大本次文档任务为编译或设备实验。

## 读取已有产物

| 资料 | 提取内容 |
| --- | --- |
| SEMANTICS.md、SPEC.md、README.md | 完整接口契约、实现规格、覆盖缺口与复现入口 |
| 候选快照、固定定义、case、有效 params 与用户 Python 文件 | 数学语义、shape、dtype、阶段、tile、成本及实际构图声明 |
| assignment 与 result | 真实任务分配、scope、总体周期、检查状态、产物路径 |
| ranked.yaml / RANKED.txt / search.json | 候选排名、有效参数、淘汰及覆盖；按实际入口选择 |
| operator、buffers、storage 与公开存储记录 | 逻辑使用者、owner、共享/别名、slots、物理字节及生命周期 |
| trace 与统计 | 计算/搬运、忙碌/等待、完整时间范围 |
| 已有设备记录 | 实现版本、数值结果、计时边界与实测收益 |

文件名按本次实际导出清单核对，不要求每个入口同时提供上述产物。某个文件缺失时
先核对入口，不能认定仿真失败。入口、字段与命令以已安装 wheel 的公开接口为准。

优先使用本次候选快照和有效参数，记录命令覆盖、workload 派生和实际硬件配置，
不能用源模型默认值替代已评价配置。核对候选、case、硬件、成本、执行与验证记录
的签名或其他可用身份依据；冲突单列，缺失时标明无法确认，不拼接不同运行的证据。
排名片段不能代替完整候选；仅有仿真或固定配置评估时，排名与最优性注明不适用。

有搜索或重评分时，按[目标与复用](framework/objectives.md)记录 provider、配置、依赖、
修订和原始评价来源／复用依据。目标结果与并列组、原始周期及资格分开；业务通过
不表示完整验收，不能为新目标改写旧评价或候选签名。

涉及[场景与控制](framework/runtime-control.md)时，补实际输入与路径、分支／循环、
输出／状态及资源归还证据；区域重构注明冻结边界及不支持组合。只取得单路径时
明确范围；缺失项保留缺口，不为填表启动实验。

交接时记录实际搬运模型，默认普通带宽、细化按需显式选择。将可调整的软件 buffer、
阶段和发射选择与固定硬件容量分开，当前排队或低效实现成本不写成硬件必然限制。
逐 VF 按[VF 成本接口](framework/vf-costs.md)记录实现、硬件、工作量与计费边界。
缺实测不阻断探索或设计交接；保留“Agent 未实测估算”的值／公式、单位、步骤与
工作量依据、分块、不确定性及探索性排序限制，说明匹配实测后的成本替换与重评。
仅在文档阶段新增的估算，不能写成先前搜索已经采用的成本。

## 存储复用与同步资料

涉及 L0A/L0B 时，按[存储接口](framework/ub-storage.md)核对有效 `buffers`、槽数、
显式 `cube.l0_layout`、DAG/Python 声明、`allocation/version`、`operand_reads`
以及生产者和全部消费者。需要物理交接或提前读取边界时，另核对
[物理接口](framework/physical-execution.md)与[支持范围](framework/backend-capabilities.md)。
已有能力不表示当前候选已启用，公开资料不能确认的自动绑定保留为缺口。

- 空间复用表示不同值共用区域，仍需搬入新值；数据复用表示同一有效 tile/版本
  驻留并被多次使用。tensor 同名、shape 相同或共用槽位均不能证明省去搬入。
- 将逻辑使用者对应到实际 owner、物理槽或拟实现区域。同一区域只计一次，
  L0A、L0B 及不同 owner 的私有区域分别计量；不按 pool 数或 Cube 次数重复分配。
- 记录用户方案的槽选择、共享关系、搬入条件、首尾块与 task/group 边界行为及依据。
  无依据时不自行假定各 stage 独立使用 `task_id % slots`，也不推断组首必然重置。
- 槽身份不能证明硬件地址布局。已选方案写明大小、偏移、对齐与来源；授权选择时
  给出预算、格式／对齐约束、能力依据与布局证明要求。模型事实、拟实现方案和验证
  结果分别标明；固定预留、容量检查状态和运行峰值分别报告。
- 记录生产者就绪、全部消费者完成及下一写入的覆盖条件。仅在当前路径支持且明确
  启用时使用 `read_done` 边界；信用归还不等于数据就绪或安全覆盖。使用公开配置、
  用户实现或本次 trace 等可用证据，不要求所有后端提供 slot trace。

无 L0A/B 时仅相关绑定项注明不适用，生命周期仍覆盖 UB、L1、workspace 等实际资源。
关键布局约束、绑定或同步能力未确定时保留缺口；具体映射已获有依据的受约束选择时
不自动阻断交接。影响执行的新布局或同步方案需要重新核对验证证据的适用性。

## 执行算法与边界展开

为用户选定的算子方案写出从输入检查、参数构造、任务映射、资源初始化到搬入、
计算／状态更新、写回与完成的语言无关算法；纯 Vector 方案同样需要。顺序方案写
完整操作链，有流水承诺时展开启动、稳态、排空及工作项的索引、有效域与阶段偏移。

- 区分逻辑选槽／绑定、命令提交、物理可用权、数据就绪与释放。每项等待明确执行者、
  约束哪条操作的开始／读取／覆盖、发布者和代次；记录受阻时仍可推进的独立操作。
  保留候选已有的耦合与 pipe 顺序，不无据增加入口阻塞，也不承诺无条件并行。
- 按值／版本、有效循环域和分支定义实际消费者集合，释放等待全部成员的安全事件。
  短循环、尾块和空分支不套用满块计数；未生成的命令不成为等待对象，空集合也不能
  跳过尚未完成的生产者。无复用的资源仍须说明存续范围。
- 对会改变循环次数、消费者或槽复用的边界，展开实际工作项、事件、槽／版本和
  释放结果，包括适用的短任务、尾块、跨任务复用及排空；有流水承诺时包含旧消费者
  受阻的事件偏序。模式边界同时展开触发与不触发路径，不能只列测试 shape。

这些是用户算法的执行契约与文档推演，未执行时标明，不从仿真周期反推设备同步原语。

## 生成内容

1. 写清算子语义、接口、完整 case、硬件/成本和模型版本；引用完整语义与实现规格。
   核对所有输出、状态、模式与用户 VF 的步骤、归约轴、转换和写域，列本模型未覆盖项。
2. 从当前 DAG 生成数据通路，按需用[数据流图](dag-dataflow-graph.md)，保留
   GM workspace 与直接片上交接的差异，勿套用其他算子的模板图。
3. 列有效分核、tiling、阶段、slots、完整循环和首尾块规则。Cube 说明 A/B 切片、
   dtype/layout、L0C 初始化与 K 累加、FIX 搬出范围及条件；无 Cube 时注明不适用。
4. 按模板记录物理分配、操作数绑定、空间/数据复用、全部消费者与同步条件。
   依赖说明覆盖用户声明的 DAG、token、dataflow、门控和跨核关系，不能只抄边表。
   给出贯通输入到写回的算法及边界事件展开，逐项关联参数、全部存储的生命周期与等待。
   具体原语可在有依据的范围内授权选择；能力未知或事件关系未闭合时保留缺口。
5. 列实际搜索范围、固定项、失败证据和同口径结果。容量不可行、依赖环、死锁、
   超时、预算未覆盖与后端不支持分别记录；`needs_replay` 表示待回放，超时不等于死锁。
   单个候选失败不证明整类方案不可行。统计注明 owner、scope、单位与比值分母，
   服务周期累计不等于忙碌区间或墙钟，不能相加为完整 case 耗时或直接作为硬件利用率。
6. 分别列结构、资源、数学参考、实现精度参考、执行回放、后端和设备验证状态；
   引用实际证据，未执行写未执行。签名一致不能代替完整接口覆盖检查。

## 交付

写入用户指定目录的 `DESIGN.md`，已有文档按用户修改范围更新。包含模型/配置/结果
路径与复现命令，保持命令使用用户模型及安装 wheel。仅有软件示例或合成成本时，
明确其范围；不补写不存在的设备收益、校准资格或全局最优结论。
交接模型时核对语义、规格和运行说明及其相对链接；候选导出本身不保证这些文档齐全。
按模板逐项核对接口、承诺、执行算法、分配、同步与证据身份，交叉检查边界展开中的
消费者、槽轮转和释放条件，再填写交接结论。正文、表格与复用附件的版本及结论一致，
历史原件另存；这是文档交付检查，不表示已有自动验证器覆盖。
复现说明包含实际路径、工作目录、环境、完整命令/参数、预期产物和执行状态。
多 case 分派另列规则、输入域、参数构造、回退与逐 case 验证，不能把逐 case 最佳配置
直接拼成已验证的分派方案。提供命令或生成文档均不表示已经执行验证。

每项承诺给出输入／执行条件、通过判据及应拒绝的替代实现。数值、结构与性能分别
验收；仅分配多个 buffer 不证明流水重叠，数值相同的 GM 中转不能证明片上交接。
这些判断仅用于实际存在的承诺，不作为所有算子的固定要求。

写入接手规则：先核对范围、承诺、依赖与补证义务，再组织实现计划；范围内自主实现。
