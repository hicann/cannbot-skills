# 性能评估常见偏差

## 输入与评分范围

完整 shape、逐核 workload、最重核参数和单配置参数不可互换。先读取
`workload.yaml:parameters`，再核对实际 assignment、group/task 与尾块。
评估现有实现时固定其不可调的 tile/分核约束；探索不同 tile 属于待实现设计。
不要通过移动 split 文件或强改派生参数来改变入口语义。

同样任务数可能有不同计算/搬运量；位置相关 mask、稀疏和 gather 要保留实际任务 ID。
比较完整耗时使用 makespan，不能将每核耗时均值或 pipe 服务周期和当作端到端时间。

## 搜索配置是否生效

`ms_hooks.py` 的导入失败会触发告警并使 hook 能力降级。检查实际加载的 SEARCH_DIMS、
阶段约束及验证输入，不能只看文件存在。搜索参数全部固定时是单点评价；
只有一个 stage 时，`phases: search` 也可能只有一个合法划分。

`SEARCH_DIMS.tiles` 必须与参数维度同单位。任务数、token 数、行数不能互作上界。
检查候选的有效参数、实际工作量及覆盖记录，避免更小评分来自少算了数据。
结果含义与限制见[DAG 搜索](../framework/dag-search.md)。

## 硬件、缓存与 VF 成本

名称为 theoretical 的 profile 不保证算子侧 VF 公式没有拟合参数；两者分别核对来源。
声明 `tier: L2` 是路由假设，物理缓存命中另需精确身份、容量与逐出模型。
硬件切换后核对路由是否提供声明的 tier，不补造 WS 等未支持档位。

VF 实测、系数/公式和可选预测按[成本契约](../framework/vf-costs.md)记录身份与适用域。
预测成功不代表实测校准；缺实测时可按[VF 成本约定](../framework/vf-costs.md)
补有依据的估算并作探索性排序。确实缺少可执行成本时不能参与有效比较。
未建模的 launch、控制或跨核开销对短 case 更敏感，不用端到端残差任意补进某条 pipe。

## 验证与解释

Replay/SimPy 一致只证明相应模型实现的后端一致，不证明设备预测或数学正确性。
数值参考、执行回放、数量/容量检查及设备实验分别记录状态。

局部快但全核不快时，检查任务不均衡、共享带宽、归约及 fill/drain。
比较先统一 case、成本、硬件、scope 和执行策略；变化的模型候选保留各自身份。
反例及未评价项随报告交付，不能把预算结束写成全局最优。
