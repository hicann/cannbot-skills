# 模型验收与失败排查

由[新算子工作流](../new-operator.md)进入。输入是六份固定定义、完整 case、语义契约、
独立数量预期和已确认硬件；命令按[仿真说明](../simulation.md)选择适用入口。
检查结果分别记录，不以一项通过替代另一项。

## 验证顺序与覆盖

| 检查 | 做法与可接受证据 |
| --- | --- |
| 语义覆盖 | 对照所有输入、输出、状态、模式和 VF 步骤，列主图／辅助图／回退的覆盖与缺口 |
| 定义与引用 | 核对字段、表达式、dtype、生产者和真实消费者、信号与条件路径 |
| 数量与分核 | 从原语义独立推导任务、MAC、读写量和输出次数，对照 Assignment 与实际逐核工作量 |
| 执行与资源 | 完整指令完成、依赖时序、容量、版本及资源归还，保留 trace 与失败原因 |
| 数值 | 分开数学独立参考、实现精度参考、实际执行回放及设备检查 |
| 候选复评 | 将候选全部有效参数应用回模型，使用相同完整 case、硬件、成本及执行范围 |

从公开 shape 构造适用的单 task、多 task、多 group、尾块、空组／空输出与核未铺满
场景；有槽复用时覆盖回绕，有状态时覆盖初始化和最终写回。用实际输入重新 derive
并核对预期数量，不强改派生的 `num_groups/num_tasks`。无需为静态模型添加无关动态场景。

多组任务数允许不均匀，合法跳过不计真实计算；实际覆盖与请求覆盖分别列出。
Replay 与 SimPy 对照时核对双方硬件、有效参数及 scope，周期一致只证明后端一致性。
默认点通过后还要完成任务要求的分核和搜索复核；预算未覆盖的候选如实记录。

## 从症状定位下一步

| 现象 | 优先核对 | 修正后的复核 |
| --- | --- | --- |
| 数量少于语义预期 | case 是否完整、任务投影、尾块、条件输出和每 AIV 分摊 | 重新派生全部数量及输出覆盖 |
| 多 task／group 才失败 | 真实跨 task 依赖、全部消费者、槽回绕和驻留创建条件 | 单组／多组及边界 trace |
| 信号引用不存在 | 条件跳过是否仍声明输出、每个实际读者是否有正确输入 | 条件两侧及空输出路径 |
| 容量错误 | dtype、NZ／stride 物理跨度、有效 slots、每实例容量 | 精确边界及超容输入，保留失败候选 |
| 搜索变成单点 | 参数全部固定还是 hook 加载失败，维度与单位是否真正生效 | 检查告警、实际覆盖及有效参数 |
| 全部候选同分 | 图／工作量是否变化、瓶颈是否改变、scope 是否一致 | 选择有辨别力的边界，不制造周期差 |
| 数值回放不支持 | 实际布局、指令绑定和元素预算 | 在受支持范围验证并列出剩余缺口 |

并发问题按[生命周期指南](concurrency.md)核对；变换和实际读写量见
[搬运契约](../framework/transfer-contracts.md)。合法空实例不添加虚假占位计算，
也不通过删除消费者、容量或数据依赖来获得周期。

## 交付检查

每份独立模型或模板都有当前 `SEMANTICS.md`、`SPEC.md`、运行 `README.md`，引用实际
模型身份、case、命令及结果。固定配置独立于搜索文件可运行；候选导出后检查文档、
相对链接、用户 hooks 和外部成本依赖完整。共享文档仍需说明本模板差异。

报告实际执行、复用证据、失败与未验证项目。只做模型时设备项目标为未执行；
真实实现另按[编译反馈](../framework/compile-feedback.md)和设备流程验收。
