# 依赖与缓冲声明检查

输入是用户模型的循环、任务、版本和缓冲声明。语法见
[DAG YAML](../framework/dag-reference.md)及[存储接口](../framework/ub-storage.md)。

## 输入要求

- 每个读取引用真实生产者；不同子块、task 和 group 的值保持身份区别。
- `after/signals/inputs/dataflow` 只表达实现要求的依赖，不由相邻时间戳反推。
- `pool/use_pools` 覆盖真实写入与全部读取，声明的 scope 与 loop/group/task 范围一致。
- 驻留值只在真实生产时声明，跨 task 版本、槽位与尺寸完整匹配。
- 条件省略的生产者不能继续作为输出；空任务不等于可以删除必要控制或数据关系。
- 原地覆盖、递推累加和组间复用须有相应公开字段，槽数不能替代正确性要求。

Python Stage 通过 `build(context)` 返回同样的 DAG 声明，见[Stage 接口](python-stages.md)。
不依据默认执行效果省略用户实现中必须存在的依赖。

## 调用与结果

以真实 case 输入覆盖单 task、多 task、多组、尾块、条件空路径和槽位回绕。
运行[完整 case](../python-api.md)，检查完成、输出覆盖、容量、版本和适用数值状态。
失败时保存输入、错误及 trace；修改后对同一组输入复评。

## 限制

一次运行完成不能证明任意输入正确。模型通过不证明设备源码具有相同同步保护。
不支持的 owner、区域或控制组合应明确记录，不修改安装包或删除约束绕过错误。
