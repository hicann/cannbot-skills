# 建模前的硬件准备

先确定目标硬件及参数来源，再保存模型的 `hardware` 引用。已有模型评估沿用保存的
配置，显式覆盖优先；本机设备与目标不同不构成自动换型的理由。解析方法见[硬件配置](hardware.md)。

## 从现有信息确定目标

1. 优先采用用户给定的完整 SoC／SKU、配置和来源，核对它们是否一致。
2. 新模型没有目标时，可用环境已有、经官方文档或本地公开帮助确认的只读查询能力
   识别当前可见设备，并与所选 CANN 包的平台配置匹配。设备查询不启动计算任务。
3. 多设备型号不同、多个包来源冲突、SKU 不完整或关键参数缺失时，仅补问影响本次
   模型的缺项。不能按芯片前缀、核数相近或模板名称猜目标。
4. 无设备或无 CANN 时使用用户提供的资料及已有配置，分别标出已核对和未核对项。
   已知目标的模型仿真不要求为了探测而安装设备工具链。

本目录不提供源码仓的硬件探测脚本，也不假定外部用户安装了其他内部 skill。
只读核对之后仍缺少适用配置时，明确参数缺口和来源要求；不以演示 profile 冒充真实硬件。

## 记录来源与差异

| 项目 | 应保存的内容 |
| --- | --- |
| 目标 | 完整 SoC／SKU，用户指定或实际设备查询来源 |
| 软件 | toolkit、runtime、compiler、driver 各自版本与来源；未知单列 |
| 平台参数 | 精确 SKU 对应的 INI 相对路径、内容摘要及所读字段 |
| 硬件配置 | YAML 引用、版本／摘要、核数、AIV 配比、时钟与各存储容量 |
| 搬运参数 | 源／目的计费量、速率单位、时钟域及每 AIC／AIV／核组／整机范围 |
| 核验结论 | 设备观测、包内声明、假设／校准参数的区别；冲突及未核验字段 |

包来源优先用户显式选择，其次已配置环境与可唯一确定的安装入口。多个真实安装根
不能按目录顺序或版本名称随意选一个；同名平台配置内容不同也须保留歧义。
使用 `<CANN_ROOT>` 等占位符和相对来源，外发文档不带本机绝对安装路径、主机名或序列号。

不同组件版本不同不直接等于包损坏；同一组件多个来源冲突则须解释。
版本以元数据原文为准，不从目录名推断，也不维护固定版本白名单。
核数和频率相近不能证明 SKU 相同，包内容量声明不当作设备实测容量。

核对带宽时先统一单位和时钟域，区分每核与共享范围；UB 总容量、可用容量与
模型固定预留分别处理。只记录配置差异，不为使比较通过而自动覆盖已有校准参数。

## 进入建模与评估

将确认的配置引用保存到模型；基线、搜索、候选复评沿用同一内容身份。
逐路由核对生效机制及后端支持，普通或细化配置都不自动代表设备校准。
改变配置时保存原因、旧版本和新版本，重评受影响的基线与候选；模型变化不计为实现收益。
