# 统一搜索接入

本页统一说明固定 DAG 配置搜索和不同实现族的搜索接入。新算子建模、性能评估与
联合寻优按本轮任务复用本页，不重复启动其他工作流的完整过程。

## 输入与比较口径

已有固定 DAG 可直接搜索合法的分核、tile、阶段、slots 与发射策略，无需先改变结构。
探索新实现族时，先提供可运行候选，再搜索各族支持的配置，并复评完整 case。

继承调用方的完整 case、硬件内容、搬运与缓存假设、成本、后端、计时范围和预算。
借用搜索入口不调用 `resolve_eval_hardware()` 重新选型；独立评估才按
[硬件选择](../hardware.md#选择评估配置)确定配置。成本变更后重评基线与所有参评候选。
现有实现不可调的常量在原实现评估中固定，修改时登记为新的实现候选。

## 调用入口

选择模型搜索时按当前输入进入配置搜索或结构探索，再做完整 case 同口径复评，按需
实现实测。算子实现中的固定值不自动构成搜索边界，也不自动成为所有入口都能调整的参数。

| 搜索任务 | 安装后的入口 | 接入与限制 |
| --- | --- | --- |
| 固定 DAG 的 tile、slots 和阶段划分 | `python -m accel_model.app.cli.dag_run MODEL --config EXPERIMENT` | `parameter_space` 或 `SEARCH_DIMS` 声明维度；`phases: search` 枚举阶段划分；显式 `slots` 是固定覆盖，实际搜索覆盖以报告为准 |
| 有界阶段 × 参数/slots × 发射策略 | `accel_model.optimize.dag.search.joint_search` | 显式传入 `phase_candidates`、`parameter_candidates`、`issue_policies`；返回排名、audit 和 coverage，预算未覆盖单独记录 |
| 已声明的候选与实验 | `python -m accel_model.app.cli.graph_search --experiment EXPERIMENT --output DIR` | 输入符合当前实验类型，支持范围取决于模型声明；以返回结果确认覆盖 |
| 可用动作与候选导出 | `python -m accel_model.app.cli.graph_search --actions MODEL` / `--apply-action MODEL` | 先检查实际动作；应用时需新输出、动作 ID、证据、收益机制和新增代价 |
| 分核方案 | `python -m accel_model.app.cli.split_run MODEL --config EXPERIMENT` | 需真实任务与依赖；保留状态递推、原子任务及输出归属 |
| 固定候选集合复评 | `graph_search --experiment EXPERIMENT --output DIR` | 比较已提供的候选，本身不产生完整切分、缓冲或流水搜索空间 |
| 搜索会话 | `python -m accel_model.app.cli.agent_search` | 登记、评价、保留及记录预算；登记或基线评价不等于完成搜索 |

`joint_search` 接受显式阶段候选；不会自动应用 `phase_filter` 替调用者选择合法空间，
也不表示支持任意 stage body 变化。

流水优化优先在预算内联合探索合法阶段划分与缓冲深度。阶段候选必须完整覆盖已声明
stage；只有一个 stage 的模型不能声称比较了多种阶段划分。固定单阶段的 slots 搜索、
候选同分和单点重放均不证明阶段空间已探索。跳过某维度时记录具体原因及未覆盖范围。

接入先恢复已知可运行基线，核对候选参数确实改变了指令、映射或资源。记录声明空间、
固定维度及理由、已评价数量、实际 slots、发射策略、非法契约、容量/依赖淘汰、预算未覆盖
以及排名与快照。Top-K 截断不是完整网格统计；空结果或单点退化不能标记为搜索完成。
使用校准成本时冻结硬件和成本身份，不能为让入口通过而切换成理论成本或删掉检查。

新增或改变 VF 后，重新核对成本与实现、shape/dtype、调用次数及运行条件的绑定。
可用来源和预测排名支持见[VF 成本](../framework/vf-costs.md)；未知成本不参与有效排名，
不能用任意常数填补。外部预测不等于实测校准，具体搜索入口分别检查其证据资格。

## 目标、复用与多输入方案

沿用调用方的目标公式、业务约束、排序及修订，见[外部目标接口](../framework/objectives.md)。
固定 DAG 入口不自动支持 provider；入口能力不足时说明候选生成限制，再对已取得的
完整方案使用支持的会话／比较入口。业务优选未必耗时最小，分数不直接称为加速比。

仅改目标先对有效原始观察 `rescore`；普通 `evaluate` 仍实际执行并计预算。
执行身份失效或观察缺失时，按支持入口补评；不承诺跨会话或逐缺项自动复用。
继续规则搜索使用新运行 ID，实际覆盖与目标修订一起保存。

多个输入共同选优使用[统一规则](../framework/policies.md)，保留每个完整方案的全部
case 观察及排名／并列组；逐 case 最小周期诊断不能代替完整方案目标。
数据相关输入与有界控制按[场景和控制接口](../framework/runtime-control.md)选择；
参数分派、冻结输入条件与中间值控制的支持域不能互换。

## 复评与交接

固定候选比较不等于生成或搜索候选；发现动作、创建配置、登记会话也不等于已评价。
保存声明空间、实际生效变化、评价数量、失败原因、预算未覆盖项和导出候选身份。
只在当前声明空间与有效成本下报告最佳结果，不从 Top-K 表推断全局最优。

核验原目标完整 case、硬件、成本、有效参数、任务分配及 scope；已有证据满足本轮
身份和复核要求时可复用，否则通过相应入口重新加载候选补评。
普通聚合、局部 DAG、代表核与物理全核结果分开呈现；数值通过、成本资格与设备收益
分别记录。已导出快照绑定输入与硬件，变化后重新生成；模型导出不保证复制说明文档，
交付时核对 `SEMANTICS.md`、`SPEC.md`、运行 `README.md` 及其相对引用。

完整调用例子见[wheel 命令](../joint-optimization/wheel-commands.md)，固定 DAG 参数
见[优化指南](../optimization.md)，结构动作与快照见[图搜索](../framework/graph-search.md)。
联合任务的交接字段见[记录契约](../joint-optimization/workflow.md#记录与交付)。

新建模型默认普通带宽，接续实验沿用调用方配置。固定硬件服务率与物理容量，
搜索软件 buffer、分块、阶段和合法发射选择；等待用作对照实验线索，不回填硬件惩罚。
仅缺 VF 实测时按[VF 成本约定](../framework/vf-costs.md)补估算并继续探索，保留
不确定性及实际资格；估算无法形成或入口不支持时才报告相应缺口。成本更新后重评。
