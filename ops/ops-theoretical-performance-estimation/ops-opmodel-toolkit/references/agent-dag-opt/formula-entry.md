# 从公式开始建模与优化

输入应包含数学公式、张量形状、dtype、输出、状态与数值容差。
没有设备实现时，先按[新算子建模](../new-operator.md)创建可运行模型与独立参考。

用户模型保存在六份固定定义中；验证完整 case 后，再声明参数和方案实验。
可从数学语义提出融合、物化、分块、驻留或归约等不同用户方案，分别保存完整目录。
这些是待验证的模型选择，不能视作工具已经自动搜索过的空间。

使用[候选比较接口](../framework/graph-search.md)比较同一输入、硬件和成本下的方案，
通过[搜索会话](../joint-optimization/wheel-commands.md#图动作与搜索会话)保留假设、
尝试、失败及预算未覆盖项。超出当前接口能力时保存最小输入和限制。

没有生产基线时，将首个通过检查的模型作为实验对照，不报告“优于生产实现”。
只完成建模时交付模型、调用命令、结果范围和验证状态；用户请求设备实现时，
再将候选落实到实现并完成独立正确性与同口径设备计时。
