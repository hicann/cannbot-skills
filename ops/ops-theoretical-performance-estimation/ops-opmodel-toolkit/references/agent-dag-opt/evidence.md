# 候选结果与使用限制

输入为同一实验的基线、候选、case、硬件、成本和输出报告。
只有评价后端、数学语义、输入与范围一致的结果才能比较。

交付每个候选的模型目录、有效参数、任务量、周期、成本来源、验证状态和复现命令。
分别报告已完成评价、失败、预算未覆盖和仅登记的候选；固定点不算参数空间搜索。
`scored` 不自动表示数值通过、成本已校准或已取得设备收益。

VF 实测、系数/公式及可选预测按[VF 接口](../framework/vf-costs.md)记录身份。
预测排名、已验收排名和 recommendation 按实际字段分别说明，不由代理自行提升资格。
候选采用后，重新加载导出模型并运行原 case；数值与设备验收另行记录。

用[会话命令](../framework/graph-search.md)保存真实结束原因。
预算耗尽、暂停或没有新实验不表示全局最优；保留未尝试方向与失败输入。
更换成本、硬件、包版本、输入场景或候选文件后核验执行身份，失效证据须补评。
仅更换目标使用[目标修订与复用](../framework/objectives.md)，保留原评价 ID、来源、
实际复用记录及新目标修订，不改写旧签名或数值证据。

完整方案目标结果／并列组、原始耗时、数值、模型和设备资格分别呈现。
会话 `per_case_winners` 只是逐 case 耗时诊断，不能代替 provider 排名或打破并列。
`evaluation_identity_mismatch` 不能由业务通过覆盖；复用命中也不自动补足资格。
有场景或动态控制时核对实际输入、路径和覆盖；未执行项和未校准控制成本明确保留。

缺少 VF 实测与缺少可执行成本分别处理。按[VF 成本约定](../framework/vf-costs.md)
补有依据的估算后，可保存探索性排序，不要求先取得测量或生产资格；入口的实际
资格原样保留，不能手填通过标记。不确定性足以反转选择时保留不同候选，匹配实测
替换成本后统一重评。已有源码的作用域绑定成本须通过来源校验，失效来源不能继续评分。
