# 空泡分析与优化

输入为一次运行的 `result.json`、完整 `trace.json`、统计表和对应用户模型。
目标是解释可观察的空闲时段，并用新的模型实验验证优化假设。

## 取得并核对输入

完整 case 的调用见[Python API](python-api.md)，使用 `export_trace=True`。
物理命令通过 `--trace` 请求时间线。以 `result.json:artifacts` 找到本次真实文件，
核对 case、硬件、成本、参数、核/阶段和时间范围。
同时固定模型内容身份和当前成本；历史 trace 与新版模型不能直接配对归因。
trace 使用 cycle，普通 case 的 trace 可能只对应关键核，不能直接套完整 case 的总周期。

## 解读公开产物

在支持 trace-event JSON 的查看器中打开 trace，保留 pid/tid 或 engine 身份。
按用户要求记录目标管线、时间窗口、可见空闲区间和对应输入/输出事件，
对照模型的依赖、任务边界和容量声明提出待验证原因。
统计字段与范围见[结果分析](analysis.md)和[trace 接口](framework/runtime-and-trace.md)。

工具集不附带独立空泡分析脚本；可按[分解方法](dag-bubble-opt/pipe-gap-analysis.md)
使用已有查看器或用户项目中的分析工具核对原始事件。未计算的指标标为未取得，
不将 CSV 的指令周期总和当作墙钟忙碌时间。等待轨不属于计算管线的服务量。

动态 trace 另核对[实际场景与路径](framework/runtime-control.md)。解释动态路径能否比较时，
同时给出以下限定，不能只回答静态任务数不可比：

- 核对实际数据场景、路径、执行身份、核／阶段与窗口；跳过记录不计为计算、搬运或
  pipe 服务，静态任务数不代表实际执行次数。查看器未支持该格式时不据未过滤统计下结论。
- 分开归因路径／工作量变化与同路径性能变化；单路径不代表全部合法输入，不能把
  工作量减少直接称作调度优化成功。
- 条件观察早于指令开始本身不是错误；按真实控制依赖检查，不因此添加无依据的串行约束。
- 保留已声明的控制成本、成本来源和模型／设备资格限制；仅分析请求不启动实验或搜索，
  缺少路径证据时明确结论范围。

已有评价和 trace 的执行身份、场景、范围均有效时可复用；仅按新目标重排时使用
[重评分接口](framework/objectives.md)，不因修改公式重复仿真。单管线利用率不代替
完整任务目标；只分析请求不自动启动搜索。

## 实验调用与交付

在模型副本中改变一项合法参数或用户声明的方案，以相同 case、硬件和成本运行新目录。
参数搜索调用见[优化指南](optimization.md)，结构方案实验见[DAG 寻优](agent-dag-opt.md)。
交付输入与 trace 身份、观察范围、证据位置、待确认原因、实验结果及未解释部分。

## 从观察到对照

| 观察 | 需要核对的证据 | 可检验的用户模型变化 |
| --- | --- | --- |
| 大空泡周期性落在相同 task 边界 | 生产者完成、消费者开始、真实依赖及实际工作量 | 允许的分块或阶段组织 |
| 增加槽数仍无收益 | 限制来自数据／token 还是容量；槽是否实际使用 | 保留约束，选择能区分原因的配置 |
| 搬运跨度增长 | 逻辑量、真实读取、服务和等待各自变化 | 保持硬件参数，比较合法读取／存储方案 |
| VF 拆分后局部更快 | VF 调用合计、额外物化与图周期 | 对照完整计划，而非只取单次 VF |

每项实验保存父候选、单一变量 diff、预期变化窗口、反证条件及真实结果。
同时核对完整指令完成、消费者与资源回收、目标窗口及完整 case；无变化或回归
也记录否定了哪个假设。组合实验列明来源，不能把相关性写成因果。

## 使用限制

时间戳相同、其他管线繁忙或 overlap 较低都不足以证明根因或双缓冲是否有效。
公开 trace 未报告的状态保持未知，不从空闲时段推断未建模的设备状态或执行机制。
保留真实数学工作量、依赖、版本与容量要求，不能通过删约束缩短周期。
局部利用率提升不表示完整 case 更快；模型改善不自动表示设备收益。
详细报告口径见[空泡分析参考](dag-bubble-opt/pipe-gap-analysis.md)。

新建对照实验沿用已确认并保存的硬件配置，已有 trace 保留原模型。VF 缺实测可先按
[VF 成本约定](framework/vf-costs.md)估算并继续已授权实验，结论限定于该假设；
实测替换成本后重新生成受影响的基线和候选 trace。软件 buffer 与硬件队列容量
分开，后者保持固定。公开等待摘要见[时间线接口](framework/runtime-and-trace.md)，
等待总和不等于关键路径收益，不能据此下调带宽或增加统一惩罚。
