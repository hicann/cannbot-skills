# CPU 标杆生成与对齐

## 标杆要求

- **独立**：预期结果只由 CPU 路径生成，不读取 NPU kernel 的输出或中间结果。
- **清晰**：优先直接表达数学公式，可读性优先于运行性能。
- **确定**：固定随机种子、输入、初始化、状态和计算顺序，同一输入重复执行结果一致。
- **稳定**：需要时使用更高精度累加或数值稳定算法，再按接口约定转换输出 dtype。
- **完整**：返回值的数量、顺序、shape、dtype、layout 和状态语义与 `docs/api.md` 一致。
- **可复用**：`reference.py` 可由 CPU 单元测试及当前工程使用的测试代码直接调用。

## 对齐方法

先用结果可人工检查的小规模输入对齐公式、计算顺序和状态更新，再扩展到接口声明的代表性、边界和非法输入。用例只从 `docs/api.md` 的实际支持范围选择，至少覆盖适用的以下类型：

- 最小合法输入、常用输入和合法的非对齐边界；
- 可选输入、属性、模式和状态的不同分支；
- 有效区、无效区、尾部和 padding；
- 零值、极小值、较大值及其它数值边界；
- 支持范围之外输入的预期异常。

fixed/varlen、chunk、head ratio 等家族特有形态或参数，仅在当前接口支持时纳入对齐用例，不作为所有算子的通用要求。

存在用户参考实现时，先在小规模用例上比较两者。采用近似算法或不同计算顺序时，记录两边的计算顺序、结果差异和比较阈值依据，不能为使 NPU 实现通过而改写 CPU 标杆。

## 比较与证据

每个输出分别确定参与比较的区域、指标和阈值。接口未定义 padding 或无效区结果时只比较有效区域，并在 `docs/api.md`、精度策略和测试代码中使用同一规则。

实际运行调用 `reference.py` 的 CPU 测试，并在 `docs/validation.md` 记录执行命令、用例范围、随机种子或固定输入、结果和可复核证据。静态文件校验不能替代本次运行。
