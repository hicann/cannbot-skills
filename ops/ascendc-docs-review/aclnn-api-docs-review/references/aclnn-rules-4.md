# aclnn 领域质检规则 - 正确性检查详细说明

**重要提示：**

- 仅使用本文件中明确定义的规则进行检查
- 规则名称、规则级别必须与本文件完全一致
- 正确性检查必须读取代码文件验证，严禁推测

## 4. 正确性检查

**重要：正确性检查必须读取实际代码文件才能进行判断，严禁仅根据文档推测！**

| 规则名称           | 描述                                   | 级别 | 需读取的代码文件   |
| ------------------ | -------------------------------------- | ---- | ------------------ |
| API 函数原型一致性 | 检查文档中的函数原型部分与代码的一致性 | 严重 | aclnn_xxx.h |
| API 参数表信息正确性 | 检查参数表中输入/输出、描述、使用说明、数据类型、数据格式、维度shape、非连续Tensor等列是否与代码一致 | 提示 | aclnn_xxx.h, aclnn_xxx.cpp |
| API 调用示例与代码不一致 | 检查文档中的调用示例代码与test_aclnn_xxx.cpp文件内容是否一致 | 严重 | test_aclnn_xxx.cpp |

### API 函数原型一致性

- 级别：严重
- 位置：`## 函数原型`章节。
- 验证步骤：
    1. 在当前算子目录 Glob 读取 `aclnn_xxx.h`文件（如 `op_api/aclnn_addcmul.h`）如检测到同级目录下有对应头文件就检测，没有就不检测。
    2. 找到函数声明。
    3. 对比文档中"## 函数原型"部分的函数签名。
- 规则：
    1. 函数名是否一致。
    2. 参数类型是否一致。
    3. 参数名是否一致。
    4. 参数顺序是否一致。
    5. 返回类型是否一致。

### API 参数表信息正确性

- 级别：提示
- 位置：`## （函数接口）`中的`参数说明`表格。
- 规则与验证步骤：检测表格中每一列的子项是否与符合对应要求：
    1. `参数名`：
        - 一个参数只有在`## 函数原型`中对应有带"*"的，才被允许带"Optional"（参数名后缀），基础类型（int/bool/float/double）不允许带后缀。
        - 例如："int64_t seedOptional" 属于基础数据不允许带 Optional 后缀。
    2. `输入/输出`：参数定位与代码是否匹配？
        - 可选（允许传空指针，例如：带optional后缀，etc.）
        - 必选（不允许传空指针）是否正确。
    3. `描述`：参数含义是否与代码匹配（避免英文直译）。
        - 参数与“功能说明-计算公式”中的变量映射关系是否正确。
        - 内容是否表述完整。例如：参数 seedOptional 的描述为 "随机"，但代码注释描述为 "生成随机数的种子"，则属于描述不完整。
        - 比对方法 ：优先找aclnn_x.h头文件注释，再找算子op_graph/proto.h注释含义。
    4. `使用说明`：①空Tensor支持度是否符合代码；②取值范围是否符合代码
        - 比对方法：
            ①手动生成：一般从aclnn_xx.cpp看是否有判断空指令（isEmpty）
                ---看返回值，succes是支持，否则就是不支持。若没有，再搜索Empty字眼，看下是否判断空，若没有找到任何判断，视为放行空Tensor，即支持空Tensor
            ② 自动生成：tiling.cpp里看是否有判断空指令---同上
    5. `数据类型`：支持的dtype范围是否符合代码
        - 比对方法：
            ①手动生成：
                a) 优先找aclnn_xx.cpp，根据check_dtype等函数获取范围+约束（无论多算子还是单算子）；
                b) 若找不到（理论上属于软件bug），就去tiling函数里找check_dtype函数（涉及多算子，若找不到check_dtype，根据入参人为判断，现在工具无法支持）；
                c）前两者都没提dtype，以底层算子def.cpp为准
            ②自动生成：先def再tiling。从op_def.cpp里获取约束，dtype不允许交叉组合，一列就是一个组合场景（不涉及多算子组合场景，是什么就是什么）
    6. `数据格式`
        - 比对方法：
            ①手动生成：优先找aclnn_xx.cpp（尝试搜索format相关字眼），其次找tiling，不行再找def----若都没找到，默认ND格式（找有没有check_format，找不到大多默认ND）
            ② 自动生成：def和tiling （不涉及多算子）和dtype一致
    7. `维度shape`：支持的shape范围是否符合代码
        - 比对方法：
            ①手动生成：优先找aclnn_xx.cpp（checkShape_*合法等，有的GetDimNum()获取维数），其次找tiling--找不到，就是默认1-8维（关键词shape去搜索，依赖大模型判断）
            ② 自动生成：只有tiling
            ③调用多算子时：一般不会出现，对于融合算子场景，先判断op-api aclnn层有没有校验，有就不看算子的；没有再看底层多算子op-host里的tiling校验，取各算子shape约束的交集
    8. `非连续Tensor`：支持度是否符合代码
        - 输入类比对方法：
            ①手动生成：一般从aclnn_xx.cpp看是否调用Continous接口，调用creatViewTensor对应的条件下也是支持非连续的----找不到，就不支持。
            ②自动生成：def文件里有固定字段.AutoContiguous();
            ③调用多算子时：一般不会出现，看入口就行
        - 输出类比对方法：
            ①自动生成：当前所有默认都不支持，框架支持后可以通过def文件里有固定字段.AutoContiguous();
            ②手动生成：通过viewCopy接口来判断，调用了就是支持的
            ③调用多算子时：一般不会出现，看入口就行

### API 调用示例与代码不一致

- 级别：严重
- 位置：`## 调用示例`章节。
- 验证步骤：
    1. 在当前算子目录 Glob 查找 `test_aclnn_xxxx.cpp`文件（如 `examples/test_aclnn_xxxx.cpp`）如在当前算子文档的目录下查找到对应test cpp文件就检测，没有就不检测。
    2. 忽略代码文件的版权许可声明 header。
    3. 比较 <代码文件内容, 原文的调用示例> 一致性。比较结果为不一致则报错
- 规则：
    1. 代码文件内容与原文的调用示例是否一致。
