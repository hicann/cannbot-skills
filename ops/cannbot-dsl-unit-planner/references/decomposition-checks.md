# 可实现性与边界检查

规划时阅读本文件；字段见 [Unit 格式](unit-format.md)。

## 设计约束与实现选择

先区分资料中的强制承诺、允许选项、示意伪码和待定候选。只将强制承诺纳入 `design_constraints`；候选机制通过补证定选，不把所有候选同时冻结。约束应来自规格、用户要求或明确的设计结论，并指向实际章节。

数值语义与实现结构分别验收。设计规定的执行域、数据通路、同步、资源上界、精度域、复杂度和发布契约，不能只凭 Golden 通过证明。选项范围内的 API 替换或内部重构，可以由实现选择；改变强制承诺时返回设计，说明失败证据、替代路线、语义/结构/资源/规模影响和受影响 Unit。既有设计修订授权沿用，不增加泛化的审批要求。

设计是否允许逐步演进需明确：中间实现可只覆盖合法子域或部分调度规模，但必须保持该子域的数值语义与必需契约，并将最终机制分配给后继 Unit。子域最小数值闭环不必同时交付全域最终流水；若某机制不能后置且无法实现，应返回设计，而非扩大首 Unit 掩盖不可实现性。

## 关键能力在首次使用前闭合

从“待验证”“机制候选”“实现期定选”等条目中识别影响关键路径的事实。API 签名、单独编译和通用环境通过，不证明组合通路的设备语义。

每项前置补证记录设计依据、已有证据层级、待确认事实、适用环境/输入域、成功判据、首次使用动作和失败返回点。证据层级应与承诺相匹配：

- 组合计算和搬运需覆盖实际采用的数据布局、类型、形状与边界，而非空程序编译。
- 跨执行域交接需真实生产/消费及多代复用的可见性证据，单一执行域的程序序不能替代。
- 新原语或自实现算法需验证实际采用的转换、索引、mask、资源与复杂度。
- 发布/加载契约若影响前序工厂或 ABI，在首次真实路径先确认；全变体完整枚举留给全部能力完成后的 Unit。

规划引用已有证据或声明待补证，不虚写通过。补证归属于首次使用它的 Unit，证据落实为验证义务或明确的检查；孤立实验本身不冒充算子能力。失败后该能力的 `provides` 不成立，依赖它的后继不具备实现前提。已知失败且没有保留承诺的路线时，返回设计并重划，不能用“实现期定选”放行。

## 能力边界、依赖与保留面

“最小合法输入”指当前 Unit 所承接设计路径/能力在其适用条件下的最小合法场景，不是整个算子所有路径必须共用的一组数值。首个数值闭环覆盖设计选定起始路径的最小场景；后继或专用 Unit 核对自身新增能力的最小场景及前序保留面，不强求其阶段域包含不适用路径的样例。场景优先来自设计已有定义，或由冻结规格、设计参数规则和实际选型条件推导；保留来源与推导，不另建字段或固定表格。没有唯一最小值时给出有依据的最小闭环场景及适用限制，不虚构全局最小值。不能为避开边界、失败或工具限制事后改选输入；依据不足、与规格冲突或不能保留设计承诺时返回具体缺口。阶段子域不升级为算子公开限制，全部 Unit 仍完整承接设计。

首个计算 Unit 可限定布局、类型、分支和属性组合，明确取值与规模；当前子域必需的校验、数学语义、边界与初始化随闭环交付。其他合法域在 out_of_scope 指明后继归属。仅按接口分支名称宣布覆盖，不足以证明输入域完整。

独立流水框架要能验证实际执行域之间的数据交接、等待/释放和覆盖保护；若设计要求重叠，还需能够区分串行和重叠执行。后继计算引入后仍须验证框架成立。占位计算、阶段名称和不同断言类型不是独立能力的依据。

增量按可分离的交付能力与主要故障面组织，例如分块累积、边界安全、布局解释、可选语义或路径组合。前序行为与设计承诺保持，内部实现可以重构；记录受影响契约并回归相关能力。若前序只是假骨架、后继必然推翻其已验收结论，调整边界。

`dependency_reasons` 说明能力来源或设计要求的先后关系。能力依赖须满足完整输入域、输出、错误与生命周期契约，字符串匹配不足以证明兼容。正交能力不因编号或共享文件自动串联；实际修改文件写入 `scope.source_files`，未知路径保留空列表，不假定可以同时修改共享文件。

## 可区分验证与实际触发条件

先按当前测试入口的实际能力分配验证形式；scope.domain_constraints 与 verification_obligations.input_conditions 是不同契约，不能因域校验支持某个键就推断它也是合法 relation。输入条件采用测试生成 Skill 当前公开谓词，并由调用方在冻结前运行其只读 Unit 契约预检；无支持的判据或无法落实的义务须在当前阶段处理，不以结构校验通过代替接收兼容性。正常计算义务在规格合法域、Unit 阶段域和触发条件的交集中构造；明确要求的负向/域外行为按自身契约核对故意违反条件、其余前提和当前能力，不要求被违反条件同时满足正常合法域。来源未明确要求的拒绝或域外结果不新增为保证。

配套 `cannbot-dsl-test-generator` 的 TDD 仅接受 `match_golden` 或 `assertions`；错误码行为使用黑盒 `raises_error:<规格错误码>`，不写入 TDD 的 `verification_obligations`，也不包装异常成普通输出或新增 kind 绕过。Unit 在已有 `design_constraints` 或 `feasibility_checks` 的 `review_evidence` 中承接该要求，写明来源、公开验证入口/证据、负责阶段、通过判据及到期时机；所需黑盒由测试阶段按规格生成，不预分配 Case ID。引用用例 ID 不等于通过，实际执行证据须对应目标实现版本、输入和所要求错误；未执行不能宣称已正确拒绝。

安排应符合调用方现有权限与设计时机：当前源码检查与后续黑盒实跑各自说明范围；不因 TDD 不支持而延迟已要求的前置验证，不假定实现阶段允许执行黑盒。时机与公开能力/权限无法同时满足时，在规划阶段报告具体缺口，不扩展 runner 或越权执行。域外成功返回不等于异常拒绝，不能套用 `raises_error` 的域校验豁免；按实际返回语义和现有可表达方式安排。仅有错误码或证据检查的碎片并入负责能力 Unit，不为它伪造空壳数值义务；Unit 非空义务的原格式保持。

每项义务说明正确实现必须成立的行为、至少一种错误实现、输入触发条件和证据来源。若正确性依赖数值与结构同时成立，应明确要求同一次真实调用提供联合证据；分别通过的输入不能替代这一要求。

- 多块义务按实际参与计算的有效工作量跨块定义，不能用分配形状代替。检查后续块的只读输入生命周期、累积状态、重标定、写回与复用。
- 多槽义务按真实在途任务及复用代次定义；连续调用变化输入与形状，区分旧值复用。需要调用序列时写清顺序、状态存活期和每次结果的判据。
- 集合/去重/筛选义务使用非退化输入，使遗漏该步骤确实改变输出；退化输出不能证明实现了步骤。
- 结构承诺写入 review_evidence，指明源码、编译产物或外部设备采集来源、检查判据和错误实现的差异；不要求算子生成事件或 snapshot，静态配置不能证明实际时序。
- 规模检查算法复杂度、资源峰值和状态生命周期，耗时门槛只采用设计或用户提供值，并明确测量条件。

不能表达触发输入、调用序列或所需结构判定时，记录证据缺口交调用方处理；不以“关联了一个 TDD Case”替代义务成立。
