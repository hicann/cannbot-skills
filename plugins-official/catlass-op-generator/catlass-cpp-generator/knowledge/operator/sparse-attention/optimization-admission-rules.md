# 接口与概念

性能变换在本类算子上有三类常见否决理由：**精度**（在低精度域上多做了一次舍入）、**表达**
（原语粒度不允许合并的形状）、**口径**（测量分辨率不足以判定收益）。本条目把「这个改动能不能上」
变成可判定的准入清单，并给出「每窗口成本花在哪」的归因方法与负结论的记账方式。

# 用法

- 任何改写先问三件事：是否引入一次新的低精度舍入？是否落在原语可表达的粒度上？收益是否大于当前测量口径的分辨率？
- 逐元素因子（缩放、平移、掩码系数）不要提前乘进低精度操作数：那等于给每个元素多加一次该精度的舍入，
  误差经非线性（exp 等）放大后**同时**污染主输出与归约因子。要省这一遍，只能在同精度域内合并
  （或把因子折进后续矩阵乘的高精度累加），并先用精度回归判定。
- 合并/折叠类改动先判表达可行性：向量原语的步长与长度按 32B 块粒度约束，跨行等长尾段只要
  行距与段长不是块粒度的整倍数就表达不出来；边界残留的少量标量处理不可避免。
- 每窗口/每块对象的成本先归因再优化：用**只测量不交付**的消融逐个屏蔽单一动作（非线性、掩码遍、
  归约遍、暂存往返），每个消融单独构建、测完即回退，在设备侧口径上给出该动作的绝对成本。
- 负结论与正结论同等记账：记「为什么不可行」的依据（精度数据 / 原语粒度 / 测量分辨率），
  避免下一轮重复试探同一条路。

# 代码模式

```cpp
// 精度准入：逐元素因子留在同精度域内施加，不要预先乘进低精度操作数
// 反例（给每个元素多加一次 fp16 舍入，误差被 exp 放大）：qFp16 = (half)(qFp16 * scaleValue);
// 正例：在 softmax 内以高精度施加（或把因子折进后续矩阵乘的高精度累加）
AscendC::Muls(sFp32, sFp32, scaleValue, rowsInTile * cols);   // fp32 域
```

```cpp
// 归因准入：单动作消融只用于测量，测完立即回退，绝不进入交付
```

## 算子算法

- 本类算子每窗口的工作量 = 若干遍向量运算（掩码 / 缩放 / 减最大值 / exp / 类型转换）+ 若干遍归约读取
  + 暂存往返；每块对的边际成本是这些动作之和。
- 归因目标是把边际成本拆成三份：**向量 ALU、搬运（MTE2/MTE3）、同步等待**。三者的比例决定后续方向：
  ALU 占主导 → 只能靠跨段重叠或减少遍数；搬运/同步占主导 → 合并动作、减少往返。
- **量纲自检（做归因前置）**：pipe 占比里的「scalar/vec 时间」不一定是运算，**握手等待会被计入其中**。
  自检方法：按代码里数出的动作数反推每动作周期数 —— 若低于该硬件的物理下限（例如标量动作 < 1 cycle/次），
  说明该 pipe 时间里主体是「等」，此时按 ALU 占比做的优化决策会全错（典型误判：去向量化逐行标量）。
  正确做法是转向减少同步事件数与串行度（摊销宽度），或直接以「去掉该动作后总时长下降多少」为准。

## 分核策略与基本块切分

- 每窗口的边际成本与每次调用的固定成本要分开量：固定成本占比高时，改小 shape 收益明显；
  边际占比高时，只有减少每窗口动作数或跨段重叠才有效。
- **成本模型与口径（实测）**：每窗口成本 = 设备任务时长 / 窗口数，其中窗口 = 4 个 128-token chunk
  （计数时含 head 与 batch 维度，少乘任一项都会把每窗口成本高估数倍）。该成本在本算子上
  几乎与 layout/dtype/头部维度/GQA 无关（波动在个位数百分比内）—— 说明它由每窗口的**固定动作数**
  （逐行归约、逐行标量、每 tile/每窗口的同步与发射）决定，而不由字节数或 MAC 数决定。
  推论：省字节、省 MAC、省一遍普通向量运算这类改动没有空间；杠杆只有「减少每窗口动作数」
  与「跨执行单元重叠」两条。
- 分批驻留与分核调整都不改变每窗口动作数，因此不改善边际成本。

## 数据路径与存储层级

- 暂存往返（写 GM → 读回）是可在归因中单独屏蔽的一项：屏蔽后结果会错，但时间有效 ——
  只用于测量，不得进入交付。
- 低精度预乘的替代路径：在同精度域内合并，或把因子折进后续矩阵乘（其累加在高精度）——
  而不是折进低精度操作数本身。

## 流水排布、同步关系与数值精度

- 重叠（矩阵侧与向量侧并行）是本类算子最大的单项杠杆，但上限受向量侧占比约束：
  向量侧占约八成时，理论加速上限在 2 倍量级 —— 单靠重叠不足以补上结构性差距，必须同时压缩每窗口动作数。
- 精度回归永远先于性能测量：一次精度不达标的改动，其性能数据没有意义，也没有交付价值。
- 测量分辨率：共享设备上单次宿主墙钟 best 值抖动可达 ±20% 量级；小于该量级的收益必须用设备侧
  计时口径或长采样判定，否则结论不可复现。

# 约束

- 不允许用「数学等价」替代精度回归：任何改变舍入顺序或位置的变换都必须过精度门禁。
- 消融实验必须可回退、明确标注为测量专用，不得混入交付路径。
- 每次改动单变量；负结论必须落账（依据 + 判定），不允许静默放弃。
- 收益判定必须使用与验收同口径的量（设备侧任务时长）或明确声明的替代口径。

# 失败表现

| 触发点 | 现象 | 观测方式 |
|---|---|---|
| 把缩放因子提前乘进低精度操作数 | 主输出与归约因子同时越限，误差量级 ≈ 该精度一次舍入被非线性放大 | 精度门禁（比值口径）+ 同输入两次运行一致性 |
| 用「数学等价」跳过一次精度回归 | 越限在后续轮次才暴露，且难以归因 | 逐例比值表 + 与上一版逐位对照 |
| 强行合并不可表达的原语形状 | 要么编译不过，要么步长/长度被静默按粒度截断成错结果 | 原语规格核对 + 逐元素比对 |
| 用宿主墙钟判定小收益 | 同一配置多次 best 的抖动大于收益本身，结论不可复现 | 先做噪声基线，再换设备侧口径 |
| 未归因就优化 | 改动方向随机，多轮无效后仍不知瓶颈 | 消融表：动作 → 绝对成本 |
| 把 pipe 占比直接当算力占比做归因 | 按动作数反推的每动作周期数低于物理下限（不可能值）；据此选的方向（如向量化逐行标量）几乎没有收益 | 动作数 × 最小 cycle 与实测 pipe 时间对照；用单动作消融的实测差值校准 |

# 验证方法

- 准入判定三段：精度回归（先）→ 性能（设备侧口径）→ 表达/结构可行性（原语粒度与同步路径）。
- 成本归因：对每窗口动作做单动作消融（只测量不交付），得到「动作 → 成本」表，再据此选优化方向。
- 精度门禁：与冻结契约同口径的逐例比值判定；改变舍入位置的改动追加「同输入两次运行一致」检查。
- 负结论登记：记录判定依据与数据，供后续轮次直接引用而不必重试。
