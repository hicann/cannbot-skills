# 接口与概念

块稀疏注意力按「每窗口 / 每 chunk / 每块对」一项的方式分配暂存区，宿主侧的区域尺寸因此随问题规模线性增长。
这类尺寸一旦跨过 32 位字节边界，宿主仍然会「成功」返回，失败被推迟到设备侧以核内异常的形式出现，
症状与规模相关而与输入内容无关。本条目给出三条互为一体的问题模式：**尺寸计算的 32 位回绕**、
**按容量分批驻留时的 id 域纪律**、**异步执行下宿主元数据上传的隐藏竞争**，以及配套的验证与测量纪律。
判据来源见文末「验证方法」。[^sparse-attention-host-workspace-and-batching-patterns-source]

# 用法

- 区域尺寸与偏移全程按 64 位计算：先把每一项的乘积算成 64 位，再对齐；不要对中间结果做 32 位转换。
- 把「整次调用一次性驻留」改成「按固定容量分批驻留」：每批跑完整流水，暂存区尺寸与问题规模解耦。
- 切批只能落在任务边界（一个任务的全部窗口必须累加进它自己的状态），批容量按单任务峰值与暂存区峰值共同定。
- 跨批仍要求全局语义的表（任务累加状态、逐行因子、描述表、索引表）用全局 id 索引；
  批次内自洽的表（每窗口暂存）才可以用批次局部 id。
- 批次边界上传描述表/切分参数前，先与已入队 kernel 建立顺序（边界同步，或带 stream 的异步拷贝
  并保证源缓冲在拷贝完成前不被改写）。

## 算子算法

- 暂存项与规模的关系是「每窗口一项」量级：窗口暂存（S/P）、逐行因子、输出暂存、索引/描述表。
- 区域字节数 = 项数 × 每项字节数；当「项数 × 每项字节数」跨过 2 的 32 次方，任何 32 位截断都会把尺寸
  或偏移变成回绕值（可能是 0，也可能是部分回绕的小值），宿主照常分配一个偏小的缓冲。

## 分核策略与基本块切分

- 分批是调度层的约束，不改分核与基本块切分：核数、每核任务分配、基本块形状都不随批容量变化。
- 批容量由暂存区峰值决定（而非核数）：容量必须至少覆盖单个任务的全部窗口，
  否则一个任务的累加状态会被拆到两批里而失去累加语义。

## 数据路径与存储层级

- 整次调用驻留 = 一份随规模线性增长的 GM 大缓冲；分批驻留 = 每批一份按容量定尺寸的 GM 暂存 + 边界同步。
- 全局语义表（任务状态、逐行因子、描述表、索引表）保持全局驻留与全局寻址；批次本地表按批容量驻留。
- 分批改造改变的是「谁和谁在同一批」，不改变任何表自身的数据布局。

## 流水排布、同步关系与数值精度

- 批次边界是流水上的新同步点：上一批的全部发射完成并读完元数据后，才允许改写下一批的描述表。
- 分批本身不改变每次调用的数学语义（批内四段顺序、累加顺序均不变），因此不引入精度差；
  但凡批次尺寸/边界逻辑一旦出错，表现为「精度下降但不崩」而非报错（见失败表现）。
- 小效应改动前先建立可分辨的测量口径：共享设备上单次宿主墙钟的 best 值抖动可达 ±20% 量级，
  小于该量级的收益必须用设备侧计时口径或长采样才能判定；每轮改动先过精度回归，再看性能。

# 约束

- 区域尺寸与偏移的计算链路里不得出现 32 位截断（含对乘积的转换与 32 位对齐宏）。
- 分批不得切开一个任务；批容量下限 = 单任务窗口峰值。
- 边界元数据上传必须与已入队 kernel 有顺序关系；宿主同步拷贝与已入队 kernel 之间默认无序。
- 跨批累加状态一律全局 id 索引；批次局部 id 不得用于全局语义表。
- 规模边界用例必须覆盖「区域字节数跨过 2 的 32 次方」的规模点，且分批正确性必须用多批用例回归。

# 失败表现

| 触发点 | 现象 | 观测方式 |
|---|---|---|
| 尺寸按 32 位截断，字节数跨过 2 的 32 次方 | 宿主分配「成功」但偏小；设备侧核内异常，宿主无报错；成功/失败边界恰好落在字节数 = 2 的 32 次方对应的规模点 | 同步返回码 + 按规模扫边界定位阈值 + 宿主侧 dry-run 打印各区域尺寸 |
| 同一尺寸表达式被多个区域复用 | 多个区域同时受影响，阈值各不相同（= 2 的 32 次方 / 该区域每单位字节数） | 逐区域独立 dry-run，与实跑边界对照 |
| 分批后 id 域混用 | 单批用例全对、多批用例错；错误集中在跨批任务的累加状态 | 多批与单批对照 + 逐任务状态比对 |
| 批次边界元数据被提前覆盖 | 精度下降但不崩，且只在多批时出现 | 多批与单批对照；边界加同步后立即恢复 |
| 用宿主墙钟判定小收益 | 同一配置多次 best 抖动达 ±20%，判定结论不可复现 | 先做噪声基线，再换设备侧口径 |

# 验证方法

- 尺寸正确性：宿主侧 dry-run 打印每个区域的项数、每项字节数与对齐后字节数，先证尺寸，再发车实跑。
- 规模边界：按「2 的 32 次方 / 每单位字节数」反推临界规模，构造恰好跨过阈值的用例，实跑验证不再出现核内异常。
- 分批正确性：至少一个多批用例（覆盖单任务峰值以上）+ 单批用例对照，逐任务状态比对。
- 地址宽度排除性探针：在超过 4 GiB 的分配内，对 2 的 32 次方附近及更高偏移做标量读写与
  GM↔UB 搬运、fixpipe 写，确认无回绕 —— 用于把「尺寸截断」与「地址宽度/索引位宽」两类假设区分开。
- 测量纪律：每轮单变量改动，先精度回归后性能；性能一律用设备侧计时口径，并在改动前后给出
  同一口径的边际成本与固定成本两项。
