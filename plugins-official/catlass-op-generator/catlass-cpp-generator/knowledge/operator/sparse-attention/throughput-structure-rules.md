# 接口与概念

本 concept 面向"主 kernel 每保留块对有效算力偏低（约为高吞吐结构一半）"类问题的结构优化：
归纳高吞吐流水在同步粒度、组宽分工、累加器分层、操作数驻留与事件密度上的设计规则。
证据为**静态调查事实**（源码可见学习，取证记录由提取侧独立保管）；迁移效果必须实测。
本 concept 不含实现仓路径、行号或可读取链接。

## 算子算法

**静态调查事实**：高吞吐结构的核心是把"每块对一次跨核同步 + 每块一次中间产物回写 +
每块重搬操作数"改造成"每组同步一次 + 可调写回深度 + 操作数按驻留层级复用"。
块稀疏先经预处理压成紧凑索引，内层按索引 gather 后退化为 dense GEMM——发出的 MAD 全部是
有效算力，无掩码空洞。参考实现按此结构达到的每块对有效算力约为朴素结构的两倍。
[^sparse-attention-throughput-structure-rules-source]

## 分核策略与基本块切分

**静态调查事实**：三种"组宽度"各管一件事，彼此独立可调：

- QK 的 N 宽 = 1 个保留块（中间产物 S 的写回单位天然是它）；
- PV 的 K 宽 = 2 个保留块（组内累加后一次写回，回写量与 GM 流量减半）；
- 同步/gather 单位 = 4 个保留块（栈宽：gather 循环、跨核标志、环形槽位、发射开销
  全部按栈摊销）。

**设计规则**：写回深度取"能整除累加器容量与带宽的第二维"；同步摊销宽度取"能整除片上
缓存预算的 KV 宽度"；两者不要绑成同一个参数。[^sparse-attention-throughput-structure-rules-source]

## 数据路径与存储层级

**静态调查事实**：操作数按"变化频率"分层驻留——

- 不随内层循环变的（Q）常驻专用 L1 区，每任务一次搬运；
- 随组变的（K/V/P）按组批量 gather，每保留块一次大粒度搬运；
- 布局分形化（Nd→Nz、行主→zN）交给搬运单元的直通转换，不经 UB 中转、无独立转置指令；
- 相邻保留块拼接进同一 L1 tile 的列空间，块间无空洞。

累加器分层：L0C 内 fp32 按组宽累加、每组合并一次写回；O 的 fp32 累加器驻留 UB，
整段 KV 结束时才归一化并写 GM 一次；分组间的 rescale 因子经 UB 环形槽跨 epilogue 传递。
[^sparse-attention-throughput-structure-rules-source]

## 流水排布、同步关系与数值精度

**静态调查事实**：错位软件流水——生产端组 g 与消费端组 g−d 同轮推进（参考实现 d=2），
环形槽数 = d+1，槽索引 = 组号 mod 槽数；生产端的领先深度直接决定可容忍的跨核延迟。
跨核可用性用"数据落地 pipe"表达（生产者以落地 pipe 置位，消费者据此等待），组内连续
发射、组间才同步；参考实现每栈仅 3 次跨核置位、生产端每栈仅 1 次等待。
核内每块对约十余个 ping-pong 事件；全部 pipe 事件在启动时预置一次（首块零等待）。
**规则**：跨核同步粒度必须 ≥ 消费者延迟 / 生产者单块耗时的比值；用"槽位距离"取代
同步次数。[^sparse-attention-throughput-structure-rules-source]

# 用法

主 kernel 每块对吞吐偏低（两倍级差距、成本在保留块数上线性）时，优先逐条核对本 concept
的七条规则定位结构性缺口；优化按单变量 PRE/POST 推进，正式结论用配对协议验收。
本 concept 为结构规则，不提供任何性能承诺。

# 代码模式

七条可迁移设计规则（静态调查事实）：

1. **同步粒度分级**：核内数据依赖靠程序序；矩阵产物跨核按"组"同步一次；组内连续发射。
   参考量级：每栈 3 次跨核置位、每块对 0.75 次；生产端每栈 1 次等待。
2. **解耦流水**：生产组 g 与消费组 g−d 同轮；环槽 = d+1；领先深度决定容忍延迟。
3. **多组宽度分工**：写回单位 / 累加宽度 / 同步摊销三者独立取值（见分核策略节）。
4. **累加器分层**：L0C 组内累加、每组合并一次写回；O 驻 UB、末尾一次落盘；
   rescale 因子走环槽传递。
5. **驻留层级**：不变操作数常驻专用缓存；变操作数按组批搬；布局转换交搬运单元直通。
6. **稀疏→压缩再 dense**：紧凑索引 + 相邻块拼进同一 tile，消除空洞算力。
7. **事件密度与启动**：每块对只留必要的 ping-pong 事件；启动预置全部 pipe 事件；
   向量侧保持"读一次中间产物、写一次结果"的单趟结构，其耗时须小于生产侧每组耗时
   （否则加大领先深度）。

**已知代价点（迁移时不要照抄）**：参考实现存在若干可改进项——随组操作数的单缓冲限制
（下一组搬运须等本组消费完，靠等待窗口遮盖而非真预取）、驻留操作数每块重复的 L1→L0
装载、每块一次阻塞式计算就绪配对（无双发）、以及槽尺寸远大于实际需要的 workspace 分配。
迁移时按自身资源预算重新推导。

# 约束

- 组内多块一次写回必须用"首块初始化累加"的条件显式表达，不得每块写回后重装。
- 共享缓冲/中间产物的跨核可用性必须以落地 pipe 的事件表达；环槽数量必须 = 距离 + 1。
- 全部 pipe 事件预置必须在一次性全核同步之后、主循环之前。
- 任何组宽/槽数/距离的改动按单变量处理并重新全量精度与性能验收。

# 失败表现

- 每块对跨核往返同步：利用率上限约 50%（同步延迟叠加在单块计算耗时上），
  成本在保留块数上呈线性——与"固定开销相近但每块边际成本约两倍"的实测指征吻合。
- 每块回写中间产物：写回带宽与事件数量倍增。
- 每块重搬驻留操作数：搬运带宽被重复数据占用，生产侧装载窗口受挤压。
- 稀疏掩码参与内层计算：有效算力按稀疏比例打折，且成本随保留数非线性。
- 启动不预置事件：首块幽灵等待或死锁。

# 验证方法

1. 统一性能口径（设备任务时长、同卡同输入、预热/采样、逐例配对）测单变量效果；
   用"固定项 + 每块边际项"分解定位吞吐瓶颈（边际成本比值的倒数即有效算力比）。
2. 每块对成本应在保留块数上线性；外推与实测偏差大说明仍处固定开销主导区（小 shape 的
   平局不能外推到大 shape）。
3. 迁移后按精度-性能双验收：全量精度回归 + 配对性能；声明覆盖范围与适用条件。
4. 本 concept 规则来自静态调查；未实测的迁移不得写成已验证收益。
