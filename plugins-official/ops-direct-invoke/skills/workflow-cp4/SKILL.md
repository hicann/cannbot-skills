# CP4 性能验收验收标准

本验收点判定**算子性能是否达标**，即基于算子代码与性能数据，性能是否满足需求文档声明的预期。按需求文档的**评测来源模式**选择验收口径：模式 A 以评测集 HAP 评分为最终裁定，模式 B 以自建性能采集（msprof op）数据对照需求文档的可量化指标判定。

## 验收对象

算子代码 + 性能数据（基于功能验收通过后的最终代码采集；模式 A 为评测集评测报告的 HAP 得分，模式 B 为自建性能采集框架的耗时/带宽/利用率数据）。

## 通过指标

以**性能实测数据对照目标**判定，不凭主观印象：

- **指标达标**：实测关键指标达到需求文档声明的性能预期。模式 A 以 HAP 阈值表述（默认 ≥ 0.5 即性能不低于 baseline；HAP 是饱和型指标，详见 `repo-knowledge` 的 evaluation-contract.md）；模式 B 以耗时/带宽/AI Core 利用率等可量化指标表述。
- **覆盖关键 shape**：性能数据覆盖需求关注的典型 / 竞品 shape（模式 A 评测器自动对通过精度的用例采集性能，模式 B 由自建框架覆盖需求关注的 shape/dtype），非单点数据。
- **数据可信**：采集环境（芯片架构、CANN 版本、采集工具）明确记录，**取值以 `.cannbot/环境信息.md` 为准**，数据可复现（模式 A 评测集 `--eval-seed` 确定性 / 模式 B 固定输入与 warmup）。测量方差显著的用例（跨轮波动跨越达标门槛）须记录多轮取值与离散度，以稳态中位数裁定，不以单次最优值判达标。
- **瓶颈维度已实测锁定**：性能数据含瓶颈维度分解（计算 / 搬入 / 搬出 / 标量各自的占比或耗时），据此锁定实测瓶颈维度；与开发方案「瓶颈维度预判与校准」节的预判**矛盾时以实测为准**——QA 在报告中标注矛盾，并把「回填实测校准结论、按实测瓶颈重排优化项优先级」列入修改意见。缺瓶颈维度分解者，性能数据判为不完整。
- **方案优化项已核对**：开发方案「性能优化项」节中落地要求为「必落地」的条目，均已在落地状态列标为已落地，或已记录放弃原因；存在未落地且无原因的必落地项，判为未按方案实现（归属算子实现）。
- **数值路径改动已过精度门**：本轮落地的优化项中标注「改变数值计算路径」为是的条目，须附权威精度断言的执行结果（判定指标实测值 vs 阈值）；缺结果或不达标的，该优化项判为不可采纳，须回退。
- **模式 A 附加**：无因锚点非法（$T_{cand} \le 0$ 或 $T_{HW} \le 0$）导致的 HAP=None 异常（异常时该用例不计入性能项，但须核查根因）。
- **通过条件**：指定 shape 集上的关键指标全部达标。判定形式为"实测值对照目标值，客观数据裁定"。

## 验收步骤

加载本 skill 时执行：

1. **按评测来源模式采集性能**：
   - 模式 A：执行评测集评测（含性能）：`run_evaluation.sh --source-dir <提交目录> --operator <Op>`（或 docker 等价命令）。
   - 模式 B：用 3.2 搭建的自建性能采集框架（`ops-profiling` msprof op）跑出性能数据，覆盖需求关注的 shape/dtype。
2. 核对性能数据的采集环境记录是否完整、可复现。
3. 核对性能数据是否覆盖指定的关键 shape 集。
4. 将各关键指标实测值对照需求文档目标值逐项裁定（模式 A 对照 HAP 阈值，模式 B 对照耗时/带宽/利用率指标）。
5. 对未达标项做瓶颈分析（计算 / 搬入 / 搬出 / 标量的占比与理论值对比），锁定实测瓶颈维度，并与开发方案的瓶颈预判对照，矛盾即标注。
6. 核对方案「必落地」优化项的落地状态，以及本轮改变数值计算路径的优化项是否附有权威精度断言结果。
7. 存在未达标项时，先过**杠杆评估门**（见下节）再定结论；随后产出性能验收报告。

## 杠杆评估门（未达标时的必经步骤）

指标未达标**不等于**应当继续回退优化。回退前先评估「本轮之后是否还有未试的实质杠杆」，避免在收益趋零的方向上重走整条复验链。

1. **列未试杠杆清单**：逐条给出——杠杆描述、面向的**实测**瓶颈维度、预期收益量级、未试原因。清单只收录与实测瓶颈维度匹配的杠杆；面向非瓶颈维度的方向不计入。
2. **排除已证伪方向**：已有负结果记录的方向（硬件不支持 / 舍入语义不等价 / 编译器调度劣化 / 近似误差不可接受等）不得重复计入，逐条注明其负结果出处。
3. **判定**：
   - **有实质杠杆**（清单非空，且至少一条预期收益量级足以跨越差距）→ 结论「不通过」，按修改意见回退优化。
   - **无实质杠杆**（清单为空；或仅剩预期收益量级明显小于差距的微优化；或全部候选方向均已有负结果）→ 结论「不通过（实现级优化已穷尽，建议按已知限制收口）」，**不再回退**，结论随报告回传调用方，转由用户决策。
4. **越权边界**：接受未达标项为已知限制，是对需求声明的硬门槛的放宽，**超出本验收点的裁定权限**——只能给出「建议收口」的结论与完整依据，不得自行判定为通过。依据须含：实现级优化穷尽的证据（已落地项 + 负结果项）、设计级方向与实测数据矛盾的证据（若适用）、未达标项与门槛的量化差距。

## 输出

本验收点产出**性能验收报告**，引用 `workflow-doc-templates` 的 `CP4-性能验收报告` 模板组织：

- **通过**：报告结论明确为"通过"，附测试环境、性能数据、瓶颈分析（含实测瓶颈维度与预判的对照）、指标对比（模式 A 含各用例 HAP 得分）。
- **不通过**：报告结论为"不通过"，并给出**结构化修改意见**——
  - 问题定位：给出瓶颈分析，定位到未达标的具体指标与 shape（模式 A 标注 HAP < 阈值的用例）。
  - 未试杠杆清单：本轮判定所依据的杠杆评估结果。
  - 问题语义归属：算子实现（性能未达标 / 必落地优化项未落地）；若瓶颈根因在上游设计，标注归属于开发方案设计，仅给定位结论、不自行改动切分策略；若实测瓶颈与方案预判矛盾，一并列出「回填实测校准结论并重排优化项优先级」的修改要求。
- **不通过（建议收口）**：报告结论为"不通过（实现级优化已穷尽，建议按已知限制收口）"，附未试杠杆清单（为空或仅剩趋零微优化的证据）、负结果记录、未达标项与门槛的量化差距。该结论**不触发回退**，作为需求级决策随报告回传调用方，由用户裁定。

报告作为中间交付件随验收结果一并返回。只验收不执行开发动作；允许做瓶颈定位，不自行优化代码、不变更上游 Tiling / 切分设计决策、不自行放宽需求声明的性能门槛。
